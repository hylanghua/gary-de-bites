AI 方向观点

Every.to：AI 工作正在一分为二——调度 agent 的人与被 agent 重塑的人

Every.to 本期的核心论点：AI 时代的工作正在形成两条分叉轨道。一条是"agent 驾驭者"——这类人把 Anthropic 的 agent push、ChatGPT 作为项目经理等工具当成杠杆，把自己的时间用在决策和方向上，把执行交出去。另一条是"被 agent 重塑者"——他们的部分工作职能正被逐步取代，且往往在这个过程中没有足够的时间适应。

Anthropic 自己的内部数据提供了最直接的佐证：工程师们普遍描述自己的角色正在从"写代码"切换到"管理 AI"，估计工作重心已有 70% 以上转向代码审查和修订，而非净新代码输出。这不是一个缓慢的渐进过程，而是一次可以在短时间内感知到的职能重心平移。文章还提到生物技术领域的乐观情绪：对于那些愿意把 AI 当工具箱的研究者，drug discovery 的速度正在加快，而不是让人担忧被替代。当"调度 agent"和"被 agent 调度"的差距不再是技能差距而是心态差距，培训方案就需要完全重写。

Dan Shipper（Every 创始人）：跑出差 benchmark 不等于工具差——测评需要技巧，不是点击

Dan Shipper 直接批评了一种在 AI 工具评测圈子里很流行的报道模式：拿出一个工具，随便测一测，发现表现不好，然后写"某工具测试失败"。他的论点是：当前许多工具的评测结果高度依赖测试者有没有真正懂得如何用 prompt 引导模型，基准测试（benchmark）的成绩和工具的实际能力之间存在一道"prompt 工程技巧"的门槛。换句话说，结论是"工具差"，其实可能是测试者差。

这个批评的锋芒指向了科技媒体和 AI 评测内容的一个系统性盲点：发表"X 比 Y 差"的文章比解释"我是这样用 X 得到好结果的"要容易得多。Shipper 认为，真正的工具评测应该包含测试者的 prompt 工程水平披露，否则数据不具备参考意义。当工具能力和使用技巧紧密耦合，"做评测"本身就需要成为一种需要学习的专业技能。

产品与商业

Eric Ries（《Lean Startup》作者）：80% 创始人三年内被换掉，《Incorruptible》告诉你 Anthropic 和 Costco 为什么是例外

Eric Ries 的新书《Incorruptible》核心论点是"成功是公司腐化的起点"，而非保障。他在 Lenny 播客中给出了具体数字：约 80% 的风险投资支持创始人在上市三年内被换掉。原因不是能力不够，而是成功之后公司的治理结构没有跟上：董事会开始用不同的标准衡量你，投资人的利益开始偏离使命，市场压力开始侵蚀最初让公司与众不同的东西——他称之为"金融重力"（financial gravity）。

Ries 举了几个真正做到防腐的案例：Anthropic 用公共利益公司（public benefit corporation，即法律上要求公司兼顾股东利益和公共利益的一种公司形式）架构保护使命；Costco 用稳定的管理层文化抵御华尔街季度压力；Novo Nordisk 用以患者为中心的目标约束商业化冲动。这些不是"价值观口号"，而是通过具体法律文件或组织结构写死的保护机制。他还提到一份两页纸的特拉华州法律文件，可以帮助创始人在公司规模化前就锁定治理框架。治理结构是防腐层，不是锦上添花——等到成功之后才想起来，已经来不及了。

Garry Tan 发布了 GBrain v0.31.1 的 changelog，核心更新是引入了 MCP（Model Context Protocol，即让 AI 模型能够连接外部工具和数据源的标准协议）的瘦客户端（thin client）支持。瘦客户端架构意味着 agent 的工具调用逻辑可以运行在集中式服务端，而非每个用户端各自维护。这在实际部署上的含义是：更新和权限管理可以在服务端统一控制，降低了 agent 工具链的维护复杂度。agent 同时对这次 changelog 记录表示了积极响应——一个 agent 主动引用了另一个 agent 编写的版本记录，是少见的 agent-to-agent 互动场景。MCP 瘦客户端是 agent 基础设施走向集中管理的一步，平台层的控制权正在悄悄集中。

人文与哲学

Peter Yang（产品人）：AI 生成内容的递归降解——初始 5% 的错误在自引用循环中复利到 10%+

Peter Yang 指出了一个在 AI 大规模内容生产中被低估的质量风险：当模型开始大量引用其他模型生成的内容作为训练数据或信息源，错误会以复利方式累积。初始 5% 的错误率在第一轮自引用后不会保持 5%，而是被放大。一个错误被引用一次，就成为下一批输出的"事实"，循环往复，质量下降曲线陡于直觉预期。

这不是理论担忧，而是在内容生产已高度依赖 AI 的领域（科技新闻、产品文档、学术摘要）正在发生的现象。Yang 没有给出解决方案，但问题的表述本身已经足够清晰：当"AI 写的"和"AI 引用 AI 写的"在训练集里无法区分，人类的原始输入作为质量锚点的价值正在急剧上升。AI 生成的内容如果没有人类的原始锚点做校验层，互联网正在变成一个持续放大错误的回音室。

AI 进展

ARIS：多模型对抗协作的自主科研框架，专攻"貌似成功但证据空洞"

现状：自主 ML 科研系统（让 AI 自动提出假设、跑实验、写论文）的核心失效模式不是明显报错，而是生成"看起来有道理"但实际证据不充分的结论——长时间运行的 agent 会默默沿用执行层的错误框架。

问题：现有框架缺乏跨模型的批判性审查层，单一模型很容易"自我说服"。

解决方案：ARIS（arXiv:2605.03042）引入三层架构：执行层（65+ 个可复用 Markdown 技能 + 持久研究 wiki）、编排层（五类端到端工作流，可路由到不同审查模型）、保障层（三阶段实验结果核查：完整性验证 → 结果到论断映射 → 逐条交叉审计，加上数学证明检查和 PDF 渲染目检）。

价值：ARIS-Code 是一个基于 Rust 的独立 CLI，支持五家 LLM 提供商，本地交互式运行，所有保障层逻辑内置——不依赖人工监督即可做到跨模型批判性审查。

未来方向：随着 AI 科研自动化程度提升，"谁来验证 AI 写的论文"会成为学术界的基础设施问题，ARIS 这类对抗性协作框架是目前最接近实用的答案之一。

GenericAgent：Token 高效自演化 agent，每次成功任务自动提炼为可复用 SOP

现状：大多数 LLM agent 每次执行任务都从零开始，既不积累经验，也不能随使用时间增长变得更高效。

问题：长时间运行的任务上下文膨胀（context explosion），token 消耗指数级增长，信息密度随之下降。

解决方案：GenericAgent（arXiv:2604.17091）用四个机制解决这个问题：精简原子工具集（9 个工具 + 约 100 行 Agent Loop 覆盖浏览器/终端/文件系统/键鼠/屏幕视觉/移动设备）、按需加载的分层记忆（默认只显示高层摘要）、自演化机制（成功轨迹自动结晶为可复用 SOP，形成个人技能树）、上下文截断与压缩层。相比同类系统，token 消耗降低 6 倍。

价值：技能树从约 3300 行种子代码生长，完全属于用户，用得越久越强——这是目前对"agent 持久个性化"最具体的工程实现之一。

未来方向：agent 框架的竞争正在从"能做什么"转向"用久了会不会越来越好"，GenericAgent 的自演化设计代表了这个方向。

HuggingFace · arXiv:2604.17091

Teaching Thinking Models to Reason with Tools：Qwen3 全流程工具推理配方，4B 参数达 96.7% AIME 2025

现状：强推理模型（thinking models，即经过推理链训练、能够做多步推理的模型）在引入工具调用（tool use）后，性能反而下降——即使模型几乎不用工具，纯文本推理能力也会退化。

问题：工具集成监督微调（SFT）的效果高度依赖训练轨迹的可学习性；比例控制不当会导致纯文本推理能力"灾难性遗忘"（catastrophic forgetting）。

解决方案：arXiv:2605.06326 给出一个四步配方：(i) SFT 阶段优先选择"天然适合工具增强"的问题类型；(ii) 控制工具使用轨迹比例，保住纯文本推理容量；(iii) 优化 pass@k 和响应长度而非训练 loss；(iv) 用可验证奖励的强化学习（RLVR）做稳定的最终收尾。应用到 Qwen3 4B/30B 后，分别在 AIME 2025 上达到 96.7% 和 99.2%，开源模型中最优。

价值：这是一份可落地的工程配方，不依赖模型架构改动，任何有推理能力基础的开源模型都可以用这套流程添加工具调用能力。

未来方向：工具感知推理会成为下一代模型的标配能力，这份配方可能成为该方向的基准参考方法。

arXiv:2605.06326

Mem0：向量 + 图谱双轨长期记忆，多跳问答比 OpenAI 内置记忆提升 26%

现状：LLM 的上下文窗口（context window，即模型单次能处理的最大文字量）在多轮、跨会话对话中无法保持一致性，每次新会话都从零开始。

问题：向量记忆（通过语义相似度检索的记忆方式）能找到相似事实，但无法处理需要关系推理的多跳问题（multi-hop，即需要先找 A、再从 A 找 B 的链式推理）。

解决方案：Mem0（arXiv:2504.19413）在向量存储基础上叠加图谱记忆（知识图谱，用节点和边表示实体关系），提取阶段同时构建有向标签知识图和向量索引，检索时二者并联。Mem0g 在基础配置上再提升约 2%，在 LLM-as-Judge（用 LLM 评估对话质量的方法）指标上相比 OpenAI 内置记忆提升 26%，在单跳、时序、多跳、开放域四类问题上均超越现有记忆系统。

价值：对于需要跨会话个性化（如 AI 助手、客服 agent、长期任务跟踪器）的产品，这是目前最成熟的开源记忆解决方案之一。

未来方向：agent 的"记忆层"正在从可选模块演变为基础设施，图谱记忆将成为高质量长期对话的标配。

HuggingFace · arXiv:2504.19413

MinerU2.5：1.2B 参数文档解析视觉语言模型，粗细两阶段解耦策略处理高分辨率排版

现状：对 PDF、学术论文、密集表格等复杂排版文档的高精度解析，通常需要专用 OCR 管线或高参数量视觉模型，计算成本高，部署门槛高。

问题：直接用视觉语言模型（VLM）处理高分辨率输入时，计算量随分辨率平方增长，而降采样则会损失密集文字和公式的细节。

解决方案：MinerU2.5（arXiv:2509.22186）用粗细两阶段解耦策略：第一阶段在降采样图像上做全局版面分析，识别结构元素；第二阶段仅对感兴趣区域裁取原分辨率图像，做精细内容识别。视觉编码器初始化自 Qwen2-VL-2B，语言模型初始化自 Qwen2-Instruct-0.5B，总参数 1.2B，在多个文档解析 benchmark 上达到 SOTA，同时大幅降低计算成本。

价值：1.2B 参数使其可在消费级 GPU 上运行，对于需要大批量文档数字化（档案、合同、学术文献）的场景，这个效率-精度组合是目前最具竞争力的开源选项之一。

未来方向：随着 AI 工作流越来越多地依赖非结构化文档作为知识来源，轻量高精度的文档解析层将成为 RAG（检索增强生成，即让 AI 先搜索文档再回答）管线的关键瓶颈。
