Simon Willison：Anthropic 与 OpenAI 都已找到产品市场契合点

Simon Willison 盯住一个数据点：Anthropic 和 OpenAI 今年 4 月同步发布新前沿模型，同步提高 API 价格，企业客户皱着眉头签了续费。他用"产品市场契合点（PMF）"的经典测试来解读这件事：真正找到 PMF 的公司，客户在涨价时的反应是"吸一口冷气，然后说好吧"，而不是立刻转走。

两个侧面强化了这个判断。微软内部取消 Claude Code 许可证、要求工程师在 6 月 30 日前迁往 Copilot CLI，表面看是 Anthropic 受挫，Willison 却把它读成需求有多真实的证明：Microsoft 之所以需要主动叫停，恰恰是因为工程师们在自掏腰包或用部门预算持续使用它，撑住了消费。OpenAI Codex 企业版同样取消了大客户折扣，直接按挂牌 API 价结算。两家公司在同一时间做出同样的定价决定，不像是协调，更像是同时读到了同一份市场信号。Claude Code 与 Codex 的定价胆量，是当前 AI 编码赛道最真实的景气指标。

Simon Willison's Weblog

swyx（Latent Space）：Harness 工程正成为 coding agent 真正的护城河

本期 AINews 汇总了过去几天 Twitter 上一个收敛的论点：coding agent 的胜负手不再是 base model 有多强，而是 harness（执行脚手架）设计得有多好。所谓 harness，指的是围绕模型的那套环境：沙盒（隔离运行环境）、验证循环、上下文管理、动态技能路由。DeepSeek 正在专门组建 harness 团队；Google Gemini 的 Managed Agents 把 agent 基础设施封装成一个 API 调用；LangChain 的最新文档把同样的栈正式命名为"context governance + trustworthy memory + dynamic skill routing"。

衡量标准也在同步演进。DeepSWE 作为新的 coding benchmark 被从业者称为"第一个与真实开发体感对齐的 benchmark"——Theo 的原话是它给出的分数分布与"你在用这些模型写代码时的实际感受"一致，这是此前大多数 benchmark 做不到的。Qwen3.7 Max 在 Code Arena Frontend 榜上排第四，大致与 Claude Opus 4.6 在 agentic webdev 任务上持平。当所有人都在卷 base model，第一个把 harness 做成产品壁垒的公司会赢。

产品与商业

Every / Dan Shipper：自动化反而驱动人类专业需求上升

Every 发布播客新集"AI & I"，Dan Shipper 被自己公司的 COO 反向采访，解释为什么"After Automation"这篇 8000 字的文章今年成了 Every 最广传播的内容。论点是反直觉的：Every 已经把每一个可以自动化的工作流都接上了 agent，公司却从 4 人长到了 30 人。

机制是这样的：当每个人都能用 AI 产出"还不错的初稿"，整个市场的 floor（基准水准）上升，同时大量接近 floor 的内容泛滥。"你的 zone 被大量差不多但不够好的东西填满。"能从这片泛滥里出头，需要的是能与 AI 协作、让输出跨越新 baseline 的专家。Agent 结构性地依赖人类来定方向；没有人决定什么重要、怎样更好，它们只产出平庸。每期新模型发布时多用 AI 做你已经擅长的事，你会比以前更被需要。

同一期邮件还提到，教宗 Leo XIV 的 AI 牧函《Magnifica Humanitas》与 Dan 的论点在同一个问题上停下来，方向却不同：AI 会让人类判断力更值钱——但，值钱对谁？「自动化让专业稀缺」不是安慰剂，但它悄悄预设了一个条件：你得先有判断力可以稀缺。

AI 进展

Language Models Need Sleep

现状：长链条 Agent（执行多步骤任务的 AI 系统）会积累极长的历史上下文，KV 缓存（存储注意力计算中间状态的内存区域）随之无限膨胀，推理成本直线上升。

问题：现有做法要么丢弃旧上下文（丢失信息），要么保留全部（成本不可持续）。

解决方案：该论文提出"睡眠"机制：模型定期进行离线整合阶段，通过 N 次递归过遍历累积上下文、将其转化为持久快权重（fast weights，可理解为压缩记忆），再清空 KV 缓存。推理（"醒着"）阶段延迟不受影响。

价值：agent 可以在不扩大 KV 缓存的前提下维持长期记忆，计算量被转移到离线的"睡眠"阶段，本质上是用异步计算换掉了内存带宽瓶颈。

未来方向：与 agent 记忆系统（如 Anthropic Memory 功能）的整合，以及在多 turn 对话和长 Agent 轨迹任务中的实测验证。

arXiv 2605.26099

MAI-Image-2.5：微软文生图模型冲进 Arena 榜前三

现状：AI 图像生成（text-to-image）排行榜长期由 OpenAI（DALL·E 系列）和 Google（Imagen 系列）占据前两位，其他玩家难以突破。

问题：微软在图像生成领域的自研能力一直落后于语言模型能力。

解决方案：MAI-Image-2.5 于 5 月 27 日发布，在 Arena 文生图排行榜（由用户对比投票决定的人类偏好排名）中以 1254 分进入第三位，打破了此前 OpenAI/Google 双寡头格局。模型在文字渲染、风格化插图和商业图像三个维度相比前代 MAI-Image-2 有"阶跃式"提升。

价值：微软自研图像模型进前三，意味着它在 Azure AI Foundry 上拥有了不依赖 OpenAI 授权的图像能力，降低了对外部供应商的依赖。

未来方向：模型预计在两周内上线 MAI Playground 和 Azure Foundry。

Microsoft AI · AINews

OpenResearcher：开源端到端长链条深度研究 Agent

现状：深度研究 Agent（能自主搜索、聚合证据、撰写报告的 AI）是当前 LLM 能力的前沿任务，商业产品（Perplexity Deep Research、OpenAI Deep Research）均为闭源。

问题：开源深度研究 agent 缺乏完整的训练轨迹数据，难以复制商业系统的表现。

解决方案：OpenResearcher 提供从轨迹合成到训练的全开源流水线：多 agent 协作模拟复杂工具整合推理，生成高保真训练数据；模型规模覆盖 2B 到 35B，支持长链条事实检索、引用溯源与报告合成。

价值：研究社区第一次有了可复现、可改造的深度研究 agent 基准，不依赖专有 API 或闭源数据。

未来方向：多源跨语言检索与科学领域专项适配（医学、法律、金融）。

arXiv 2603.20278

MiniMax M3：双阶段块稀疏 Attention，百万 token 下效率飞跃

现状：主流 Transformer 的 Full Attention（全注意力机制）计算量随输入长度平方增长，1M token 以上的推理成本极高。MiniMax 前代模型 M2 曾因稀疏 attention 不够稳定而回退到 Full Attention。

问题：如何在保持精度的前提下，让超长上下文推理在工业规模上可用。

解决方案：M3 重新启用稀疏 attention，采用"Index Branch + Sparse Branch"双阶段设计：Index 分支快速筛选候选 token，Sparse 分支精确计算注意力，避免了全量计算。据报告，与 M2 相比，在 1M token 场景下预填充（处理输入）加速 9.7 倍，解码（生成输出）加速 15.6 倍。

价值：如果数字属实，M3 将使超长文档分析、多轮长对话在实际产品中的推理成本降低一个数量级。

未来方向：开源计划已披露，但技术细节（论文、die photo 等验证材料）尚未发布。

AI Base · AINews

CUSP Benchmark：模型能选方向，但不知道突破什么时候发生

现状：AI for Science 的一个关键主张是：AI 能加速科研。但"加速"的哪个环节，有多少实证，仍模糊。

问题：现有 AI 科研 benchmark 多数测"能否做出已知正确答案的题"，无法测"能否预判什么方向值得研究、何时会出现突破"。

解决方案：Sakana AI、Stanford、Oxford 和 AI2 联合构建 CUSP benchmark，专门评估模型在科学预测任务上的能力：不仅要识别有潜力的研究方向，还要预判突破的时机。结论：当前模型在"识别方向"上表现尚可，在"预判突破何时发生"上表现明显更差。

价值：为 AI 科研能力设立了更接近真实科学工作的评估标准——科学家的核心判断力之一是 timing sense（时机判断），而不只是方向感。

未来方向：将此类时序预测能力整合进科研 agent，而非只评测文献综述与假设生成。
