新闻速递

Meta Muse Spark 1.3：比肩 Fable，逼近前沿

Meta 发布 Muse Spark 1.3，主攻代码与 agentic（能自主规划、多步执行任务的 AI）工作负载。在第三方 AI Arena Code 排行榜上，Muse Spark 排名第一，超过 Claude Opus 5 Max；百度系研究机构 AAII 则给出「全球第三」的评价。相比上一代，新模型减少 25% token 用量、支持并行工作流、在长上下文任务上表现更稳。

定价策略值得注意：同意让 Meta 用你的数据训练，价格直降 90%。这不是小恩小惠，而是用数据换算力——Meta 没有 OpenAI 或 Anthropic 那样密集的企业付费用户，靠这种交换既降低开发者门槛，又积累训练语料。开源权重尚未最终决定，但 Zuckerberg 已公开承诺「即将到来」。Meta 用一年时间从追赶者变成了争议中的并列第一，而这次它还在押注开放生态。

Gemini 学会按需看视频：token -88%，成本 -66%

Google 为 Gemini 3.7 Flash、3.6 Flash 和 3.5 Flash-Lite 加入「agentic 视频理解」。以前处理视频是固定帧率全量采样；现在 Gemini 可以自行决定跳到哪一段、以什么速度重播、哪里需要加密关注——就像人类看视频时会快进跳过无聊段落。

结果是 token 用量减少 88%、费用降低 66%，准确率反而提升 7%。长视频场景尤其受益：Gemini 能在几小时的素材里定位一个特定瞬间，或对快速动作片段自动提高采样频率。这个能力已通过 Gemini API 开放，Gemini App 和 Ask YouTube 将在后续跟进。视频处理不再是「吃多少算多少」，而是和人一样懂得分配注意力。

Claude Code 后台电脑控制：用户终于不被 AI 占屏

Anthropic 宣布 Claude Code/Cowork 获得后台电脑控制能力（computer use）：AI 可以在用户继续使用电脑的同时，在后台独立完成桌面操作任务。此前 Claude 的电脑控制会「接管」屏幕，用户必须等待；现在的体验更接近 OpenAI Codex 的并行工作模式。该功能目前以 beta 形式向 Pro 和 Max 订阅用户推送。Agent 从占据你的屏幕，变成了真正意义上的后台助手。

Gemini 3.8 Flash Cyber：网络安全专用版，Flash 速度，专项性能

Sundar Pichai 宣布推出 Gemini 3.8 Flash Cyber，Google 定位为最强网络安全模型，同时保留 Flash 级速度和定价。公布数字包括：在 CyberGym（漏洞发现和利用综合评测）得分 86.2%，在 CWE-Bench（代码漏洞修补评测）得分 47.2%，内部跨 20 种编程语言的漏洞发现 benchmark 成功率超 70%。

AI 方向观点

Stanford 砍掉 85% 课程，重写成 Agent 工程：信号比模型发布更重

Stanford 教授 Mihail Eric 宣布，该校软件工程课程《The Modern Software Developer》的 85% 内容将在秋季学期整体替换——进去的是：agent 技能、上下文工程（context engineering，指精心设计给 AI 的输入信息）、MCP（Model Context Protocol，标准化 AI 工具接口协议）、agent 感知代码库设计、安全、并行后台 agent、软件工厂。

同期，另一门 Stanford 新课 CS329Z「Engineering AI Agents」聚焦从零构建 agent 系统：harness（agent 运行框架）、评估、内存、工具和编排，完全不把「怎么调模型」当核心内容。这两门课的信号不是「AI 很重要」，而是：软件工程这个职业的核心技能树，正在被系统性重新定义。当最保守的机构也开始推倒重来，这不是风向，而是已发生的事实。

Madhu Guru：AI 产品的终局，是让用户永远不需要选模型

Madhu Guru 提出：每一个 AI 产品都应该朝着「把模型选择从用户那里抽象掉」的方向努力。用户不应该知道、也不应该在意后端用的是哪个模型——就像用电不需要知道是哪座电厂发的一样。这个方向本身不新，但放在今天「各家都在打 benchmark 比分」的背景下，是一个对产品设计者的有效提醒：用户的信任建立在体验上，不在参数上。AI 产品的成熟标志，是让「换了哪个模型」变成用户永远不会问的问题。

Zara Zhang：我们录会议，已经不是给人看的了

Zara Zhang（Basis AI）在 X 上写道：「We are not recording meetings for humans anymore.」会议记录已经主要是喂给 AI agent 来处理的，而不是给人类同事回看。这句话的重量不在技术细节，而在于它揭示的使用方式已成常态的速度——从「AI 可以帮你回顾会议」到「会议本来就是给 AI 录的」，这个过渡悄无声息。

这是个信号比结论更值得停下来想的观察。如果信息的生产已经预设接收者是 AI 而不是人，那「表达」和「沟通」本身的语境就在改变。当你写一段话的第一读者默认是 AI，人与人之间真正在读什么，就成了一个新问题。

AI 进展

MinerU2.5：本周 HF 最热论文，文档解析走向多模态

现状：文档解析（把 PDF、扫描件、表格转成 AI 可用数据）长期依赖规则引擎和 OCR，面对复杂版式、混合语言、图文混排时准确率差。

问题：规则引擎难以泛化，跨语言文档更是软肋。

解决方案：MinerU2.5 引入视觉语言模型（VLM，能同时理解图像和文字的 AI）来解析文档，涵盖九种语言，将版式理解、内容抽取整合进同一个模型。

价值：本周在 Hugging Face 斩获 177 次点赞，是该平台本周最受关注的论文，说明工程师对这个方向有明确需求。

未来方向：随着更多企业把 RAG（检索增强生成，让 AI 从文档库里找答案）与内部文档对接，高质量的文档解析会成为整条链路的质量地板。

HuggingFace Papers

Prime Agent：递归 subagent 让长任务规划真的跑起来

现状：单个 AI agent（自主完成多步任务的 AI）处理复杂长任务时，容易丢失上下文、陷入循环或无法协调子任务。

问题：长任务的瓶颈不是模型智能，而是多步骤之间的状态管理和任务分配。

解决方案：Prime Agent 用递归 subagent 架构：主 agent 将任务拆解，派生子 agent 分头执行，子 agent 之间可以相互协调（agent-to-agent coordination），结果汇总后再由主 agent 整合。持久计算意味着子任务可以并行推进。

价值：在需要长时间跨多步骤的任务（如科研辅助、复杂代码重构）上，有效突破单 agent 的上下文限制。本周获 48 upvotes。

未来方向：agent-to-agent 协调协议的标准化，将是后续落地的关键挑战。

HuggingFace Papers

UrbanGround：把真实城市变成 multimodal agent 的交互沙盒

现状：评测 AI agent 的环境往往是人工构造的简化场景，与真实世界差距大。

问题：在真实环境里评测 multimodal agent（能同时理解图像、文字、地图等多种信息的 AI）成本高、可控性差。

解决方案：UrbanGround 把真实城市数字化为可交互的沙盒（sandbox，隔离的测试环境），让 multimodal agent 在其中导航、查询、决策，测试集覆盖城市规模的复杂度。

价值：为机器人、自动驾驶、城市规划 AI 提供了更接近实际部署条件的评测平台，本周获 42 upvotes。

未来方向：真实城市数据 + agent 评测的结合，将推动具身 AI（能在物理世界行动的 AI）更快进入实际测试循环。

HuggingFace Papers

ASI-Bench：在 AGI 门槛上定义「人工超级智能」的评测

现状：AI 能力评测的 benchmark（基准测试集）不断被刷新，但没有一个评测框架是专为「超越人类专家水平」这个档次设计的。

问题：当模型开始在 AGI（通用人工智能）边界附近徘徊，现有 benchmark 的天花板太低，无法区分「前沿」和「真正超越」。

解决方案：ASI-Bench 设计了专门针对「人工超级智能」门槛的评测任务集，任务难度超出人类专家的常规上限，用于检验模型是否在多个领域实现了真正的超人表现。

价值：为接下来几年可能到来的能力跃迁提前建立评测尺度；也让各家实验室的「AGI」声称有了更硬的核验标准。

未来方向：benchmark 本身的「被刷」速度将成为衡量能力进展真实速率的指标。

HuggingFace Papers

Demystifying Agent Skills：技能库让整体提升，却在实际用到的任务上反而拖后腿

现状：给 AI agent 配备技能库（预存的函数、工具调用模板）被认为能提升任务成功率。

问题：聚合指标看起来有提升，但论文提出 RIAE（Retrieval-Invoked Actual-Use Effect）方法：把「有技能检索触发的任务」和「没有触发的任务」分开评测，发现技能检索在实际触发的任务上可能反而有负效果。

解决方案：横跨 17 个 LLM、在代码和数学任务上验证这一现象，并提出配对评估框架，让技能库的真实贡献可量化。

价值：对维护技能库或工具目录的团队是一个实际警告：不要用聚合提升来替代真实触发场景下的效果验证。

未来方向：技能检索和工具调用的可靠性，将成为生产级 agent 系统最难调优的环节之一。
