AI 方向观点

Peter Steinberger（OpenClaw @OpenAI）：别再 prompt 了，设计让 Agent 自循环的 loop

Peter Steinberger 发出了本周最炸的一条技术判断，获得 13,734 个点赞：「你不该再 prompt 编程 Agent 了。你应该设计的是让 Agent 自动运行的 loop（循环，指无需人工干预、由代码或触发器持续驱动 Agent 工作的工作流架构）。」

这句话触碰了一个真实的分水岭：大多数人仍在把 AI 当成问答工具——有问题才开聊，聊完关掉。而「设计 loop」意味着把 Agent 变成基础设施：你定义目标、设定验证条件、安排触发节点，然后退出来，让它自己跑。Boris Cherny 同天发布的帖子（见下条）从工程操作层面给出了具体方法，二者形成互补。

从「问 AI」到「设计让 AI 自转的系统」，这是 AI 使用方式的代际跃迁，而不是技巧升级。

Boris Cherny（Claude Code @Anthropic）：Opus 长时自主运行的五条配置原则

Boris Cherny（Claude Code 的核心开发者之一）在观察到多项 benchmark 显示 Opus 在长时工作上表现最强后，总结了让 Opus 能运行数小时乃至数天的五条具体配置：① auto 权限模式，让 Claude 不必反复询问批准；② 动态工作流，驱动 Claude 编排数百乃至数千个子 Agent 完成任务；③ 使用 /goal 或 /loop 指令，提示 Claude 持续推进直到完成；④ 在云端运行 Claude Code，这样你可以合上笔记本；⑤ 给 Claude 提供端到端的自我验证手段——网页用 Chrome 扩展，移动端用 iOS/Android 模拟器 MCP（模型上下文协议，让 AI 工具访问外部服务的接口），后端则是能完整启动的服务器或服务。

自主运行的上限由「自验证」决定：Claude 能检查自己做对了，才能真正放手跑。

Addy Osmani「意图负债」：模型不知道「为什么」，改变了「不写文档」的经济逻辑

Addy Osmani 提出了「意图负债」（intent debt）概念：技术债（technical debt，因赶工或省事积累的代码质量问题）已被广泛讨论，但真正贵的是「意图负债」——那些从来没被写下来的目标、约束和决策背景，只存在于某些人的头脑或散落的会议记录里，不成体系，残缺不全。

在人工编程时代，这种债务成本是隐性的：老员工离职，知识蒸发。但在 Agent 工程时代，成本被急剧放大。模型只知道代码是什么，不知道代码为什么这样。当 Agent 被要求修改一个系统时，它会根据表面特征做决策，而不知道有哪些约束是不能碰的、哪些设计是因为某次特定事故而生的。「不写」的经济学因此彻底改变：过去你可以赌团队成员记得，现在 Agent 不会记得，而且 Agent 的失误是批量的。

AI 把「写 vs 不写」的判断从「沟通成本」变成了「系统可靠性」问题——意图是人能给 Agent 的唯一燃料。

Every.to「我的编辑抓出了 AI 腔，现在 AI 先于编辑抓出我」：把写作坏习惯训练成一个 AI skill

Every.to 的 Working Overtime 专栏本周分享了一个具体的工作流：作者把自己的写作坏习惯整理成清单——那些反复被编辑标注、让文章读起来像 AI 写的措辞和句式——然后把这份清单喂给模型，训练出一个专门针对自己声音问题的批评 skill（技能，Claude Code 或 Claude 中的自定义专项指令集）。结果是：以前需要等编辑反馈才发现的问题，现在在初稿阶段就被模型拦下。

这是一个在 AI 写作工具泛滥之后才有意义的工作流。过去「听起来像 AI」是工具的问题，现在成了作者的问题——因为作者自己也在大量使用 AI，声音正在被工具拉平。让 AI 监督 AI 的影响，是这个工作流成立的前提。

用 AI 抵抗 AI 对声音的侵蚀，这条路的本质是：把自我认知做成可执行的 skill。

Aaron Levie（Box CEO）：AI 让开发成本下降，但 GTM 成本分毫未减——「可能反而更贵了」

Aaron Levie 反驳了「AI 会消灭企业软件」的论断。他的分析切入点不是技术，而是成本结构：大多数企业软件公司，研发（把软件做出来）只是成本的一部分，GTM（go-to-market，市场进入，包括销售、营销、客户成功、实施支持等获客和留客成本）才是花钱的大头——因为企业级软件的销售天然是重度咨询和关系驱动的。

AI 把开发效率提上去了，让更多软件诞生；但 AI 没有减少买家在复杂市场里做决策的困难，甚至因为市场更拥挤、选项更多，差异化和被发现的难度反而上升。他的结论：「如果你让一件东西（开发）更便宜、更丰富，那么那件东西（在市场里脱颖而出）就成了最难的部分。」

AI 消灭的是开发成本，不是销售成本——那些把「AI 写代码」等同于「不需要 GTM」的判断，搞错了企业软件的成本重心。

Aditya Agarwal（前 Dropbox CTO）：经历两次 IPO 的人会说——财富放大的是早已存在的欲望，不创造新的

Aditya Agarwal 参与过 Meta 和 Dropbox 两次 IPO（首次公开募股），见过大规模财富兑现对人的真实影响。他的观察是：主流叙事说「早期员工发财后就去买豪宅、躺着休息」，这对有些人确实成立，但对更多人来说，钱不是让他们停下来的东西，而是让他们做更疯狂事情的资本——创立新公司、投资新东西、继续硅谷这个「疯狂循环」。

他说的「循环」是一个具体的系统：IPO 让早期员工获得流动性，流动性流向新创业、新投资，新投资孵化下一批公司，下一批公司再走向 IPO。这不是抽象理论，是他见过的真实轨迹。他的结论：财富放大的是欲望，不是创造欲望。想休息的人有了可以休息的底气，想继续做事的人有了更大的子弹。

财富是放大器，不是转化器——在 IPO 之前你是什么样的人，你之后还是那种人，只是规模更大。

Wisereads · Stephen M.R. Covey《信任与激励》：领导力的真正杠杆是对人潜力的信任，而非命令与管控

Wisereads Vol. 146 本周精选了 Stephen M.R. Covey（《信任的速度》作者，管理学经典《高效能人士的七个习惯》的作者之子）的新书《Trust and Inspire》（信任与激励）。Covey 的核心论点：多数管理者默认的姿态是「命令与管控」（command and control），给任务、设约束、监督执行；而真正释放人潜力的姿态是「信任与激励」（trust and inspire）——相信人有能力做好，然后给出空间。

这不是软性口号。Covey 认为，当你领导的是一个家庭、一个团队、还是一家公司，决定成果上限的往往不是策略有多精准，而是信任关系有多深。信任是效率，不是风险；对人潜力的轻视，是大多数组织最隐蔽的成本。在 AI Agent 已经可以自主执行任务的时代，「管控」的冲动会被进一步放大——Covey 的框架对人的管理成立，也在提醒我们对 Agent 的设计不要只想着约束。

「信任是效率」这个判断，放在 AI Agent 部署的语境下比任何时候都更有操作意义。

AI 进展

dots.tts：2B 参数自校正后训练，刷新文本转语音基准，本周 HuggingFace 最高票论文

现状：文本转语音（TTS，text-to-speech）模型通常依赖奖励信号或强化学习来对齐生成质量，训练复杂度高，音质和自然度难以同步优化。

问题：传统自回归 TTS 模型在全历史条件（full-history conditioning，生成每一帧时参考所有之前音频帧）下计算开销大；奖励模型的引入又增加了管道复杂性和对高质量奖励标注的依赖。

解决方案：dots.tts 是一个 2B 参数的连续自回归 TTS 基础模型，结合 Audio-VAE（将音频压缩进潜空间的变分自编码器）和带全历史条件的 flow-matching（流匹配，一种无需逐步去噪的生成建模方法）。训练后阶段采用「无奖励自校正后训练」（reward-free self-corrective post-training）：模型通过自我对比和纠错提升质量，完全不依赖外部奖励信号。

价值：以较小参数量达到当前 SOTA（state-of-the-art，最优水平）的语音生成质量；无奖励训练路线大幅降低了高质量 TTS 的落地门槛，本周在 HuggingFace 获得 210 颗星，是当日最高。

未来方向：无奖励自校正路线有望推广到其他生成式多媒体任务，不只是语音。

SubtleMemory：长时 Agent 关系记忆辨别基准，测试「矛盾记忆并存时 Agent 能否做对」

现状：长期运行的 AI 助手（如 OpenClaw 类系统）在与用户持续交互后，会积累大量相互关联的记忆片段，这些片段之间可能互相强化、也可能在不同语境下发散、甚至直接矛盾。

问题：现有长期记忆 benchmark（标准化评测集）很少测试 Agent 在复杂记忆关系下的表现——大多数评测只检查单条记忆的召回，不测试当多条关联记忆并存时 Agent 能否做出正确区分和判断。

解决方案：SubtleMemory 构建了包含 1,522 个评测实例的基准，跨越 10 段长期交互历史，覆盖「互补关系」「细微差异关系」「直接矛盾关系」三种记忆变体类型，以及用户相关和非用户相关两类查询。对 6 个独立记忆系统、5 个带记忆模块的 Claw 风格 Agent 进行评测。

价值：评测结果显示，当前所有系统在细粒度关系记忆辨别上表现「持续薄弱」——这是长时 Agent 走向真实部署前必须正视的能力缺口。

未来方向：关系感知记忆架构（而非纯向量检索）将成为企业级持久 Agent 的下一代基础设施方向。

arXiv 2606.05761 · HuggingFace

ToolMaze / When Tools Fail：工具失效时的动态重规划基准，LLM Agent 的异常恢复能力系统测评

现状：LLM Agent 在执行多步任务时高度依赖工具调用（tool use，调用外部 API、函数或服务来完成任务的能力）。实验室环境下工具通常可靠，但生产部署中工具会超时、返回错误、或行为与预期不符。

问题：现有评测集假设工具始终正常工作，缺乏对「工具失效后 Agent 能否诊断原因、重新规划、完成任务」这一核心生产场景的系统化测评。

解决方案：ToolMaze 构建了一个覆盖多种工具异常模式（超时、错误码、部分返回、格式异常等）的 benchmark，测量 LLM Agent 在工具失效后的动态重规划（dynamic replanning）和异常恢复（anomaly recovery）能力，开源于 GitHub（Zhudongsheng75/ToolMaze）。

价值：填补了从「玩具环境」到「真实工具链」之间的评测空白，为 Agent 框架选型和鲁棒性优化提供量化基础。

未来方向：工具异常感知将成为生产级 Agent 的必备能力层，而非可选优化项。

arXiv 2606.05806 · HuggingFace

Astra「用想象力思考」：VLM 主动向世界模拟器查询缺失视角，把空间推理变成主动视觉证据采集

现状：视觉语言模型（VLM，能同时处理图像和文字的大模型）在做空间推理时，往往受限于输入图像提供的固定视角，无法主动获取回答问题所需的缺失观测。

问题：空间推理问题（如「从另一个角度看，这个物体遮挡了什么？」）常常需要从当前输入中不可见的视角获取信息，而现有方法只能被动处理已有输入，无法主动「去看」。

解决方案：Astra 把这个问题重新定义为「用想象力思考」（thinking with imagination）：系统将 Astra-VL（基于 Qwen3-VL 的 RL 强化学习训练策略模型）与 Astra-WM（基于 Bagel 的世界模拟器，World Model，对环境的内部表示）耦合，让 VLM 在需要时主动查询世界模拟器获取缺失视角，用返回的「想象观测」来回答空间问题。

价值：把视觉空间推理从被动处理变成主动证据采集，与具身认知（enactive cognition）的理论框架共鸣：理解不是内部运算，而是主动寻找所需观测的过程。

未来方向：模拟器介导的主动感知将成为下一代具身 Agent 和机器人视觉推理的核心框架。

arXiv 2606.06476 · HuggingFace

OpenSkill：LLM Agent 从开放世界资源中自主合成技能，无需外部目标任务监督

现状：LLM Agent 通常需要针对特定任务进行微调或提供人工标注的示例才能习得新能力，泛化到陌生任务时成本高昂。

问题：依赖「外部目标任务监督」意味着每进入一个新领域就要重新收集数据或设计奖励，限制了 Agent 在开放世界（open-world，任务分布未知、不断变化的真实环境）中的自主成长空间。

解决方案：OpenSkill 是一个让 LLM Agent 自我进化的框架：Agent 从开放世界资源（如代码库、文档、网页）中自主合成 grounded skill（有地基的技能，即与真实执行路径锚定的可调用能力单元）和验证信号，完全不需要外部为目标任务提供监督。代码开源于 OpenLAIR/OpenSkill。

价值：提供了一条无需人工干预的 Agent 能力扩充路线，令 Agent 的技能库可以随接触到的资源自然生长。

未来方向：「从资源中自学技能」将成为通用 Agent 基础设施的关键组件，与工具调用和记忆管理并列。
