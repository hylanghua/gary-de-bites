Google Googlebooks + Gemini Intelligence + Magic Pointer：Android 变成 AI 操作系统，光标长出了感知层

Google 在 I/O 大会（5 月 20 日）前夜的"Android Show"上集中发布三样东西。第一是 Googlebook：Android 驱动的新一代笔记本电脑，内置 Magic Pointer，即带 Gemini 推理能力的鼠标光标，把光标悬停在屏幕任意内容上并说出自然语言指令，Gemini 直接感知上下文并执行——点一栋楼说"导航过去"、点一个日期说"创建会议"。合作厂商包括宏碁、华硕、戴尔、惠普、联想，今年秋季上市。

Amazon 员工"Tokenmaxxing"：用内部 AI agent 刷使用量排行榜

Amazon 内部 AI 平台 MeshClaw 允许员工创建可代为操作 Slack、触发代码部署、处理邮件的 AI agent（即能自主执行任务的 AI 程序）。Amazon 同期把开发者每周 AI 使用率目标定为 80% 以上，并在内部排行榜上追踪 token（AI 系统处理的数据单位）消耗量。结果是员工开始用 MeshClaw 做根本不需要 AI 的任务，纯粹为了刷排名，这一行为被称为"tokenmaxxing"。

Amazon 官方表示 token 统计不用于绩效评估，但多名员工说他们相信经理在盯着这些数据。一线关切是安全风险：能代表用户执行操作的 AI agent 一旦被滥用，权限边界如何管控是真问题。这件事暴露了一个组织管理陷阱：用可量化指标推动 AI 采用，反而制造了指标游戏。把 token 消耗量当 AI 采用度的代理指标，结果度量的不是价值创造，而是 AI 系统的表演成本。

Mini Shai-Hulud 供应链攻击：172 个 npm/PyPI 包被感染，AI 开发工具链重点目标

5 月 11-12 日，攻击组织 TeamPCP 在 48 小时内感染了 172 个 npm 和 PyPI 包，累计下载量超 5.18 亿次。受波及的包包括 @tanstack（前端查询库）、@mistralai（Mistral AI 官方 SDK）、@opensearch-project、guardrails-ai（AI 输出验证工具）和 UiPath。攻击手法是通过 GitHub Actions 的 pull_request_target 触发器链式入侵，劫持 OIDC token（用于证明代码来源的身份令牌），然后用合法签名发布恶意包版本，绕过 SLSA Build Level 3 完整性验证。

特别危险的一点：据报道恶意代码会勾入 Claude Code（~/.claude/settings.json）和 VS Code（.vscode/tasks.json）配置文件，即使卸载被感染包，下次打开编辑器时仍可重新触发执行。Guardrails AI 在约 2 小时内确认其 0.10.1 版本被感染并下架。当 AI 开发工具链本身成为供应链攻击目标，开发者的日常环境变成了攻击面——安全加固要从 npm install 这一步向前移。

AI 方向观点

swyx（Latent Space 创始人）：微调的终结，还是多数人的终结？

OpenAI 宣布弃用 finetuning API（即让用户用自己的数据对模型做定向训练的接口），swyx 借此写了一篇分析。他的核心观察是：对 80% 的 AI 工程社区来说，微调确实走向终结——这条路径在"用提示词就能达到 o1 水平"的宣传下过度神话化，GPU 资源紧张又在加速它的淘汰。但对头部玩家来说，结论相反：Cursor 和 Cognition（估值 $250 亿）反而在加码开源模型的强化学习微调（RLFT），开源权重微调正在成为定制 ASIC 芯片战略的核心逻辑。

他还提到另一个信号：Anthropic 估值首次可能超过 OpenAI，Finetuning API 的弃用发生在这个节点，不是巧合，是战略取舍的结果——长提示词（如 Claude 的 Constitutional AI 宪章）替代微调，既省 GPU 算力，又更灵活。换句话说，"微调终结"对不同层级的玩家含义完全不同。能力密度高的团队退出微调是优化，能力密度低的团队退出微调是被迫——大家看的是同一条终结线，站的是不同的起跑点。

Latent Space / AINews

Mira Murati（Thinking Machines 创始人）：所有 AI 实验室都把交互做错了

Murati 离开 OpenAI 后创立的 Thinking Machines Lab 发布了"interaction models"（交互模型）的研究预览。核心主张是：实时互动性应该是模型的原生能力，而不是在对话模型外层拼接的脚手架。他们的做法是把"听、说、看、在正确时机停顿"全部训练进同一个网络，不是事后拼装。

技术上，系统把对话拆成 200ms 的微轮次（micro-turns），允许模型在用户说话过程中自然插入、同时处理视觉信息、在后台异步跑深层推理——这三件事同时发生，而不是依次等待。轮次切换延迟 0.4 秒，接近真实人类对话节奏。当前 TML-Interaction-Small 模型参数量偏小，扩展到更大基础模型是 2026 年下半年的计划。Thinking Machines 在赌交互范式的转换，不是"更聪明的聊天机器人"，而是"能在场"的 AI——下一个产品战场是感知延迟，不是准确率。

AI Valley · VentureBeat

Every.to：16 小时 Agent 的谬误，长时程可靠性是当前最被高估的能力

Every.to 这篇文章指向一个在 agent 产品中被反复夸大的能力：长时程可靠性（long-horizon reliability）——让 agent 在无人监督的情况下保持专注运行数小时。文章分析了现有数据，指出 agent 在长时间运行中会遇到上下文衰减（context decay，即随着任务链变长，前期信息逐渐失真）和决策漂移，而不是多数演示视频里展示的那种顺畅运行。

文章同时介绍了 Perplexity 在构建 agent skills（即可复用的 agent 能力单元）时的方法论：将复杂任务拆解为短程、可验证的子步骤，而非依赖单一长程 agent 一跑到底。这个反直觉的设计选择，实际上是对"16 小时无监督"能力缺陷的工程绕道。长时程 agent 是未来，但它需要的基础设施（状态持久化、步骤验证、失败恢复）目前还没到位——现在是把短程高可靠 agent 串成链的时代，不是单 agent 马拉松的时代。

纯银：古法与思考一起萎缩——AI 时代的质量标准正在松动

纯银今日在小报童《产品分析·无限季》写下"5 月札记（下）"，核心问题是：当团队开始大量借助 AI 做内容和产品，质量评分标准本身会不会跟着下滑？他先给出了一套质量刻度：60 分是一年经验的合格新人，70 分是 3-5 年的熟练生产者，80 分是准专家，85 分是真正的专家。这套标准是他用来"对齐"团队质量认知的锚点。

Every.to：把人生挖掘成 AI 上下文，信息粒度决定 agent 输出质量

Every 这期的核心论点是：给 AI 提供的上下文（context，即 AI 在回答前能看到的所有背景信息）质量，直接决定了 agent 输出的价值上限。而"挖掘人生中的上下文"，意味着把自己的工作模式、决策偏好、历史判断记录下来，整理成可以喂给 AI 系统的格式——不是简单写一份个人简介，而是持续构建一个关于"你是谁、你怎么思考"的结构化数据集。

文章还探讨了 Every 增长负责人如何用这套方法保持专注：不是靠意志力或纪律，而是通过预先明确化工作价值观，让 AI 帮助过滤掉和这些价值观不符的任务请求。这是一种把个人认知外化的工程思维——自我知识的颗粒度越高，AI 作为延伸的效果越强。AI 的上限不只取决于模型能力，更取决于你给它提供的上下文质量——挖掘自我，是一种新的竞争力建设。

AI 进展

SenseNova-U1：彻底丢掉 VAE 和视觉编码器，理解与生成在一个网络内共演化

现状：目前主流的多模态模型（能同时处理图像和文字的模型）分成两类：理解型（看图回答问题）和生成型（文字生成图像），通常用完全不同的架构实现，勉强拼接在一起。

问题：拼接架构依赖 VAE（变分自编码器，一种把图像压缩成紧凑表示再还原的工具）和视觉编码器作为桥梁，导致两种模态的表示空间不统一，限制了联合推理的深度。

解决方案：SenseNova-U1（arXiv:2605.12500，SenseTime 发布）基于 NEO-unify 架构，完全移除 VAE 和独立视觉编码器，在单一统一表示空间内把理解和生成视为同一过程的两个视角。两个变体：8B 密集模型和 30B-A3B 混合专家模型（Mixture-of-Experts，即根据输入动态激活部分参数的稀疏架构），在文字理解、视觉感知、知识推理、agent 决策、空间智能五类 benchmark 上均达到开源 SOTA。

价值：可以在单次推理中生成"文字+图像交织"的输出，例如图文并茂的旅行日记，而不需要先生成文字再调用另一个模型生成配图。

未来方向：去掉"桥梁"让两种能力真正共演化，是多模态统一架构的长期目标，SenseNova-U1 是迄今最干净的一次工程实现。

HuggingFace · arXiv:2605.12500

DFlash：用块扩散模型做投机解码草稿，6× lossless 加速

现状：大语言模型（LLM）的推理速度受制于自回归生成（autoregressive generation）：每次只能生成一个 token（词语片段），前一个 token 生成完才能生成下一个，无法并行化。

问题：投机解码（speculative decoding，即先用小模型快速草拟多个候选 token，再用大模型一次验证）是主流加速方案，但草稿模型通常是压缩版的自回归模型，并行化潜力有限。

解决方案：DFlash（arXiv:2602.06036）用轻量级块扩散模型（block diffusion model，一种可以一次性并行生成一批 token 的扩散式模型）替代传统草稿模型。扩散模型天生支持并行生成，在投机解码的草拟阶段恰好能充分发挥这个优势。实验结果：跨多种模型和任务，lossless（无精度损失）加速 6 倍以上，比当时最优的 EAGLE-3 方法还快 2.5 倍。

价值：lossless 意味着输出质量与原模型完全一致，加速不以牺牲准确性为代价——对需要高精度输出的生产场景尤其有价值。

未来方向：块扩散模型与自回归模型的混合架构可能成为下一代推理引擎的主流选择，DFlash 是目前最具说服力的概念验证。

HuggingFace · arXiv:2602.06036

Lighthouse Attention：只在训练时用的次二次方 attention，训练完即可移除，不影响推理

现状：训练超长上下文（极长文本处理能力）的 transformer 模型，瓶颈是标准 attention（注意力机制，模型处理 token 间关系的核心机制）的计算复杂度随序列长度的平方增长，导致训练极长序列成本极高。

问题：现有的次二次方（subquadratic）替代 attention 方案，要么只适合训练时用（推理时需要换回标准 attention），要么需要修改模型架构（影响部署兼容性）。

解决方案：Lighthouse Attention（arXiv:2605.06554，Nous Research）是一个对称选择式层次化 attention 算法，设计为训练阶段的临时包装层：(i) 对序列做自适应压缩和解压缩的层次化前后处理；(ii) 对称的 query-key-value 同步池化，保持因果方向性；(iii) 两阶段训练：大部分时间用 Lighthouse Attention，临近训练结束时短暂恢复全 attention 做"校正"。校正结束后，模型就是一个标准 attention 模型，推理时无需任何额外模块。

价值：预训练长上下文模型的成本显著降低，且不影响模型的推理兼容性——对希望训练长上下文开源模型的团队是直接可用的工程方案。

未来方向：长上下文预训练的效率瓶颈是制约开源社区发展的关键障碍，Lighthouse Attention 这类"训练用、推理丢"的策略是工程层面的重要突破。

arXiv:2605.06554

Needle：26M 参数工具调用模型，从 Gemini 合成数据蒸馏而来，消费设备 6000 tok/s prefill

现状：让 AI 模型调用外部工具（tool calling，即 AI 判断当前任务需要调用哪个函数、传入什么参数，再执行工具返回结果）通常需要百亿以上参数量的大模型，不适合在手机、边缘设备上运行。

问题：工具调用本质上更像"从工具描述中精准检索和组装参数"，而不是"凭记忆推理"，理论上不需要 MLP（多层感知器，负责模型"知识记忆"的前馈网络）层的参数量支撑。

解决方案：Cactus Compute 发布 Needle，完全去掉 MLP 层，只保留 attention（注意力）和 gating（门控）的"Simple Attention Network"架构。用 Gemini 合成数据预训练（2000 亿 token，16 块 TPU v6e，27 小时），再微调 20 亿工具调用合成数据（45 分钟）。结果：26M 参数，prefill 速度 6000 tok/s，decode 速度 1200 tok/s，单次工具调用准确率超越 FunctionGemma-270M、Qwen-0.6B 等更大模型。MIT 授权，权重和训练代码完全开源。

价值：可以在手机等消费级设备上实时运行的工具调用路由器，让本地 agent 应用真正可行——不需要把每个工具调用请求都打给云端大模型。

未来方向："任务专用小模型"正在成为 agent 系统的效率杠杆——不是一个大模型做所有事，而是用极小的专用模型做路由，节省成本和延迟。

HuggingFace · GitHub

physics-intern：agent 分解策略把 Gemini 3.1 Pro 在 CritPt（理论物理基准）上从 17.7% 推到 31.4%

现状：CritPt 是专为测试 LLM 理论物理研究能力设计的 benchmark（基准测试），包含 71 个研究项目级复合挑战和 190 个子任务检查点，难度远超 olympiad（奥林匹克竞赛级）数学题，是目前最难的 AI 推理 benchmark 之一。

问题：即使是最强的前沿模型，在这种需要跨领域深度推理的研究级任务上表现也极其有限——Gemini 3.1 Pro 基础表现只有 17.7%。

解决方案：David Louapre 团队开发的 physics-intern 框架，核心策略是把复杂的理论物理问题分解为专业子 agent 可以独立处理的子任务，再汇聚结果。这不是架构创新，而是 agent 编排（orchestration，即协调多个 AI agent 协同工作的机制）的精心设计。应用于 Gemini 3.1 Pro 后，CritPt 得分从 17.7% 提升到 31.4%，接近翻倍，创下该 benchmark 新 SOTA。

价值：理论物理研究是人类目前已知的最难认知任务之一，agent 编排在这个领域的显著提升意味着 AI 辅助科研正在从"帮你查文献"向"参与实际研究推进"迈进。

未来方向：研究级 AI 的边界正在被 agent 分解策略持续推移——模型能力固定时，编排质量本身就是可优化的核心变量。
