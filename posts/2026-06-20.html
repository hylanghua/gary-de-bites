Guillermo Rauch（Vercel CEO）：下一个热门"编程语言"是 Markdown

Rauch 今日发布了一个极简 Agent 文件结构示意图：一个 agent/ 目录，里面是 instructions.md 和 skills/ 子目录，技能文件全部是 .md。然后他加了一句："用一行命令部署到 Vercel。"他的结论："这是最易接近的编程范式。"

这个观察触及了 Agent 工程正在发生的一次隐秘迁移：以前"写代码"意味着用 Python 或 TypeScript 实现逻辑；现在越来越多的 Agent 行为是通过 Markdown 文件定义的——指令、上下文、技能描述、输出格式都可以用 Markdown 表达。对于 PM 和设计师而言，这是第一次"写代码"可以不涉及任何语法错误的机会。Rauch 说的不只是 Vercel 在卖什么，而是他看到了一个入口：程序员和非程序员之间的那堵墙正在被 Agent 范式从底部凿穿。

Aaron Levie（Box CEO）：Agent 成功的主变量是上下文，不是模型

Levie 今日明确指出：在实际部署 Agent 时，"能不能让 Agent 拿到完成任务所需的上下文（context，即执行任务时所需的背景信息、历史记录和相关数据）"才是决定成败的主变量，而不是用哪个模型。他进一步说，实现这一点的关键是为 Agent 创建一个"共享工作区"（shared working area）——Agent 的所有操作、产出和状态都在一个统一的位置发生，而不是散落在不同工具和接口之间。

这个判断对构建 AI 工作流的团队有直接操作价值：你在"选模型"上花的时间，可能比不上你在"怎么让 Agent 看到对的信息"上投入的工程量重要。许多 Agent 失败案例不是因为模型不够强，而是因为模型在关键时刻拿不到它需要的东西。Levie 把 Agent 工程的核心问题从"哪个模型最好"重新定位成了"怎么设计上下文传递系统"，这是 2026 年最值得 PM 记下来的一句话。

Guillermo Rauch（Vercel CEO）：Agents 正在逼迫所有好的软件工程习惯归位

Rauch 今日的另一条推文把视野拉到了更大的架构层面。他观察到：Agents 正在激励大量健康的软件工程实践回归——开放 API（open APIs，即第三方可调用的标准接口）、文档（documentation，即 Agent 需要读懂的技能描述文件）、测试与评估（tests/evals）、Unix 哲学（CLI 优先，即命令行接口，Agent 最容易调用的交互方式）、支付与商业协议，甚至 HTTP 的 Accept 头（用于协商返回格式是 Markdown、JSON 还是 HTML）。

这个观察揭示了一个有趣的因果关系：过去十年，很多团队因为"先跑起来再说"而欠下了大量工程债——没有文档、没有 CLI、API 不稳定。但当 Agent 开始代替人类调用你的服务时，这些"债务"立刻变成了不可接受的阻塞。Agent 的到来不是在给糟糕的工程锦上添花，而是在强制执行一次工程纪律复审。Rauch 说的是：Agent 不只是一种新工具，而是一种让工程团队没有退路的新标准——你之前欠下的技术债，现在必须还了。

Garry Tan（YC CEO）：把你最怕给董事会看的东西做成第一张幻灯片

Tan 今日分享了一条董事会沟通技巧：挑出你最不想在董事会上提及的那件事，把它放在第一张幻灯片上，并把它定义成一件大事——你在主动处理的大事。他补充了一个前提："当然，这只能在一个好的董事会里这样做。"

这个建议的本质是控制叙事的主导权。大多数创始人倾向于把坏消息压在后面、藏在乐观数据后面，希望用好消息的惯性稀释坏消息的冲击。结果是，当董事会成员在第 15 张幻灯片时挖出那个问题，提问者就成了叙事的主导者，而创始人只能被动应对。Tan 的方法反过来：你先提出问题，你就定义了问题的框架、严重程度和解题路径。激进透明的核心不是展示软弱，而是掌握定义权——把"最差的事情"说出来，比被人挖出来早十分钟。

Amanda Askell（Anthropic 伦理研究员）：我被慢性疼痛折磨了 30 年，可能只因为医生觉得我不配知道扫描结果

Askell 今日分享了一段个人经历：她被慢性疼痛困扰了大半生，直到一位医生做了核磁共振（MRI），发现了一个先天性病因，手术后才彻底解决。她的追问是：这 30 多年的疼痛，是否只因为此前的医生认为让患者知道扫描结果"不合适"？

她的第二条推文延伸了这个问题：有观点认为，扫描更多会导致"偶然发现"（incidental findings，即无症状的异常发现），从而造成过度诊疗和不必要的焦虑。Askell 不认同。她的反驳是：问题从来不是"扫描太多"，而是"我们对扫描结果的响应规范（norms）还没调整好"。如果发现了没有症状的异常，可以选择忽略——这是一个可以训练的认知，而不是扫描本身的错误。在她看来，随着扫描越来越普及，社会对"不是每个发现都需要行动"的接受度也会自然演化。Askell 把医疗信息壁垒的问题说得非常透：被剥夺知情权的代价，不只是焦虑，有时是 30 年的疼痛。

Zara Zhang（红杉资本 VP）：AI 时代让你脱颖而出的三件事：Agency、Taste、Distribution

Zara 今日以三个词定义了 AI 时代的人才差异化要素：Agency（主动性，即不等待指令、主动推进的行动力）、Taste（品味，即在无限选项中找到"好的"的判断力）、Distribution（传播力，即让你的想法和产品触达正确受众的能力）。

在工具日益民主化的背景下，这三个特质的稀缺度不降反升。因为当每个人都能"做出东西"时，做出来的质量和能不能被看见，就成了真正的分水岭。Agent 可以帮你执行，但你得知道要执行什么（Agency）；AI 可以生成，但你得知道哪个版本是对的（Taste）；工具可以发布，但你得知道怎么让人知道（Distribution）。Zara 的三件套是对"AI 会取代人"的最简洁反驳：AI 取代的是执行层，而执行之上的判断力、品味和连接力，是下一个时代最贵的稀缺品。

AI 进展

Context-Aware RL：RL 训练模型在长上下文中锁定决定性证据

现状：LLM 在处理长上下文或复杂上下文（如几百行工具调用轨迹、含细节差异的图像对比）时，经常无法识别"那一个决定性线索"——它能读完整个上下文，但找不到最关键的那一句话或那一个像素细节。

问题：标准的 RL（强化学习，即通过奖励信号训练模型改进行为的方法）通常以最终任务结果为奖励信号，无法直接告诉模型"你应该更关注上下文的第 X 行"，这使得模型在粗粒度上能完成任务，但在细粒度上依然会漏失关键证据。

解决方案：论文提出"上下文感知 RL"：给模型提供一个 query、一个 answer、以及两个高度相似但关键差异在细节处的上下文，奖励模型选出真正支持 query-answer 对的那个上下文。两个训练域：coding agent 用工具轨迹（1k 对，通过条件过滤构造）、多模态推理用图像对（7k 对，通过生成编辑和相似度搜索构造）。

价值：让模型学会"主动锁定证据"，而非"被动扫描全文"——对依赖长上下文推理的 Agent 工作流（如代码库级别的理解、多文档知识整合）有直接提升效果。

未来方向：上下文感知能力的专项训练，将成为下一代长上下文 Agent 的标准组件，与通用推理训练并列。

ImageWAM：机器人世界模型不需要视频生成，图像编辑模型已经足够

现状：当前主流的机器人世界模型（World Action Model，即能预测"执行某个动作后世界会变成什么样"的模型）通常基于视频生成框架——模型输出的是一段动态视频，然后从中提取动作信号，这套路径计算量大、推理慢、对硬件要求高。

问题：视频生成框架为了表达"连续变化"而引入了大量视频 token 和时序建模开销，但机器人控制任务实际上需要的是"当前状态到下一状态"的离散跳跃，而非平滑的视觉过渡——这是一个解法与需求不匹配的过度工程问题。

解决方案：ImageWAM 将预训练的图像编辑模型（image editing model，即"给定当前图像和指令，输出编辑后图像"的模型）重新用作机器人动作预测的视觉主干，用图像间的差异编码动作信号。提供 1.1B（Ovis-U1）至 9B（FLUX.2）共四个模型变体，最小模型在多个机器人基准上与更大模型竞争力相当。

价值：证明了"替代视频生成"是可行路线，计算成本大幅降低；为资源受限的机器人研究团队提供了一条更实用的世界模型路径。

未来方向：图像编辑基础模型将成为 Physical AI 世界模型的高效预训练骨干，视频生成框架的必要性将受到系统性质疑。

arXiv 2606.19531 · HuggingFace Papers

AgentAtlas：挑战 LLM Agent 的单一结果排行榜范式

现状：当前 LLM Agent 的评测主要依赖"完成率排行榜"——任务完成了得 1 分，没完成得 0 分，然后按正确率排序。这张榜单简单直观，但提供的信息极为有限：它告诉你"哪个 Agent 最后答对了"，但不告诉你"失败的 Agent 在哪一步出了什么问题"。

问题：对于要在生产环境部署 Agent 的团队来说，单一完成率排行榜根本不够用。你需要知道：这个 Agent 在哪类任务上会以哪种方式失败？失败是因为推理错了，还是因为工具调用时序不对，还是因为上下文丢失？目前没有标准框架回答这些问题。

解决方案：AgentAtlas 提出四个组件：六状态控制决策分类法（Six-state control-decision taxonomy）、九类轨迹失败分类法（Nine-category trajectory-failure taxonomy）、分类法感知的评测方法论，以及 benchmark 覆盖度审计工具，让 Agent 评测从"结果排名"升级为"失败模式诊断"。

价值：第一次为 Agent 失败提供了可重复使用的分类语言，让不同团队之间对 Agent 缺陷的描述可以对齐和对比，是 Agent 工程走向成熟的必要基础设施。

未来方向："失败模式诊断"将逐步替代单一完成率，成为生产级 Agent 评估的行业标准。

arXiv 2605.20530 · HuggingFace Papers

SpatialClaw：给 VLM 一个有状态 Python 内核，空间推理变成可操作的逐步计算

现状：视觉语言模型（VLM，能同时理解图像和文字的模型）在空间推理上的表现远不如语言推理：要判断两个物体的相对位置、估算角度、追踪多视角下同一物体的位置，对当前 VLM 来说都是挑战，因为这些判断需要维持跨帧的状态，而 VLM 天然是无状态的单轮处理模式。

问题：现有的 VLM 空间推理通常是"单步感知"——看一眼图像，给出判断。对于需要多步累积证据的空间任务（如"从三个视角分别看这个物体后，推断它的完整 3D 结构"），这种方法不可靠，错误会随步骤积累。

解决方案：SpatialClaw 维护一个预载了输入帧和感知/几何工具包的有状态 Python 内核（stateful Python kernel），允许 VLM 支持的 Agent 每步写一个可执行的代码单元（executable cell），并在所有先前输出的基础上进行条件处理——把空间推理从"单步感知"变成"有状态的逐步计算"。

价值：让 VLM 获得了空间任务中"记住之前看过什么"的能力，在机器人感知、AR 空间定位、多视角 3D 重建等场景有直接应用价值。

未来方向：有状态的计算内核将成为 VLM 应对复杂多步任务的标准增强方式，不限于空间推理。

arXiv 2606.13673 · HuggingFace Papers

LedgerAgent：结构化状态让工具调用 Agent 真正遵守复杂策略

现状：工具调用 Agent（tool-calling agent，即能调用外部 API、数据库或系统接口的 Agent）在执行多步任务时，经常违反业务策略约束——比如在没有满足前置条件时就调用某个工具，或者在已触发某个状态时仍重复调用。这类违规在单步任务里不明显，但在多轮长任务中会造成严重逻辑错误。

问题：现有的工具调用 Agent 通常把策略约束塞进提示词（prompt），依赖模型自己记住规则。但随着任务长度增加，模型在长上下文中遗忘约束的概率显著上升，"遵守策略"变得不可靠。

解决方案：LedgerAgent 引入结构化的策略状态账本（ledger，即对当前任务中所有已满足/未满足约束的显式记录），在每次工具调用前自动查询账本，确保调用决策与当前策略状态一致。状态不存在提示词里，而是在账本里持久化。

价值：把"遵守策略"从"依赖模型记忆"变成"依赖外部账本校验"，在合规要求严格的企业场景（如金融审批流、医疗操作流）下，Agent 的可靠性从根本上提升。

未来方向：策略状态显式化（policy state externalization）将成为企业级 Agent 部署的必要安全层，类似传统软件的权限中间件。
