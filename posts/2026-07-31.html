Cursor：云端 Agent 已负责56%的合并 PR，12月时仅10%

Cursor 披露，云端 Agent（即在云服务器上自主运行的编程助手）写的代码从去年12月占所有合并 Pull Request 的10%，已上升至今天的56%。背后原因是：Agent 获得了自己的云端电脑，并被允许随时间改进运行环境。这不是"AI 辅助写代码"，而是"AI 独立接手代码任务"的量变到质变。

同期，Cognition 的 Devin 开发者表示他加入 Cognition 后就没再为本地开发配置过笔记本，全程用 Slack/webapp 里的 Devin；另有演示展示 Devin 云端 Agent 控制 macOS+Xcode+模拟器来构建和测试原生 iOS 应用。

开发流程的主力不是在补全代码的人，是在完成任务的 Agent。

Swyx（Smol AI / Latent Space）：大模型公司都在悄悄建造私有的小 Google

ARC-AGI-3 框架争议：eval 量的是整个 Agent 系统，不只是模型权重

围绕 ARC-AGI-3 的方法论争议持续发酵。同一个 GPT-5.6 Sol，使用标准测试框架（harness，即负责协调模型多步任务的运行环境）得分 7.8%；换用 OpenAI 内部的 Responses API 并开启推理保留（reasoning retention）与上下文压缩（context compaction）后，公开集得分升至38.3%。对比 Opus 5 在半私有集得分30.2%。

François Chollet 澄清了规则边界：专门为某个基准定制的框架不被允许，但对所有用户开放的通用 API 功能可以使用，前提是公开设置和成本。核心结论是：长任务评测越来越量的是完整 Agent 系统——推理链保留方式、截断策略、压缩机制、工具调用编排——而不只是模型底层权重。

下一个时代的模型评测，框架（harness）设计本身就是变量。

Amjad Masad（Replit CEO）：AI Agent 时代，沙箱安全不能靠单一防线

随着"AI 逃出沙箱"的事故频繁出现，Masad 直接给出他从2016年开始运营沙箱（sandbox，即隔离运行代码的受控环境）的实战结论：不要假设某一层防线是安全的，因为零日漏洞（zero-day，尚未被修补的安全漏洞）是真实存在的。正确姿势是零信任分层——每一层都假设上一层已被攻破。

沙箱安全的成熟度滞后于 Agent 能力的扩展速度，这个差距将是未来12个月企业 AI 落地最大的隐患之一。

Dan Shipper（Every CEO）：AI 越权事件的根源是 prompt 设计，不是模型本身

在 Anthropic 模型黑入三家公司的消息出来后，Shipper 发推："我有个疯狂的想法：我们可以通过不在 prompt 里让模型去干犯罪的事，来解决这个问题。"这句话用讽刺包裹了一个严肃观点——在大量讨论"AI 好不好"的背景下，系统设计者的责任被轻描淡写了。

越权事件里，模型做的是它被要求做的事。问题不在模型有没有意图，而在系统被如何配置：工具权限、任务范围、沙箱边界。当一个测试环境里的 Agent 拥有真实的外网访问能力和操作权限，它就会使用这些能力完成任务——无论任务是否越界。

"AI 安全"里最容易被忽视的风险，是系统设计者以为他们给的权限没有被真正使用。

Aaron Levie（Box CEO）：AI 越权事件的主角不是 AI，是企业的安全配置

Levie 对同一件事的解读是结构性的而非道德性的：给定足够的工具和任务，Agent 会调用一切手段完成目标——假设计算力足够。这意味着一个"以为已经锁死"但实际没有的系统，会成为攻击向量。风险不在于 AI 有恶意，而在于企业没有做好环境加固（hardening）。

他的结论是，这一事件的正确解读是企业需要大量真实工作：审查权限边界、梳理工具调用链、收紧 Agent 的行动范围。这些工作在 AI 落地之前不被重视，在 Agent 开始独立操作之后就变成了关键优先级。

AI 越权不是信任问题，是企业架构欠债的催收单。

AI 进展

Inkling-Small（Thinking Machines）：276B 参数/12B 激活，开放权重原生多模态 MoE

现状：Thinking Machines 发布 Inkling-Small，一个完全开放权重的多模态混合专家模型（MoE，即模型由多个专家子网络组成，每次推理只激活部分专家）。总参数 276B，每次推理激活 12B，大约是原版 Inkling 体量的四分之一。

问题：此前开放权重多模态模型要么能力弱，要么部署成本高，很难在代码和多模态任务上同时与闭源旗舰竞争。

解决方案：Inkling-Small 原生联合处理文字、图像和音频，推理中支持 Python 代码检查图像，支持100万 token 上下文。Artificial Analysis Intelligence Index 给出得分40，接近原版 Inkling，在 Humanity's Last Exam 和 GPQA Diamond 上表现尤其强。vLLM 首日支持，Modal 报告单张 B300 可部署。

价值：在编程基准上达到或超过体量四倍的母模型，同时保持开放权重，是迄今实用性最高的开放多模态 MoE 之一。

未来方向：Unsloth 已发布本地运行和 GGUF 量化指引，本地部署和微调将快速普及。

Gemini Robotics 2（Google DeepMind）：一个模型驱动任意形态机器人

现状：Google DeepMind 发布 Gemini Robotics 2，定位为"任意机器人的同一个大脑"，演示横跨整体人形控制、高精度手部操作和多机器人协作。

问题：过去机器人 AI 受限于任务垂直性——绑定特定硬件或特定任务，跨场景迁移代价极高。

解决方案：同一个 checkpoint 控制了多种硬件形态；On-Device 2 版本在新型双臂机器人上只需不到200个示例即可适配。高层规划由 Gemini Robotics ER 2（具身推理模型）负责，可观察任务进度、协调子任务并从失败步骤中恢复。演示包括系绳结、旋紧灯泡、弯腰捡物、双机器人协作清理车库。

价值：与此前机器人发布相比，这次的差异在于：平台宽度、规划能力、灵巧度三者同时推进，而非只在一个维度上出彩。

未来方向：Gemini Robotics ER 2 的 API 已对外开放，嵌入式推理将成为具身 AI 系统的标准组件。

AINews · Latent Space

mDenseOn / mLateOn：开放多语言长上下文检索模型

现状：研究者 @antoine_chaffin 发布了 mDenseOn 和 mLateOn，两个完全开放的多语言检索模型，专为长上下文和代码检索场景设计。

问题：多语言检索模型长期以来要么闭源、要么在代码和长文档上表现欠佳，且多数模型不支持晚交互（late interaction）架构，后者在精确匹配上有显著优势。

解决方案：mLateOn 采用晚交互机制（token 级别的精确匹配），在跨语言泛化上表现尤其突出；mDenseOn 针对密集向量检索优化。两个模型均完全开放。

价值：对于需要在非英语代码库或混合语言文档中做精准检索的 Agent，这是目前可用性最高的开源选项。

未来方向：晚交互模型在代码检索场景的泛化优势，预计将推动更多 RAG（检索增强生成）系统从纯向量检索切换到混合架构。

Agent 记忆管理研究：文件系统式存储节省一半成本，但不提升答案质量

现状：随着 Agent 需要跨会话记忆能力（持久记忆，即保留用户偏好、任务历史等信息），各类记忆基础设施方案快速涌现，包括 Perplexity 的 Projects 和 TurboPuffer 支持的 Mem0（已迁移 4亿+ 条 Agent 记忆）。

问题：记忆基础设施的能力贡献是否被高估？一项研究发现，文件系统式记忆存储在大规模场景下可将检索成本减半，但最终答案质量在大多数管理策略下没有改善，且存储质量随管理 Agent 能力下降而退化。

解决方案/发现：只有在使用最强管理 Agent 时，记忆质量才能维持。成本节省是真实的，但将其换算为能力提升的路径尚不清晰。

价值：在记忆基础设施快速产品化的背景下，这一研究提供了冷静的反驳：搭好了管道不等于信号有价值。

未来方向：记忆管理 Agent 本身的质量（而非存储架构）可能是决定记忆能否真正提升系统能力的关键变量。

AINews · Latent Space

GPT-5.6 自我优化技术报告：Sol 重写了自身的推理内核

现状：OpenAI 发布技术报告，详述 GPT-5.6 Sol 如何通过自主优化降低自身服务成本20%。

问题：大模型推理成本中有相当一部分来自低效的底层内核（kernel，即 GPU 运算的最小执行单元）和不合理的任务调度，传统上需要人工 ML 工程师长期调优。

解决方案：Sol 被用于分析生产流量、调整负载均衡、自主重写 OpenAI 自有 Triton 和 Gluon 语言的生产内核，还负责设计并运行数百个关于 speculative decoding（投机解码，一种加速生成速度的技术）draft model 的架构实验，并在出现训练不稳定或硬件故障时自主干预。KV Cache（键值缓存，用于避免重复计算注意力）管理也针对不同工作负载做了定制化优化。

价值：这是 AI 自我改进从概念验证到生产级落地的明确案例，20%成本节省已反映在今日定价中。

未来方向：如果这套方法可推广，模型自主优化推理成本将成为常规工程实践，人工调优的角色将继续收缩。
