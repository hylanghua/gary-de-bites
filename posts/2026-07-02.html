AI 方向观点

Aaron Levie（Box CEO）：Devin 的 agentic mapreduce 是 100x 推理需求的活证据

Aaron Levie 今天在 X 上转发并深度评论了 Devin 最新发布的 agentic mapreduce（代理式映射-归约，借用分布式计算术语：把一个大任务拆分给多个 agent 并行处理，再汇总结果）用例。Devin 的做法是：先扫描整个代码仓库找出相关信号，再将代码切分成有边界的分片分发给多个聚焦 agent 并行处理，最后把所有发现汇总成一份报告，并在独立沙盒（sandboxed environment，隔离的执行环境）中验证严重漏洞。这一次的场景是代码安全审计，但 Levie 的判断是这只是一个典型，同样的模式可以在文档处理、知识管理、风险分析、药物发现等任何大规模非结构化数据场景中复制。

他的核心结论：这类 agent 工作流依赖大量 token 吞吐——混合使用前沿模型（做复杂推理和最终验证）和低成本模型（处理并行分片任务），才能在经济上可行。这意味着"多模型分层部署"不是可选功能，而是让 agent 工作流跑得起来的基础设施条件。Levie 在 Box 也正在做同样的事：帮助企业客户处理数百万份文档做风险识别、洞察提取和关系梳理。

Devin 把代码安全审计变成了一个可以全自动、全覆盖、全并行的流水线——Levie 的意思是，这个句子里的"代码安全"可以替换成任何知识密集型工作。 X @levie

Paul Bakaus（Impeccable 作者，via Latent Space）：Skill engineering 是新兴职业——给 AI agent 赋予设计词汇表，才能解决输出同质化

Latent Space 今日发布对 Paul Bakaus 的深度访谈。Bakaus 是开源设计技能系统 Impeccable 的创始人，他的核心论点是：大多数 AI agent 不够有创意，"因为它们趋向收敛——如果所有人用同一个技能做前端设计，最终所有界面都会长一个样"。解法是 skill engineering（技能工程）——一个正在成形的新职业，核心工作是把领域专家的专业词汇和判断逻辑转化成 agent 可以可靠执行的技能文件。

他的关键发现：一个设计师和一个工程师用同一个模型做同样的设计任务，产出质量差距极大——不是因为能力，而是因为设计师知道怎么描述自己想要什么。Impeccable 的做法是把"大胆（bold）"不定义为"加渐变、加霓虹效果"，而定义为"提升信息层级、加大关键元素比例、用决断性排版来吸引注意力"。"形容词加上没有任何背景，只是一个漂亮的撇号。你必须告诉 agent 你真正的意思是什么。"他把这个过程叫做给词汇"赋予意义（imbue with meaning）"。

更大的判断是：设计、工程、产品管理的边界正在模糊。"设计师正在进入代码，工程师正在进入设计，双向都在发生。"只做"把 Figma 稿转成代码"的工程师和只做"让现有界面看上去还行"的设计师，都面临自动化压力。Bakaus 认为，设计师和 PM 的角色实际上在向同一层收敛：思考"要做什么"，而不是"如何实现"。

Skill engineering 的价值不在于让 agent 更聪明，而在于让人类的领域判断得以被系统性封装和复用——这是一个把专家知识工程化的新职业，而不只是"写更好的 prompt"。 Latent Space / X @swyx

产品与商业

Guillermo Rauch（Vercel CEO）：agentic deployments 新增 dry-run 步骤——让 agent 先验证，再推

Guillermo Rauch 今日宣布 Vercel 正在为 agentic deployments（agent 自主触发的部署流程，不需要人工手动执行部署命令）推出 dry-run（干运行，即不产生实际变更的预检验步骤）。他的观察："Agents love to check their work before they push. You probably see it in the form of `node --check`, `tsc --noEmit`, `next build` etc all over your agent sessions."（"Agent 喜欢在推送前检查自己的工作。你大概已经在 agent session 里见过各种形式的检查指令了。"）干运行的意义是：在真正触发部署之前，在云端完整模拟一次构建，确认没有错误，再实际执行——把 agent 已有的"自我检查"习惯提升成平台级的标准步骤，而不是依赖 agent 在 session 里自发做。

结合 Rauch 同日分享的另一个案例（WordPress on Vercel + Docker + MySQL on PlanetScale，30 秒完成含 docker build 的云端构建），可以看到 Vercel 的方向：把传统开发工作流（包括 WordPress 这种二十年老栈）整合进 agentic deployment 体系，而不是要求开发者重写工作流来适配 AI。

Dry-run 是 agentic deployment 从"能用"到"可信"的关键一步：让 agent 的部署权限不再是全有全无，而是"先验证、再确认、后执行"的分级授权。 X @rauchg

Zara Zhang：构建技能的反直觉方法论——"你不是从 skill 开始，你是以 skill 结束"

Zara Zhang 今日在 AIEWF 期间发了一条方法论总结："HOW TO BUILD A SKILL: You don't START with a skill. You END with a skill. Building the skill is the last step of your workflow, not the first step."（"如何构建技能：你不是从技能开始，你是以技能结束。构建技能是你工作流的最后一步，不是第一步。"）

这个直觉对很多人来说是反向的：很多人的做法是先想好"我要做一个技能"然后去设计它，但 Zara 的框架是：先把工作流跑通（反复用 agent 完成实际任务），在跑通之后，把整个流程提炼、结晶成一个可复用的技能文件。Skill 是 workflow 成熟后的产物，不是工作的出发点。这和 Latent Space 今日对 Paul Bakaus 的访谈（Impeccable 也是从扩展 Anthropic 前端技能开始，而不是从"设计一个完整技能系统"开始）形成了方法论上的呼应。

先做工作、再提炼工具——这个顺序看起来显而易见，但在 AI 工具爆炸的语境下，很多人恰恰在没有跑通工作流之前就急于封装。 X @zarazhangrui

AI 进展

Agents-A1（上海 AI Lab）：35B 参数超越万亿参数模型——靠的不是参数量，而是 agent 决策深度

现状：AI 模型能力竞争长期依赖规模化参数（parameter count），万亿参数模型（如 Kimi-K2.6、DeepSeek-V4-Pro）被视为性能天花板，而训练和部署成本极高。

问题：能否在更小的参数规模下，通过改变 agent 的决策方式而不是增加参数，达到同等甚至更好的效果？

解决方案：上海 AI Lab 的 InternScience 团队推出 Agents-A1，一个 35B MoE（混合专家，Mixture-of-Experts，让模型根据任务动态激活不同子模块的架构）模型。核心创新是构建"长视野知识-行动基础设施"（long-horizon knowledge-action infrastructure）：训练数据平均每条轨迹约 45K tokens，远长于常规训练样本。三阶段训练：全领域 SFT（监督微调）→ 领域级教师模型 → 多教师域路由在线策略蒸馏。开源于 Hugging Face（InternScience/Agents-A1）。

价值：SEAL-0 基准 56.4，IFBench（指令遵循）80.6，FrontierScience-Olympiad（跨领域科学题）79.0，全面达到或超过训练成本高出数倍的万亿参数模型。这是一个"花更少训练更多"路径的实质性证明：决策深度可以部分替代参数规模。

未来方向：在资源受限环境下（边缘设备、私有化部署）实现高能力 agent，以及进一步提升多领域泛化能力。

arXiv 2606.30616 · HF Week 27 #1

VibeThinker-3B（WeiboAI）：3B 参数达到 AIME26 94.3%——小模型可验证推理的新边界

现状：大型推理模型（如 OpenAI o3、DeepSeek-R1）在数学竞赛和代码题上取得突破，但参数规模通常在数百亿到数千亿级别，推理成本高、延迟大。

问题：30 亿参数（3B）以内的小模型，是否能在可验证推理任务（有标准答案可以自动评分的任务，如数学、代码）上接近甚至超越更大模型？

解决方案：WeiboAI 团队提出 Spectrum-to-Signal 后训练范式，三步组合：课程制 SFT（从易到难有序微调）→ 多领域强化学习（让模型在不同类型的可验证任务上自我改进）→ 离线自蒸馏（让模型从自己过去的好答案中持续学习）。同时支持 claim-level 测试时扩展（推理时对中间步骤做二次验证）。

价值：AIME26（美国数学邀请赛，2026 题目）94.3%（含 claim-level 扩展达 97.1%），LiveCodeBench v6 Pass@1 80.2%，最近 LeetCode 周赛 96.1% 通过率。3B 小模型达到这一水平，意味着强推理能力向私有化、低成本部署场景迈出关键一步。

未来方向：进一步压缩推理时 token 消耗（当前强推理仍较长），以及在开放域问答（非可验证任务）上的泛化。

arXiv 2606.16140 · HF Week 27

AutoTrainess：让 LM agent 自动完成整个后训练流程——AI 训练 AI 的系统性实践

现状：大模型的后训练（post-training，包括 SFT、RLHF、评估、迭代等环节）高度依赖人类专家判断：怎么构建训练数据、怎么调超参、怎么判断 checkpoint 质量，每一步都需要经验积累。这既是成本瓶颈，也是很多团队无法追上前沿的核心壁垒。

问题：能否把人类后训练专家的决策逻辑封装成 agent 可执行的工作流，让 AI 在无人干预的情况下自主完成整个后训练循环？

解决方案：AutoTrainess 把后训练流程拆解为 agent 可调用的步骤：规划迭代方向 → 构建与 benchmark 对齐的训练数据 → 执行稳定的训练任务 → 评估 checkpoint → 保存跨多小时交互的实验状态。把人类专家知识外化为显式工作流（explicit workflows）和 agent-computer 接口（agent 和计算环境交互的标准化接口）。

价值：在 PostTrainBench（后训练能力评估基准）上，AutoTrainess + GPT-5.4 达到 26.94，优于 CLI-only 基线的 23.21；把 DeepSeek-V4-Flash 从 12.13 提升到 19.58。自动化后训练不只节省人力，更重要的是让后训练能力不再是少数顶级实验室的专属资源。

未来方向：与搜索类 autoresearch（自动科学研究）系统整合，构建"从假设到训练到评估"全自动化的模型改进闭环。

arXiv 2606.31551 · HF Week 27

CAT: Confidence-Adaptive Thinking（ACL 2026 工业赛道）：用置信度动态分配推理预算，让大推理模型不再一律慢

现状：大推理模型（Large Reasoning Models，如 OpenAI o 系列、Claude 扩展思考模式）通过长链式思考（chain-of-thought）显著提升复杂任务准确性，但代价是几乎每个请求都消耗大量 token，包括那些其实不需要深度推理的简单问题。

问题："What is 2+2?" 和"证明黎曼假设"使用完全相同的推理深度，是资源浪费，也是延迟过高的根本原因。如何在不降低准确率的前提下，让推理预算（reasoning budget）随问题难度动态伸缩？

解决方案：CAT（Confidence-Adaptive Thinking）在推理时实时估算模型的置信度（confidence signal），高置信度请求分配更短的思考链，不确定的请求扩展推理轨迹。置信度估算本身是轻量级的，不需要额外前向传播。已被 ACL 2026 工业赛道录用。

价值：在保持准确率的同时显著降低平均推理成本和延迟，尤其对混合难度的生产环境（如 API 服务、实时应用）价值突出。让大推理模型从"昂贵的专用工具"向"自适应的通用工具"迈进。

未来方向：与 token 预算约束（token budget constraints）结合，以及在多模态推理中的扩展。

arXiv 2607.00862 · HF Week 27

Perceive-to-Reason（浙江大学 ZJU-REAL）：把感知和推理拆成两步，精细视觉推理准确率大幅提升

现状：多模态大模型（如 GPT-4o、Claude Vision）在需要精细视觉理解的任务上仍有明显弱点：对高分辨率图像中的小细节、多元素关系、需要定位再回答的问题，模型容易"看到但没看懂"。

问题：视觉推理失败往往不是推理能力问题，而是感知（perception）层没有把对的视觉证据提取出来——模型直接从原图做推理，而不是先找到相关区域再推理。

解决方案：P2R（Perceive-to-Reason）两阶段框架：Perceiver 阶段先在高分辨率图像中定位与问题相关的视觉证据（画出标注框、裁剪出相关区域）；Reasoner 阶段再基于标注图和裁剪区域给出答案。训练方法是 PRA-GRPO（Perception-Reasoning Alternating GRPO，感知-推理交替强化学习），交替进行"聚焦感知能力"和"聚焦推理能力"的更新，只用最终答案做监督信号。

价值：在多个精细视觉推理基准上取得显著提升，尤其在需要定位+理解的场景（如图表细节、医学影像、密集文字图）。仅用最终答案监督（不需要标注中间步骤）是实用性的关键。

未来方向：扩展到视频理解（时序感知+推理）和具身智能（需要感知→计划→行动的闭环场景）。
