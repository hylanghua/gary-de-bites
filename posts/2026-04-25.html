AI 方向观点

DeepSeek V4 Flash 才是真正的颠覆者

DeepSeek V4 发布的头条被 Pro（1.6T 参数）占据，但研究者们私下谈的是 Flash：284B 参数，1M 上下文，输入 $0.14 / 输出 $0.28 每百万 token。Luka Blagojevic（@teortaxesTex）说得直接：「他们完成了任务——真正可用的超长上下文」。

技术上，V4 引入了 Compressed Sparse Attention（CSA）和 Heavily Compressed Attention（HCA）两层注意力压缩方案，让 1M token KV 缓存从 V3.2 的 83.9 GiB 压到 9.62 GiB，再配合 FP4/FP8 混合量化后再降一半，最终只占约 10%。Flash 版本甚至可以在 256GB Mac 上跑。Arena 数据显示 Flash 的推理得分与 Pro@high 设置几乎持平，但成本便宜 12 倍。

这意味着「把 1M 上下文送进每一个 agentic 工作流」在经济上首次真正可行。不过有个隐患：V4 Pro 在 Artificial Analysis 的评测中用掉了 1.9 亿输出 token，按件计费时的实际账单仍可能吓人。

开放权重的长上下文战争已经有了第一个真正的民用选手，问题是谁先把它嵌进产品。

Latent Space AINews

swyx（Latent Space 创始人）：今天的热门技能，明天就是 posttrain 目标

swyx 用一句话击中了 AI 时代学习焦虑的本质：「今天流行的技能，明天就会成为模型 post-training（后训练，即 RLHF/微调等步骤）的标准化目标。」换句话说，你越努力学一项当下最吃香的技能，这项技能被自动化掉的速度就越快，因为大量人类示范数据正在为下一代模型铺路。

这个逻辑没有「不学就安全」的出路，而是指向另一个方向：持续向前移动到模型还没覆盖的地方，或者去做模型永远需要人类判断力的事。

swyx 描述的不是焦虑，是一张加速时代的漂移路线图。

Aditya Agarwal（SPC 创始人）：我们正在进入「后 Prompt」时代

「我们正在接近一个不再需要 prompting（手动写指令）的世界。」Aditya Agarwal 的这句断言背后的逻辑是：随着模型自主性增强，让 AI 理解意图的方式从「写好指令」变成「给出目标和上下文」，再到「让系统自己推断意图」。Prompt 工程作为一项专业技能正在走向平台期。

这不代表 prompting 消失，而是它从前台走向幕后，成为框架和系统的内部实现，而非用户日常操作界面。

Aditya 指的不是 prompt 写法变了，是 AI 交互的主接口正在位移。

X @adityaag

Dan Shipper（Every 创始人）：任何 AI 都比任何单个人类知道得更多

Dan Shipper 直接说出了那个让人不舒服的事实：就信息量和覆盖范围而言，任何一个 AI 都已经超过任何一个人类个体。这句话的意义不在于「AI 更聪明」，而在于个体知识的垄断性（即「因为我知道你不知道，所以我有价值」）正在被瓦解，真正的竞争优势将越来越依赖判断力、关系和执行力，而非存储式知识本身。

Dan 描述的是知识经济的底层重构，不是 AI 能力的炫耀。

Amjad Masad（Replit CEO）：几次点击导入 Vercel / Lovable 项目

Replit 上线了一键迁移功能，可以直接把 Vercel 或 Lovable 上的项目导入到 Replit 环境，保留文件结构和依赖配置。Vercel 和 Lovable 都是当前 vibe coding（即用自然语言生成代码的快速原型工具）最主流的宿主平台，Replit 此举等于在入口侧开了一个吸管。

对用户来说，这意味着可以从「纯生成」工具平滑过渡到 Replit 的「可部署、可运行」环境，而不用手动复制代码。Amjad Masad 一贯的策略是降低切换成本、拓宽用户来源，这次动作延续了这个逻辑。

Replit 把自己变成所有 AI 原型项目的第二站，而非第一站，这是一步防守中的进攻。

petergyang：GPT-5.5 + Codex 15 分钟做出《星际火狐》，AI 自测 bug

Peter Yang 用 GPT-5.5 和 Codex（OpenAI 的代码 agent 工具）做出了一个可运行的《星际火狐》风格射击游戏，整个 prompting 过程不到 15 分钟。更有趣的是后半段：他让 AI 自己去玩这个游戏进行测试，模型在「玩」的过程中发现了几个逻辑漏洞并自行修复。

人文与哲学

Tim Ferriss 5-Bullet Friday：从《饮食男女》到技术乐观主义作为一种宗教

本期 Tim 推荐了李安 1994 年的《饮食男女》：一个台北老厨师与三个未婚女儿共享每周日晚饭，食物是仪式，饭桌是家庭力学的放大镜。Tim 说他看了至少五遍，每次都饿着肚子出来。电影现在在 YouTube 免费可看。

阅读部分，Tim 转发了 Reid Hoffman 新 Substack「Theory of the Game」的首篇《Faith in the Possible》。Reid 把科技乐观主义解剖成一种宗教结构：有信条（创造本身是意义），有宗派（激进加速主义 vs 审慎乐观主义），有异见者。Tim 特别提醒：评论区比正文更值得一读，有不少批判性视角把创业公司作为「进步引擎」这一假设拆得很彻底。

Kevin Kelly 的《Some Contemporary Heresies》同样在列，收录了一批「聪明人才敢说出口的离经叛道判断」。聪明不等于正确，但 Kelly 的框架是：只有异见才能在思想上给人留下真正的划痕。

本期压轴语录来自拉比哲学家 Jonathan Sacks：「在家庭中，我学会了爱的复杂编排——给予、索取、分享；从服从到责任的成长；犯错、原谅、争吵、和好；赢而不骄，输而知收。」

Tim 这一期把三个不同时代的声音串在一起，共同问的是同一件事：什么给生命提供结构，什么给信念提供基础。

AI 进展

TIP：在线蒸馏中只有 50% 的 token 真正有效（arXiv 2604.14084）

现状：在线蒸馏（on-policy distillation）让学生模型在自己生成的数据上接受教师模型的 token 级监督，是目前压缩大模型能力的主流方法。

问题：全量 token 训练中，大量 token 对学习几乎没有贡献，造成计算和显存浪费。

解决方案：论文提出 TIP（Token Importance in on-Policy distillation）框架，用「学生熵」和「师生分歧」两个维度对 token 打重要性分，高熵（学生不确定）和高分歧（学生自信但和教师不同）的 token 最有效。只选 50% 高价值 token 训练，可节省约 47% 的峰值显存。

价值：在保持或超越全量训练质量的前提下，将训练成本减半，对中小团队跑蒸馏实验意义明显。

未来方向：将 token 选择策略推广到非在线蒸馏场景，以及与 LoRA 等参数高效方法结合。

arXiv 2604.14084 · HuggingFace Papers

Hyperloop Transformers：参数减半，性能不减（arXiv 2604.21254）

现状：标准 Transformer 每增加深度（层数）都要线性增加参数量，显存和推理成本随之上升。

问题：如何在不损失能力的前提下，大幅压缩参数规模。

解决方案：MIT 团队提出 Hyperloop Transformer，将模型分为「头尾正常层 + 中间循环层」结构，中间部分反复复用同一批权重（looped，即权重共享式循环）。循环层再配合 DeepSeek 在论文中引入的 Hyper-connections（超连接，对残差流做矩阵化扩展）强化信息传递，整体参数约为同深度标准 Transformer 的 50%。

价值：在 240M、1B、2B 三个规模上均超越同深度标准 Transformer，且量化后性能保持稳定，适合显存受限的部署场景。

未来方向：探索更大参数规模的 Hyperloop 架构，以及与 MoE（混合专家）结合的可能性。

arXiv 2604.21254

Tool Attention Is All You Need：每轮工具 token 从 47K 压到 2.4K（arXiv 2604.21816）

现状：Agent 系统通过 MCP（Model Context Protocol，模型上下文协议）或 function calling 接入多个工具时，每个工具的 schema（描述文档）都要塞进 context，120 个工具 / 6 个服务器的场景下每轮高达 47K token，占用近 70% 的有效上下文空间，推理质量明显下降。

问题：每轮给模型「所有工具说明书」既浪费又降效，但提前不知道这轮会用哪个工具。

解决方案：论文提出 Tool Attention，一个运行在中间件层的注意力机制，用 ISO（意图-schema 重叠度）评分实时决定加载哪些工具的 schema，不相关的工具延迟到真正需要时才注入（lazy loading）。120 工具基准测试中，每轮 token 从 47.3K 降至 2.4K，降幅 95%，上下文利用率从 24% 升至 91%。

价值：对在生产环境中接入大量 MCP 服务的团队是直接的成本和质量双优化。

未来方向：将动态 schema 注入与 agent 内存系统结合，支持跨会话 tool 使用历史感知。

arXiv 2604.21816

StructMem：结构化分层记忆，提升 LLM 长对话推理（arXiv 2604.21748）

现状：长对话 agent 需要记住事件之间的关系，不只是孤立事实，才能做时间推理和多跳问答。

问题：平铺记忆（flat memory）省算力但丢关系结构；图结构记忆（graph memory）能建关系但构建代价高且容易出错。

解决方案：StructMem 提出「结构化分层记忆」框架，在事件级做双视角时间锚定，并定期做语义整合。在 LoCoMo 长对话推理 benchmark 上，同时提升了时间推理和多跳问答得分，还减少了 token 用量、API 调用次数和运行时长。

价值：为需要跨对话持久记忆的 agent 提供了一个在质量和成本之间取得平衡的新选项。

未来方向：将结构化记忆推广到工具调用历史和用户偏好的跨会话积累。

arXiv 2604.21748

MesaNet：线性 RNN 新架构，固定内存推理追平 Transformer（arXiv 2506.05233）

现状：标准 Transformer 的 softmax 注意力在推理时显存和计算随序列长度线性增长；线性 RNN 模型（如 Mamba、xLSTM）可以做到固定推理成本，但能力通常略逊。

问题：如何在保持 RNN 固定内存优势的同时，在能力上真正匹配 Transformer。

解决方案：MesaNet 基于 Mesa layer 构建，用共轭梯度法（conjugate gradient solver）在每个时间步做局部最优化，支持分块并行（chunkwise parallelizable）且数值稳定。在 MAD benchmark（测试序列模型多种推理能力的综合基准）上，MesaNet 超越所有现有线性 RNN 架构，并与 Transformer 持平。

价值：为长序列推理场景提供了一个在显存开销上有明显优势的 Transformer 替代方案。

未来方向：在更大规模语言模型上验证，以及与 hybrid attention 架构结合。
