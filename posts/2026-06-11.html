AI 方向观点

Sarah Guo（Greylock）：「不可训练」的三个角落——意图、领域翻译、维护，AI 最终无法消化的稀缺资源

Greylock 合伙人 Sarah Guo 在她的 Substack「The Untrainable」里提出了一个框架：随着智能越来越便宜，价值将向「模型触达不了的地方」滑移。她列出了三个「不可训练」的角落：其一是「意图」（决定做什么，而不是怎么做）——「模型会做你指向的任何事，但无法告诉你值得指向什么，你也没法对它做 benchmark，所以没法训练它」；其二是「领域翻译」（把公司的私有现实整理成模型能行动的形式，再把领域专精工程师放在客户旁边持续维护）；其三是「维护」（集成和维护只要关系存在就不会结束）。

她最后写道：「每年我真正找到三次。模型在那里帮不了你。这也是为什么既有玩家拿不走一切：他们守住既有地盘，而下一件事总是来自那些比其他人更早看到用途的人。也许意图是比算力更稀缺的投入。」AINews（Swyx）在总结中补充：这个框架同时解释了「开放模型为什么能存活」和「Agent 实验室为什么比模型实验室更有壁垒」——应用层赚的是「翻译不断结束、然后再开始」的钱。「意图比算力更稀缺」这个判断，是今年 AI 行业里最值得长期押注的命题。

AI 进展

Agents' Last Exam (ALE)：13 大行业 1000+ 真实任务，顶级 Agent 最难层仅过 2.6%，GPT-5.5 意外压过 Fable 5

现状：现有 Agent 基准（benchmark，衡量模型能力的标准化测试）大多基于学术题目或合成任务，无法反映 AI 在真实职业场景中的实际表现。

问题：GPQA、SWE-bench 等现有基准被模型快速饱和，最高分 Agent 的表现已无法区分「真正有用」和「擅长刷分」。

解决方案：ALE 由 Dawn Song 团队联合 250+ 行业专家构建，覆盖 13 大非体力行业（参照 O*NET/SOC 2018 职业分类，包括金融、法律、医疗、工程等）、55 个子领域、1000+ 任务。每个任务来自专家真实完成的项目，Agent 拥有完整的 GUI 和 CLI 访问权限，结果由确定性代码（非人工打分）评估。最难层（Tier 4）的平均全通过率为 2.6%。

价值：VentureBeat 报道了一个意外结果：GPT-5.5 在 ALE 上压过 Fable 5，这与 Fable 5 在多数其他基准上的领先表现形成反差，说明不同任务结构下模型优势存在显著差异，单一基准无法代表「综合能力」。

未来方向：以真实职业任务为单位的 Agent 评测方法论将成为行业标准，「能不能替代真实工作」将比「benchmark 第一」更有说服力。

arXiv 2606.05405 · HuggingFace

DiffusionGemma：Google DeepMind 发布 26B MoE 扩散文本模型，4 倍速、1200 tok/s，Apache 2.0 开源

现状：主流大语言模型（LLM）均采用自回归（autoregressive）架构，即逐词预测下一个词，速度受串行解码限制。

问题：自回归解码天然无法并行化，在长输出场景下速度慢，且难以支持「修改中间段落」这类迭代式编辑操作。

解决方案：DiffusionGemma 采用文本扩散（text diffusion）架构，同时生成并精炼 256 个 token 的文本块，而非逐词生成。模型为 26B MoE（混合专家，一种只激活部分参数的模型结构），推理时仅激活 3.8B 参数，支持 256K token 上下文和 140+ 语言。在单张 NVIDIA H100 上实测 1200+ tok/s，在 RTX 5090 上达 700+ tok/s，量化后显存需求约 18GB（可在高端消费级显卡上运行）。

价值：在 vLLM（主流开源推理框架）中原生支持，是首个在生产推理框架中可用的扩散文本模型。整体输出质量低于 Gemma 4 标准版，但速度优势显著，适合批量生成、实时场景、fill-in-the-middle 编辑等自回归模型天然弱势的任务。Apache 2.0 协议，商用无限制。

未来方向：文本扩散架构重新打开了「非线性生成」的研究方向，对迭代精炼、约束编辑、错误纠正等场景有潜在优势，可能成为自回归的互补而非替代。

Externalization in LLM Agents：统一综述记忆、技能、协议、框架工程四大维度，梳理 Agent 架构的外化逻辑

现状：Agent 系统（能自主执行多步任务的 AI 应用）的工程文献分散在记忆系统、工具调用、多 Agent 协议、框架设计等多个子领域，缺乏统一视角。

问题：对 Agent 架构设计的理解高度碎片化，工程师难以系统判断在不同场景下应选择哪种「外化」策略——把什么放在模型参数里，什么放在外部状态里。

解决方案：该综述提出「外化」（externalization）作为统一框架，将 Agent 架构的核心设计问题归结为四类：记忆外化（什么信息存在 Agent 之外）、技能外化（什么能力以工具/函数形式提供）、协议外化（多 Agent 如何协调）、框架工程（harness，即组织 Agent 运行流程的脚手架）。

价值：为 PM 和工程师提供了一个判断 Agent 系统「胖瘦」的分类语言：什么该在模型内，什么该外化。理解这个分类，有助于在真实产品设计中做出更有依据的架构选择，而不是跟风使用最新框架。

未来方向：随着 Agent 系统从研究原型走向企业部署，架构标准化压力增大，「外化」框架有望成为 Agent 工程的共同语言。

arXiv 2604.08224

Agentic Code Reasoning：半正式结构化推理在 Agent 代码任务上持续有效，形式化思维与自然语言的混合是关键

现状：在代码生成和调试等 Agent 任务中，模型通常采用纯自然语言推理（chain-of-thought）或纯代码输出，两种方式各有盲点。

问题：纯自然语言推理在复杂代码逻辑上容易犯「言之成理但代码错误」的错误；纯代码输出缺少中间推理过程，难以调试和修正。

解决方案：研究发现，「半正式」（semi-formal）结构化推理——在自然语言推理中嵌入伪代码、类型标注、前置后置条件等形式化符号——持续提升 Agent 在代码推理任务上的成功率，且这一效果跨模型家族、跨任务类型均稳定成立。

价值：对工程师的直接启示：在 prompt 设计中引导模型用「半正式」风格思考（比如先写函数签名再写实现，或先写断言再写逻辑），而非只要求「写出正确代码」，可以系统性提升 Claude Code、Codex 等工具的输出可靠性。

未来方向：半正式推理与现有 Agent 框架（工具调用、多步规划）的结合是下一步研究方向，有望成为代码 Agent 系统设计的标准推理模式。

arXiv 2603.01896

ViDoRe V3：2.6 万页多模态 RAG 基准，揭示当前模型在非文字元素和开放式查询上的明显短板

现状：RAG（检索增强生成，让 AI 能从外部文档库里检索相关信息后回答问题）系统在企业文档理解场景中被广泛应用，但现有评测集大多只覆盖纯文字文档。

问题：真实企业文档包含大量表格、图表、图像、混合排版等非文字元素（non-textual elements），当前 RAG 管道在这些元素上的表现远低于纯文字场景，但现有基准无法量化这一差距。

解决方案：ViDoRe V3 覆盖 10 个专业领域（金融、制药、工业维护、电信、物理等），包含约 2.6 万页文档和 3,099 条人工标注查询，支持 6 种语言。通过 12,000 小时人工标注，覆盖检索相关性、包围框定位和参考答案验证三个维度。结果发现：视觉检索器（visual retrievers）普遍优于纯文字检索器，但所有模型在开放式查询和精细视觉定位上仍有明显短板。

价值：已整合进 MTEB（多任务文本嵌入基准，业内主要的检索能力排行榜），成为评估企业级多模态 RAG 能力的新标准，填补了「真实文档检索」与「学术评测」之间的空白。

未来方向：随着 Agent 需要读懂包含图表和图像的真实报告，多模态检索能力将成为企业 AI 系统的核心能力门槛，ViDoRe V3 类基准将持续推动这个方向的进步。
