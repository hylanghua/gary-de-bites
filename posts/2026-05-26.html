新闻速递

Microsoft 内部撤销 Claude Code 许可，工程师限期迁往 Copilot CLI

Microsoft 的 Experiences & Devices 部门已取消大多数 Claude Code 许可证，受影响工程师被要求在 6 月 30 日前迁往 GitHub Copilot CLI（命令行 AI 编程工具）。据报道，这次撤退的核心原因是经济账：在当前 token（AI 处理文本的基本计价单位）定价下，大规模部署 Claude Code 的成本模型对企业而言还没算平。

这不是对 AI 编码工具的否定，而是一场定价博弈的信号弹。Anthropic 用 Claude Code 攻企业市场，Microsoft 用 Copilot 守，两者的单位经济谁能撑得住，答案会在未来一两年内明朗。

Huawei 宣称 2031 年前追上 TSMC 1.4nm 制程

华为宣布已找到"可行且低成本"的路径，将在 2031 年前造出对标 TSMC 下一代 1.4nm 制程（芯片生产工艺中晶体管之间的最小间距，越小算力越强）的产品。美国 2022 年起对华实施先进半导体出口管制，华为一度被困在 7nm。与此同时，中国已禁止本土企业采购 Nvidia 等美国芯片，内需倒逼自产的压力持续加码。

九年看起来很长，但半导体路线图从来不只是技术竞争，它同时是政治意志和资本规模的赛跑。这是制裁以来北京最大胆的公开反制声明。

MCP 协议 7 月 28 日重大升级：长任务、强认证、app 式界面

MCP（模型上下文协议，让 AI agent 访问外部工具和服务的通用接口标准）将于 7 月 28 日定版重大更新。新规格加入：内置对 app 式界面的支持、长时间运行任务的原生接口、更强的登录和权限验证规则、更清晰的工具定义格式，以及协议版本迭代的标准化流程。协议越成熟，开发者在其上的投入就越安全。

教宗 Leo XIV 发布 4.2 万字 AI 牧函：以"巴别塔"警告权力集中

教宗 Leo XIV 发布了一份宗座信函，篇幅达 4.2 万字（约三本书的体量），专题警告 AI 风险。核心论点：若以效率最大化为目标，AI 将把人类降格为系统中的零件；少数私人主体对 AI 技术的垄断，必须以某种方式加以对抗。他以《创世记》中"巴别塔"——人类因傲慢建塔、最终因语言混乱崩溃的故事——为比喻，警示人类正站在同样的岔路口。Anthropic 联合创始人 Chris Olah 受邀出席牧函发布仪式并在场发言。

教宗的 AI 立场历来是产业道德修正力量，但 4.2 万字的严肃体量说明这次不是走程序。

AI 方向观点

Aaron Levie（Box CEO）：AI 不消灭工作，它让市场无限涌现新需求

Levie 转发 Goldman Sachs CEO 的 AI 就业乐观论，加上自己的框架：历史从未出现"同样的工作量却更少工人"的局面，因为每当生产率提升，市场的胃口也同步扩张。律师如今给出的法律意见更全面，分析师的报告更精细，医生能做的检测更多——不是同样的工作变少了人，而是工作的边界被重新画大了。他指出悲观派的根本错误：把经济当作一个静态结构，假设需求的总量是固定的。

AI 就业辩论的核心分歧，不在技术，而在"需求是否有上限"这个经济学信仰问题。假设需求是固定的，AI 消灭工作；假设需求会膨胀，AI 创造工作。

Peter Yang（Roblox PM）：Codex 很强，但 design/frontend 任务 Claude 仍赢

Yang 实战对比两个工具：Codex 最令他印象深刻的能力是用内置的 browse 功能自己打开浏览器、测试代码输出——这是多数 AI 编码工具不具备的自验证循环。但在任何涉及视觉设计或 frontend 组件（面向用户的界面层代码）的任务上，Claude 仍然胜出。

这是早期来自实战 PM 的工具分层信号：Codex 接管逻辑层和测试循环，Claude 保留设计感知——下一个问题是 Anthropic 会不会给 Claude 也配上类似的浏览器自测能力。

Garry Tan（YC CEO）：用三个前沿模型互评 skill file 质量，迭代速度出乎意料

Garry Tan 给出一个具体的 eval（评估测试）技巧：让 agent 在完成任务后，调用三个不同的前沿模型，分别评审 skill file（存储 agent 工作流程与指令的配置文件，类似永久提示词）的输入与输出，给 1-10 分，并回答"为什么不是满分？如何改进？"。连续跑几轮后，skill file 的质量提升速度令他意外。加上单元测试，这套系统会持续变好且不退化。

LLM 当评委（LLM-as-judge）不是新思路，但 Garry Tan 把它包装成任何人 15 分钟内可以跑一遍的小实验。这是从"我不知道 prompt 好不好"到"模型会告诉我哪里不好"的范式切换。

产品与商业

纯银：概率漂移 — AI 的"错误"强调，意外成为产品突破口

运营同事用 AI 分析 4 万条公开用户评论，挖出的总结（版本 A）突出"仓位"这一概念（用户对投资组合中资金分配比例的关注），触动了纯银和拍档的灵感，确定了新的产品方向：围绕"仓位"来诠释长钱的投顾服务。随后纯银和拍档各自独立跑了一遍同样的语料，结论（版本 B、C）完全不同——仓位在两个版本里排名靠后，没有任何灵感触点。三人折腾了一两个小时，精疲力竭，以为是自己方法出了问题。

后来复盘的结论：版本 A 是特定组合（内置 skill 的 Codex）在"概率漂移"下随机强调了仓位这个本来并非头部反馈的概念，恰好击中了团队直觉。Claude Code 跑出的结论最专业、最扎实，但"没有任何启发"——因为专业的结果真实还原了客观分布，而触发灵感的版本 A 恰恰漂移出了客观分布。纯银的结论不是"AI 的随机性是坏事"，而是：AI 分析有时候的价值来自统计上的偶然，而非事实的忠实还原，这不靠技巧能稳定复现。

AI 分析工具里最难被量化的变量，是哪次漂移恰好对上了人的直觉——这是一次概率彩票，复盘起来像玄学，但产品就这样设计出来了。

小报童 · 纯银

Ben Tossell：SaaS 工具越长越胖，agent 时代的赢家是 API/CLI-first

Ben 的判断：SaaS 工具的商业模式要求持续增长，于是不断堆功能、改界面，很快成长到远超用户所需。用户最初为一个"切片"付费，但工具越来越大、价格越来越高，实际用到的功能越来越少。在 AI agent 时代，用户可以把不同模块自己拼合起来再接上 agent，SaaS 工具"一站式"溢价开始瓦解。

他认为，像 WorkOS（企业认证工具集）、Stripe（支付 API）这类 API/SDK-first——先做接口、可按模块拆解购买——的公司在这个时代天然占优。SaaS 的死亡不是因为 AI 替代了它，而是因为它把用户锁进了一个越来越大、越来越贵的捆绑包。

Peter Steinberger（OpenClaw 开发者）：写 skill 文件里别写论文

Steinberger 指出一个容易被忽视的问题：skill 文件（Claude Code 等 AI 工具里存储工作流指令的配置文件，每次对话都会被加载进上下文）的描述越详尽，每次对话消耗的 token 就越多，等于给自己增加了隐性成本和延迟。他的建议：写 skill 时让 agent 放弃完整语法，只保留关键词和简短说明。他甚至专门写了一个 skill 来扫描自己最浪费 token 的 skill 文件——用 AI 优化 AI 的工具。

写 skill 文件的极限不是功能完备，而是：去掉哪个词之后，它才开始失效。

Microsoft Webwright：给 agent 一个终端，让它自己开浏览器完成长链 web 任务

现状：大多数浏览器 agent 框架依赖持续的屏幕截图或 DOM 快照来感知页面，产生大量视觉噪声，且难以跨多个标签页并行操作。

解决方案：Webwright 给模型一个终端接口（命令行入口），让 agent 自行启动多个浏览器会话，按需截图而非全程录制。每个 web 任务的完成结果被封装成可重复运行的 Python 脚本，下次遇到同类任务可直接调用，避免"跑一次、失败重来"。

价值：在长链网页任务 benchmark（测试 AI 完成多步骤网页操作的标准评测集）上达到 SOTA（当前最优）。

未来方向：将可复用脚本库与 agent 规划能力结合，逐步形成"积累型" web 操作知识库。

TLDR

AI is doing something weird to Science：提问权仍属人类，但科研后三步正在被 AI 接管

现状：科学发现可分解为四个角色：提问者（决定研究什么）、提案者（设计实验方案）、验证者（执行实验）、策展者（判断哪些结果值得保留和传播）。

问题：AI 正在快速渗透后三个角色，但"哪个问题值得问"的判断尚未被自动化——这个缺口是暂时的还是根本性的，目前无定论。

价值：论文指出"科学加速"和"科学方向失控"可以同时成立：产出量爆炸，但问题选择权若缺席人类判断，科研方向可能被模型的训练分布所隐性塑造。

未来方向：谁控制提问权，谁就控制科学的议程——这将是 AI 与学术界的下一场博弈。
