GPT-5.5 正式发布，NVIDIA 同日将 Codex 铺开至 1 万名员工

OpenAI 正式推出 GPT-5.5，向 Plus、Pro、Business 和 Enterprise 用户开放。与前代 GPT-5.4 相比，5.5 在推理任务上用更少 token 完成更高难度的工作，延迟持平。Aaron Levie 报告 Box 在金融、医疗、公共部门等实际业务评测中，GPT-5.5 准确率较 5.4 提升了 10 个百分点。Sam Altman 同日分享 Codex 与 NVIDIA 联合部署的案例：NVIDIA 旗下工程、法务、市场、财务等部门共 1 万多名员工已接入由 GPT-5.5 驱动的 Codex，运行在 NVIDIA GB200 NVL72 架构上，相比上代硬件，每百万 token 成本降低 35 倍，每瓦吞吐量提升 50 倍。

Peter Yang 用 F-Zero（经典赛车游戏）作为模型测试场景，发现 GPT-5.5 + Codex 是迄今唯一能跑出可玩游戏的组合，且自动加入了多个 NPC 对手。Dan Shipper 则给出一个简洁的行为描述：大多数模型"做了很棒的计划，然后临阵退缩"，GPT-5.5 是目前最接近"直接就做"的模型。

DeepSeek V4 今日开源：1.6T MoE，1M 上下文，Apache 2.0

DeepSeek 在 GPT-5.5 发布同日推出 V4 系列：V4-Pro（1.6T 总参数，49B 激活参数）和 V4-Flash（284B 总参数，13B 激活参数），均支持 100 万 token 上下文，Apache 2.0 许可开源。关键架构创新是 Hybrid Attention（混合注意力机制），结合 CSA（压缩稀疏注意力）和 HCA（重度压缩注意力），使 1M context 场景下的单 token 推理计算量仅为 DeepSeek V3.2 的 27%，KV 缓存（键值对存储，推理时的中间记忆）用量降至 10%。

V4-Pro 在数学和编码 benchmark 上超过所有开源对手，在知识类任务上接近 Gemini 3.1-Pro，略逊于 GPT-5.4。Amjad Masad 指出：这恰好说明美国政客关于"中国蒸馏"的恐慌叙事站不住脚——中国科学家的实际贡献是架构创新，而非数据盗取，而且是完全开放共享的。

Claude Managed Agents 记忆功能公测上线，记忆体以文件形式存储

Anthropic 宣布 Claude Managed Agents（托管式 Agent 平台，4 月 8 日上线，提供沙箱执行、权限管理、端到端追踪等能力）的记忆功能正式进入公测。记忆层挂载到文件系统（即像读写文件一样存取记忆），Claude 可复用 bash 和代码执行能力来管理记忆；记忆以文件形式保存，开发者可通过 API 导出和控制 Agent 保留的内容，也可在多个 Agent 之间共享记忆。这是同类服务里少有的"记忆归开发者所有"设计。

AI 方向观点

Aaron Levie（Box CEO）：AI 让工作变多，不是变少

Levie 在 X 上分享了一个反直觉观察：AI 没有减少工作量，反而让他做了更多以前做不完的事。原因是：AI 大幅降低了"启动一件事"的门槛，让很多原本因为人工成本太高而永远排在待办清单底部的任务，突然变得值得去做。一旦开始，后续的完整执行仍需要人，于是产生更多工作。

他还指出一个更有趣的经济逻辑：当 Agent 让某类任务足够便宜，它甚至会让你意识到这件事值得长期雇人专门来做，但在此之前你永远不会尝试。工作总量不是固定的，大多数公司有无限多可以做但一直没做的事，AI 只是把"能不能做"的阈值降低了。

AI 时代的生产力方程不是"人减少"，而是"待办清单变无限长"。

X @levie

Amjad Masad（Replit CEO）：中美 AI 叙事的扭曲

Masad 直接点名：美国政客和游说机构正在用"中国蒸馏"（distillation，即从美国模型提炼能力）这个词恐吓公众，但现实是，今天 DeepSeek V4 做的架构创新——Hybrid Attention——与训练数据来源毫无关系，纯粹是底层算法突破，并且是开放给全世界的，包括小型美国实验室。

他的隐含论点是：地缘政治恐慌叙事把注意力引向了错误的竞争维度。开放共享的架构创新无法被"保护"，也无需被保护，因为它让所有人都受益。真正的竞争优势在别处。

把"开源 AI"包装成"国家安全威胁"，是混淆视听而非清醒的战略判断。

AI 进展

DeepSeek V4 技术报告：Hybrid Attention 让 1M 上下文 token 成本降至 10%

现状：长上下文推理是当前大模型的主要瓶颈，KV cache（键值对缓存，存储推理中间状态的内存结构）随着上下文长度线性增长，内存占用极高。

问题：现有注意力机制在 1M token 场景下推理成本高到不实用，限制了 Agent 在长会话和复杂文档场景中的应用。

解决方案：DeepSeek V4 引入 Hybrid Attention，组合 CSA（压缩稀疏注意力，对远距离 token 大幅压缩）和 HCA（重度压缩注意力，极端降低 KV 用量），在 1M context 下单 token 推理 FLOPs 降至 V3.2 的 27%，KV cache 降至 10%。

价值：V4-Pro（49B 激活参数，1.6T 总参数）在编码和数学 benchmark 超越所有开源对手，在知识类任务上直追 Gemini 3.1-Pro，且以 Apache 2.0 协议完全开源。

未来方向：1M 上下文的高效化为 Agent 长期记忆和大型代码库分析开辟了实际可行的路径，后续看小型量化版本的社区部署速度。

Agentic Reasoning for LLMs：Agent 推理能力综述（arXiv 2601.12538）

现状：LLM 已从单次问答演进为多步骤 Agent，推理能力是 Agent 行为的核心驱动力。

问题：Agent 推理散布在规划、工具调用、记忆、多 Agent 协调等不同模块，缺乏统一的分析框架。

解决方案：这篇综述系统梳理了推理如何整合进 Agent 的各个子系统，包括 MCTS（蒙特卡洛树搜索，一种多步规划算法）、工具调用、长期记忆、反馈驱动的自适应，以及多 Agent 协调机制。

价值：为研究者和工程师提供了统一的 Agent 推理地图，有助于诊断系统中的薄弱环节。

未来方向：作者认为 Agent 推理与 RL（强化学习）的结合是下一个主战场，特别是带有可验证奖励的推理训练（RLVR）。

arXiv 2601.12538 · HuggingFace Papers

Predicting LLM Output Length：ICLR 2026，低成本预测输出 token 数

现状：推理服务（inference serving，将模型部署为 API 供实时调用的系统）的延迟和吞吐量高度依赖能否预先知道每个请求的输出长度，以便合理分配批次和显存。

问题：现有方法要么需要单独的预测模型（额外开销），要么只能在推理开始后动态估算。

解决方案：论文提出 EGTP（Efficient Generation Token Predictor），在不引入额外模型的前提下，以可忽略不计的延迟和内存代价预测输出长度，并在 GSM8K（数学推理基准）等任务上验证有效性。

价值：推理服务优化的低成本方案，对构建实时 Agent 流水线的工程团队有直接参考价值。

未来方向：结合动态批处理调度，在高并发 Agent 场景中进一步压缩端到端延迟。

arXiv 2602.11812 · ICLR 2026

LLM Agent 推理开销过高问题：高 token 消耗、执行不稳定、组件不可复用（arXiv 2604.19756）

现状：LLM Agent 在实际部署中面临三大系统性障碍。

问题：高推理开销（每次任务消耗大量 token）、不稳定执行（相同输入产出差异大）、组件不可复用（子任务结果难以在后续调用中直接利用）。

解决方案：论文提出结构化的 Agent 架构改进方案，将高频子任务模块化，减少重复推理；引入执行稳定性约束，提高跨调用一致性。

价值：直接针对工程落地中最常见的三个痛点，有助于降低 Agent 产品的运营成本并提升用户体验。

未来方向：与 Agent 框架（如 LangGraph、Claude Managed Agents）的深度集成，将模块化复用变为默认行为。

arXiv 2604.19756

NS-Mem：神经符号长期记忆，提升多模态 Agent 跨会话推理（arXiv 2603.15280）

现状：多模态 Agent（同时处理图像、文本等多种输入的 AI 系统）的长期记忆主要依赖纯神经表示（向量），难以支持精确的逻辑推理。

问题：向量记忆在模糊语义检索上表现好，但在需要精确规则或约束推理的任务（如"上次用户说了什么条件"）上可靠性不足。

解决方案：NS-Mem（Neuro-Symbolic Memory，神经符号记忆）将神经存储与显式符号结构（规则、约束、关系图）结合，跨会话保留结构化知识，既保留语义灵活性，也支持逻辑精确性。

价值：在需要长期追踪用户偏好、任务状态或复杂约束的 Agent（如个人助理、科研助手）中，有望显著提升可靠性。

未来方向：与文件系统式记忆（如 Claude Managed Agents 的实现方式）结合，探索符号结构在实际 Agent 产品中的落地路径。

arXiv 2603.15280
