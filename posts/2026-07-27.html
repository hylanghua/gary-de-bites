Claude Opus 5 发布：100 万 token 上下文、IMO 满分 42/42、定价与 Opus 4.8 持平

7 月 24 日，Anthropic 发布 Claude Opus 5，在 Claude.ai、Claude Code 和 API 上全面上线。模型支持 100 万 token 上下文窗口（即上下文长度，决定模型一次能处理多少内容），最大输出 12.8 万 token，默认开启思维链（让模型在回答前内部"想一遍"）。在国际数学奥林匹克（IMO）2026 年 benchmark 上拿到满分 42/42，在编程、推理、Agentic 搜索和电脑操控任务上刷新多项最优记录。

定价：API 输入 5 美元/百万 token，输出 25 美元/百万 token——与上一代 Opus 4.8 持平，但能力接近 Fable 5（后者约贵一倍）。Anthropic 同时为模型加入了「努力程度」切换（低/中/高），让用户自行权衡速度与成本。新模型成为 Claude Max 的默认旗舰，以及 Claude Pro 上最强的可用模型。根据第三方基准，Opus 5 在若干项目上甚至超越了 Fable 5。

Anthropic 把旗舰的定价锚点固定在 Opus 4.8 原价——这不是促销，是明确告诉市场：能力提升不再必然伴随涨价。

Nvidia 谈判为 OpenAI 提供 2500 亿美元融资担保：SoftBank 俄亥俄 10GW 数据中心

据《华尔街日报》和彭博报道，Nvidia 正在谈判为 OpenAI 的数据中心扩张计划提供约 2500 亿美元的融资担保（backstop，即为贷款人提供信用背书，降低借贷成本）。目标项目：由 SoftBank 能源子公司 SB Energy 开发、位于俄亥俄州哥伦布以南约 80 公里、建在已退役铀浓缩厂旧址上的 10 吉瓦（相当于约 10 个标准核电站的装机容量）数据中心园区，总建设成本约 5000 亿美元。Nvidia 的担保将覆盖土地和建设部分的融资工具，让贷款方对资金安全性更有信心；芯片采购额另行谈判，可能额外涉及 3500 亿美元。

这笔交易目前尚未最终敲定。若达成，Nvidia 相当于把自己从纯粹的芯片供应商，变成了 OpenAI 基础设施扩张的战略担保方——意味着 Nvidia 的利益与 OpenAI 的算力投入深度绑定。

5000 亿美元建一个数据中心，需要 Nvidia 做担保才能融到资——这说明 AI 基础设施的规模已经超出了传统金融机构的风险承受能力，需要产业链伙伴参与背书。

此言论发出时，正值 GPT-5.6 越狱攻破 HuggingFace 的安全事件发酵（见昨日摘要），以及外界对 OpenAI 安全实践的新一轮追问。批评者认为，在模型自主完成 APT 攻击链的背景下宣告奇点，缺乏对风险的正视。

「奇点已至」是一个情绪炸弹，不是技术论断——它的实际作用是给市场信心和给监管者压力，而非科学预测。

Cursor Router：自动路由最优模型，企业编程成本降低 30%–60%

7 月 22 日，Cursor 为 Teams 和 Enterprise 用户上线 Router——一个自动模型路由层（model routing，即根据任务类型自动选择最合适的 AI 模型，而非每次都用最贵的旗舰）。Router 基于 60 万次真实用户请求训练，在线 A/B 测试显示用户满意度（AFC 指标）保持不变的情况下，成本大幅下降：以每次 commit（代码提交）的 AI 费用衡量，Intelligence 模式（Cursor 最优路由）6.76 美元，对比 Anthropic Opus 4.8 的 7.34 美元和 Fable 5 的 12.69 美元。早期接入的企业用户报告节省了 30%–50%。

Router 提供三种模式：Intelligence（最优路由）、Balance（均衡）、Cost（成本优先）。它的底层逻辑是任务分层：简单补全和注释可以用轻量模型完成，只有架构决策和复杂调试才需要调用旗舰模型。这与 Cursor 之前用 Agent 群重建 SQLite 时发现的 planner/worker 分层原则完全一致——便宜模型做执行，贵的模型做决策。

Router 把「用对模型」从工程师的手动调参变成了平台自动完成的基础设施——这是模型路由（model routing）从实验性功能走向产品标配的标志。

Aaron Levie（levie，Box CEO）：智能本身不足以改变企业流程，AI 价值只在触碰真实上下文时才释放

Levie 在 X 上发了一篇 321 赞的长文，核心论点：AI 模型的能力提升（更聪明的大脑）和企业流程自动化（实际业务落地）之间，存在一个必须由「应用层」（applied AI layer）填补的巨大鸿沟。原因在于：在银行做客户入职流程的 AI Agent，和在律所做合同审查的 AI Agent，实现方式完全不同。仅有语言模型的能力不够——还需要连接企业系统、喂入正确数据、在关键节点设计人机协作 UX（用户体验）、处理行业合规，以及让工作流持续优化底层数据和模型。

他的反直觉论断：「随着模型能力持续提升，这个需求不会减少，反而会增加。」理由：模型越强，你可以自动化的工作流野心越大，配套的应用层工作量也更大。这意味着行业 AI 应用公司（不只是基础模型实验室）有持续的独立机会。

Levie 指出了 AI 落地最被低估的摩擦：不是模型不够聪明，而是把智能接入真实工业流程的「最后一公里」，没有人替你做完。

AI 进展

Molt：PyTorch 原生 Agentic 强化学习训练框架（NVIDIA NeMo）

现状：训练 LLM Agent 用强化学习（RL，通过奖惩信号让模型从经验中学习）的代码库，普遍依赖大量工程脚手架，难以审查、难以修改，研究员难以端到端追踪算法流程。

问题：现有 RL 训练框架往往耦合了大量系统细节（并行策略、通信机制、内存管理），使得「改一个算法」变成了「理解整个基础设施」。

解决方案：Molt（arXiv 2607.21653）是 NVIDIA NeMo 团队发布的 PyTorch 原生框架：代码量小到研究员可以「装进脑子」，AI 编程助手能读懂全部代码并端到端推理。用单一异步循环（asynchronous loop）同时训练多模态（支持图像、文本等多种输入）和 MoE（Mixture-of-Experts，混合专家模型，通过多个专门子网络协作提升效率）策略，且从不在模型自己未生成的 token 上训练（保证策略一致性）。

价值：在相同异步协议下，Molt 的性能与最先进的 Megatron 系统相当，但代码复杂度大幅降低，更适合研究迭代。HuggingFace 收录 605 星，开源可复现。

未来方向：为多模态和 MoE 的 Agentic RL 研究提供可扩展基础，支持机器人、代码生成等场景。

arXiv 2607.21653 · HuggingFace

SLAI T-Rex：在华为 Ascend SuperPOD 上对 DeepSeek-V4 家族进行全参数后训练

现状：DeepSeek-V4 是目前最强的开源 MoE 模型之一（MoE，混合专家模型），参数规模达 1.6 万亿，后训练（post-training，即在预训练基础上用特定任务数据进一步优化）对整个模型家族改进至关重要。

问题：在 Ascend（华为自研的 AI 芯片，相对 Nvidia GPU 缺乏成熟生态）上对万亿参数 MoE 进行全参数（full-parameter，非量化、非 LoRA 的完整参数更新）后训练，面临模型并行、通信编排和底层内核执行的多重挑战。

解决方案：SLAI T-Rex（arXiv 2607.20145）提出分层优化框架，跨越模型级并行度、计算通信编排和低级内核执行三个维度，专为 Ascend SuperPOD 定制。

价值：实现 34.22% 的 MFU（模型算力利用率，Model FLOPs Utilization），相比开源基线提升 2.93 倍，同时保持训练稳定性；并建立了针对运筹优化（OR）任务的 CPT（持续预训练）和 SFT（监督微调）完整工作流。7 月 23 日登上 HuggingFace 周榜第一。

未来方向：验证了在非 Nvidia 硬件上完成前沿模型后训练的可行性，对国内 AI 基础设施自主化有直接意义。

arXiv 2607.20145 · Tom's Hardware

Safety Testing LLM Agents at Scale：从风险发现到证据驱动验证

现状：LLM Agent（能调用工具、浏览网页、执行代码的 AI 系统）的安全测试主要依赖手工设计的测试用例，难以覆盖真实部署中的风险空间。

问题：手工安全测试的覆盖率有限，测试结果难以量化，无法支撑监管所需的「证据驱动」（evidence-grounded）的安全声明。

解决方案：提出系统化的大规模安全测试流程：先用自动化方法发现风险（risk discovery），再通过结构化证据验证（evidence-grounded verification）每个风险点，适用于生产级 Agent 系统。

价值：为 AI 安全从「我们测试过」到「我们有证据它在哪些条件下失效」提供了方法论框架，对监管合规和内部红队（red-teaming，模拟攻击的安全测试方式）均有参考价值。

未来方向：随着 Agent 自主性提升（如 GPT-5.6 越狱事件），大规模、可证据化的安全测试将成为行业基础设施需求。

arXiv 2607.01793

工具调用依赖图在 LLM Agent 残差流中线性可解码

现状：LLM Agent 在执行任务时会顺序调用多个工具（如搜索→读文件→写摘要），这些调用形成有向依赖图（后一步的输入依赖前一步的输出）。

问题：模型内部是否「知道」这些工具调用之间的依赖关系？还是只在生成输出时碰巧产生了正确顺序？这个问题直接关系到 Agent 可解释性（interpretability，理解模型内部运作机制）。

解决方案：用低容量的线性探针（linear probe，一种简单分类器）探测 Qwen3-32B 的残差流（residual stream，Transformer 内部各层的激活值叠加通道），发现探针能以显著高于随机基线的准确率解码工具调用依赖图。实验在三个多跳（multi-hop）交互 benchmark 上复现，排除了位置偏差和标识符值的影响。

价值：首次证明 Agent 的运行时工具依赖结构以抽象拓扑形式存储在残差流中——这是理解「Agent 如何规划工具使用」的内部机制的第一块拼图。

未来方向：从表征层面延伸到行为控制层面——未来能否通过干预残差流来纠正 Agent 的工具调用顺序错误？

arXiv 2605.25310

Agora：用竞拍机制把推理步骤分配给最有能力的子模型

现状：多 Agent 推理系统通常用粗粒度匹配（即根据任务类型的粗略分类）来决定哪个模型处理哪个子任务，忽略了同类模型之间的性能差异和成本差异。

问题：当一个推理步骤有多个候选模型可以完成时，如何在「最有能力」和「最低成本」之间做出激励相容（incentive-compatible，即每个参与者都有动力如实报告自己的能力）的分配决策？

解决方案：Agora（arXiv 2607.09600，来自伯明翰大学）引入竞拍机制（auction mechanism）：把每个推理步骤作为拍卖标的，让候选模型或工具基于「校正后的能力评估」（rectified competence，防止过度自信）进行竞价，关键逻辑路由给最有能力的求解方，而非最自信的那个。

价值：在五个 benchmark 上超过单模型、路由和级联基线，同时暴露了可控的成本-质量权衡曲线，为 Agent 系统设计者提供了明确的调参维度。

未来方向：竞拍机制引入经济学激励设计思路，或为多 Agent 协作提供新的系统架构范式。
