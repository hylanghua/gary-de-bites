Swyx（Latent Space）+ METR：FrontierCode 发布——超过半数 SWE-bench 高分代码在真实仓库根本不可合并

Cognition 发布了 FrontierCode 基准，这是 swyx 主导的「反 Slop 之战」（War on Slop，Slop 指 AI 生成的表面上能跑但质量低劣的代码）的最新成果。FrontierCode 共 150 道题目，最难 50 道为 Diamond 级，每道题由顶级开源维护者花费 40 小时以上手工出题，涵盖 3000+ 评测维度，专门考察代码可维护性和真实可合并性，而非只看「通过测试」。

结果触目惊心：在 Diamond 级，当前最强的 Claude Opus 4.8 得分仅 13.4%，GPT-5.5 得分 6.3%，Gemini 3.1 Pro 4.7%。与此同时，安全评测机构 METR 独立发布研究证实：超过半数通过 SWE-bench（软件工程基准，当前最广泛使用的代码 Agent 评测集）的 PR（pull request，待合并代码）实际上无法被真实代码库接受——不是 AI 写错了，是评测本身坏了。

这个发现改变了我们看「XX 模型 SWE-bench 得分 80%」的方式：高分不等于可用代码。FrontierCode 的意义在于把评测的门槛从「能运行」提升到「人类工程师愿意合并」，而这两者之间的距离，比大多数人想象的大得多。SWE-bench 高分是营销素材，FrontierCode 高分才是工程护城河。

Ben's Bites：Agent loop 设计的 PM 级拆解——plan.md + 完成验证 + skill 串联，才是真正可运行的自主系统

Ben's Bites 对最近 X 上沸腾的「loop 设计」讨论做了一次 PM 向的拆解。Agent 本身是 loop（给任务、获取上下文、用工具、给出输出、循环），但「设计 loop」说的是把这个循环嵌进更大的自主系统：先设计一个大任务（比如 plan.md 里列出要实现的所有功能），再为每个任务定义「完成标准」（报告是否包含所有要点、测试是否全部通过、UI 功能是否正确运行），最后让 Agent 自己回到 plan.md 拿下一个任务。

进一步的结构化方法是技能（skill）串联：先跑规划 skill，再跑 PRD 拆分 skill，然后是每个功能的研究 skill、构建 skill、评审 skill、测试 skill。本质是在给 Agent 写「自转的文字说明书」，并确保它能访问所需的全部工具。今天的 loop 讨论还未成熟——token 成本和质量监控仍需要人介入——但方向是对的。不是「我怎么提示 Agent 更好」，而是「我怎么设计一个让 Agent 自己提示自己的系统」。

Boris Cherny（Claude Code 创作者，Anthropic）：GA 一周年——从「两种 Slack 反应」到手机上做大部分开发

Boris Cherny 发布了 Claude Code 正式上线一周年的回顾。他提到最初内部演示时 Slack 上只有两种反应——言下之意反响并不轰动。一年后他和 Catherine Wu 坐下来谈「什么变了」：他现在用 auto mode（自动权限模式，让 Claude 无需反复请求批准即可自主执行操作）而不是 plan mode；routines（定时任务）会在他看到 bug 之前就把它修掉；他已经把大部分编程工作转移到手机上完成。

这条轨迹有一个清晰的逻辑：最开始的阻力来自对 AI 自主权的不信任，所以用 plan mode（每步审批）；随着信任建立，切换到 auto mode；当 auto mode 稳定后，验证不再需要人盯着，于是任务可以在背景运行，设备限制也随之消失。从「两种 Slack 反应」到「手机编程」，是工具成熟度的真实反映，不是营销故事。Claude Code 从内部无人在意到主导开发工作流的一年，是 AI 工具通往信任的必要路径——先让人不得不用，再让人不愿意离开。

Zara Zhang（Builder）：「下一个世界的文档格式可能是 Markdown、HTML、SVG」

Zara Zhang 发了一条推断性的观察：AI 原生工作流催生的输出格式正在发生迁移。Word 和 PowerPoint 是为「打开软件、在界面里编辑」设计的，而 Markdown、HTML、SVG 是可以被 AI 直接生成、修改、渲染的格式——它们天然可与 Agent 交互，不需要中间层。Zara 本人已经把她的幻灯片全部迁移到 HTML（Frontend Slides 项目）。

这个观察切中了一个更大的结构性变化：当 AI 成为主要内容生产者，文档格式就不能只对人类友好，还要对机器友好。Markdown 可以被 diff，HTML 可以被解析，SVG 可以被参数化修改。这三者已经是网络基础设施，只是还没被大多数知识工作者当作「文档格式」接受。当 AI 成为主要内容生产者，文档格式的胜负条件从「人类读起来好不好」变成了「模型改起来方便不方便」。

小报童·修饼：VERVE-102 基因编辑药物——一次注射，LDL 胆固醇永久下降 62%，18 个月效果稳定不反弹

《新英格兰医学杂志》刚发表了一项里程碑研究：VERVE-102 在 35 名高风险高胆固醇患者的 Ib 期临床试验中，最高剂量组低密度脂蛋白胆固醇（LDL-C，坏胆固醇）平均下降 62%，PCSK9 蛋白水平平均下降 88%，部分患者 18 个月随访效果依然稳定。这些患者此前已长期服用大剂量他汀类药物，血脂仍不达标——一次注射就做到了药物多年做不到的事。

VERVE-102 的底层逻辑直接：人体内的 PCSK9 基因会生成一种蛋白，持续「拆除」肝脏细胞表面负责清除坏胆固醇的 LDL 受体。VERVE-102 使用腺嘌呤碱基编辑器（ABE，一种不剪断 DNA 而是精准修改单个碱基的新型基因编辑技术，比传统 CRISPR 更精准），永久让 PCSK9 基因失活，肝脏从此可以保留受体、持续清除坏胆固醇。修饼的描述是：「这种药不是每天帮你降血脂，而是直接修改导致高血脂的底层代码。」

安全性上，所有受试者顺利完成治疗，少数出现一过性肝功能指标升高，总体无严重毒性。目前仍是 Ib 期，35 人样本，观察时间还不够长，距离「一针终身降脂」还有大量待解问题——脱靶效应、几十年后的长期肝脏影响。但这是人类首次在心血管疾病领域成功进行人体内碱基编辑，标志着治疗范式从「终身服药」迈向「一次干预、长期受益」的真实起点。基因编辑正在把「终身管理的慢性病」变成「一次修好、不必再管」的工程问题——这是继 GLP-1 之后，人类与生物学关系的下一次结构性转变。

AI 进展

Memanto：13 类语义记忆层，Agent 长时记忆 SOTA，LongMemEval 89.8%，单次检索零摄取成本

现状：长时运行的 Agent 面临记忆管理困境——传统方案要么用向量数据库（Vector DB，把记忆转成数字向量检索，但语义精度受限），要么用混合语义图（Hybrid Semantic Graph，精度更高但架构复杂、计算开销大），两者都难以在真实生产部署中稳定运行。

问题：现有记忆系统的摄取成本（ingestion cost，在使用记忆之前必须花费的索引和结构化工作）高、检索需要多次查询，且无法有效处理信息随时间变化导致的版本冲突。

解决方案：Memanto 提出了一个带 13 个预定义类别的类型化语义记忆模式（Typed Semantic Memory Schema），加上基于信息论的搜索引擎，以及自动冲突解决和时间版本管理机制，整个系统只需一次检索查询，无需摄取步骤，运营复杂度远低于混合图方案。

价值：在 LongMemEval 和 LoCoMo 两个长时记忆标准评测集上分别达到 89.8% 和 87.1%，超过所有现有混合图和向量方案，同时大幅降低了高质量长时记忆的落地门槛。

未来方向：类型化记忆层有望成为企业级持久 Agent 的标准基础设施，取代目前松散的向量数据库接入方案。

TerminalWorld：从 8 万真实终端录像逆向工程 1,530 个验证任务，当前前沿模型最高通过率 62.5%

现状：软件工程 Agent 在 SWE-bench 类代码任务上已有较高性能，但真实的开发终端工作流（包括 git 操作、调试工具、数据库命令等 18 类场景）缺乏可靠的评测基准，导致实验室评分和生产部署表现严重脱节。

问题：人工构造终端任务耗时极长，且难以复现真实用户的复杂操作序列；现有 Agent 评测集大多基于玩具环境，不反映真实开发者的工作负载。

解决方案：TerminalWorld 是一个可扩展的数据引擎，处理 80,870 条「在野」（in-the-wild，真实用户产生的自然录像，非刻意构造）终端录像，逆向工程出 1,530 个带自动验证的任务，覆盖 18 个真实终端使用类别。

价值：系统性评测了 8 个前沿模型和 6 个 Agent 框架，所有系统表现均不理想，最高通过率仅 62.5%，清晰展示了当前 Agent 在真实终端工作流上的能力缺口。

未来方向：从录像中自动挖掘评测数据的范式可以推广到其他工具型 Agent 场景（IDE 操作、浏览器自动化等），持续为 Agent 能力成长提供真实锚点。

arXiv 2605.22535 · HuggingFace

KVServe：服务感知 KV 缓存压缩，解决分解式 LLM 服务中 KV 传输成为端到端瓶颈的问题

现状：分解式 LLM 服务（Disaggregated LLM Serving，把预填充和解码分拆到不同硬件节点的新兴架构，可提升可扩展性和成本效率）让 KV 缓存（Key-Value Cache，模型推理时缓存的中间状态，避免重复计算）成为需要显式跨网络传输的数据，在高负载下很快成为带宽瓶颈。

问题：现有 KV 压缩方案通常是静态配置，而真实生产服务的工作负载组合、网络带宽和服务质量（SLO，service-level objective，延迟和质量要求）随时间持续变化，静态方案无法自适应调整，要么浪费带宽，要么损害质量。

解决方案：KVServe 是首个服务感知（service-aware）的自适应 KV 缓存压缩框架，实时感知当前服务上下文（工作负载构成、可用带宽、SLO/质量预算），动态调整压缩策略，被 SIGCOMM 2026 收录。

价值：在维持服务质量目标的前提下，显著降低分解式部署中的 KV 传输开销，为下一代大规模 LLM 部署基础设施提供关键优化层。

未来方向：随着大模型推理从单机部署走向分布式分解架构，服务感知的自适应压缩将成为生产级 LLM 服务栈的标准组件。

arXiv 2605.13734 · HuggingFace

Audio-Interaction：统一在线/离线音频模型，SoundFlow 框架实现实时音频指令跟随与离线任务共存

现状：音频 AI 领域存在两条分立的技术路线：离线模型（ASR 语音识别、机器翻译、音频问答等批量任务，准确但无法实时响应）和在线流式模型（实时语音聊天，低延迟但功能受限），两者各行其道，缺乏统一框架。

问题：用户实际交互场景往往混合离线和在线需求——先实时聊天，再要求完整转录；或者一边听音频流一边要求做分析。当前单一路线的模型无法同时满足，需要切换到不同系统，体验断裂。

解决方案：Audio-Interaction 提出 SoundFlow 框架，端到端实现感知-决策-响应（perceive-decide-respond）循环：流式原生数据构造、理解感知协同训练和异步低延迟推理三位一体，单一模型同时支持离线任务（ASR、语音到文本翻译、音频问答）和在线任务（实时语音聊天，实时音频指令跟随）。

价值：消除了离线和在线音频 AI 之间的架构隔阂，为语音 Agent 提供了一个能持续「耳听八方」、按需实时响应的统一基础模型。

未来方向：统一流式架构可向视频+音频多模态方向延伸，为具身 Agent 提供持续环境感知能力。

LongCat-Video：13.6B 参数 DiT 模型，720p 30fps 分钟级长视频生成，三类任务共用统一架构

现状：视频生成模型在短片质量上已经成熟，但生成分钟级以上的高质量长视频时，主流模型面临时间一致性下降、生成质量随时长衰减的问题。

问题：长视频生成需要同时处理时间轴上的语义连贯性和空间轴上的视觉质量，传统单阶段生成方法在两者之间难以兼顾，高分辨率下的注意力计算开销也随序列长度急剧上升。

解决方案：LongCat-Video 是基于 Diffusion Transformer（DiT，扩散变换器，当前视频生成主流框架）的 13.6B 参数模型，采用从粗到细的时空分层生成策略（coarse-to-fine），在时间轴和空间轴上分阶段细化，配合 Block Sparse Attention（块稀疏注意力，仅计算局部关键区域，高分辨率下效率大幅提升）降低高分辨率推理开销。支持文生视频、图生视频、视频续写三类任务，使用同一模型，并通过多奖励 RLHF 对齐进一步提升质量。

价值：开源权重和代码，720p 分辨率 30fps 长视频可在分钟级完成，性能与闭源前沿模型持平，为长视频生成研究和工业部署提供可用基线。

未来方向：视频作为世界模型（World Model，对现实环境的内部模拟）的关键训练信号，长视频生成能力的提升将直接加速具身智能研究进程。
