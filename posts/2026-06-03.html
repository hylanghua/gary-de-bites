AI 方向观点

swyx（Latent Space 主编）：MAI-Thinking-1 的 109 页技术报告是一份行业教材——它让「认真建模型」有了参照系

本期 AINews 的核心判断不是「Microsoft 发布了新模型」，而是「Microsoft 公布了它是怎么建这个模型的」。这份技术报告的稀缺性在于：从头预训练（非蒸馏）、零合成数据、零第三方模型数据混入，同时披露了训练架构、数据方法论和对齐策略的关键细节——研究者们称其为「对这个量级模型来说透明度最高的报告之一」，可以「当当前 LLM 训练的更新版教科书」来读。

MAI 团队的核心方法论是「Hill-Climbing Machine」（爬坡机器，指一套让模型开发的每个环节都可持续迭代优化的联合设计流程）：模型能力的提升不依赖单点突破，而依赖整个训练-评估-对齐流水线的协同爬坡。这种思路与过去几年靠蒸馏和合成数据快速追赶的路线形成明显对比。Microsoft-Inflection 合并仅两年，MAI 从零到能与 Sonnet 4.6 正面比拼，验证了「从头建」的路线不是慢，而是慢开始、稳增速。MAI-Thinking-1 的意义不只是一个新的推理模型，而是一份关于「如何严肃地构建前沿模型」的公开路线图。

Guillermo Rauch（Vercel CEO）：YES-CODE——代码已经廉价且充沛，真正稀缺的是把语言变成世界 API 的能力

Rauch 用「YES-CODE」这个词来对抗过去两年「No-code 就是未来」的叙事：代码不是障碍，代码现在便宜、容易、充沛，谁手里有代码能力、谁就有杠杆。问题不是「要不要代码」，而是「哪种代码生产力算高」。

配合另一条推文「Language is the new API to the world」，他的逻辑是：以前写代码是把意图翻译成机器语言，现在语言本身就是接口，你用自然语言描述意图，模型和 Agent 负责翻译成系统调用——代码作为中间层正在薄化，但不是消失，而是被推到更深的执行层。Rauch 的判断是：写代码的人不会失业，但能让「语言直接驱动世界」的那套能力才是下一个护城河。

Thibault Sottiaux（OpenAI Codex 团队）：ChatGPT 的同义词将从「AI」变成「agents」——10 亿 MAU 是平台卡位完成的信号

Sottiaux 的观察简洁：今天提到「AI」，大多数人脑子里浮现的是「ChatGPT」；接下来，提到「agents」（AI 自主代理，能接收任务、自主规划并执行多步操作的程序），大多数人脑子里浮现的还会是「ChatGPT」。ChatGPT 在 10 亿月活的尺度上，正在成为「AI 行为本身」的代名词，而不只是一个聊天产品的名字。

这个判断的背景是：AI Valley 今日报道 ChatGPT 月活达到 10 亿，是有史以来最快达到该里程碑的 App（比 TikTok 和 Instagram 快得多）。当一个产品在这个量级上被「无差别联想」，它的品类定义权就不在竞争对手手里了。OpenAI 用 10 亿用户锁定了「agent 这个词」的使用权，其他玩家在品类认知上要绕过一座山。

产品与商业

Amjad Masad（Replit CEO）+ Microsoft：Rayfin 上线——AI agent 一行命令把 app 后端部署到 Fabric，治理和合规随企业 tenant 自动继承

Microsoft Build 的另一条主线是 Rayfin：一个开源 SDK + CLI，让开发者（或 AI Agent）用代码或自然语言描述想要的 app 后端（数据库、身份验证、存储和访问策略），然后一条命令部署到 Microsoft Fabric（微软的企业数据和分析平台）。部署后自动继承 Entra 身份验证和 Purview 合规管控——用企业自己 tenant 里的规则运行，不需要额外配置治理。

Replit 是 Rayfin 生态的核心搭档：在 Replit Agent 里描述产品，生成代码，Rayfin 打包后端，一键上 Fabric——整条链路不离开对话界面。这是「vibe coding 进企业」的最清晰路径之一：创意草稿速度保留，合规和安全要求也不放弃。Masad 的那条推文——「Your whole business laid out on a canvas」——描述的就是这条链路打通后的体验。Rayfin 是第一个让 AI 生成的代码在企业级治理框架里自动合法运行的产品，它填平了「demo 好看、生产跑不了」的那道沟。

Peter Yang（产品人）：SaaS 越来越难卖了，因为 AI 技能灵活解决问题——builder 没有真实用户就发布产品，这个病正在扩散

Yang 今天发了两条互相印证的观察。第一：SaaS 订阅逻辑在松动——以前买一个垂直工具是因为它解决了特定问题，现在 AI 技能可以跨场景灵活解决问题，用户没有理由为每个场景单独付座位费；软件的边界在溶解，工具的护城河在变浅。第二：越来越多 builder（独立开发者或早期创业团队）在没有任何真实用户的情况下就发布产品，热衷于用 AI 快速生产功能，却没有去找到能感受到真实痛点的用户对话。

这两条放在一起是一个完整的警告：AI 降低了生产门槛，但没有降低「判断什么值得生产」的难度。供给侧的爆发不能自动创造需求侧的匹配。Yang 的观点是纯银的中文版英文回响：软件供给泛滥，但找不到真正用户的产品不管有多完善都是无效供给。

Aaron Levie（Box CEO）：token 预算越来越大，模型路由将变成企业 AI 基础设施的必选项

Levie 的判断直接：随着企业给 AI Agent 分配的 token 预算（单次任务允许消耗的 token 上限，决定了任务的复杂度和成本）越来越大，用一个模型包打所有任务越来越不划算。不同任务需要不同的速度、成本、推理深度和专业领域优势，路由（model routing，根据任务特征自动为每个子任务选择最合适的模型）将从「高级玩法」变成企业 AI 堆栈的标配选项。

这与 AI Valley 报道的 Factory Router（「为每个任务自动选最优 AI 模型」）同日出现，印证了这个方向在产品层的落地。「没有最好的模型，只有最合适这个任务的模型」——这句话将在 2026 年下半年被更多企业的 IT 采购流程接受为基本预设。

AI 进展

HarnessForge：联合进化 Agent harness 和策略——调度框架与大脑同步迭代，而不是只训练模型

现状：LLM Agent 系统由两部分组成：policy（策略，即模型本身的行动决策能力）和 harness（调度框架，即控制任务流、工具调用、上下文管理的外层脚手架）。现有研究几乎只优化 policy，harness 被当作固定基础设施。

问题：固定 harness 成为瓶颈：策略进化了，但外层调度框架跟不上，系统性能受限于两者之间的不匹配。

解决方案：HarnessForge 把 agent 系统形式化为 harness-policy 对（pair），通过闭环交互同步进化两者——harness 根据 policy 的行为调整任务流设计，policy 根据新 harness 的信号更新决策逻辑。

价值：这和 swyx 本期关于「harness 竞赛」的判断高度呼应：真正的 Agent 性能提升在于调度框架的迭代，不只是模型的迭代。未来方向：harness-policy 联合优化将成为 Agent 开发的基础范式，而不是当前主流的「固定框架 + 换模型」方法。

arXiv 2606.01779 · HuggingFace

UCE：统一上下文进化——Agent 经验外化为可复用的类型化「进化上下文单元」，跨 session 记忆问题有了新解法

现状：LLM Agent 缺乏跨 session 的长期记忆（memory）：每次对话结束，之前积累的经验和知识就消失了。现有方法要么依赖大 context 窗口（把历史全塞进去），要么用固定格式的外部记忆库，灵活性有限。

问题：Agent 经验不可持久化、不可结构化复用——学过的东西用完就扔，每次从头再来。

解决方案：UCE（Unified Context Evolution）是一个无梯度（gradient-free，不需要重新训练模型）框架，把 Agent 经验外化（externalize）为一个动态库，每条经验被封装成类型化的 ECU（Evolvable Context Unit，可进化上下文单元），带有结构化元数据，可被检索、复用和更新。

价值：Agent 经验积累变成可读、可调试的知识资产，而不是黑盒状态。未来方向：类型化的外化经验库是解决 Agent 长期记忆问题的一条绕开训练成本的实用路径。

arXiv 2606.02304 · HuggingFace

SkillRevise：Trace 驱动的技能修订——Agent 技能成功率从 36% 跳到 61.63%，靠的是学失败，不是学成功

现状：LLM Agent 的技能（skill，指由 LLM 编写的可复用子任务解决函数）通常一次性生成，出错了就换一个策略重试，缺乏系统性的「从错误中学习」机制。

问题：一次性生成的技能质量受限于模型首次推断的准确性；错误积累但不被利用；技能库没有进化能力。

解决方案：SkillRevise 用 trace-conditioned skill revision（轨迹条件化技能修订）：把 Agent 执行失败的完整执行轨迹（execution trace，记录每一步操作和结果的日志）输入修订流程，让模型精准定位失败根因并更新技能。

价值：在 SkillsBench 上，基础 Agent 成功率从 36.05% 提升到 61.63%，提升幅度超过 70%。未来方向：失败轨迹作为训练信号将成为 Agent 技能持续改进的标准机制，优于随机重试或完全重写。

arXiv 2606.01139 · HuggingFace

COMAP：世界模型与 Agent 策略协同进化——Agent 在行动前先预测环境反应，规划质量大幅提升

现状：大多数 LLM Agent 直接生成行动，依赖外部环境反馈来纠偏，没有内部的「世界模型」（world model，Agent 对环境如何响应自己行动的内部预测模型）。

问题：缺乏世界模型的 Agent 容易做出代价高的试错，在长视野规划任务上性能低；世界模型和策略分开训练则存在分布不对齐问题。

解决方案：COMAP（Co-evolving world Model And Policy）通过闭环交互同步进化文本世界模型和 Agent 策略——世界模型预测候选行动的未来状态反馈，策略在预测反馈指导下优化行动选择，两者互相强化。

价值：Agent 能在执行前「想一步」，显著降低无效尝试，提升复杂任务的规划质量。未来方向：内嵌轻量世界模型将成为需要长视野规划的 Agent 系统的标准组件。

arXiv 2606.02372 · HuggingFace

Agent-RRM：推理奖励模型为 Agent 轨迹生成结构化批评——GAIA 43.7%，WebWalkerQA 46.2%，超越现有 Agent 基准

现状：Agentic RL（强化学习训练的 Agent）在推理和工具使用上取得进展，但奖励信号（reward signal，告诉模型「这步做得好不好」的反馈）通常是稀疏的结果奖励（任务完成了才给分），无法指导中间步骤的质量。

问题：缺乏过程级奖励导致 Agent 在复杂多步任务上难以系统性改进；现有奖励模型不专门针对 agentic 轨迹（trajectory，Agent 完整执行一个任务的动作序列）设计。

解决方案：Agent-RRM（Agent Reasoning Reward Model）为每条 agentic 轨迹生成三层结构化反馈：显式推理轨迹（记录模型对每步的判断）、聚焦批评（指出具体错误）、整体评分（综合过程表现）。

价值：在 12 个多样化基准上验证，Reagent-U 在 GAIA（通用 Agent 评估）达到 43.7%，WebWalkerQA 达到 46.2%。未来方向：过程级推理奖励将取代稀疏结果奖励，成为复杂 Agent 训练的主要反馈形式。
