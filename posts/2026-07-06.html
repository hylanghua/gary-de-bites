Amazon Leo 390+ 颗卫星到位，年内商用，正式挑战 Starlink

Amazon 卫星互联网项目 Leo 已累计部署超过 390 颗卫星，达到对外提供服务的最低门槛。去年已向部分企业客户提供预览服务，正式商用将在今年内分区域推出。与此同时，Amazon 宣布计划发行至少 200 亿美元债券，资金将部分用于卫星基础设施的持续扩建。

这意味着 Starlink 将在低轨道卫星互联网市场迎来第一个有真实规模的竞争对手。对于偏远地区、海洋航运和军事通信等对网络可靠性要求高但铺设光纤成本极高的场景，双寡头竞争局面将带来定价压力，也将加速整个行业的服务标准提升。低轨卫星互联网从「SpaceX 独场」变成「双巨头竞争」，正式进入有压力的市场阶段。

AI 超级预测师已经出现：多家公司声称在预测市场稳赚、跑赢股市

Scott Alexander 在 Astral Codex Ten 发了一篇深度分析：现在有好几家公司，拿着改造过的 AI agent（通常是带研究 scaffold 的系统，会引导模型完成长链条调研过程）去打预测市场。这些公司声称盈利表现惊人，有的还宣称跑赢了股市。

这件事本身的争议点不在技术，而在验证：这些收益是真实的 alpha，还是在特定时间窗口内的幸存者偏差？超预测（superforecasting）领域原本就以「真实成绩可审计」为核心标准，AI 版本的声明目前还缺乏同等级别的透明度。但如果成立，它意味着：AI 对现实世界不确定性的推理能力，已经高到可以在金融市场提取真实利润。AI 超级预测师的故事，如果是真的，将是 AI 推理能力走向现实世界的里程碑；如果是假的，也是一堂关于 AI 声明核查的经典课。

AI 方向观点

Simon Willison：理解才能参与——AI 写的代码看不懂，下一步就卡死

Simon Willison 在 Geoffrey Litt 的演讲「理解是新瓶颈」之后写了一篇短文。核心论点：当你和 coding agent 协作，agent 会越来越快、越来越大地修改代码库；如果你没有对代码库保持足够深的理解，你就会欠下「认知债」（cognitive debt）——你知道代码在做什么，但不知道它为什么这样做，更不知道怎么往前走。

他的关键区分是：你需要的不是完全读懂每一行，而是足够深的概念模型，让你能继续创造性地参与。一旦缺乏这种流畅感，你提的问题变差，你审查 agent 输出的能力变差，你对整个系统的信心也随之崩溃。这不是「懂不懂技术」的问题，而是任何一个和 AI 深度协作的人都要面对的认知管理挑战。AI 让代码生产速度翻倍，但理解速度跟不上，认知债最终会以「推不动」的形式还回来。

Addy Osmani：Agent 自主度分级——从单线程到「不打扰我就别回来」

Google Chrome 工程总监 Addy Osmani 发了一篇框架文章，把 coding agent 的自主度分成几个层级：低自主（每步问人）、中自主（并行子 agent，各自独立 worktree）、高自主（manager agent 接任务队列、自动调度、出问题才回来找人）。

高自主的核心卡点不是技术，是任务切割：你必须把任务分解成彼此隔离的小块，让不同 agent 各自占有自己的文件和状态，否则并行运行只会带来合并冲突和重复决策——表面上看起来在「跑很多 agent」，实际上是制造混乱。frontier 的形态是：manager agent 持续把任务队列转化成工作输出，只在真正需要人类判断时才打断你。Agent 自主度不是越高越好，而是要匹配任务的可分解性：切不好就是并行乱炖，切好了才是真正的代码工厂。

How I AI Bench 首发：Sonnet 5 对 Sonnet 4 盲测，结果平平

Lenny Rachitsky 播客网络旗下的「How I AI」本周发布了他们自建的模型评测框架 How I AI Bench：用冻结输入（frozen inputs）、固定评分标准（rubric）和相同任务，确保每次新模型上线时可以横向对比。本期测试是 Sonnet 5 对 Sonnet 4 的盲测，直接用 Claude Code 跑。

结论是 Sonnet 5 在盲测中没有表现出明显优势——结果「平平」。这和之前 Every 团队的使用感受吻合：Sonnet 5 在价格、速度、智力三项各有更好的替代品，夹在中间显得尴尬。How I AI Bench 本身还是版本一，团队承认评分标准需要进一步打磨，但这个「可重现基准」的思路本身值得关注。同期节目还涵盖如何从手机端运行 autonomous coding agent。模型评测一直缺乏可重复的横向框架，How I AI Bench 是一次真正有参照价值的尝试，哪怕第一版还不成熟。

产品与商业

纯银：顾问生涯的超能力——如何在最短时间内读懂一门陌生生意

纯银在新一期专栏里讲了他在咨询生涯中积累出来的核心能力：极快地建立对一门陌生业务的结构化理解。他的方法不是读行研或找业内人聊，而是从三个底层问题入手——钱从哪来、成本卡在哪、用户凭什么留——顺着这条链条快速收敛到业务本质。他把这称为顾问工作真正的壁垒：不是行业经验积累，而是快速建模的元能力。

这件事放在 AI 时代有额外的分量。当信息获取成本趋近于零，懂得用什么框架去提问、去组织信息，比拥有更多信息本身更有价值。纯银的「超能力」本质上是一套认识论工具，而不是任何具体行业的知识。在一个所有人都能问 AI 的时代，知道该问什么、怎么问，才是真正的差距所在。

Dan Koe：21 世纪最赚钱的技能不是 AI，是理解人性

Dan Koe 在本周专栏提了一个反直觉的命题：所有商业活动的核心都是说服，而说服的底层是对人类决策模式的理解。AI 只是工具，工具会被更好的工具替代；但人性几千年没变。他把「懂人」拆成三层：读懂他人的核心欲望（而非表面需求）、识别恐惧驱动的行为模式、设计能引发情绪共鸣的信息框架。

他的推论是：越多人用 AI 来生产内容，差异化就越集中在「是否真正理解你的受众」这一点上。AI 可以写文案，但读不懂为什么某个人在某个时刻会做某个决定。「懂人」比「懂 AI」先到达真正的竞争护城河。

人文与哲学

Nan Yu：吹自己开了 10 个 Claude Code 标签页，不过是表演

Nan Yu 在 X 上直接说：炫耀同时跑多少个 coding agent 是「theater」——表演，而非真实的效率提升。他的观察是：agent 并发数量不等于认知吞吐量，多开标签页更多制造的是「我在高速运转」的感觉，而不是真实的工作输出提升。他同期还把 agent 调度类比成即时战略游戏里的多线管理——核心限制永远是指挥者的带宽，而不是 unit 数量。

这个观察和 Simon Willison 的「认知债」论点形成呼应：快是快了，但谁在消化输出？谁在做真正的判断？当 agent 数量超过人类的有效监督边界，多出来的并发只是噪音。真正的瓶颈不在于你能开几个 agent，而在于你能有效处理几个 agent 的输出。

Nan Yu (@thenanyu)

Garry Tan：日本的好，是经济结构的理性选择，不只是文化习惯

Garry Tan 在 X 上连发了几条关于杠杆、经济约束与日本服务品质的推文。他的核心观察是：日本的极致服务标准，不只是文化习惯或「民族性」的结果，而是特定经济约束下的理性最优解——当劳动力相对可得、服务密度极高时，把每一个服务节点做到精细是有经济逻辑支撑的。他把这扩展到杠杆的讨论：不同约束条件下，「值得做」的投入点是完全不同的。

直接从一个生态系统复制另一个生态系统的最优策略，往往是失败的——因为没有同步复制那套约束条件。硅谷的「规模优先」在不同经济结构里未必是最优解，日本案例是一个很好的反例。理解约束，才能找到真正的杠杆点；不理解约束而直接搬策略，只是在模仿表象。

AI 进展

GLM-4.5V：智谱新一代多模态大模型，视觉理解与推理全面升级

智谱 AI 发布 GLM-4.5V，是 GLM-4 系列的多模态扩展版本，在图像理解、视觉推理和多模态对话上相比前代全面提升。论文展示了在多个视觉语言基准上的性能，覆盖图表理解、文档解析、复杂场景描述等任务，训练方法上针对视觉编码器与语言模型的联合训练做了专项优化。

GLM-4.5V 的发布让国内多模态模型赛道再次加速。在 GPT-4o 和 Claude 系列定义了多模态能力天花板之后，GLM-4.5V 代表了开源/国内模型追赶这一能力层级的最新进展。多模态理解正在成为通用 AI 的基础能力，而不是可选的附加功能。

arXiv 2507.01006

Self-Compacting Agents：让 Agent 自动压缩上下文，解决长时运行的记忆瓶颈

论文提出一种让 agent 在运行中自动压缩自身上下文的机制。核心思路是：当上下文窗口接近上限时，由模型自身判断哪些历史信息可以被摘要压缩、哪些必须保留为精确记录，从而让 agent 持续运行而不丢失关键状态。论文在多个长时任务上验证了自压缩策略对任务完成率的提升。

目前大多数 agent 框架采用外部强制截断，而让 agent 自己决定什么值得保留，是从工具走向主体的重要迈进。解决上下文瓶颈的最优解，可能不是更大的窗口，而是更聪明的遗忘。

arXiv 2606.23525

HMPO：分层多策略优化框架，提升复杂任务中的 Agent 决策质量

HMPO（Hierarchical Multi-Policy Optimization）提出一种分层优化框架：高层策略负责任务分解和目标规划，低层策略负责具体行动执行，两层通过共享奖励信号协同更新。论文在代码生成、工具调用和多步推理等任务上验证了框架有效性，相比平层策略在复杂任务上有显著提升。

层级化决策是强化学习领域研究多年的方向，在 LLM agent 的语境下重新获得了实用意义。复杂任务的 agent 优化，可能需要向生物认知体系借鉴分层控制的架构逻辑。

arXiv 2606.01934

不要在不公开 harness 的情况下比较 LLM Agent：评测基础设施必须透明

论文指出一个严重的评测方法论问题：LLM agent 的基准测试表现高度依赖于 harness（评测脚手架）的设计——包括工具调用格式、提示策略、错误处理逻辑等。但绝大多数论文不公开这些细节，导致不同论文之间的「比较」实际上是在比较不同的 harness，而不仅仅是模型本身。

作者呼吁建立强制披露 harness 细节的学术规范。当「模型 A 比模型 B 强 X%」这个结论取决于研究者如何设计跑分工具时，结论本身的科学价值就存疑了。Agent 评测的透明度危机，和十年前深度学习评测的复现性危机如出一辙。

arXiv 2605.23950

Coding Benchmarks 与 Agentic SE 脱节：现有评测体系在衡量错误的东西

论文系统分析了现有代码生成基准（如 SWE-bench、HumanEval 系列）与真实 agentic 软件工程实践之间的差距。核心发现：现有基准过度聚焦于单次函数级代码生成，而真实 agent 任务需要跨文件编辑、工具调用序列规划、错误诊断和迭代修复等能力——这些在传统基准中几乎未被测量。

作者提出了更贴近 agentic SE 实际需求的评测维度框架，用它重新评估几个主流模型后，结论与现有排行榜有显著差异。评测方向决定优化方向；衡量错误的东西，优化出来的只是在错误赛道上跑得更快。
