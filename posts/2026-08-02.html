AI 方向观点

Andrej Karpathy：$10、两小时、5500行 three.js——LLM 的边界不在代码量，在感知能力

Karpathy 把《魔戒》（Lord of the Rings）全文喂给 Opus 5，要求用 three.js（一个基于 WebGL 的3D渲染库）生成程序化的故事场景渲染代码，跑了约两小时、花了约$10，最终输出5500行可运行代码。规模上没问题。

问题出在感知层。他发现，当涉及「让 LLM 审计一个动态变化的游戏世界」（比如判断场景里有什么、发生了什么）或「处理视频内容」时，当前模型有显著局限：它可以写代码描述世界，但无法真正"看到"和"感知"世界的运行状态。$10 能买到代码的生成，买不到理解力的延伸。

代码量不是 LLM 的墙，感知能力是——下一代突破点在「理解正在运行的世界」，而不是「写出更多代码」。

产品与商业

Every.to：「Your AI Is a Team of Specialists」——把 AI 用作专家团队，而非全能助手

Every 本周的核心文章提出了一个很实用的框架转变：与其把 AI 当作一个「能做一切事情的超级助手」，不如把它拆开，像招募专家团队一样使用——不同的 AI agent（智能体，指能自主执行任务的 AI 程序）专注于不同的子任务。一个负责初稿，一个做事实核查，一个优化结构，一个检查语气。

这个框架在实际使用中的优势是：单个 agent 的上下文窗口更聚焦，输出质量更一致；整体系统更容易调试和迭代，因为你知道是哪个「专家」出了问题。Every 的团队同期发布了14套语音转文字（voice-to-text，将口语输入直接转化为文字指令的工作流）工作流指南，全部基于这一框架搭建。

AI 工具的下一步不是让单个模型更强，而是让多个专家模型的协作更顺——这和组建一支好团队的逻辑完全一致。

Every · Context Window

Lenny's 播客：Whatnot CPO Tom Verrilli——「我后悔产品管理这门学科存在」

Tom Verrilli 是 Whatnot（美国增长最快的直播购物平台，历史 GMV 已超过80亿美元）的首席产品官，此前是 Twitch CPO。他在 Lenny 播客上直接说：Whatnot 的产品团队从一开始就建立在「我们后悔产品管理这门学科存在」的前提上。

他的核心论点：用「PM 数量与工程师比例」来衡量组织健康度是一个陷阱。更少的高级别 PM 直接做 IC（Individual Contributor，独立贡献者，即直接产出工作成果而非单纯管理协调的职级）工作，比任何比例驱动的组织架构都表现更好。他同时分享了 AI 如何正在重塑 Whatnot 的 PM 角色：现在 PM 需要能直接用 AI 做数据分析，而不是把需求交给数据科学团队再等两周。

他总结的「手风琴」（accordion）心智模型：好的 PM 知道什么时候展开（扩散思考、收集信息），什么时候收缩（聚焦决策、推进执行）。这比任何职级描述都实用。

「减少 PM，让他们做实事」——这句话如果出自一个失败团队的 CPO，是借口；出自 Whatnot 这种量级，是教训。

Lenny's Newsletter

Nan Yu（Linear 产品负责人）：GitHub Issues 代币质押——让 Agent 替你提 PR，从机制层消灭 slop

Nan Yu 提出了一个很有意思的 GitHub 产品想法：在 Issues 上引入「代币质押」（token pledge）机制。提交者可以在 Issue 上质押资源，直接把 Issue 定向给一个可运行的编程 Agent（agent，指能自主执行代码的 AI 程序），由 Agent 在提交者的算力成本下自动创建 PR（Pull Request，即代码变更合并请求）。

这个设计的精妙之处在于：它把「创建一个 Issue」的成本从零变成「承担对应 Agent 运行成本」。这从根本上改变了 slop PR（slop，指大量低质量、无实质内容的提案）的经济学——没有皮肤在游戏里，就没有资格发出请求。

机制设计比审核更有效：不是靠人力过滤垃圾，而是让质押本身成为门槛。

Wisereads Vol. 154：「为什么一切感觉如此无趣」+「Noticing」——丰盛时代的注意力空洞

本期 Wisereads 有一条内在的线索：两篇文章都在谈同一个问题——我们拥有了前所未有的丰盛，却感觉不到相应的快乐。

《卫报》的长文《为什么一切感觉如此无趣？欢迎来到去享乐的丰盛时代》（"Why does everything feel so joyless? Welcome to the age of decadence without pleasure"）引用了牛津文学教授 Michèle Mendelssohn 和哈佛学者 Charlie Tyson 的诊断：现代丰盛去掉了「渴望」这个前提。没有匮乏，就没有欲望；没有欲望，享受就变成了单纯的消耗。他们引 Walter Pater 的话对抗 Bryan Johnson 式的"延长寿命"执念：「我们来这世上只有数量有限的脉搏，正因如此，才要去渴望快乐。」

Richard Louv 的新书《Noticing：与自然世界的亲密相遇》（Noticing: Intimate Encounters With the Natural World）则从另一个方向进入：他认为「注意」（Noticing）是一种可以被训练、也可以被剥夺的能力。算法把我们的注意力从感知世界的能力里拖走，而找回它的方式，不是技术，而是走出去。

我们的问题不是缺乏选择，是失去了「想要」的能力；丰盛的下一个瓶颈，是重新学会匮乏感。

Zara Zhang：「代理性是最重要的人类品质。世界会给你贴标签——抵抗它。」

「Agency is the most important human quality. The world will try to box you, label you, define you. Resist that.」这条推文没有背景，没有案例，没有解释——只有结论。这反而是它的力量。

AI 最终会代劳执行，但它替代不了「选择做什么」的人——代理性不是个性，是生存能力。

AI 进展

Nemotron 3 Super：NVIDIA 混合 Mamba-Transformer，推理速度比同级别模型快 2.2-7.5 倍

现状：大型推理模型在能力上持续提升，但推理速度和内存开销已成为实际部署的主要瓶颈，尤其是长上下文（百万 token 以上）场景下 Transformer 的二次方复杂度代价极高。

问题：如何在不牺牲能力的前提下，大幅提升长上下文推理的吞吐量和效率？

解决方案：Nemotron 3 Super 是 NVIDIA 推出的120B参数混合架构模型（活跃参数12B），结合了 Mamba（一种基于状态空间模型的序列处理架构，复杂度为线性而非二次方）和 Transformer 注意力机制，并采用 LatentMoE（稀疏混合专家架构）。在 NVFP4 精度下预训练，支持长达100万 token 的上下文。

价值：与 GPT-OSS-120B 相比吞吐量提升2.2倍，与 Qwen3.5-122B 相比提升7.5倍，同时在推理能力基准上保持竞争力。模型以开放权重发布。

未来方向：混合 Mamba-Transformer 架构将成为需要长上下文、高并发 agent 任务的首选路径；纯 Transformer 在效率上的劣势在超长上下文时将越来越难以忽视。

arXiv 2604.12374 · NVIDIA

DarkForest：多智能体系统里「少说话」反而更准确，绝对提升 2.52-5.00 分

现状：多智能体（multi-agent）LLM 系统通常假设 agent 之间的充分通信能提高集体表现，因此倾向于设计大量交流轮次。但更多通信意味着更多 token 消耗和更大的信息干扰噪声。

问题：多智能体系统中，通信越多是否真的越好？过度通信是否反而损害了每个 agent 的独立判断？

解决方案：DarkForest 采用一种「减少通信」策略，让 agent 在更多决策步骤中独立推理，只在关键节点交换信息，避免早期信息共享导致的「锚定效应」（anchoring，即 agent 被其他成员的判断先入为主影响）。

价值：在数学推理、代码生成、常识问答、科学问答、金融推理、法律推理等多个基准上，DarkForest 比第二强基准高出 2.52-5.00 绝对分（相对提升4.5%-30.7%），同时消耗 token 更少。

未来方向：多智能体系统的设计原则可能需要反转——不是「让 agent 尽量多沟通」，而是「在正确的时机、以正确的方式沟通」。

arXiv 2605.25188

MuSEAgent：用「有状态经验」替代轨迹检索，多模态推理超越 Reflexion 近 8%

现状：多模态 Agent（能同时处理图像和文字的 AI 推理程序）在复杂视觉推理任务中，通常依赖轨迹级别的历史经验检索（trajectory-level retrieval，即把过去完整的决策路径作为参考），但这类检索粒度太粗，难以捕捉细粒度的状态级别信息。

问题：如何让多模态 Agent 从过去的经验中提取更精准的决策信号？

解决方案：MuSEAgent 提出「有状态经验学习」（stateful experience learning）范式——把历史交互数据拆解成原子级别的决策经验（atomic decision experiences），通过回顾推理（hindsight reasoning）抽象并过滤，构建多视角嵌入的经验库，在推理时支持宽搜索（广度优先）和深搜索（深度优先）的组合策略。

价值：在 Qwen3-VL-32B 上，MuSEAgent 达到65.30%平均准确率，比最强轨迹级别基准 Reflexion（57.33%）高出近8个百分点。论文被 IEEE CVPR 2026 GRAIL-V Workshop 接收。

未来方向：原子级别的经验分解方式有望迁移至具身 AI、机器人操作等需要细粒度状态感知的场景。

arXiv 2603.27813 · DeepExperience / CVPR 2026

VistaHop：多跳视觉深度搜索新基准，最强模型只拿到 24.31%

现状：现有视觉理解基准大多评测的是「单步图像问答」——给一张图、问一个问题。但真实的视觉搜索任务需要模型反复检视图像的不同区域、跨步骤积累证据，才能回答复杂问题。

问题：当前的多模态大推理模型（MLRM）在需要「多跳视觉推理」（multi-hop visual reasoning，即需要多次回到图像不同部位收集线索并串联推理）的任务上表现如何？

解决方案：VistaHop 构建了包含300张图像、25个视觉搜索场景、350道多跳问答题的评测集，配套 VistaArena 统一评测环境，支持视觉检索、图像局部检查和基于证据的推理工具调用。

价值：即使是当前最强的 MLRM（SenseNova-MARS-32B），Pass@1 也只有24.31%，说明多跳视觉推理仍是当前模型的重大短板。

未来方向：VistaHop 类型的基准将推动模型从「一次看懂图」迈向「反复探索图」，为 visual agent 的落地奠定评测基础。

arXiv 2606.03273

EpiBench：多轮科研工作流基准，最强模型在难例集上只有 29.23%

现状：科学研究本质上是多轮、多步骤的工作流——主动检索文献、比对图表、跨论文整合证据——但现有 AI 基准大多评测单轮单文档的理解能力。

问题：多模态 Agent 能否真正执行一套完整的科研工作流？跨论文证据整合的能力现在在哪个水平？

解决方案：EpiBench（episodic multi-turn multimodal benchmark）要求 Agent 在多轮对话中跨论文导航，从图表和表格中对齐证据，并基于积累的记忆回答需要跨论文对比和多图整合的客观问题。同时引入过程级评测（process-level evaluation）框架，用于细粒度诊断 Agent 在哪个步骤出错。

价值：在难例集（hard split）上，当前最强模型仅达到29.23%准确率，大量提升空间仍在。由哈尔滨工业大学团队构建，已于2026年4月发布。

未来方向：「多轮跨文档推理」将成为 AI 科研助手落地的核心能力瓶颈，EpiBench 为这一方向提供了第一个系统性评测工具。
