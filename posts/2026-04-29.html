AI 方向观点

Aaron Levie（Box CEO）：agentic coding 的维护悖论

Levie 今天谈到 agentic coding（由 AI 代理自主编写代码的工作方式）的一个新摩擦点：Agent 极大降低了启动一个新项目的成本，很多以前因为人工成本太高而搁置的想法现在可以快速试验。但随之而来的是：维护这些 Agent 生成的代码本身变成了新的挑战，质量参差不齐，修改起来比从头写可能更费时。

这与他上周"AI 让工作变多而非变少"的判断构成一个递进：先是工作总量扩大，再是维护摩擦累积。Agent 不是消除工作，而是把工作从"创建"搬到了"维护"。

agentic coding 真正的挑战不在生成，在维护一大堆自己没写的代码。

X @levie

Dan Shipper（Every 联合创始人）："agent-native" 应用设计——为 agent 而设计，而非事后接入

Shipper 提出一个新的设计概念：真正好的产品应该在架构层预设 agent（AI 自主代理）的参与，而不是把 AI 当成事后贴上去的功能。他区分了两类产品——一类是"在原有产品上加 AI"，另一类是"为 agent 参与而从头设计的产品"，后者在信息组织、操作触发、权限结构上都有本质不同。

这个概念对 PM 来说值得认真对待：今天很多团队的 AI 集成是在现有产品形态上硬贴的，真正"agent-native"的产品设计还几乎是空白。

"agent-native"不是功能，是一套不同的产品设计哲学。

Garry Tan（YC CEO）：2026 年是 agent 的"永恒九月"

Tan 写道："如果你已经受够了听到 agent，2026 年对你来说就是永恒的九月。""永恒九月"（Eternal September）是互联网术语，源自 1993 年 AOL 接入 Usenet，导致永无止境的新手涌入——老用户永远在重复解释基础知识的那个九月。

这个比喻锋利在于：它既是对抱怨者的反击（你只是老用户），也承认了 agent 正处于大众扩散阶段的基本事实。Garry 不是在说"大家别烦了"，而是在说"这个阶段就是这样，忍着吧"。

agent 疲劳是扩散期的噪音，不是信号；抱怨天天听到 agent，和 1993 年抱怨天天讲互联网是一样的位置。

产品与商业

纯银：把困境放在结构中观察，是走出困境的最短路径

纯银今天的更新围绕一句话展开："只有在一个结构中，你才能更准确地辨别当下。"他用三段亲历来说明这件事。第一段是 2012-2016 年断断续续做了三年半的旅行 UGC（用户生成内容）产品，产品越做越好，但始终感觉困在某种瓶颈里——后来他意识到，问题不在产品本身，而在于"旅行 UGC"这个赛道的结构性天花板：用户生产内容的动力和消费内容的路径之间存在根本错位，产品再好也无法绕过。

他的核心论点是：我们陷入困境时，往往在"事件层"上寻找原因（这个功能没做好、那个决策走错了），却忽略了困境真正所在的"结构层"（这个市场的竞争结构、这个组织的激励结构、这个产品的信息流动结构）。看清结构，才能知道哪些努力是在结构内挣扎、哪些是可以改变结构本身的杠杆。

这个视角对 PM 和创业者尤其有用：遇到反复出现的问题时，先问"这是什么结构造成的"，比反复优化执行层有更高的效率天花板。

小报童 · 纯银

Every：算力是新现金——AI 补贴终结后的算力经济学

Every 今天的主题文章"Compute Is the New Cash"探讨了一个正在发生的结构性转变：早期 AI 浪潮里，OpenAI、Anthropic 等公司以大幅折扣甚至免费向开发者和企业提供算力，用"补贴算力"换市场占有率。但随着各公司需要真实收入，这波补贴正在退潮。

算力从"成本中心"（需要压缩的开销）变成"资本品"（像现金一样可以配置、投资、交换的资源），影响的是整个 AI 公司的财务结构。持有或获取算力的能力，开始成为谈判筹码和竞争壁垒。一篇子文章"你真的想和 Agent 说话吗"则从产品角度质疑了"对话界面"是否是 Agent 交互的最优形式。

当算力开始被像现金一样定价和分配，AI 公司的商业逻辑就要用资本结构而非技术优势来理解。

Every

Peter Steinberger（PSPDFKit 作者，独立开发者）：每次向 main 合并，Codex 自动触发审查修复循环

Steinberger 今天分享了一个实际在用的工程实践：他在每次代码合并到主分支（main，项目的核心代码库）时，自动启动一个 Codex 实例（OpenAI 的编程 Agent）做代码审查，发现问题后自动尝试修复，再循环。这把 AI 代码审查嵌进了 CI（持续集成，每次提交代码后自动运行的检查流水线）而不是手动触发。

他描述自己一边"闻到了内存泄漏的气味"，一边让 Codex 去追查，同时自己继续做其他事。这是 Agent 不改变开发者主流程、只在后台运行的典型形态——不是"AI 写代码"，而是"AI 做代码守卫"。

把 AI 审查嵌进 CI 而非靠人工触发，是让 Agent 真正产生持续价值的工程姿态。

人文与哲学

Garry Tan：AlphaGo 十年，站在此刻的感受

Garry Tan 发了一条很简单的推文："AlphaGo 已经过去十年了，令人难以置信。"2016 年 3 月 AlphaGo 击败李世石的那一周，很多人把它标记为 AI 时代开始的时间节点。十年，按原来的速度感，应该是一个完整的科技周期。

但站在 2026 年回看，这十年发生的事情密度高到让"十年"这个单位失去了原来的刻度感：GPT-2 到 GPT-5.5，不过七年；Stable Diffusion 到今天多模态 Agent，不过四年。AlphaGo 那一刻的震撼，放在今天的语境里已经像是上上个时代的事。

AI 进展的速度正在压缩历史的厚度，十年前的里程碑在今天读起来已像三十年前的事。

AI 进展

NVIDIA Nemotron 3 Nano Omni：30B/3B active 多模态 MoE，256K 上下文，9× 吞吐量

现状：多模态 Agent（同时处理文本、图像、视频、音频的 AI 系统）通常需要多个专用模型协作，部署复杂、延迟高。

问题：现有开源多模态模型要么覆盖模态不全，要么在吞吐量（单位时间处理请求数）上远落后于闭源系统，难以支撑生产级 Agent 工作流。

解决方案：NVIDIA Nemotron 3 Nano Omni 采用 MoE 架构（混合专家，每次推理只激活部分参数），30B 总参数仅激活 3B，256K token 上下文，覆盖文本、图像、视频、音频和文档五大模态，内置语音理解（Parakeet 编码器），在 Open ASR（语音识别）排行榜上词错率 5.95%。发布当天即在 OpenRouter、Ollama、LM Studio、Fireworks 等主流平台同步上线，较同类开源多模态模型吞吐量提升约 9 倍。

价值：一个模型覆盖五种模态，大幅简化多模态 Agent 的部署架构；MoE 设计让推理成本可控，适合实时 Agent 场景。

未来方向：当前英语限定，多语言支持和视频理解深度是下一步看点；在 GB200 等 Blackwell 架构上的硬件加速效果值得持续观察。

Latent Space / AINews

Poolside Laguna XS.2：33B/3B active MoE 编程模型，Apache 2.0，单 GPU 可运行

现状：高质量开源编程模型通常参数量大、推理成本高，单张消费级 GPU 无法运行，限制了个人开发者和小团队的实际使用。

问题：现有开源编程模型要么精度不足（小模型），要么部署成本过高（大模型），中间档位缺乏真正可用的选项。

解决方案：Poolside 首次公开发布 Laguna XS.2，33B 总参数、仅 3B 激活参数的 MoE 编程模型，完全从零自建训练基础设施、数据管道、RL（强化学习）和推理栈，Apache 2.0 开源，声称性能接近 Qwen-3.5，单张 GPU 可运行；Ollama 在发布当天即完成收录。同批还发布了 Laguna M.1（225B/23B active）和配套 Agent 脚手架（用于快速搭建编程 Agent 的代码框架）。

价值：对个人开发者和小团队最直接：一个够用的编程 Agent 现在可以完全在本地运行，无需 API 调用，无隐私顾虑。

未来方向：Poolside 完全自建训练栈的路线是否可持续，以及模型在真实 SWE-bench 类 benchmark 上的独立验证结果，是后续关注点。

Latent Space / AINews

Microsoft TRELLIS.2：4B 图像转 3D，1536³ PBR 贴图资产，开源

现状：高质量 3D 资产创建是游戏、影视、建筑等行业的核心瓶颈，传统流程需要专业建模师耗费数小时乃至数天，PBR（基于物理的渲染，一种让材质在不同光照下看起来真实的渲染标准）贴图的质量直接决定最终视觉效果。

问题：现有图像转 3D 模型普遍存在分辨率低（几何细节丢失）、贴图质量差（材质不写实）、输出格式受限等问题。

解决方案：TRELLIS.2 是 4B 参数的开源图像到 3D 生成模型，基于原生 3D VAE（变分自编码器，一种将图像压缩再重建为 3D 结构的神经网络）训练，16 倍空间压缩，输出分辨率达 1536³，直接生成带 PBR 材质的完整 3D 资产，可直接导入 3D 软件使用。

价值：开源且输出质量达到专业级，对独立游戏开发者和小型工作室降低 3D 资产制作成本有直接意义；配合上线 Blender 的 Claude 连接器，AI 辅助 3D 创作的工具链正在快速闭合。

未来方向：视频转 3D 和多视角一致性是下一个难关；与 CAD 软件（计算机辅助设计）的集成是工业场景的关键路径。

Latent Space / AINews

World-R1：视频生成模型通过 RL 激活隐含 3D 结构，无需重新训练

现状：构建理解三维空间的 AI 通常需要专门的 3D 训练数据和特殊架构，成本极高。

问题：现有视频生成模型被普遍认为只是"表面的像素预测"，不含真正的空间理解能力，导致 3D 感知需要独立建模。

解决方案：World-R1 研究发现，现有视频生成模型的权重中已经隐含编码了真实的 3D 结构信息，只需通过 RL（强化学习，用奖励信号引导模型行为的训练方式）"唤醒"这些隐含能力，不需要修改模型架构、不需要额外视频训练数据、不增加推理成本。

价值：如果结论可复现，这意味着大量已有视频模型可以免费获得 3D 感知能力，大幅降低世界模型（能理解物理世界的 AI）的研发门槛。

未来方向：独立复现验证是当前最紧迫的步骤；结合 RL 的视频模型在机器人规划和自动驾驶场景的应用前景值得持续追踪。

Latent Space / AINews

vLLM v0.20.0：TurboQuant 2-bit KV cache，4× KV 容量，FA4 重启

现状：LLM 推理服务（将大模型部署为 API 的系统）的核心瓶颈之一是 KV cache（键值对缓存，存储推理中间状态的显存结构）：上下文越长，KV cache 占用显存越多，同时处理的请求数越少，成本越高。

问题：长上下文和高并发的需求同时增长，KV cache 显存占用成为硬件扩容和成本控制的主要障碍。

解决方案：vLLM v0.20.0 引入 TurboQuant 2-bit KV cache，将 KV cache 的精度从通常的 FP16/FP8 压缩到 2-bit（每个数值用 2 比特表示），在相同显存下可存储 4 倍更多的 KV 状态，配合 FA4（Flash Attention 4，加速注意力计算的算法，针对最新 Hopper 架构 GPU 重新启用）在 SM90+ GPU（NVIDIA Hopper 架构及以上）上优化 MLA prefill（多头潜在注意力的预填充阶段）。同版本还新增 DeepSeek V4 MegaMoE（超大混合专家）在 Blackwell 架构上的支持，端到端延迟报告改善约 2.1%。

价值：对运营推理服务的团队：相同显存可撑住 4 倍的并发长上下文请求，是直接降成本的工程改进。

未来方向：SemiAnalysis 的测试显示 B300 在 DeepSeek V4 workload 上比 H200 快 8 倍；结合 DeepGEMM MegaMoE 的 mega-kernel 融合，vLLM 0.20 的真实吞吐量上限还未被充分测试。
