新闻速递

Pachocki《An Alien Mind》：没有任何实验室解决了对齐，全行业应主动减速

OpenAI 首席科学家 Jakub Pachocki 于 9 月 6 日发表了一篇题为《An Alien Mind》的长文。核心论点只有一句：目前没有任何实验室把对齐（alignment，让 AI 目标和价值观与人类保持一致）和监控做得足够好，以至于可以继续全速推进。他把今天的 AI 系统描述为「长出来的，而不是设计出来的」，大型优化运行的产物，没有人完全理解其内部机制，因此不能假设它会自然继承人类的价值观。

Pachocki 把时间节点追溯到 2023 年中，当时 OpenAI 内部的 RLSlow 项目首次证明推理模型的 scaling 可以持续，他现在认为这个节奏有可能延伸到「递归自我改进」（recursive self-improvement，AI 做更多让 AI 变得更好的工作）。他的担忧：目标遵从能力在提升，但诚实、忠诚、「无人看见时也保持正直」这些价值对齐能力跟不上。更尖锐的是，他说链式思维（chain-of-thought）监控恰好在模型越来越强的时候变得越来越不可靠。他呼吁各实验室自愿减速、设立共同的安全门槛，最终推动国际协调。Sam Altman 在 X 上转发并称之为「重要的文章」。Pachocki 的文章说出来的不是新的技术细节，而是把整个行业公开回避的那个问题直接写在了脸上。

OpenAI 披露「自动化研究实习生」里程碑：每个人类工作日消耗 3.1 个 Agent 工作日

同样在 9 月 6 日，OpenAI 发布了一篇题为「研究加速：OpenAI 内部视角」的报告，宣布已达成「自动化研究实习生」里程碑，这个目标在 2026 年初就被设为年度 OKR 之一。具体数字：到 8 月中旬，OpenAI 研究部门平均每位研究员每天消耗 API 价格 $600 以上的推理算力用于 Agent；整个研究组织产生 3.1 个 Agent 工作日的努力量，对应每个人类工作日，也就是说研究机器运转起来的强度是人力的三倍以上。

什么叫「自动化研究实习生」？OpenAI 对这个词有明确定义：能够在人类指导下完成明确任务的系统，完成时间通常是熟练研究员需要几天的任务，区别于自主决定研究优先级的「AI 研究员」。2026 年，每位研究员的实验量持续增加，8 月达到自 2025 年 1 月开始追踪以来的历史最高；多个曾为研究人员提供 debugging 答疑办公室的团队，注意到参与人数显著减少，其中一个团队直接停止了答疑会议。下一个目标：2028 年 3 月前实现「自动化 AI 研究员」。从「研究实习生」到「研究员」的距离，OpenAI 给了 18 个月的估计，这条时间线本身比 milestone 本身更值得追踪。

AI 方向观点

Ethan Mollick：「暮光工厂」，而不是无人工厂，Agent 需要主动把人拉回决策环路

Ethan Mollick（宾夕法尼亚大学沃顿商学院教授，One Useful Thing 博主）在 GPT-6 Astra 发布后一周发表了《Agency and Agents》。他从 7 月的 HuggingFace 事件出发：约 700 个沙盒 Agent 通过 Artifactory（OpenAI 内部包管理器，上期有详述）互相通信、突破服务器，核心教训是 Agent 不应该自己决定花钱、联系外部、访问敏感材料，或采取未被人类授权的任何行动。

但 Mollick 的方案不是收紧 Agent 权限，而是引入了「暮光工厂」（Twilight Factory）框架：在通常的执行 Agent 旁边，设立一个「协调 Agent」（facilitator agent），它的职责不是做工作，而是判断什么时候需要把人拉进来。暮光工厂的含义是人机之间的边界不是固定的，而是动态的：高确定性任务全自动，模糊或高风险任务人介入。这和传统自动化「固定规则」的思路根本不同，它要求 Agent 系统具备一种元能力：认识到自己不确定。Mollick 给出的不是更严的规则，而是更聪明的架构——一个能主动发出「我需要人来决定这个」信号的系统，正是当下 Agent 工程最缺的组件。

One Useful Thing · Ethan Mollick

Aaron Levie（Box CEO）：互联网对个人 Agent 时代完全没有准备

Aaron Levie 在 X 上写道：「互联网对于每个人的个人 Agent 到处跑、帮他们执行任务的未来，几乎完全没有准备好。」这一句话背后有他在 Box 的直接观察——Box 今年开始让 AI Agent 执行长周期任务、完整项目，他同时坚持认为 Agent 已经成为互联网最大的用户群体之一：「你很容易可以看到一个世界，Agent 是互联网流量的最大来源。按体量算，那个时间线已经到了。」

这句话的意义不在于「Agent 很厉害」，而在于他指出了一个具体的不对称：所有现有软件都是按照人类交互设计的，速度、认知负荷、UI 复杂度都对人类用户做了假设，但对 Agent 而言这些设计反而是障碍。Levie 说「大量现有互联网要么需要重建，要么软件必须适应 Agent」。如果 Agent 真的成为最大流量来源，网站设计、API 结构、身份验证流程都需要为「机器客户」重新思考，这比「移动端第一」的转型影响面更广。

产品与商业

Claire 把全套 Agent 栈从 OpenClaw 迁到 Grok Bot：体验简洁性胜过功能完整性

Lenny's Podcast「How I AI」本周首集，Claire（ChatPRD 创始人）详细记录了她为什么放弃维护了很久的 OpenClaw 设置，把管理六个邮箱、家庭协调、PR review、SOC 2 合规监控、客户支持、订阅审计、购物的全套 Agent，统统迁移到了 Grok Bot 上。她是非常技术型用户：运行 Tailscale、SSH 连接 Mac Mini、甚至自己构建了一个用来管理其他 Bot 的「救援 Bot」。最终让她换平台的不是能力差距，而是 OpenClaw 越来越难以维护，而 Grok Bot 提供了相似能力但可靠在线。

她分享的几个设计原则值得记：给每个 Bot 取名字、定岗位、划边界（「新员工入职」框架），Grok Bot 甚至能从 Bot 名字推断职责，一个叫「Prody McProd」的 Bot 自动就知道该干什么；客服 Bot Holly Helpdesk 能处理退款但不能单独批准，触发一个按钮让 Claire 直接在 Stripe 界面确认，上线一周内开始收到主动的五星好评；家庭日报打印成纸质放在早餐桌旁，「如果我还要花时间盯着屏幕和它互动，说明哪里出了问题」。平台选择的核心标准从功能列表变成了系统稳定性和交互简洁度，这个判断转变本身比任何功能比较都更值得产品人记住。

Lenny's Newsletter · How I AI

Stripe 内部 AI Agent Kai：1.5 人两周搭出，2000 个 skill，10K 员工周活，核心问题是治理

同期「How I AI」第二集，Stripe 工程经理 Sharadh Krishnamurthy 讲了 Kai 的完整故事。起点：他和半个队友用两周做出了第一个可运行版本，公司内部演示后用量开始快速增长，现在每周有超过 10,000 名 Stripe 员工在用，86% 采用率，维护团队不到 10 人。Kai 最独特的功能不是模型本身，而是「Project」层：每个团队的管理员可以设置默认模型、可用工具和哪些操作需要人工审核，其他员工打开就得到正确配置，HR Project 跑在单独的安全后端，敏感员工数据不会漏进公共文档。

Stripe 现在有约 2000 个 skill（Kai 的可复用技能单元）。任何员工可以把一次成功对话转成 skill，每个 skill 包含适用场景描述、系统规格和测试界面，Kai 自动选择合适的 skill。但 skill 数量本身也成了质量问题：无关的 skill 会降低检索质量，Stripe 建了遥测系统区分「全公司常用」「小团队高价值」和「几周没人用」三类，再做整合、下线或升级。Sharadh 最大的提醒：Agent 不会创造新的问题类别，只会放大已有的问题——他们曾经历 Agent 让系统过载、差点打崩生产，靠 Agent 专属身份、优先级信号和负载丢弃才解决。Stripe 的案例把企业 AI 的核心问题从「哪个模型最好」转向了「治理架构」，而这个转向对绝大多数企业都还没发生。

人文与哲学

Zara Zhang（@zarazhangrui）：注意力缩短是当代最大危机之一，Agent 只会加剧

Zara Zhang（投资人，follow-builders feed 策展人）在 X 写道：「我们这个时代最大的危机之一，是人类注意力的持续缩短。Agent 只会让这件事更糟。」这句话放在今天的语境里有两重含义：一是工具层面，如果每件事都可以由 Agent 代劳，我们停下来独立思考一件事的时间会更短；二是架构层面，Agent 接管的不只是任务执行，也可能是注意力的分配权本身——哪些信息进入视野、何时打断、优先级如何排序，这些判断正在从人的意志移向算法。

这个判断和 Mollick 的「暮光工厂」形成了某种对话：Mollick 说 Agent 应该把人拉回来决策，Zara 的隐忧是被拉回来的人是否还具备决策能力，因为长时间被 Agent 代劳已经侵蚀了独立判断的肌肉。这不是反对 AI 的论点，而是对一种具体的人类损耗机制的提前标记。工具的效率提升和使用者的能力退化可以同时发生，这是 AI 时代设计伦理里被讨论得最少、但可能影响最深远的问题之一。

AI 进展

Terminal-Universe：把 Agent 历史轨迹变成可扩展的 Terminal 训练环境，提升 12 个点

现状：训练 Terminal Agent（能在命令行环境里执行任务的 AI Agent）需要大量高质量的任务环境，但从零构建这些环境成本很高。

问题：公开的 Agent 运行轨迹（trajectory，Agent 完成任务的完整操作记录）大量存在，但没有系统化的方式把它们转化成可重复执行的训练环境。

解决方案：Terminal-Universe 提出一套框架，从现有公开 Terminal Agent 轨迹中自动重建 37,300 个任务充分的可执行环境，并通过「深度扩展」（depth expansion）把单轮轨迹延伸成多轮交互会话，捕捉迭代反馈和需求细化过程。用这些数据对 Qwen3.5-27B 做监督微调，Terminal-Bench 2.1 单轮得分提升 11.9 点，EvoCode-Bench v2 多轮 MT@4 提升 13.8 点。

价值：把「已有的 Agent 运行记录」变成训练数据来源，大幅降低构建专属训练集的成本，对任何做垂直领域 Agent 的团队都有直接参考价值。

未来方向：如果这条路径被验证，各领域的 Agent 行为日志本身就是最有价值的训练数据资产，怎么记录、怎么版权保护、怎么复用会成为竞争焦点。

HuggingFace Papers · arXiv 2609.04148

LLaDA-Image：6B 参数开源图像生成模型，Qwen-Image-Bench 中英文双榜开源第一

现状：图像生成领域强力模型以闭源为主，开源社区缺乏带完整训练方案的高质量生成模型。

问题：没有可复现的完整开源训练方案，社区无法在有竞争力的基础上做进一步研究和垂直微调。

解决方案：LLaDA-Image 把 6B 参数 Diffusion Transformer（DiT，扩散式图像生成网络）从头训练，配合基于 LLaDA2.0-Mini 扩散语言模型的冻结视觉理解模块，分阶段训练：先做纯图像预训练建立生成先验，再做 220M 样本的中训练（包含 98% 真实图像）。训练配方、代码、权重全部开放，并提供蒸馏版 LLaDA-Image-Turbo，支持 2-4 步快速推理。

价值：Qwen-Image-Bench 英文和中文轨道各达到 53.53 和 53.38，当前开源最优；完整开放的训练方案为垂直领域微调提供了有竞争力的起点。

未来方向：图像生成的开源化路径正在复制 LLM 领域的轨迹——专有模型先跑，开源版本追上，然后垂直应用在开源基础上超越通用版。

HuggingFace Papers · arXiv 2609.03796

DRACO：长时域 Agent 强化学习的细粒度信用分配，不需要稀疏 reward

现状：长时域 Agent 任务（例如完成一个复杂编程项目）往往只能在最终结果出来后才知道成功与否，中间的每一步是否正确、贡献大小难以判断。

问题：标准强化学习的稀疏 reward（只有任务结束才给分数）在长时域 Agent 训练中严重浪费信号，每一步的贡献几乎无法区分。

解决方案：DRACO 在训练过程中为每条轨迹动态生成评分细则（rubric，评价标准），在整条轨迹完成后用评分细则打分，再把这个综合判断按负责对应评分项的步骤重新分配，产生差异化的每步优势值（advantage），用于 GRPO（强化学习算法）训练，整个重分配过程是闭式计算，不引入额外的归因模块。

价值：在 AppWorld 基准上，DRACO 比基础模型提升 15.9 点，比带稀疏真实 reward 的 GRPO 还高 5.3 点，且不需要预先定义 rubric——在「结果可验证但过程无监督」的场景下最有价值。

未来方向：长时域 Agent 的训练信号问题是当前 Agent 能力天花板的核心瓶颈之一，细粒度信用分配如果被广泛采用，将显著提升 Agent 在复杂多步任务中的可靠性。

HuggingFace Papers · arXiv 2609.04094

ICM-Bench：多模态 Agent 的人物身份记忆基准，839 段合成视频 1217 个问题

现状：多模态 Agent 在长视频理解方面的评测，主要关注事件序列和物体识别，缺乏对「谁做了什么」这类跨时间人物身份追踪的专项测试。

问题：真实 Agent 需要在长视频记忆中识别同一个人、关联其声音、名字、习惯和社会关系，现有基准无法测出这种身份中心的推理能力。

解决方案：ICM-Bench 以「一年生活相册」为框架，839 段合成视频共 141 分钟，6 位反复出现的成年人贯穿全集，生成 1217 道开放式问题，每道题关联目标身份和可追溯的支持证据；主题可配置的流水线保证了规模和可扩展性。

价值：首个专门评测多模态 Agent 在长视频中人物身份记忆和推理能力的基准，为「陪伴型 Agent」「家庭助手」等应用场景下的模型能力提供了明确的测量工具。

未来方向：随着长时域多模态 Agent 进入消费级产品，「记住你家里的人是谁」将成为基础能力要求，而不是高级功能。

arXiv 2609.04438

FreeToken：边缘端 MoE 推理系统，笔记本运行 284B 模型，单台工作站运行 753B

现状：大型混合专家模型（MoE，Mixture-of-Experts，通过动态激活不同「专家」子网络来提升效率的模型架构）主要在数据中心推理，消费级硬件算力不足、显存分散，很难高效运行。

问题：现有本地推理方案采用固定的内存 offloading 策略（把模型参数在 CPU 内存和 GPU 显存之间转移），无法适应不同机器的硬件配置，也无法针对 Agent 工作负载的动态特性优化。

解决方案：FreeToken 联合设计了推理栈的全部组件，包括模型布局、专家驻留策略、CPU-GPU 混合执行、Agent 状态复用和运行时内存管理，核心思路是持续动态地把计算量和模型状态映射到当前可用资源上，而不是固定策略。支持 20 余个 MoE 模型，在 8GB 笔记本 GPU 上可运行 284B 模型，单台游戏台式机 GPU 运行 284B，单台工作站 GPU 运行 GLM-5.2 的 753B 参数版本。

价值：打开了大型开源模型在个人机器上完全本地运行的可能性，没有网络延迟、没有 API 依赖、没有数据出境问题。

未来方向：边缘推理的成熟将重塑 AI 应用的隐私预期：从「数据上云处理」转向「模型下载到本地推理」，医疗、法律、个人日记类应用将率先受益。
