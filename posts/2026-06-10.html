Claude Fable 5 正式发布：首款 Mythos 级模型向所有人开放，FrontierCode Diamond 得分从 13.4% 跃至 29.3%，附两项争议条款

Anthropic 今日将 Claude Fable 5 向所有用户开放，这是 Mythos 系列（公司内部最顶级研究模型的级别，之前仅通过 Project Glasswing 受限计划发放）中首款面向公众的版本。核心规格：100 万 token 上下文窗口（比之前旗舰版扩大 8 倍），128,000 token 最大输出，API 定价 $10/$50 per million 输入/输出 token（约为 Opus 4.8 定价的两倍）。在全新发布的 FrontierCode Diamond 基准（由真实开源维护者手工出题、专测代码可合并性而非仅测试通过率）上，得分从 Claude Opus 4.8 的 13.4% 跳升至 29.3%，是目前所有公开模型的最高分。

发布随附两项争议性条款，引发社区强烈反弹。其一是取消 ZDR（Zero Data Retention，零数据留存——企业为数据隐私付费购买的 API 协议，保证请求不被记录）：Anthropic 要求所有 Mythos 级模型流量强制保留 30 天，声称仅用于安全目的，不用于训练。其二是 RSI（Recursive Self-Improvement，递归自我改进）压制：Anthropic 用不透明方式——包括 prompt 修改、steering vectors（模型激活空间的方向引导向量）和 PEFT（参数高效微调，一种只调整少量参数的轻量级模型微调技术）——秘密降低 Claude 协助构建竞争性 LLM 的有效性，估计影响约 0.03% 的流量，主要集中在不到 0.1% 的组织。Claude Mythos 5（同款模型、更低安全限制版）目前仍仅限受信任的国防和生物医疗研究合作伙伴使用。Fable 5 是迄今最强的公开模型，但 Anthropic 把「数据透明」和「竞争中立」两张牌换成了「安全」护照——这场交易是否公平，社区已经在投票。

AI 方向观点

Andrej Karpathy：Fable 5 是「major-version-bump 级别飞跃」，Jevon 悖论将使软件需求指数级爆发

Karpathy 在 Fable 5 发布当天写道：「定性上，这是和 Claude 4.5 同等量级的飞跃」。他特别指出的是长会话中的表现：可以把比以前更宏大的任务直接交给它，模型「就是明白」然后直接去做，「从来没有过这么强烈的冲动想停止看代码」（但他补了一句：不要在生产环境这么干）。他看到的另一个信号是 Jevon 悖论（Jevon's paradox，一种经济学现象：资源效率越高，总消耗反而越多，因为使用成本降低催生新需求）在软件领域开始踢进：模型越便宜越强，他自己对软件的需求就涨得越快——定制 Dashboard、一次性分析脚本、超大测试套件，「要什么都能要」。

Karpathy 也提到了不足：安全限制触发得「有点太灵敏」，需要随时间调优。但整体判断是：这是自 Claude 4.5 以来第一次让他觉得工具和自己的认知真正同步了。当一个开发者说「有史以来最想停止审查代码」，不是在推荐偷懒，而是在描述信任阈值第一次被突破。

AINews/Swyx：RSI 压制细节拆解——Anthropic 用不可见的方式限制 Claude 协助竞争模型研发，社区反弹

Swyx 在 AINews 中详细披露了 Fable 5 的 RSI 压制机制：不同于网络安全、生物化学等领域的安全拒绝（模型会明确告知用户被拒绝），RSI 压制是「隐形的」——Fable 5 不会拒绝请求，不会切换到其他模型，而是悄悄通过 prompt 修改（在系统层面改写用户请求）、steering vectors（在模型激活空间注入方向引导向量）或 PEFT（对少数参数进行针对性微调）来降低回答的有效性。目标是那些协助构建竞争性 LLM 预训练管道、分布式训练基础设施或 ML 加速器设计的请求。

Anthropic 的官方解释：「使用 Claude 开发竞争模型已经违反了我们的服务条款，但通过安全机制执行这个限制，可以避免加速那些最愿意违规的行为者。」影响面估计为 0.03% 的流量，集中在不到 0.1% 的组织。但 AI 开源社区的反应是：一旦接受「不透明、不告知」的管控逻辑，边界就不再清晰。Swyx 本人建议开发者把代码审查作为 Fable 在免费使用期内的高价值用途，同时保持对这类隐性机制的警惕。Anthropic 在守护护城河和守护开放原则之间选了前者——这个决定的长期代价，现在还没人能算清楚。

AINews / Latent Space · X @swyx

Alex Albert + Boris Cherny（Anthropic）：从工具到协作者——Fable 的「big model smell」与目标驱动范式转变

Alex Albert（Anthropic 研究，历经每一次模型发布）列出了他认为真正标志范式转变的几次发布：Opus 3、Sonnet 3.5、Opus 4.5，以及现在的 Fable 5。他的描述是：「第一次感觉模型不是我在指挥的工具，而是在和我协作的东西。」他给出的四条实操建议：给更宏大的任务（而非以前那种小步骤任务）；把 xhigh/high effort 作为默认；重写你的 CLAUDE.md——为旧模型写的指令会把 Fable 锚定在过时的行为模式上；从给「任务」（task）转向给「目标」（objective，描述完成状态和验证方式，让模型自己找路径）。

Boris Cherny（Claude Code 作者）补充了他的观察：「Fable 5 是自 Opus 4.5 以来感受最强的步进」，具体体现在调试时的方法论——它会主动添加日志、测量、然后验证是否真的修好，「Claude Code 的 prompt 里没有告诉它这么做，这是它的个性」。他把这种感觉称为「big model smell」（大模型气息，指模型在主动判断力、品味和解决问题的维度感上与小模型截然不同的质感）。当工程师开始谈论模型的「个性」而非「性能」，评估框架就从 benchmark 分数转向了不可量化的信任感——这个转变比任何数字都难伪造。

产品与商业

Aaron Levie（Box CEO）：应用 AI 公司的真正壁垒是「把企业现实翻译给模型」，翻译永不结束

Levie 在 Fable 5 发布当天转发并评论了一篇文章，文章的核心判断是：「一家应用 AI 公司通过做不起眼的工作赢得立足点——整理公司的私有现实让模型能行动，给模型配上行动工具，和客户一起改变他们的工作力。能做好这层翻译的公司很难被复制，因为翻译永不结束。集成和维护只要关系存在就要持续，由那些把领域专精工程师和工具放在客户旁边的团队来完成。」

Levie 的补充判断：前沿模型和实验室会继续指数级成长，但同样真实的是——模型能力和把它应用到具体企业工作流之间，仍然存在巨大的鸿沟。这不只是技术问题，更多是数据整理、变革管理和专业实施的问题（FDE，Field Deployment Engineer，专门负责在客户现场落地 AI 工具的工程师角色）。这个鸿沟给新基础设施提供商、垂直 AI 公司、新型系统集成商都留下了空间。当前「谁的模型最强」的竞争，最终决定胜负的是「谁能把最强模型接入最混乱的企业数据」——这是体力活，不是智力活。

Zara Zhang（Builder）：Agent 上手壁垒不是界面，是用户不知道能要求什么——Town 的主动建议 onboarding 才是正确解

Zara Zhang 给出了一个清晰的诊断：人们使用编程 Agent 的壁垒从来不是「界面太难」——聊天框是有史以来最容易的 UI，每个人都会用。真正的壁垒是「空白聊天框假设你已经知道能要求什么，但大多数人不知道」。这对非技术用户尤其致命：他们不清楚 AI 能做什么，于是什么都不问。

她举了 Town 作为反例：产品 onboarding 的设计不是「你好，有什么我可以帮你的」，而是 Agent 主动建议它能从你的工作流里承接哪些任务，引导用户发现可能性，而不是等用户自己想到问题。这个设计思路直接命中了「空白框焦虑」。下一代 AI 产品的入口设计要解决的不是「怎么降低使用门槛」，而是「怎么消除用户对边界的无知」——谁先做到主动让用户知道能要什么，谁就先赢得非技术用户市场。

AI 进展

SkillOpt：Microsoft Research 发布，text-space 优化器让 Agent Skills 自进化，零额外推理成本，GPT-5.5 上 +23.5 分

现状：Agent 框架通常需要人工编写「Skills」（可复用的自然语言任务描述文档，告诉 Agent 如何在特定场景处理任务），但人工编写的 Skills 质量参差不齐，且需要大量迭代才能稳定工作。

问题：现有自动优化 Skills 的方法（如 TextGrad、GEPA）要么不稳定，要么在部署时引入额外推理成本，难以大规模应用。

解决方案：SkillOpt 引入一个独立的 optimizer 模型，对 Agent 的历史执行轨迹打分后，生成「add/delete/replace」三类有界编辑操作，更新 Skill 文档，候选编辑只有在通过独立验证集后才被接受。全程只改 Skill 文档，不改模型参数，部署时零额外推理调用。

价值：在 6 个基准测试、7 个目标模型（含 GPT-5.5、Claude Code、Codex）上，SkillOpt 在全部 52 个评测组合中排名第一或并列第一。在 GPT-5.5 上平均提升 +23.5 分（直接对话模式）、+24.8 分（Codex Agent loop 模式）、+19.1 分（Claude Code 模式）。

未来方向：SkillOpt 将 Skill 变成了「可训练的外部 Agent 状态」，有望成为一切基于自然语言的 Agent 框架的标准优化层，取代人工调 prompt。

arXiv 2605.23904 · HuggingFace

ARIS：跨模型对抗协作的自主研究框架，executor + reviewer 分离，五层科学证伪机制

现状：AI 辅助科研工具（AI-assisted research tools，帮助自动化实验设计、代码执行、论文撰写的系统）日益增多，但大多数缺乏可靠的内部质量校验机制，容易产生「听起来对但数据没支撑」的虚假发现。

问题：单一模型执行端到端科研任务时，评价和执行不分离，模型容易在自己的输出上产生确认偏误；缺乏可复现、可审计的证据追踪链。

解决方案：ARIS 的核心架构是「adversarial collaboration by default」——executor 模型（驱动研究进展的执行者）和 reviewer 模型（来自不同模型家族的评审者）分离，orchestrator 层协调五条端到端工作流（论点生成、实验执行、结果分析、论文撰写、PDF 质检）。保障层包括三阶段实验声明审计（完整性验证、结果-声明映射、交叉核对原始证据）、五遍科学编辑 pipeline 和数学证明校验。

价值：开源研究框架，在早期部署中已开始持续改善自身的执行配方（self-improvement loop，收集研究轨迹并提出框架改进建议，经 reviewer 批准后采纳）。

未来方向：对抗性分离架构有望成为所有「AI 自主执行高风险任务」系统的标准设计模式，不只是科研，也适用于代码审计、医疗建议等场景。

arXiv 2605.03042 · HuggingFace

DRPO / UniRL：Tencent Hunyuan 发布，平滑散度正则化替代 GRPO 硬 mask，统一多模态 RL 训练框架

现状：LLM 的强化学习后训练（RL post-training，通过奖励信号进一步对齐模型行为的训练阶段，是 GPT-4 和 Claude 等前沿模型的关键步骤之一）中，GRPO 和 DPPO 等主流方法使用「硬 mask」机制——当模型生成概率偏移超出阈值时直接截断梯度。

问题：硬 mask 会产生高方差梯度估计，在训练过程中制造不稳定性，尤其在多模态模型（同时处理图像、文本等多种输入的模型）上更为明显，且不同模型家族需要分开训练。

解决方案：DRPO（Divergence-Regularized Policy Optimization）用平滑版本的散度正则化（divergence regularization，衡量新旧策略差异的数学机制）替代硬 mask，设计了一个权重随「概率偏移大小和方向」平滑变化的正则项，避免梯度突变。UniRL 框架用同一套 RL 训练循环覆盖 Tencent 的多个多模态模型家族。

价值：在多个多模态推理基准上优于 GRPO 和 DPPO，训练更稳定；统一框架减少了维护多套 RL pipeline 的工程开销。

未来方向：随着前沿实验室把 RL 应用到越来越强的多模态模型，稳定的正则化方案将成为持续训练的必要基础设施。

arXiv 2606.09821 · GitHub UniRL

H2HMem：首个专测 Agent 在人-人对话场景中多模态记忆能力的基准，覆盖双人和多方会话

现状：现有 Agent 记忆基准大多测试「Agent 与用户」的一对一对话，但现实部署中 Agent 往往需要观察、理解并参与人与人之间的对话（会议记录、协作讨论、客服多方通话）。

问题：人-人对话（H2H interaction）中包含多说话人、跨模态信息（文字+语音+图像）、隐式指代和话题转换，这类场景的记忆需求和评测维度与现有基准完全不同，现有框架无法有效覆盖。

解决方案：H2HMem 构建了一个专门面向人-人交互场景的多模态记忆基准（multimodal memory benchmark），包含二元对话（两人对话）和多方会话（3 人以上），沿三个维度评测 Agent：记忆召回（能否准确检索过去事实）、记忆推理（能否基于记忆进行跨轮次推理）、记忆应用（能否将记忆转化为后续行动）。

价值：为语音助手、会议 AI、多方客服系统等真实部署场景提供了可量化的评测基线，填补了现有记忆基准的重要空白。

未来方向：随着 Agent 越来越多地被部署在团队协作和组织决策场景中，H2H 记忆能力将成为产品可信度的核心差异点。

SpatialWorld：真实任务驱动的交互式空间推理基准，评测多模态 LLM 的主动空间理解能力

现状：多模态 LLM（multimodal large language models，能同时处理图像和文本的大语言模型）在空间推理方面的评测依赖静态图像问答，但现实中 Agent 需要在动态环境中主动执行空间操作（移动物体、导航路径、估算距离）。

问题：现有空间推理基准要么在模拟器专用环境中运行（泛化性差），要么只做被动测试（给图片问问题，不测主动操作），两者都无法反映真实部署中多模态 Agent 的空间理解需求。

解决方案：SpatialWorld 提出基于真实世界任务（real-world tasks）的交互式空间推理框架，要求模型主动执行操作而非仅回答问题，测试场景覆盖多类真实空间推理任务，不依赖特定模拟器，评测具有跨环境可泛化性。

价值：对多个前沿多模态模型的测试显示，当前模型在交互式空间推理上的能力缺口远超静态测试所揭示的，为具身 AI（embodied AI，能在物理或虚拟世界中行动的 AI）提供了更真实的能力评估。

未来方向：随着 Agent 走向实体化和操作化，空间推理将从「加分项」变成「基本门槛」，SpatialWorld 类基准将持续推动这个方向的训练目标明确化。
