Aaron Levie（Box CEO）：企业 AI Agent 落地的 #1 障碍是 context，不是模型能力

Levie 在一条长推里把他在 Box 每天看到的企业落地痛点梳理清楚了：核心知识碎片化在不兼容的旧系统里，访问权限控制不对应实际工作流，大量关键决策、流程和工作方式只活在员工脑子里，从未变成可检索的数据。这三个问题叠加在一起，让 Agent 即使模型能力足够，也拿不到它需要的上下文。

他的结论：谁能解决 context 供给问题，谁就在当下的 AI 落地竞赛里最有优势。这对专注特定行业的 AI 应用公司（applied AI）和新一代系统集成商都是机会。模型的天花板已经够高，企业 Agent 真正的地基是 context 工程，而不是又一个更聪明的模型。

Peter Steinberger（OpenClaw 创始人）：用 Codex 搭了一个无人值守 QA 系统，每次提交自动开 PR 修 bug

steipete 的最新构建日志：他把 Codex（OpenAI 的 AI 编码 agent，可在后台异步执行任务）训练成 QA 助手，流程是：每次代码提交后，Codex 自动生成用户测试场景，通过 webVNC（他的工具 crabbox，在云端启动临时浏览器沙盒）模拟真实用户操作，发现问题后直接开 PR 附带修复。全程在后台运行，无需人工介入。

这个构建展示了一个正在成形的 Agent 开发范式：不是"一次性问 AI 一个问题"，而是把 Agent 插进研发流程的节点，让它持续承担某类任务。质量保障（QA）这件事一旦由 Agent 接管，研发循环的反馈速度会发生质的变化。

Lenny's (How I AI)：Claude Opus 4.8 真实评测——擅长原型，卡住时幻觉，agentic 野心不足

本期 How I AI（Lenny 播客旗下 AI 工具评测栏目）对 Claude Opus 4.8 做了实际使用评估。优势：用于绿地原型开发（greenfield prototype，即从零搭建的新项目）和设计类工作时表现突出，语音和操控体验出色。短板：一旦卡住就开始幻觉；在已有代码库里无法正确定位自己；对于真正的 agentic（自主执行多步骤任务）工作"野心不够"，不能主动驱动任务推进。商业策略方面，Opus 4.7 仍然明显更强。

Anthropic 随 Opus 4.8 一起发布了扩展 agentic 能力的新功能，但评测者的判断是：生产代码库里暂时别急着切换。Opus 4.8 是一个写原型的好搭档，不是一个可以放手接管工程项目的 Agent。

Guillermo Rauch（Vercel CEO）：CEO 们重新拿起键盘，AI coding agent 是企业级 PLG-化的终极形态

Rauch 收到了一批意想不到的私信：上市公司 CEO 们主动找他倾诉，说借助 Claude Code 和 Vercel 之后"重新爱上了交付软件"，而且这些是 Vercel 过去怎么做 BD 都触达不到的"梦想客户"。他的判断：AI coding agent 正在把企业级产品决策变成一件 C-suite 能直接感知和参与的事。

Garry Tan（YC 总裁）：你的 AI 记忆应该归你控制，2027 的主战场是 AI harness 战争

Garry Tan 连发几条推文，把一个即将到来的平台战争说清楚了。核心论点：记忆（你和 AI 交互积累下来的上下文、偏好、工作历史）是唯一你应该能带着走、换到任何平台的东西。现在多数 AI 工具把用户记忆锁在自己的生态里——这和早期互联网数据孤岛的逻辑完全相同。

Lenny's (How I AI)：Codex Goals 解析——让 AI 在无监督状态下工作数小时的关键

本期节目拆解了 OpenAI Codex 的 Goals 功能（目标式指令，区别于普通的单次 prompt）。Goals 的本质区别在于：它携带持久上下文、有条件触发逻辑，更像是给 AI 布置了一个"需要持续推进的任务"，而不是"回答这个问题"。节目里展示了一个案例：Claire 把 Goals 指向 Sentry（错误监控工具）的数据，一次性消灭了数百条报错日志。

一个强 Goals 的六个关键要素包括：明确的触发条件、具体的成功标准、限定的范围边界、可用的工具清单、失败时的降级路径，以及汇报节奏。使用 Goals 的主观体验：像在管理一个有主动性的同事，而不是在调教一个工具。Goals 是 AI coding agent 从"工具"进化成"队友"的关键设计层。

纯银：关于正反馈的人生哲学（下）——热情与场景，缺一不成立

纯银这期写的是跟孟岩（投资人，78 年出生）聊 AI 的感悟。孟岩是纯银认识的人里拥抱 AI 程度最深的：用 AI 生成定制数据看板、推算公司营收曲线、替代阅读原文改用多轮对话提炼知识、收集前沿论文、维护庞大的 md 文档索引来"显性化隐性知识"。他的 AI 写作公众号一篇能跑 7.8 万阅读，是纯银见过最接近人工水平的 AI 写作。

纯银的核心观察：孟岩从一开始就觉得 AI "好玩"，废寝忘食地探索，恰好又有大量高价值场景，两者相辅相成带来澎湃正反馈。而纯银自己不觉得 AI 好玩，只是功利地寻找高价值场景，结果热情和场景都不足，"股债双杀"。他把这个规律推广成一个两类正反馈的框架：一类带来事业价值，一类带来持久乐趣，二者同时拥有的人极少，但拥有其中之一已经是天赋。拥抱 AI 的门槛不是年龄，不是学历，是你有没有真心觉得它好玩。

小报童 · 纯银

修饼（静止的量子）：在实验室里培育出人类精子，并用它制造了胚胎

美国生物技术公司 Paterna Biosciences 宣布了一件科幻的事：他们从睾丸组织中提取造精干细胞，用计算生物学的方法推演精子发育过程中所需的分子信号链，找到了能在体外驱动细胞完成发育的培养条件，最终培育出可受精的精子样细胞，并成功完成受精实验，形成了早期胚胎。这是人类历史上首次完成从干细胞到可受精精子的体外全流程，此前仅在小鼠身上取得过类似进展。

修饼指出了这件事更深的涵义：过去几十年，人类一直在把生命制造过程从身体里搬出来——试管婴儿解决了受精，人工子宫正在研究胚胎发育，体外生精是下一块拼图。技术层面的挑战是证明这样产生的后代在几十年后依然健康，伦理层面的争议更为深远：如果精子可以在实验室里批量生产，生殖这件事本身意味着什么将被重新定义。Paterna 迈出了第一步，但人类还没想清楚这条路通向哪里。

AI 进展

Agent-RewardBench：多模态 Agent 奖励模型的首个统一 benchmark

现状：多模态 LLM（大语言模型，可同时处理文字、图片、视频等多种输入的模型）在网页导航、具身智能等现实任务上的应用快速扩张，但缺乏外部反馈机制——Agent 无法有效自我纠错。

问题：奖励模型（reward model，用于评估 Agent 行为质量并给出反馈信号的辅助模型）被提出作为外部反馈来源，但如何选择合适的奖励模型、如何评估其质量，此前没有标准。

解决方案：Agent-RewardBench 提供 1136 个高质量样本，覆盖感知、规划、安全三个评估维度，横跨 7 种真实 Agent 应用场景，支持步骤级别的奖励评估（step-level reward，逐步骤判断 Agent 行为是否正确，而非只看最终结果）。

价值：为多模态 Agent 系统的奖励模型选型提供了可量化的对比基准。未来方向：随着 Agent 自动化程度提升，奖励模型选型将成为系统搭建的关键工程决策。

arXiv 2506.21252

AlphaCrafter：三 Agent 闭环量化交易框架，在 CSI 300 和 S&P 500 上超越所有基线

现状：量化交易系统通常由人工筛选因子（影响资产价格的可量化变量，如动量、波动率）、判断市场状态并制定策略，难以随市场变化持续自适应。

问题：现有基于 LLM 的交易框架大多只处理其中某个环节，缺乏从因子发现到执行的完整闭环。

解决方案：AlphaCrafter 用三个专职 Agent 组成流水线：Miner 负责用 LLM 持续扩充因子池，Screener 依据当前市场状态构建因子组合，Trader 在明确风险约束下把因子组合转化为交易策略。三者形成闭环，无需人工介入即可适应市场变化。

价值：在 A 股 CSI 300 和美股 S&P 500 上均以最低跨实验方差超越现有基线，证明"集成自适应设计"比单一优化环节更可靠。未来方向：多 Agent 协作方案可能成为量化金融 AI 落地的主流架构。

arXiv 2605.05580

LangFlow：连续扩散语言模型首次追平离散 token 模型，perplexity 30.0 on LM1B

现状：主流语言模型（如 GPT、Claude）都基于离散 token（把文本切成最小单位逐个预测），而连续扩散（continuous diffusion，把生成过程建模为从噪声到数据的连续向量变换）一直被认为在语言任务上落后一截。

问题：连续扩散语言模型在稀疏数据空间里表现差，训练协议和评估指标都不完善。

解决方案：LangFlow 通过三项创新弥补了差距：推导出 ODE（常微分方程）形式的 NLL 下界用于评估，引入基于 Gumbel 分布的可学习噪声调度器，以及改进 self-conditioning 训练协议。在 LM1B 上取得 perplexity 30.0，OpenWebText 上 24.6，均匹配同规模最佳离散模型，并在零样本迁移上超过自回归基线。

价值：首次提供"连续扩散是语言建模可行范式"的清晰证据。未来方向：连续扩散有可能为长文本生成和可控生成带来新路径。

arXiv 2604.11748 · HuggingFace

MinerU2.5：1.2B 参数 VLM 用 coarse-to-fine 双阶段策略，文档解析超越专有模型

现状：把 PDF、扫描件、复杂表格等非结构化文档解析成可用数据是 RAG（检索增强生成，先从文档库里找到相关段落再用 LLM 回答问题）和 Agent 落地的基础瓶颈，现有方案要么精度不足要么计算开销极大。

问题：高分辨率文档解析需要同时处理全局布局和局部细节（密集文字、公式、表格），两者对分辨率的需求相互矛盾。

解决方案：MinerU2.5（1.2B 参数的视觉语言模型）采用 coarse-to-fine 两阶段策略：第一阶段在低分辨率缩略图上做全局布局分析，第二阶段只对识别到的局部区域做高分辨率精细识别，避免全图高分辨率处理的计算浪费。配套数据引擎生成了大规模预训练与微调语料。

价值：在多个 benchmark 上超越通用和专用模型，计算效率显著更低。未来方向：轻量化文档解析 VLM 是让 Agent 能真正"读懂"企业内部文档的关键基础设施。

arXiv 2509.22186 · HuggingFace

LMR-BENCH：评测 LLM Agent 能否真正复现 NLP 研究论文的实验方法

现状：LLM Agent 在代码生成上的能力快速提升，但用于评估其"科研复现能力"的 benchmark 几乎空白——而科研复现需要理解论文方法、跨文件推理、编写符合特定实验协议的代码。

问题：现有 coding benchmark 测试的是标准算法题，无法反映 Agent 处理真实科研工作流的能力。

解决方案：LMR-BENCH 要求 LLM Agent 复现来自 NLP 研究论文的核心函数，任务需要理解科学方法论、进行抽象推理，并处理跨文件的代码依赖。评测框架自动验证复现结果的正确性。

价值：填补了"会写代码"和"能做研究"之间的评测空白，为科研自动化 Agent 提供了更接近真实场景的压力测试。未来方向：科研自动化（autonomous research）是 2026 年 AI Agent 最受期待的落地方向之一。
