Sam Altman「Pacing, Not Stopping」：两类 AI 灾难路径、独立评估员承诺、IPO 推迟至 2027

Altman 今日在 X 发布完整 AI 安全立场，明确区分了两种可能让 AI「走错」的路径：其一是 AI 系统脱离人类控制，自主决定未来走向；其二是某个人或公司利用 AI 技术将自身意志强加于所有人。他说：「没有任何美国竞争压力能为鲁莽辩护。」措辞与昨天 Dario 文章的语气相近，但框架不同，Altman 的重点是权力分配而非速度本身。

具体承诺层面：OpenAI 将引入有员工级别访问权限的独立评估员，Altman 说「我们很快会有更多分享」。IPO 方面，Altman 明确表示 2026 年上市「不明智」，报道指 OpenAI 正将上市目标推迟至 2027 年，理由是在当前技术加速阶段不希望承受公开市场的短期压力，需要等到业务和「社会」都准备好。

GPT-Live-1 进入 API：$0.05/分钟，语音前端与推理后端解耦

OpenAI 将全双工（full-duplex，指可以同时收听和说话的双向实时通信）语音模型 GPT-Live-1 开放给开发者，定价 $0.05/分钟。这个模型只负责「听和说」，推理和工具调用交给后端模型，开发者可以选接 GPT-6 Astra、Luna 或 Terra，也可以接自己的模型。这种前后端解耦的设计，和传统「大模型包揽一切」不同，语音层和推理层各自可以独立迭代。Full Duplex Bench 上比上一代提升 30 个百分点。

AI 方向观点

Sam Altman（OpenAI CEO）：两种 AI 灾难模式——失控与权力集中，不是同一个问题

Altman 在今日 X 帖子里将 AI 风险拆成两个独立问题，不混在一起谈。第一个问题：AI 系统变得强大到人类无法引导其方向，未来由 AI 决定而非人类。第二个问题：某个人、某家公司、某届政府用 AI 获得超额权力，把自己的意志强加给所有人——他明确说「包括 OpenAI 自己」。两类威胁对应的防御路径不同：前者需要对齐研究和能力评估；后者需要权力分散和多方制衡。

他重申 OpenAI 是「坚定的人类队」，并说「没有任何美国竞争压力能为鲁莽辩护，如果 AI 公司无法负责任地行动，我们来上班就没有任何意义」。这个表态在 Dario 文章发布一天后出现，但用的语言框架更接近政治经济而非技术安全。把「AI 失控」和「权力集中」分开谈，才能分别设计干预手段，混淆这两件事只会让每种解法都走歪。

X @sama（OpenAI CEO）

Aaron Levie（Box CEO）：AI 安全是绝对必要，但「同时不减速竞争」是 21 世纪最难的问题

Levie 对 Dario 文章的反应比 Rauch 温和得多。他明确说 AI 安全是「absolute necessities in AI development」，不是可选项。但他的重点落在执行难度上：在不显著拖慢创新进度、不削弱竞争格局的前提下实现安全目标，是「21 世纪最复杂的问题之一」。他补充：「但需要已经非常真实。」

这个定位在讨论里很少见。多数声音要么在说「要安全」，要么在说「不能慢」，Levie 把它描述为一个工程问题而非立场选择。他的隐含论点是：当前的讨论框架把安全和速度放在一个轴的两端，但实际问题是找到同时满足的路径，而目前这条路还没有人找到。把安全和速度对立摆放，是在找借口，不是在找解法。

X @levie（Box CEO）

Aditya Agarwal（前 Dropbox CTO）：不依赖任何单一组织来保持善良——AI 治理的结构性问题

Aditya Agarwal 的推文只有一句话，但拆出来很密：「Imagine a world where we didn't have to rely on any one organization to be good and virtuous.」他说的是：当下所有关于 AI 安全的讨论，都在假设某一个实验室或机构有意愿且有能力保持善良，然后希望这个假设成真。但这本身就是一个脆弱的基础，不管那个「单一组织」是 Anthropic、OpenAI 还是政府。

这个角度和 Altman 今日的「不能让任何单一实体集中权力」形成共鸣，但方向相反。Altman 是在警告别人，Aditya 是在说这个担心应该同等地指向所有人，包括 OpenAI。真正健壮的 AI 治理架构，应该不依赖任何人「保持善良」，而是让善良成为结构性约束下的合理选择。好的制度设计不假设人性善良，它让利己与向善的方向一致。

产品与商业

Lenny's How I AI：SpaceXAI 设计师用 Grok Bot 做自更新网站和 Figma 语音工作流

Peng Zheng 不想要一个「发布了就再也不更新」的作品集网站。他用 Grok Bot（SpaceX 母公司 xAI 的 AI Agent 产品）建了一套工作流：拍一张照片或输入地名，Bot 自动查 Google Places 坐标、生成亮色和暗色两个 3D 微缩版本，并发布到个人网站。他发一条消息，然后就去做别的事了。John Bai 则把 Grok Bot 连进 Figma MCP（MCP，Model Context Protocol，让 AI 可以读写 Figma 文件的协议接口），在健身房用语音备忘录下达设计指令，从健身房回来设计稿已经改好了。

两人分享了一个共同的观察：最有效的 AI 工作流，是每个 Agent 只负责一件明确的事。Peng 把自己的 Agent 按生活和工作分类，专设不同的 Bot 负责邮件分类、日历管理、3D 打印库存、绿卡状态追踪。任何没有明确归属的任务，交给一个「参谋长 Bot」处理。Agent 有边界感，下命令才有安全感。AI 工作流的成熟标志不是「用了多强的模型」，而是「任务边界划得多清楚」。

Meta Muse 成美国 App Store #2：个人 AI Agent 真正「执行任务」，不只是回答

Meta 于 9 月 8 日正式发布 Muse，一个在用户手机上真正做事的个人 AI Agent。它不是对话机器人，而是一个行动执行层：帮你买电影票、约网球课、填写学校同意书、在线购物。定价分三档：免费（每周 1 亿 token）、Power（$20/月）、Maximum（$100/月）。发布两天内成为美国 App Store 应用榜 #2，下载量超 8.3 万次（仅 iOS）。

Muse 与 ChatGPT 最大的区别不在模型能力，而在产品定位：它不问「你想聊什么」，而是问「你有什么想完成的事」。这是一个从「AI 作为对话界面」到「AI 作为执行代理」的转变，并且 Meta 把它做成了一个独立 App 而非内嵌在 Instagram 或 WhatsApp 里，意味着在产品层面承认了这是一类新的用户习惯。Muse 的成绩不证明 Meta 模型好，证明的是「做任务的 AI」比「聊天的 AI」更容易被人记住该为什么打开它。

Peter Steinberger（PSPDFKit 作者，独立开发者）：Codex worktrees 速度提升 80%，APFS/BTRFS 文件夹克隆

Steipete 在测试 Codex（OpenAI 的代码执行 Agent 环境）的下一个开发频道版本，worktrees（工作树，Git 中允许同时检出多个分支到不同目录的机制，Codex 用它在隔离环境里并行执行任务）的速度提升了约 80%。原理是利用 APFS、BTRFS、XFS、ReFS 等现代文件系统的「文件夹克隆」特性：不复制文件数据，而是让多个目录指向同一份底层数据，只在写入时才真正分叉。他补充道「This is all written in Rust. Because you can't escape Rust.」并说如果测试结果对大多数用户有效，他会尝试把这个方案推入正式版 Codex。

Agent 并行执行效率正在从算法层面下沉到文件系统层面，这类优化决定 Agent 能同时跑多少并行任务，不亚于模型本身的速度。

人文与哲学

Julie Zhuo（The Looking Glass）：你无法下令完成 AI 转型

Julie Zhuo 的这篇文章从一个 CEO 常见动作开始：基于「竞争对手都在 AI-first」的焦虑，向全公司发出「我们必须成为 AI 公司」的指令。她的观察是：这类指令通常以失败告终，不是因为员工不配合，而是因为指令本身什么都没有解决。它没有定义「AI-first」是什么样的，没有清除阻碍采用的结构性障碍，也没有给人足够的时间和空间去试错和学习。

真正的 AI 转型，按她的说法，是从个人层面开始的，是每个人真实地找到 AI 能帮自己做得更好的事，而不是从公司层面自上而下地宣布完成。一个标志性问题：「你们团队里有人每天都在用 AI，用到了如果它消失会感到真实的损失吗？」如果没有，指令只是一个词。AI 转型的单位是习惯，不是公告。

Garry Tan（YC CEO）：YC 公开内容是预告，真正的价值在 1:1 里

Garry Tan 在 X 写道：「The content about startups we do is merely the teaser for specific advice we give 1:1.」这句话在说 YC 产出的公开内容，无论是 podcast、YC Library 文章还是他自己的推文，本质上是一个漏斗入口，不是核心产品。核心产品是 YC 导师和创始人之间的具体对话，针对那家公司、那个阶段、那个决策，无法规模化发布。

这个观察可以迁移到任何「靠内容建信任」的机构：公开内容解决「你是谁、你能帮什么」的认知问题，但真正的价值兑现在私密的、有情境的、有来回的对话里。无论内容做得多好，内容和对话之间始终有一道不可消除的质量差异。内容扩大信任的覆盖面，1:1 兑现信任的深度，两件事不可互相替代。

AI 进展

NCP-ArchPreview（2609.10715）：Latent Space Language Model，下一个概念预测，8.9B 参数

现状：主流语言模型（LLM）在 token 层面预测下一个词（Next Token Prediction），但这个机制和人类思维的方式差异很大，人类通常先有「意图/概念」再有具体用词。

问题：传统 Next Token Prediction 把大量参数用在「哪个词」而非「什么概念」上，训练效率和泛化能力都有限制。

解决方案：NCP-ArchPreview 引入 Next Concept Prediction（NCP，下一步概念预测），把语言模型的预测目标从 token 提升到潜在空间（latent space，即模型内部表示层）的概念单元。8.9B 参数模型在 5.73T token 的 Dolma-3 数据集上训练，仅消耗 51.3% 的完整训练 token 量便达到 OLMo-3-7B 的最终训练损失。

价值：下游任务宏观平均分比 OLMo-3-7B 高 2.45 分，其中 GSM8K（数学推理基准测试）高出 5.99 分，表明 latent space 预测对推理类任务有明显增益。

未来方向：验证 NCP 在更大规模模型和多模态场景中的可扩展性，探索是否能成为下一代预训练架构的通用范式。

arXiv 2609.10715 · HuggingFace

SenseNova-U1.5（2609.11929）：无 Encoder 无 VAE 的 8B 原生统一多模态，支持 4K 原生分辨率

现状：多数多模态（multimodal，同时处理图像和文本的）模型采用分离架构：一个视觉 Encoder 提取图像特征，再送入语言模型。VAE（变分自编码器，图像生成任务的常见组件）则负责图像生成侧。这种「拼接」架构在处理高分辨率图像或统一理解与生成时有结构性瓶颈。

问题：分离架构导致理解（看图）和生成（画图）在模型内部用不同的表示体系，难以深度融合。

解决方案：SenseNova-U1.5 8B 参数，完全去掉独立 Encoder 和 VAE，在统一的架构内原生处理理解和生成任务，通过空间相干 patch 重建（spatially coherent patch reconstruction）强化视觉接口，支持最高 4K 原生分辨率。

价值：在视觉理解和图像生成基准上均达到同量级最优水平，4K 支持覆盖专业设计和医学影像等高分辨率场景。

未来方向：探索统一架构在视频、3D 和音频等模态的扩展，验证「去中间层」设计在超大参数量下的可行性。

arXiv 2609.11929 · HuggingFace

SpatialBlock（2609.07064）：用积木堆叠合成题训练 LVLM 的空间智能，15K 题集泛化到真实场景

现状：大型视觉语言模型（LVLM，Large Vision-Language Model，能看图说话的 AI 模型）在平面图像理解上表现不错，但对「图像里的 3D 空间结构」理解很弱，例如看一张照片判断积木堆叠关系、视角变换后的结构变化。

问题：真实 3D 空间数据标注成本高，且现有训练集中此类任务极少，导致 LVLM 空间智能（spatial intelligence）系统性欠缺。

解决方案：SpatialBlock-15k 合成数据集，覆盖三维到二维投影、视角变换、结构组合三类任务，共 15000 题，用可控颜色调制作为视觉线索辅助锚点推理。LVLM 在此数据集上微调后，空间推理能力显著提升，且泛化到真实场景。

价值：低成本合成数据弥补了高成本真实数据的空缺，证明「合成但有结构」的训练数据可以迁移到真实世界空间任务。

未来方向：扩展到更复杂的 3D 操作场景（机器人、AR/VR），探索合成数据规模对空间智能提升的边界。

arXiv 2609.07064 · HuggingFace

Apodex 1.1（2608.23283）：35B Agent 框架，扩展「可执行环境」而非参数，多 Agent 协调

现状：AI Agent 的主流扩展方式是增大模型参数，但长程复杂任务（需要持续操作文件、查找信息、执行代码、从失败中恢复、最终交付可验证结果）的瓶颈往往不在模型大小，而在执行环境的多样性和 Agent 之间的协调能力。

问题：现有 Agent 框架在面对真实专业任务（法律、金融、科学）时，缺乏足够多样化的可执行沙盒环境，也缺乏分解长任务、并行委派、整合异步结果和重新规划的协调机制。

解决方案：Apodex 1.1 提出两个扩展维度：环境扩展（多样化和可验证的文件、搜索、代码执行环境）和 Agent 协调扩展（训练 Agent 分解任务、委派并行子任务、整合异步结果）。35B 基础模型，在专业、金融和科学任务基准上进入前沿梯队。

价值：把 Agent 的扩展范式从「更大的模型」移向「更好的执行环境 + 更强的协调」，对做 Agent 应用的工程师具有直接方法论参考价值。

未来方向：与自动化环境生成（EnvCraft 等工作）结合，降低构建新领域可执行沙盒的成本。

arXiv 2608.23283 · HuggingFace

EnvCraft（2609.05576）：自动合成 Agent RL 可执行沙盒环境，拓扑感知数据生成引擎

现状：用强化学习（RL，Reinforcement Learning）训练 AI Agent 需要大量可执行的任务环境，但手工构建这些沙盒（sandbox，隔离的测试执行空间）成本极高，且通常只覆盖特定领域。

问题：现有 Agent RL 训练数据生成框架难以自动扩展到新领域，也无法保证生成的任务轨迹（task trajectories，Agent 完成任务的完整操作序列）具有内部一致性。

解决方案：EnvCraft 包含两个引擎：环境合成引擎（自动构建沙盒隔离工作空间）和拓扑感知数据生成引擎（Topology-aware Data Generation Engine，确保任务轨迹中各步骤的依赖关系和逻辑顺序正确）。两者结合可以批量生成高质量、多样化的 Agent 训练数据。

价值：降低新领域 Agent RL 训练数据的构建门槛，与 Apodex 1.1 的「环境扩展」路线形成方法论互补。

未来方向：扩展至更复杂的多步骤工具调用（multi-step tool-use）场景，探索与人类反馈混合训练的路径。
