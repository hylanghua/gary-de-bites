Anthropic 9 月威胁情报报告：154 页，阻断生物武器研究，点名 7 家中国 AI 实验室蒸馏 Claude

Anthropic 发布了有史以来最完整的 Claude 滥用案例报告，覆盖 2025 年 12 月至 2026 年 8 月共 8 个月。报告记录了 35 个「可能引发担忧」的研究项目，涵盖七类危害场景。最引人注目的单一案例：一位科学家请求 Claude 帮助起草基孔肯雅病毒（chikungunya，一种通过蚊子传播的热带病毒）增益功能（gain-of-function，指人为增强病毒感染力或传播力的研究）的基金申请，Anthropic 生物安全分类器将其标记后中断服务。其他记录案例包括：也门某用户用 Claude Code 开发火箭制导软件；一套设计用于监控马里 2500 万条电话线的系统；4700 个约会 App 虚假人物角色；以及专门绕过杀毒软件检测的恶意代码。

报告最直接的政策含义来自这句话：「旧版模型远低于可以有意义地辅助生物武器开发的门槛，但新模型已不再如此。」Anthropic 同时点名 7 家中国 AI 实验室，包括阿里巴巴、DeepSeek、月之暗面（Moonshot）和小米，通过数千个虚假账号蒸馏 Claude 能力。月之暗面和 DeepSeek 更是把用户的真实提问转发给 Claude，再把 Claude 的答案冒充自己的模型输出——用户以为在用中国 AI，实际上在用 Claude。这是 Anthropic 首次公开如此具体的蒸馏行为证据。

ChatGPT for Financial Services：GPT-6 Astra 进驻华尔街，内置 PitchBook/LSEG/Crunchbase，目标是初级银行分析师的工作流

OpenAI 正式发布 ChatGPT for Financial Services，本质是在 ChatGPT Work 基础上针对金融服务行业定制的版本，底层模型为 GPT-6 Astra。产品预置了 Daloopa、PitchBook、LSEG News 和 Crunchbase 四大金融数据源，同时整合 S&P Capital IQ、MSCI、Moody's 等平台数据。功能覆盖公司研究、估值分析、LBO 建模（杠杆收购财务模型，投行日常核心工作之一）、买方筛选、财报分析和路演材料准备。摩根士丹利和 Evercore 是设计合作伙伴，OpenAI 计划用金融机构的使用反馈训练未来模型。

CNBC 的报道标题直接写明了目标：「OpenAI 瞄准华尔街初级银行家的工作」。GPT-6 Astra 可以解析财务报表里的附注和表格，完成分析后直接生成 Excel 模型、研究报告和 PowerPoint 路演材料，并保留可供检查的数据来源。GPT-6 Astra 的能力支柱是「信息检索 + 财务推理 + 文件生成」三位一体——这正好覆盖了 junior analyst 日常 80% 的机械劳动。

Sam Altman 向全员表示 OpenAI 愿意减缓前沿模型开发，并已向国会咨询协同减速是否触犯反垄断法

Sam Altman 在本周的全员会议上告诉 OpenAI 员工，公司愿意放缓前沿模型的开发节奏，并希望其他主要 AI 实验室也能同步跟进——他主动提议，可以在几家顶级实验室之间协调这个节奏。OpenAI 已经在私下向国会议员咨询：AI 行业的协调减速，是否可能触犯《谢尔曼反垄断法》（Sherman Antitrust Act，美国最核心的反垄断法律，禁止竞争者之间协调限制产出）。目前已有两党联合推动的《CATS 法案》（Collaboration on Adversarial Threats and Security Risks Act），试图为 AI 安全协调设立反垄断豁免，但尚未通过。

Altman 这次的表态，和他过去几年「全速冲向 AGI」的公开立场形成了明显落差。驱动这一转变的，一方面是内部安全压力（OpenAI 已在过去数月暂停了部分内部模型训练），另一方面是法律不确定性迫使他们公开寻求国会的意见。但这里有一个结构性困境：如果减速协议在法律上不可行，而 OpenAI 单方面减速，竞争对手不减，OpenAI 就只是在让自己落后。Altman 公开讨论减速，不等于减速会发生，但这是 AI 行业历史上最有分量的一次公开表态。

AI 方向观点

Aaron Levie（Box CEO）：企业 AI 的首要顾虑是网络安全，不是效率——多模型部署和 Agent 身份管理正在制造新的复杂度

Aaron Levie 在 X 梳理了他和大型企业谈 AI 时反复出现的几个现实：网络安全顾虑排在所有障碍的首位，超过效率目标和成本压力；前沿企业不是在挑选一个 AI 供应商，而是在同时部署多个模型，根据任务类型分配不同的前沿模型；遗留系统集成是拖慢采用速度的第二大阻力，不是能力不够；真正产生 ROI 的不是在现有工作流上叠加 AI，而是重新设计工作流（workflow reengineering，完整地重画任务路径，而不是在老路上加一个 AI 插件）。

Levie 还专门提到了 Agent 身份管理（agent identity management，指在企业系统里，AI Agent 以什么身份运行、有什么权限、对什么负责）正在成为新的基础设施需求。对大企业的 IT 团队而言，「一个 Agent 替代一个员工」不是他们的第一个问题，「这个 Agent 是谁、能访问什么、如果出错谁承担责任」才是。企业 AI 的瓶颈从来不在智能，在于信任——而信任是工程问题，不是模型问题。

Madhu Guru（Meta AI）：Agent 评估不能只看最终答案，每一步操作都必须可验证——「做对了」和「用对方法做对了」是两回事

Madhu Guru 在 X 分享了他对 Agent 评估（agent evaluation，对 AI Agent 完成任务的全过程进行评分，而不只是判断最终输出）的方法论立场：判断一个 Agent 是否可用，不能只测量它最后交出来的答案对不对，而要逐步验证每一个中间步骤。他的核心判断是：一个在过程中用了错误路径但碰巧得到正确答案的 Agent，在生产环境里是危险的——下一个任务它可能就交出一个错误答案，但你的评估系统什么都没发现。

这一点对 PM 理解 AI 产品的质量问题有直接含义：当我们说「测试了，效果不错」，我们测的是答案的质量，还是过程的可靠性？两者的差距，就是你的 AI 产品在生产里的意外故障率来源。Agent 的可信度不是由它的最好表现决定的，而是由它的最差过程决定的。

产品与商业

Ben Thompson（Ben's Bites）：「Design Words」——2 天 38 个会话 381M token，帮非设计师向 AI Agent 说清楚视觉风格

Ben Thompson 这期 Ben's Bites 不是资讯，是一份过程实录。他想解决一个具体问题：非设计师在用 AI Agent 生成网站或工具时，总是拿到同一批「AI 训练出来的默认风格」，因为他们不知道怎么用设计语言描述自己想要的东西。他花 2 天、用 Pi 头脑风暴、Factory Droid 构建、GLM 5.3 和 Fable 5.1 混用，累计生成了 11 个原型版本，最终做出「Design Words」：用户选择布局类型、圆角幅度、阴影、调色板、字体风格等参数，网站实时生成对应视觉样例，并提供一个可复制的文字描述，直接粘贴到 Agent 的指令里。

最值得停下来看的，不是工具本身，而是他构建过程里的那些真实困惑。他多次重复「我不知道这东西对不对」「方向是不是错了」，用「让它好一万倍」这样的 prompt 逼 Agent 从侧面给他反馈。他混用开源模型（GLM 5.3、DeepSeek V4 Flash）来控制 token 成本，用 Opus 5 子 Agent 做设计批评，用 Luna 在浏览器里直接测验 UI。整个过程里 Fable 5.1 只在「需要更大视野重新设计 UX」时上场，其余用更便宜的模型跑细节。

这篇文章最有价值的副产品是一种工作方法：用批评 prompt（「对它做残忍的诚实评价」）、「好10倍/好1000倍」的激进迭代指令，以及「新鲜上下文的子 Agent」来推翻自己的判断惯性。AI 辅助产品开发的难题不在于写 prompt，在于知道什么时候推翻已有原型、什么时候在现有基础上加注——而这需要你一直在做、不能只是在规划。

GPT-Live-1 API 上线：全双工语音 AI，听和说同时进行，前端每分钟 $0.05，Speak 报告中断率降低 80%

OpenAI 正式向开发者开放 GPT-Live-1 API。关键能力是「全双工」（full-duplex，语音双向实时传输，和电话一样说话同时也在听，不像对讲机必须轮流）：GPT-Live-1 在说话的时候同时处理用户的语音输入，当你打断它，它能立刻感知并调整，不再出现传统语音 AI 里「我已经说到一半了，你打断我我还是要说完」的割裂感。这是通过单一模型同时推理输入输出语音实现的，而不是把「语音识别 → 语言模型 → 语音合成」三个模块串在一起。

定价结构：前端语音层每分钟 $0.05，背后调用的语言模型（Astra、Codex 等）另行计费。Speak 语言学习 App 是早期合作伙伴，报告中断率（用户意图说话但被 AI 抢话的情况）降低了约 80%，让语言学习者有更多时间整理语言而不用担心 AI 「话赶话」。开发者可以通过 system prompt 定义 Agent 的语气、语速和对话风格。Devin 已经基于此推出「Devin Voice」：用语音告诉 Devin 要做什么，它直接开始写代码。

Boris Cherny（Anthropic Claude Code）：原型可以完全黑盒，生产 AI 代码不能——「自主生成」和「可生产」是两套标准

Boris Cherny（Claude Code 创始工程师，现 Anthropic）在 X 分享了他对 AI 生成代码质量标准的判断：给原型用的代码，完全可以是「黑盒」，没有测试、没有注释、结构混乱，只要能跑通想法就够了；但要进入生产环境，AI 代码必须经过和人类代码同等的审查——测试覆盖、Code Review（代码审查，一个或多个工程师逐行检查新代码的流程）、自动化安全扫描，缺一不可。他本人已经八个月没有手写一行代码，Claude Code 用 Claude Code 写自己，但这不意味着生产标准可以降低。

这个区分有现实意义：很多团队现在用 AI 写代码之后，直接把原型版直接推进产品——因为「AI 写的」给了他们一种错误的安全感，或者流程没跟上速度。Cherny 从 Anthropic 内部的视角给出了一条清晰的线：用 AI 加速，不等于绕过工程标准。AI 生成代码和 AI 部署代码之间，缺的那一步正是传统工程团队维持质量的那整套流程，不是技术问题，是纪律问题。

AI 进展

DriftNet：轻量双头 Transformer 检测 Agent 轨迹中的 Prompt 注入，不到 200 万参数，无需访问模型内部

现状：间接 Prompt 注入（indirect prompt injection，攻击者通过污染 Agent 会读到的外部内容来劫持 Agent 行为，而不是直接操控用户输入）已经成为 AI Agent 部署的核心安全威胁。现有防御方案要么需要访问模型内部（不可行于 API 接入场景），要么重新执行任务（成本极高）。

问题：如何在只有 Agent 日志（工具调用历史记录）的条件下，一次性判断：这个 Agent 轨迹是否被攻击、攻击发生在哪一步、哪些步骤受到污染？

解决方案：DriftNet 把 Agent 的工具调用序列序列化为文本，用冻结的句子编码器嵌入，经过不超过三层 Transformer 后产生两个输出头：一个做整体分类（受攻击 / 未受攻击），另一个对每一步标注四类标签（正常 / 注入点 / 被劫持 / 注入失败）。在 AgentDrift 基准（71,024 个步骤标注）上，DriftNet 是首个产生此类联合输出的监督检测器，总参数量不到 200 万，比当前 LLM 规模的防护方案小三个数量级。

价值：让 Prompt 注入检测从「需要访问模型内部」变成「只需要日志」，大幅降低了现有 Agent 系统的安全审计成本，且可以部署在任何基于 API 的 Agent 工作流之外。

未来方向：随着 Agent 系统被授予越来越多的生产权限（文件操作、网络请求、代码执行），Prompt 注入的潜在危害面也在扩大，轻量可部署的检测层将成为 Agent 架构的标准组件。

arXiv 2609.10892

AgentIdeaBench：33 个 LLM、40 个子领域的科学构想能力基准，引入「科学世界建模」评测假设生成

现状：OpenAI 用约一万个 Agent 在 88 小时内宣称逼近了纳维-斯托克斯问题的证明——科学发现正在成为 AI Agent 的新战场。但现有基准（benchmark，指用来衡量模型表现的标准测试集）对「AI 能否产生新科学构想」的测量方式太粗糙，要么只测最终答案，要么覆盖面太窄。

问题：如何系统地评估 AI 在不同学科、不同阶段的科学构想能力，包括既能提出假设、又能主动探索来验证和完善假设？

解决方案：AgentIdeaBench 覆盖 5 个学科领域、40 个细分子领域，对 33 个主流 LLM 进行测试。独特之处在于「科学世界建模」（Scientific World Modeling）机制：模型在提出假设草案之后，可以通过结构化思想实验（有点像文献中的「假如这个假设成立，那么应该能观察到…」推演）主动精化和修正构想，而不只是一次性生成。评估框架使用多维度文献验证评分，而不是纯粹的人工打分。

价值：为「AI 是否在科学发现上真正有用」提供了跨学科、可复现、多维度的测量工具。

未来方向：随着 AI 辅助科研成为现实，「AI 构想能力」将从学术讨论变成研究机构选型的实际评估指标。

arXiv 2609.07611

EULER：带证据验证的多 Agent 数学发现框架，用「探索未用链接」推进协作证明

现状：纳维-斯托克斯等数学难题的 AI 求解，目前主要依赖海量 Agent 并行搜索。但「并行暴力搜索」和「有结构的数学推导」之间存在巨大差距——后者需要多个 Agent 在推理链上相互校验，而不只是各跑各的。

问题：在多 Agent 协作数学推理中，如何避免「一个 Agent 的错误推论传染给整个协作过程」？

解决方案：EULER（Exploring Underused Links with Evidence-Checked Return）在每个 Agent 生成推理步骤之后，强制执行一个证据验证（evidence-checked return）环节：其他 Agent 独立检查该步骤的推理证据，验证通过才能被纳入共享推理链。「探索未用链接」指框架会主动搜索当前推理图里还未被充分利用的连接，引导 Agent 往尚未探索的方向推进。

价值：比纯粹的单 Agent 搜索在复杂数学推理上更可靠，同时比无验证机制的多 Agent 协作更不容易累积错误。

未来方向：如果多 Agent 数学框架能提供有说服力的证明步骤（而不只是宣布答案），AI 在数学发现里的角色才会从「自动搜索机器」升格为「推理合作者」。

Stealing Reasoning Traces from Proprietary LLM APIs：从闭源 API 提取推理轨迹，揭示知识蒸馏的新边界

现状：主流的顶级模型（GPT-6 Astra、Fable 5.1 等）通过 API 提供服务，不公开权重或推理过程。闭源模型的能力边界，以往只能通过输入输出对（input-output pairs）来蒸馏（distillation，用大模型的输出来训练小模型）——Anthropic 今天的威胁报告就记录了 7 家中国实验室的蒸馏行为。

问题：如果能直接从 API 提取推理轨迹（reasoning traces，推理型模型在给出最终答案前生成的思维链过程），蒸馏的质量将大幅超越基于输入输出对的传统方法。这在技术上可行吗？

解决方案：研究者展示了通过精心设计的查询序列，可以从推理型 LLM API 中提取具有统计显著性的推理轨迹特征，进而用于训练更小的开源模型，使其在推理能力上超越了单纯用输入输出对蒸馏的版本。实验覆盖多个闭源推理模型 API。

价值：为「API 调用即数据集」的蒸馏攻击（这正是 Anthropic 今日点名的行为的学术版本）提供了可复现的方法论。

未来方向：如果推理轨迹提取变得廉价和普遍，闭源模型的竞争护城河将比现在更浅——这既是商业威胁，也是模型治理需要面对的新维度。

VWG-Bench：视频生成模型的视频推理评估基准，9 个维度 38 个细粒度任务

现状：视频生成模型（以 Sora、Wan2.2 等为代表）已经能产生高度逼真的视频，但「好看」和「理解视频内容中的时间关系、物理规律、因果链条」是不同的能力。现有图像评估框架直接套用于视频会丢失大量时间维度信息。

问题：如何系统评估视频生成模型「是否真正理解视频推理」，而不只是看生成质量高不高？

解决方案：VWG-Bench（Video-with-Generation Benchmark）从 9 个推理维度（包括时序理解、物理合理性、因果推断、空间关系等）展开 38 个细粒度任务，同时覆盖模型作为生成器和作为评估者（critique）两个角色。基准包含配对的视频问答对，测试模型在生成之后是否有能力判断自己的输出是否符合逻辑。

价值：填补了视频生成模型在「生成能力 vs. 推理能力」评估上的空白，为视频生成 Agent 的开发者提供更细粒度的能力地图。

未来方向：视频生成模型从「创意工具」走向「世界模型」（可以预测未来帧并回答反事实问题），需要的不只是生成质量，而是真实的时间推理能力——这个基准是测量这段距离的起点。
