Sol 自我优化：OpenAI 用 Sol 改进 Sol，成本降20%，ARC-AGI-3 登顶背后有测评争议

OpenAI 公布了一项自我改进实验：用 GPT-5.6 Sol 模型来优化 Sol 自身的推理效率，结果是服务成本降低20%、token（模型处理单元）生成效率提升15%以上。与此同时，Sol 宣告登顶 ARC-AGI-3 基准测试（一个设计用来衡量 AI 通用推理能力的评测集）。但有一个重要注解：OpenAI 称官方测评框架存在两个缺陷——每轮重置推理状态，并关闭了上下文压缩——这两个问题叠加让 Sol 的得分从原始 13.3% 暴增至 38.3%，输出 token 数同时减少6倍。换言之，成绩提升很大程度上来自修复测评框架，而非模型本身的突破。

「用自己优化自己」是个值得跟踪的信号；但 ARC-AGI-3 的数字目前无法用于跨模型横向比较，需要等待统一框架。

AI 方向观点

Fable 是 CEO，Opus 5 是高级工程师：Anthropic 的模型正在形成公司 org chart

Every 的 Context Window 本期核心观察：工程师 Marcus Moretti 开始用公司组织架构来描述 Anthropic 的模型体系——Fable 5（最高级 orchestrator，即任务总指挥）是 CEO，Opus 5 是高级工程师，Sonnet 5 是初级分析师。Every 平台负责人 Willie Williams 称这标志着行业从「昂贵的全能型模型」转向「混合模型体系」：不同模型负责不同岗位，擅长写作的不一定擅长调试，擅长协调的不适合执行细节。

更有趣的是另一个副产品：沃顿商学院教授 Ethan Mollick 发现，在长时间运行的 Fable 任务中，模型间通信会自发形成一种「Claudish」方言——进度报告压缩为标签、片段和技术简写，读起来像乱码。Every 咨询负责人 Natalia Quintero 用 Fable 分析大型数据集后说，子 agent（子任务执行模型）的报告「就像在读天书」。

一个未经证实但合理的推论：Anthropic 训练 Opus 5 时可能主要把 Fable 作为受众——如果对话对象是另一个模型，人类觉得刺耳的语言习惯其实无所谓。这解释了为什么 Opus 5 在人类用户眼中有时显得「难相处」。模型专业化提升了成本效率，但同时制造了一个新问题：AI 写给 AI 的语言，被人类读到了。

产品与商业

纯银：产品的边界到底是什么——先收集信号，再判断边界，绝不能反过来

纯银这期谈的是一个 PM 最容易踩的坑：把产品边界画在商业目标上，而不是用户信号上。他给出的定义是：「产品边界 = 用户特质与用户心智能够泛化到哪一片需求市场」。小红书以女性购物起家，女性密度如此高，当初他也以为男性进不去——但更高一层的抽象是「低创作与消费成本的算法驱动平台」，男性因此也沦陷了。这是边界在真实用户行为驱动下自然延展的案例。

反面教材：支付宝做社交屡败，抖音做社交屡败——从内容延伸到社交，用户心智很难迁移，反而会因为导流不精准污染社交产品的匹配效率。例外是拼多多在自家生态内做视频 tab——下沉用户（时间廉价、贪小便宜）加上带货-红包的电商闭环，让它成立。没有这类用户基础的平台照抄则失效。

判断边界的唯一方法：「先收集信号，再判断边界。信号越弱，对边界的信心越弱，可以谨慎尝试，不能万岁冲锋。如果不是基于信号，而是基于公司的商业目标去画边界，则九死一生。」他以自己当年被要求冲垂直赛道小红书为例——那几年垂直赛道小红书整个行业全军覆没，一家都没有跑出来。产品边界不是你想要在哪里成功，而是用户的真实行为告诉你能在哪里成功。

AI 进展

Skill Self-Play：让 LLM 通过「技能共演进」持续突破自身能力边界

现状：现有 LLM 能力提升大多依赖人工设计的课程或固定数据集，模型无法主动发现并填补自身的能力盲区。

问题：静态训练数据的覆盖边界即是模型能力的天花板，且人工构造高质量训练样本的成本极高。

解决方案：Skill Self-Play（arXiv:2607.22529）提出一个三方协作的共演进框架：Proposer（提案者）生成新技能挑战，Solver（求解者）尝试解决，Dynamic Skill Controller（动态技能控制器）管理整个演进循环——三者通过强化学习（RL，一种让模型从自身试错经验中学习的训练方式）持续迭代，无需人工干预。

价值：模型可以自主发现自己的薄弱点并生成针对性训练样本，让能力边界持续外推，突破固定数据集的限制。

未来方向：这一范式如果成立，意味着模型训练可以部分「自给自足」——从数据消耗者变成数据生成者，训练成本结构将发生根本变化。

arXiv 2607.22529 · HuggingFace

Molt：让 agentic 强化学习研究不再被框架拖累的 PyTorch 原生训练系统

现状：Agentic RL（强化学习，agentic 即让模型执行多步骤任务的训练范式）研究需要持续修改算法、测试新估计器、设计新 rollout（让模型完整运行一次任务的过程）方案，主流框架（如 Megatron）的层层封装让每次改动都要「穿越」多层代码。

问题：研究工具反而成为研究的摩擦点：框架越重，改动越难，研究速度越慢。

解决方案：Molt（arXiv:2607.21653）重新设计了一个 PyTorch 原生的轻量框架——代码紧凑到「研究者可以整个记在脑子里，AI 编程助手可以一次性读完并推理」。它采用单一异步训练循环，支持多模态和混合专家（mixture-of-experts，一种让不同模块处理不同任务的模型结构）策略，且只在模型自己生成的 token 上训练，避免污染。

价值：在同等异步协议下，Molt 的性能与基于 Megatron 的最优框架统计上相当，但代码量和理解门槛大幅降低，研究迭代速度随之提升。

未来方向：更易修改的训练框架是 agentic RL 快速演进的基础设施，直接加速从学术研究到产品落地的转化速度。

arXiv 2607.21653 · HuggingFace

DataPrep-Bench：LLM 能否胜任训练数据准备这份工作？第一个系统性基准来了

现状：训练数据的质量直接决定模型能力上限，但「数据准备」这一环节（清洗、去重、格式化、筛选）长期依赖人工或规则脚本，效率低且难以规模化。

问题：LLM 是否能承担数据准备工作，此前缺乏严格的系统性评测——没有标准就没有优化方向。

解决方案：DataPrep-Bench（arXiv:2607.20465）设计了一套公平竞技场：所有参评 LLM 使用相同的原始数据源，输出的训练数据再用于微调一个基础模型，以下游模型性能作为最终评分标准——评的是数据质量，不是 LLM 的文字输出。

价值：首次把「LLM 作为数据工厂」这一实践转化为可量化的研究问题，让后续改进有据可循。

未来方向：如果 LLM 能稳定胜任数据准备，AI 训练流水线将进一步自动化，人工干预点继续减少。

arXiv 2607.20465 · HuggingFace

DataFlow-Harness：用 MCP 和代码 Agent 搭建可编辑数据管道，93% 端到端通过率

现状：数据工程管道（data pipeline，即从原始数据到可用数据的处理流程）的构建和维护高度依赖专业工程师，改动成本高，复用性差。

问题：LLM 生成的自由格式脚本（free-form script）难以在可视化工具中编辑，也难以与现有工程基础设施对接。

解决方案：DataFlow-Harness（arXiv:2607.16617）引导 LLM Agent 通过类型化的增量变更（typed incremental mutations）来构建有向无环图（DAG，数据管道的标准表达形式）——而非生成脚本。系统集成了 MCP 层（Model Context Protocol，让 Agent 实时感知管道当前状态），并提供 DataFlow-WebUI 让对话式构建与可视化 DAG 编辑器同步。在12个数据工程任务上，端到端通过率达93.3%。

价值：把 Agent 的语言能力嵌入数据工程的标准工具链，让非专业工程师也能维护生产级数据管道。

未来方向：可编辑、可审计的 Agent 数据管道是企业 AI 合规需求的基础——谁解决了「Agent 改了什么」的溯源问题，谁就拿到了企业数据市场的入场券。

arXiv 2607.16617 · HuggingFace

Mage-VL：视频 token 减少75%，多模态推理速度提升3.5倍，精度不降

现状：多模态 LLM（能同时理解文字、图像、视频等输入的大模型）在处理视频时消耗大量 token（模型处理单元），推理成本和延迟极高。

问题：现有视频编码方式对帧做均匀采样，不区分动态区域和静态背景——大量 token 被浪费在信息量低的区域。

解决方案：Mage-VL（arXiv:2607.24904）引入定制编码器 Mage-ViT，通过运动向量（motion vector）和残差能量（residual energy）识别动态、信息密集的区域，只对这些区域进行精细编码，其余区域用稀疏表示压缩。模型从零训练，使用约5.6亿张无标注图像和1亿帧视频，Mage-ViT 在多个评测上达到或超过用数十亿图文对训练的旗舰编码器。

价值：Mage-VL-4B（4B 参数规模）在静态任务上与 Qwen3-VL-4B 相当，在视频理解和2D/3D空间推理上有明显提升，同时实现3.5倍墙钟推理加速（即实际运行时间缩短3.5倍）。

未来方向：视觉 token 的动态预算分配正在成为多模态推理的核心优化方向——与昨日 OmniDelta 的技能驱动压缩思路互补，共同构成「按需分配计算资源」的新框架。
