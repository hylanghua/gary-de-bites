OpenAI 通用推理模型推翻 Erdős 1946 年单位距离猜想

OpenAI 宣布，内部一个通用推理模型（speculated GPT-5.6，不是 AlphaProof 或 Lean 等专用数学工具）自主发现了平面单位距离问题（planar unit distance problem，即在平面上 n 个点之间距离恰好为 1 的最多点对数量问题）的新反例构造族，推翻了数学界 80 年来认为最优解是类网格排列的主流信念。推理链输出约 125 页，计算花费不足 1000 美元，耗时不足 32 小时。Fields 奖得主 Timothy Gowers 评价称，这是"AI 首次清楚解决一个有名的数学开放问题"，外部数学家已独立验证结果。研究者 Hongxun Wu 把它定性为推理 LLM（大语言模型的推理版本）在"最难问题上"的内部里程碑。OpenAI 同时强调这一模型尚未推到极限，计划未来面向公众发布。

技术注脚：这是一个反例（disproof），而非正向证明——说明之前认为"最好解就是网格式排列"的假设是错的，并给出了更好的构造。社区讨论焦点是推理时计算（test-time compute，即让模型在回答时花更多计算量深度推理）作为当下进展主要动力的证据又添一条。

AI 方向观点

Dan Shipper（Every CEO）：《After Automation》——AI 越进步，人的工作反而越多

Dan Shipper 今日发布长报告《After Automation》，核心论点反常识：Every 把能自动化的都自动化了，Agent（AI 自主操作工具）写代码、起草邮件、做客服、整理 newsletter，但人的工作总量比以前更大，不是更小。他的解释是：廉价能力大量涌入之后，产生的是"同质化"（sameness）——当所有人都能用 AI 高效完成同样的事，差异化的压力反而转移到了人的判断力、框架和品味上。人始终需要给 AI "定帧"（hand it a new frame），这个定帧动作本身不会被自动化。

报告以 Every 内部实践为案例：用 benchmark 衡量哪个 Agent 有效，做 prompt engineering（提示词工程，即精心设计给 AI 的指令以提升输出质量），弄清"人在结构上保持领先"意味着什么。Shipper 说报告是 agent-native 的，可以直接丢进 Claude 或 Codex 辩论。

自动化降低了执行门槛，但也升高了判断力门槛——人在 AI 时代的核心竞争力，是决定什么值得让 AI 去做。 Every

产品与商业

Aaron Levie（Box CEO）：Agent 落地的最大阻力不是技术，是变革管理

Levie 今日发布长推，总结他与多位企业 CIO（首席信息官）和 FDE（field deployment engineer，企业现场部署工程师）交流后的观察：大公司推进 Agent 的最大难点不是模型能力，而是"技术实施与变革管理的双重要求"。模型快速迭代意味着企业需要不断重新评估工作流设计，而这触动了组织习惯和岗位定义，远比典型的 IT 工具采购复杂。

换句话说：企业 AI 从"买模型"进入了"部署 agent、管理流程变化"的阶段，CIO 们的核心压力从"技术选型"变成了"人和流程跟上技术"。这和昨日他提到的 token 成本可见性话题形成了完整的企业 AI 运营画像：算力可见、流程可管、组织可变。

Agent 落地最终是组织问题，不是技术问题——这个认知在大公司 CIO 圈子里刚刚开始普及。 X @levie

Dan Shipper：Anthropic 收购 Stainless，MCP Server 的设计哲学是"少即是多"

Dan Shipper 今日讨论 Anthropic 收购 Stainless API（一个专注 API/SDK 设计工具的公司）的意义，并延伸到 MCP Server（Model Context Protocol，模型上下文协议，一种让 AI 模型标准化接入外部工具的规范）的设计方向。他的核心观点：好的 MCP server 应当"lean and precise"（精简而精确），减少工具数量比增加工具更难，每个工具的定义要精确到模型能准确判断"什么时候用它"。

这个洞察对 PM 和 builder 都有实际价值：给 AI 设计工具集和给人设计功能集的逻辑是相反的——人喜欢全，AI 喜欢精。堆功能会让 agent 迷失，砍功能才能让 agent 可靠。

MCP Server 的设计哲学是反直觉的：给 AI 的工具集越精简，agent 的行为越可控。 X @danshipper

AI 进展

OpenAI GPT-next：自主反驳 Erdős 平面单位距离猜想

现状：平面单位距离问题（planar unit distance problem）由数学家 Erdős 于 1946 年提出，询问 n 个平面点之间距离恰好为 1 的点对数量上界，数学界 80 年来普遍认为最优构造是类网格排列（square-grid-style）。

问题：这一信念从未被证明也从未被打破，直至今日。

解决方案：OpenAI 内部一个通用推理 LLM（speculated GPT 5.6，不是 AlphaProof 等专用数学 AI）自主发现了一组新构造族，改进了现有最优界，推翻了"网格是最优"的假设，生成约 125 页推理输出，计算成本不足 $1000，耗时不足 32 小时。

价值：Fields 奖得主 Gowers 和多位数学家独立验证结果成立。这是通用 LLM（而非专用定理证明器）首次在有名的经典开放问题上给出经外部验证的新数学成果，验证了推理时计算（test-time compute）作为科研加速器的可行性。

未来方向：OpenAI 表示模型尚未达到极限，计划面向公众发布；社区认为这对形式化科学和数学的 AI 加速有直接外推意义。

Google Gemini Omni：面向任意输入/任意输出的多模态世界模型

现状：现有视频生成模型（如 Veo、Sora）主要处理静态生成任务，缺乏对场景物理、历史和文化上下文的深度推理能力。

问题：视频 AI 的生成-理解-编辑能力分散在不同系统，用户无法在单一模型内完成互动式视频创作。

解决方案：Gemini Omni 是一个多模态世界模型，首个版本 Gemini Omni Flash 专注视频生成和会话式视频编辑，能推理"场景里下一步应该发生什么"，整合 Gemini 对历史、科学和文化的广域理解。DeepMind CEO Demis Hassabis 称这是迈向 AGI 的重要一步，未来版本目标是处理"任意输入/任意输出"。

价值：将视频生成从"文字转画面"升级为"推理驱动的交互式创作"，标志着视频 AI 进入可对话、可编辑、懂上下文的新阶段。

未来方向：Google 同步测试 AI 虚拟形象生成，Omni 系列向更多模态组合扩展。

AI Valley · Ben's Bites

Gemini 3.5 Flash：前沿推理能力 + 4 倍速 + 多步工具调用

现状：Gemini 3 Flash 在速度与推理能力之间有明显取舍；企业 agent 工作流需要可以持续处理长任务的模型。

问题：之前的 Flash 模型推理能力（特别是多步骤任务和代码能力）与 Pro 系列有明显差距，且知识截止较早。

解决方案：Gemini 3.5 Flash GA（正式可用），4 个思考强度挡位（minimal/low/medium/high）+ 跨轮次思维保留（让模型在多轮对话中记住推理过程）+ 1M token 上下文 + multimodal function responses（多模态函数响应）+ 代码执行与图像结合。Artificial Analysis 测试：Intelligence Index 55 分（比 Gemini 3 Flash 高 9 分），MMMU-Pro 得 84%，代码 Arena 排名第 9。

价值：以 Flash 的速度（声称比同等前沿模型快 4 倍）提供接近 Pro 的推理水平，适合企业 agent 的长跑任务；Shopify、Salesforce、Databricks 已开始 piloting。

未来方向：知识截止仍是 2025 年 1 月（不含 vibe coding 及以后），3.5 Pro 预计下月发布。

Figma 设计 Agent：在画布内生成多方向、批量编辑、遵循设计系统

Ben's Bites

Basis：把 Monorepo 改造成对 Agent 友好的代码库需要 3 个月 + 3 条原则

现状：代码 agent（AI 自动写/改代码的工具）有自己的失败模式：上下文窗口有限、对代码结构有特定偏好、需要明确的规范才能可靠执行，现有 monorepo（把所有项目代码放在一个仓库）组织方式并非为此设计。

问题：把 agent 塞进已有代码库的效果往往不稳定，原因在于 agent 无法判断什么是"规范"、什么是例外，上下文质量决定输出质量。

解决方案：Basis 用 3 个月将 monorepo 重构为对 agent 友好的结构，三条核心原则：可验证性（agent 能自动测试自己的输出）、互操作性（模块之间的接口标准化）、规范上下文（canonical context，即把项目的隐性约定显式写进 agent 可读的位置）。

价值：重构后 agent 的可靠性显著提升；文章认为原则是非显然的，做这件事的工作量比预期大。

未来方向：代码库的"agent-ergonomics"（对 agent 的人体工程学）将成为工程团队的新型基础设施话题。
