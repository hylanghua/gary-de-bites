AI 方向观点

Benedict Evans：AI 就是 1997 年的互联网，价值最终不在模型层而在分发层

a16z 前分析师 Benedict Evans 接受 Lenny Rachitsky 采访，把一个混乱的议题掰开讲清楚了。他的核心框架：AI 和互联网、移动互联网一样大，但也仅此而已，不会更大。我们现在大约在 1997 年，浏览器已经出现，一切都在爆发，但 Amazon 要到 2004 年才盈利，Google 刚刚起步。

关于职位消失的争议，他提了一个更精准的问题：你干的是"任务（task）"还是"工作（job）"？AI 可以执行任务，但工作是由一组任务加上判断、关系和情境组成的，这两者的替代路径完全不同。他还指出，咨询公司（麦肯锡、埃森哲）反而在 AI 时代迎来增长，因为企业需要有人帮他们消化和落地这波技术浪潮。

关于价值分配，他认为随着软件构建成本暴跌，分发能力（谁能触达用户）和场景嵌入深度会成为护城河，而非模型本身。最终赢家不是最聪明的模型，是最难被绕过的入口。

Lenny's Newsletter

Peter Steinberger（PSPDFKit 创始人，OpenClaw）："Yielding agents is a skill"

Peter Steinberger 过去以独立开发者身份构建 PSPDFKit 而知名，现在他的精力已经完全转向 AI agent 工程。他的最新观察：把 GPT 5.5、/goal 指令、autoreview（自动代码审查循环）和 crabbox（一个在 AWS / Hetzner 上快速启动临时沙盒机器的工具，让 agent 在干净环境里执行任务）四个工具组合在一起，他的单次编码任务时长从原来的 30–60 分钟提升到了经常 4–10 小时，而且对输出结果的信心也明显更高。

"Yielding agents"（驾驭 agent）是他自造的说法，意思是让多个 agent 依次接力、相互验证，而不是靠一次大 prompt 一次性出结果。他另一条获得近 2700 个赞的推文进一步说明了心态变化：告诉 Codex"代码里有 bug"，它会不停循环查找；只告诉它"看一下有没有 bug"，它会说没有然后停下来。提问方式决定了 agent 的执行深度。把 AI agent 当工具用，效果天花板低；把它当实习生培训，结果天差地别。

Guillermo Rauch（Vercel CEO）：用不用 AI 不重要，做最好的产品才是护城河

Rauch 用一句话打掉了整场"AI 化程度"竞赛的错误框架："Ship the best product. Use lots of AI, some AI, maybe no AI. Just be the best."（发布最好的产品。大量用 AI、适量用 AI、也许完全不用 AI。做到最好就行。）这条推文 2599 个赞，转发 236 次，引发了不少共鸣。

背后的逻辑：当下许多团队的精力耗在了"我们是 AI-first 还是 AI-native"的定义争论上，而用户评判产品的标准从来只有一个：好不好用。AI 是手段，产品质量才是目的。把 AI 用量当竞争指标，是把方法论当成了产品本身。

Aaron Levie（Box CEO）：大企业不是靠 AI 裁人，而是把省出来的预算重新投入增长

Levie 在观察到一个反直觉的现象后写了这条长推：他与大量 CIO、CTO、CEO 对话后发现，大多数大企业要么因 AI 在新职能上增加招聘（Forward Deployed Engineer、AI 工程师等），要么把效率提升省出来的钱重新投进销售、营销和客户成功。高盛 CEO David Solomon 在《纽约时报》的观点文章中也表达了类似判断。

他的核心洞察：绝大多数企业过去都被限制性约束着，比如"能生产多少软件"、"能招多少销售"、"能跑多少营销活动"。AI 让这些约束松动后，钱不会凭空消失，而是流向了之前被压抑的需求。专注于省钱的公司长期反而跑输，专注于用 AI 服务好客户的公司才会赢。AI 提效的果实不是裁员指标，是企业长期积压的增长意志被重新释放。

人文与哲学

Packy McCormick：AI 时代，差异化是道德义务

Not Boring 的 Packy McCormick 花了很长时间查阅佛教、基督教、伊斯兰教、犹太教、印度教、以及维克多·弗兰克尔（《活出意义来》作者，纳粹集中营幸存者）、甚至一个在迷幻剂研究中突破的科学家，问同一个问题：AI 把越来越多的事情交给机器后，人的意义感从哪里来？

他发现所有这些传统的答案出奇地一致：你是宇宙体验自身的一个碎片。这强加给你一项义务：成为你最完整、最奇异、最不可替代的版本。他的结论翻译过来是：在一个 AI 可以无限量生产平均水准的内容和判断的世界里，做独特的自己不只是个人策略，更是对存在本身负责。

文章标题"Riding the Leopard"来自 Giuseppe Tomasi di Lampedusa 的小说，意思是骑上了一只豹子，已经不能轻松跳下来，只能学着与它共处。AI 时代最奢侈的东西不是算力，是那个没有办法被替换掉的你。

Wisereads Vol. 145 · Not Boring

Aditya Agarwal：印度城市为什么只生一个，答案和你想的不一样

South Park Commons 合伙人 Aditya Agarwal（前 Dropbox CTO）观察到：他在印度交谈的大多数人只有一个孩子，有些有两个，极少三个。他告诉他们自己有三个孩子时，对方的第一反应是惊讶，然后说"哦，意外吧"。背后的原因不是经济负担，是在大城市的核家族结构下，养孩子的真实成本是时间和精力，这比金钱更稀缺。

这个观察折射出一个更宏观的问题：当一个社会的生产力越来越高、物质越来越充裕，决定人口生育意愿的那根弦已经不是"养得起养不起"，而是"有没有人手和心力"。经济发展到一定程度，孩子的成本从金钱变成了你唯一不能外包的东西：陪伴。

AI 进展

SkillOpt：让 agent 的 skill 文件像模型权重一样被优化

现状：AI agent 的 skill（技能）通常靠人手写、一次性生成或松散自修改，没有像深度学习训练模型权重那样被系统优化的机制。

问题：手工 skill 的质量天花板低，一旦任务变复杂就迅速失效，且很难跨模型、跨环境迁移。

解决方案：Microsoft Research 的 SkillOpt 把 agent 的纯文本 skill 文件当作"可训练参数"，通过轨迹驱动编辑（trajectory-driven edits）、验证门控更新（validation-gated updates）来迭代优化，模型本身保持冻结。优化后的成果是一个可部署的 best_skill.md 文件。

价值：在 6 个 benchmark、7 个目标模型、3 种执行环境（直接对话、Codex agentic loop、Claude Code）的 52 个评测格上全胜所有对手。GPT-5.5 上平均准确率提升 +23.5 分（直接对话）、+24.8 分（Codex）、+19.1 分（Claude Code）。

未来方向：优化后的 skill 可以跨模型尺度迁移，在 Codex 和 Claude Code 之间互换，还能迁移到相邻 math benchmark 上而无需重新优化。

arXiv 2605.23904 · HuggingFace

PaperMind：测试多模态 LLM 在科学论文上的 agent 推理能力

现状：主流多模态 LLM benchmark 聚焦于日常图像理解，缺乏对科学论文中复杂图表、推导和跨段落推理的系统评测。

问题：现有模型声称的"科学理解能力"没有严格的 agentic 评测框架，难以区分真正的推理与表面模式匹配。

解决方案：PaperMind 构建了一套以科学论文为语料的 benchmark，要求模型不只是回答问题，还要主动提出批判性质疑（critique），模拟同行评审的思维模式。

价值：为评测 AI 在科研辅助、论文审查、知识发现等高价值场景中的实际能力提供了更贴近真实工作的标准。

未来方向：框架设计支持动态难度扩展，可随模型能力提升自动调整考题难度。

arXiv 2604.21304

ViDoRe V3：多模态 RAG 的压力测试 — 26K 页、3099 查询、6 种语言

现状：RAG（检索增强生成，即让模型在回答时先从文档库里找到相关段落，再基于这些段落作答）评测长期依赖纯文本语料，忽视了真实文档中普遍存在的图表、表格和图像。

问题：现有多模态 RAG 评测规模小、语种单一，难以反映企业实际部署时遇到的复杂性。

解决方案：ViDoRe V3 覆盖 10 个专业领域的数据集，共 26000 页视觉丰富文档，配有 3099 条经人工核验的查询，每条查询提供 6 种语言版本，标注了 12000 小时人工注释，涵盖检索相关性、边界框定位和参考答案。

价值：提供了迄今为止最全面的多模态 RAG 评测基准，揭示了当前最强模型（含 GPT-5.2）在视觉检索上仍有显著差距。

未来方向：多语言、跨领域设计使其可直接用于企业级文档 AI 系统的选型评估。

arXiv 2601.08620

MMedAgent-RL：多 agent 协作让医疗推理 +23.6%

现状：医疗视觉问答（VQA，即给模型看医学影像并提问，评测其诊断推理能力）是 AI 落地医疗最重要的场景之一，但单模型在复杂多模态病例上容易出错。

问题：现有多 agent 框架缺乏针对医疗推理的专项优化，agent 之间的协作方式是手动规定而非训练出来的。

解决方案：MMedAgent-RL 用强化学习（RL）优化多个 agent 之间的协作策略，让 agent 学会在什么时候征询其他 agent 的意见，以及如何整合分歧意见。

价值：在 5 个标准医疗 VQA benchmark 上，相较于强基线平均提升 +23.6%，超越开源和闭源医疗 LLM。

未来方向：多 agent RL 框架有望泛化到其他需要多专家协作的高风险决策场景，如法律、金融分析。

arXiv 2506.00555

动态协议 vs 静态 Benchmark：让评测题目随 LLM 能力自动升难

现状：LLM 在静态 benchmark（一组固定题目）上的得分越来越高，很多 benchmark 已接近"饱和"，无法区分能力差异。

问题：静态 benchmark 一旦被模型"刷穿"，就失去了评测价值，研究者不得不不断制作新题库，形成"猫鼠游戏"。

解决方案：该研究提出以 agent 为中心的动态评测协议，把 LLM agent 嵌入异常检测任务中，任务难度随被测模型的能力自动缩放，强模型遇到更难的场景，弱模型遇到匹配其水平的场景。

价值：从根本上解决了静态 benchmark 饱和的问题，无需每隔几个月重新构建测试集。

未来方向：动态协议框架可扩展至任何需要持续评测快速迭代模型的领域，包括代码生成、推理和工具使用。
