Apple 正在研究如何让 AI agents 通过 App Store 审核

Apple 正在探索将 AI agents 纳入 App Store 的方式，同时维持其隐私和安全标准。AI agents（即能代表用户自主执行复杂任务的 AI 程序）的行为边界比传统 App 难以预判——App Store 规则原本设计用来防止恶意软件传播和规避分成，但 agents 可以动态决定要执行什么操作，这让静态审核规则失效。

Apple 的核心诉求是两全：让 agents 合法上架（守住 App Store 抽成收入），同时对 agents 的行为保持足够控制权（保住隐私和安全品牌）。这两个目标本质上存在张力，如何解决将直接决定 Apple 生态能接纳什么样的 AI agent 产品。

Apple 的 agents 策略核心是维权而非拥抱——App Store 30% 抽成要守住，但 agents 的行为边界是没有现成答案的硬题。 TLDR

Amazon 关闭 Rufus 聊天机器人，All-in Alexa Shopping Agent

Amazon 正式将 Alexa 定位为 AI 购物战略的唯一核心，推出 Alexa for Shopping：一个能回答问题、代替用户执行购物操作的 e-commerce bot（电商机器人）。它调用购物历史和个人数据提供个性化体验，不需要 Prime 会员即可使用。Rufus——此前独立运作的 AI 购物聊天机器人——被同步关闭。

Amazon 的逻辑是把分散的 AI 尝试收归一个统一入口，用 Alexa 这个已有巨大用户基础的品牌承载 agent 能力，而不是另起炉灶。这是 Amazon 在 AI 时代把产品矩阵做减法的信号。

Amazon 押注平台统一入口而非多产品并行——Alexa 的胜负关乎 Amazon 能不能在 AI 购物时代守住主场，不让答案跑到 ChatGPT 或 Perplexity 里去。 TLDR · AI Valley

Anthropic 企业采用率首超 OpenAI + 同日宣布 API 计量；OpenAI 立即推 Codex 两月免费切换优惠

swyx（Latent Space 创始人）：AI 竞争的赛道从"谁的模型更强"悄悄切换到"谁控制开发者工作流"

Anthropic 计量 programmatic usage 的新政策，第一反应是社区把它读成"缩水"——用 70-90% 折扣使用 Claude 的黄金时代结束了。但 swyx 的分析更冷静：这是 Anthropic 在 Claude Code 建立了足够品牌和黏性之后，把最优惠的定价锁定在自己的工具链内，不再为第三方工具的使用买单。他用"mandate equinox（指令赤道）"描述 Anthropic 和 OpenAI 之间交替领跑的 6 个月周期。

当下的格局：Claude Code 提升 50% 每周限额并延长至 7 月 13 日，Codex 则对企业切换者提供两个月免费。他的结论是："best model wins"是 2023 年的故事，2026 年的战场是：补贴 + 工作流控制 + harness 兼容性（harness 即 agent 的执行宿主环境，如 Claude Code 或 Codex 各自的 CLI）。企业客户迁移成本的主要构成已经从"迁移数据"变成"迁移工作流依赖关系"。

Anthropic 和 OpenAI 打的不是模型战，是开发者的肌肉记忆——谁的工具先让开发者习惯，谁就获得了比技术领先更难被替代的优势。 Latent Space / AINews

纯银 Vol.20260514：心生一计到底是什么产品？"记录一生中会重复发生的事"

纯银在今日《产品分析·无限季》中重新审视自己开发的产品"心生一计"。他的问题直接：这款产品的核心服务是什么？不是日记（首发时的定性错了），不是笔记，不是打卡，不是手帐。他给出的最精确的答案是：记录一生中会重复发生的事。

一件事，如果在你的生命中会反复发生——某类吵架的模式、某种决策时的心理路径、某类情绪触发点——记录它的意义不在于回忆，而在于识别模式、提前准备、让下一次发生时更从容。这不是记录过去，而是为未来的自己建立索引。纯银同时谈到他现在对独立产品的看法：做一个真正属于自己定义的产品，前提是先想清楚它的服务是什么，而不是对标已有类型往里填功能。

"记录一生中会重复发生的事"——这一行定义比任何功能列表都更有说服力，这就是产品从特性集合进化为服务哲学的那一跳。 小报童 · 纯银

Ben Tossell：把屏幕录制扔给 agent，用视频直接做结构化反馈报告

Ben Tossell 在最新一期 Ben's Bites 分享了一个 agent 工作流新玩法：不再用文字或截图给 agent 提反馈意见，而是直接屏幕录制并配音，把整段视频文件交给 agent，让它自动生成一份 HTML 反馈报告——包括视频转录、链接时间戳的关键帧截图、以及一份 actions 待办清单。他把这个工作流压缩成了一个 Claude Code skill（可复用的 prompt 指令文件）：`video-to-html`。

好处是：可以在视频里直接导航到参考案例（"这就是我想要的效果"），agent 能从视频操作上下文生成 GIF 演示，而不只是文字描述。代价是 token 消耗高——他也提到可以用 ffmpeg 先剪出关键片段再喂给 agent，如果 token 成本是考量的话。

视频作为 agent 输入是被低估的交互方式——把"我想要什么"的上下文全编码进一段屏幕操作，远比写需求文档更诚实，也更难被误解。 Ben's Bites

AI 进展

Token Superposition Training：预训练速度 2.5×，无需改推理架构

现状：大型语言模型预训练成本极高——一次 10B 参数模型的预训练需要数周 GPU 时间，每一步算力都在计数。

问题：传统 next-token prediction（逐个预测下一个词）在预训练早期效率极低，模型要花大量计算处理"还没学会的低质量猜测"。

解决方案：Nous Research 的 Token Superposition Training（TST，arXiv:2605.06546）将预训练拆成两阶段：超级位阶段把连续的多个 token 打包成一个"bag"，用多热交叉熵（MCE，一种同时预测多个目标的损失函数）训练，显著提高早期训练的 FLOPs（计算量）利用率；恢复阶段切换回标准 next-token prediction。在 10B A1B 混合专家模型（MoE，即根据输入动态激活部分参数的稀疏架构）上，相同 FLOPs 预算下训练损失更低，wall-clock 时间节省约 60%，即约 2.5× 加速。已验证规模：270M 至 3B 密集模型，以及 10B A1B MoE。

价值：无需改变推理时的模型架构或 tokenizer，drop-in 替换预训练流程，开源社区可直接采用。

未来方向：2.5× 的预训练加速如果被广泛采用，意味着开源模型的实验周期大幅压缩——更多实验轮次，更快的迭代节奏，对算力资源有限的团队尤其有价值。

Multi-Stream LLMs：打破单线程瓶颈，并行思考/输入/输出流

现状：当前所有主流 LLM 训练的都是"单流"交互模式——模型在说话时不能思考，在阅读时不能行动，在行动时不能继续接收新输入。

问题：这个顺序等待的结构是 agent 任务中延迟和"上下文阻塞"的根源，不是模型智能不够，而是训练格式把并发能力锁死了。

解决方案：Jonas Geiping 团队（arXiv:2605.12460）提出将 instruction-tuning（指令微调，即教模型如何回应指令的训练方式）的格式从顺序消息流改为并行多流——模型同时维护独立的"思考流"、"输入流"、"输出流"，三者可并发运行。实验结果：延迟降低，推理与工具使用的可读性更强，因为推理和行动不再混在同一输出流里。代码已开源。

价值：对 agent 产品设计影响直接——"模型在执行操作时还能继续推理"意味着长链任务中的中间状态更稳定，更少因为等待 IO 而丢失上下文。

未来方向：多流架构可能成为 agent-native 模型（专为 agent 任务设计的模型）的基础范式，这篇论文是架构层面最清晰的早期信号之一。

δ-mem：冻结 attention 主干 + 在线联想记忆，平均分提升 1.10×

现状：大型语言模型的核心记忆机制（full attention，全注意力机制）随上下文长度增长，无法像人类记忆一样无限积累"新学到的东西"。

问题：想给模型增加持续学习能力，通常要微调（修改大量参数，成本极高），或者依赖外部 RAG 系统（检索增强生成，即先检索再拼接到提示词里，延迟高且不稳定）。

解决方案：declare-lab 的 δ-mem（arXiv:2605.12357）在冻结的全注意力主干旁边附加一个轻量级在线联想记忆模块——每次新 token 到来时，通过 delta-rule（增量学习规则）把信息写入一个紧凑的状态矩阵，不改动原模型参数。在 Qwen3-4B/8B 和 SmolLM3-3B 实验上，平均得分提升 1.10×，记忆密集型 benchmark 上提升 1.15×。

价值：冻结主干意味着部署时不用重新训练模型，记忆模块可以独立更新——是"给已有模型加记忆"的最轻量工程路径之一。

未来方向：在线记忆 + 冻结主干是让边缘设备（edge device，如手机、IoT 设备）上的小模型具备持续学习能力的关键方向。

HuggingFace · arXiv:2605.12357

NVIDIA Star Elastic (ICML 2026)：一次 post-training，同时得到 30B/23B/12B 三个推理模型

现状：训练大小不同的推理模型通常需要独立训练每个尺寸，成本随尺寸数量线性叠加，多数团队只维护 1-2 个 checkpoint（保存的模型权重文件）。

问题：不同场景对模型大小有不同需求——高精度场景用大模型，低延迟场景用小模型——但独立训练多个尺寸成本太高，让灵活部署成了奢侈品。

解决方案：NVIDIA Star Elastic（已接受 ICML 2026）把三个不同参数量的推理模型（30B、23B、12B）嵌套在同一个 checkpoint 里，通过约 160B token 的 post-training（即在预训练基础上的额外训练）一次性完成。应用于 Nemotron Nano v3（Mamba-Transformer-MoE 混合架构，30B 总参数、3.6B 活跃参数）后，额外得到 23B 和 12B 变体，无需额外训练。存储节省明显：分开存三个模型需 126.1GB，单 elastic checkpoint 只需 58.9GB。

价值：动态预算控制（如 23B 思考、30B 回答）在精度-延迟 Pareto 面上最高提升 16% 精度或 1.9× 速度；而相比从头预训练，token 消耗减少约 360×。

未来方向：弹性模型家族（elastic model family）可能成为企业部署推理模型的标配——不用每次换硬件就重新选模型。

SciResearcher：深度研究 agent 自动化前沿科学推理，AI 辅助科研向"参与推进"迈步

现状：科学研究任务需要跨领域多步骤推理，加上大量专业文献——这对单次调用的 LLM 来说几乎不可能完成。当前 AI 在科研辅助上主要停在"检索文献"和"总结摘要"。

问题：前沿科学推理要求"提出假设、设计实验、分析数据"，而不只是检索和总结。这需要 agent 能自主拆解任务、并行处理子问题、再整合结果。

解决方案：SciResearcher（arXiv:2605.01489）是全自动 agentic 框架，核心创新在于将科学任务自动拆解为概念性子任务（定义、推导、解释）和计算性子任务（数值计算、公式推导、代码验证），由不同专用 agent 并行处理后汇聚。这套数据构建流程同时产出了用于训练更好科研 agent 的数据集。

价值：在前沿科学推理 benchmark 上显著优于现有 LLM，在数学、物理领域展示了 agent 分解策略的可扩展性。

未来方向：AI 辅助科研的天花板不在于模型记住多少知识，而在于 agent 能否把科研工作流拆得足够细——SciResearcher 是目前最系统的工程实现之一，与同期成立的 Recursive AI 研究方向形成呼应。
