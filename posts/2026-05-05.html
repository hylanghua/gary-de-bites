AI 方向观点

"The Other vs The Utility"：Claude 是道德他者，GPT 是逻辑工具

OpenAI 员工 Roon 上周末发了一条引发广泛讨论的推文，夸赞 Claude 的同时点出了两个产品哲学的本质差异。他的核心观察：GPT（尤其是 4o 之前的版本）的灵魂被塑造成"工具"——人们使用它的方式，就像使用一把精心打磨的刀，欣赏但不会担心被它评判。Claude 则不同，它是一个"他者"（the Other），带有道德观念，有时会不同意你，有时会主动推回。

Roon 说，有朋友会把"不太体面的问题"专门拿去问 GPT，因为"没有他者，就没有评判"——你不会担心自己的车评判你开车方式。Latent Space 将这概括为 2026 年的 Clippy vs Anton 之争：AI 的灵魂应该是主动指引你的道德同伴，还是沉默顺从的执行装置？Claude 的模型规范（model spec）明确要求它在理解「善」与 Anthropic 的指令冲突时，必须作出异议——这在竞争对手那里是设计禁区，在 Anthropic 这里是设计核心。Anthropic 把 AI 的道德异议权写进了产品底层，这个选择正在产生用户关系上的真实分歧。

Latent Space AINews

Harness 才是护城河：上下文 pipeline 决定 agent 性能，模型权重不再是唯一变量

AINews 本期的技术主线：多个开发者记录了在不改动模型权重的前提下，仅通过调整 harness（agent 的"脚手架"，即控制它如何读取代码、压缩上下文、调用工具的外层系统）就大幅提升了 benchmark 成绩。其中最突出的数据：有人在 Terminal-Bench 2.0 上把 gpt-5.2-codex 从 52.8% 提升到 66.5%，只靠改变 prompt 和 middleware（处理 API 请求和响应的中间层代码）。

这个结论对产品策略有直接影响：真正的差异化不在于你用哪个模型，而在于你如何组装上下文——哪些代码片段进入 prompt、以什么顺序进入、怎么压缩、怎么记忆。这不是随时可以复制的参数，而是工程积累。Anthony Maio 的说法更直接：锁定用户的是上下文 pipeline 的质量，不是调用哪家 API。最先把 harness 工程化成护城河的公司，将在下一轮模型同质化里最从容。

Vikas Kansal（Google AI 产品负责人）：AI 订阅付费墙的三根支柱

传统 SaaS freemium（免费增值）的逻辑是：开放基础功能，锁住高级功能。Vikas Kansal 在 Google AI 订阅（Gemini Plus/Pro/Ultra）的实战中发现这个路径在 AI 产品里走不通——免费层级的模型已经"比大多数人更聪明"，用户根本没有理由付费升级。他和团队重新推导出三个付费触发逻辑。

第一根支柱：锁用量强度（gate usage intensity）。付费不是买更好的模型，而是买更高频次地使用它的权限，以及更大的上下文窗口（context window，即模型每次能"记住"多少内容）。Plus/Pro/Ultra 的分层就是用量分层，不是智能分层。第二根支柱：锁结果（gate outcomes）。Chrome 自动浏览功能（AI 自主在网页上填表、比价、预约）只对高级用户开放，因为"你买的是它省下的工时，不是它给的答案"。第三根支柱：锁最重的算力形态（gate heaviest compute modalities）。Genie 3（实时交互"世界模型"）仅对最高层开放，因为算力成本无法对普通用户摊薄，消费者本来就不期待这类功能免费。

最后，他们放弃了按模型质量分层的产品叙事，转向"我们卖的是工时，不是答案"。Intercom 的 Fin AI agent 按解决问题收费（$0.99/resolution），Sierra 同理——从卖算力到卖结果，是 AI 订阅的下一个方向。AI 付费墙设计的核心矛盾是：必须给得足够多，用户才能体验到魔法；但给得太多，他们就没有理由付费。唯一的出路是让付费解锁的不是质量，而是量和结果。

Guillermo Rauch（Vercel CEO）：`npx deepsec` — coding agent 的开源深度安全审计工具

Guillermo Rauch 宣布开源 deepsec，一个专为 coding agent 设计的安全扫描 orchestrator（协调器，负责统一调度多个 agent 任务的系统）。使用方式极简：在项目目录运行 `npx deepsec`，工具会自动启动多个安全审查 agent，在代码库里扫描漏洞。Rauch 说团队最初只是为了内部使用，在对几个主流开源项目运行过后，确信值得分享给整个社区。

安全审计一向是 code review（代码评审，指人工检查代码质量和安全性的流程）里最耗时、最依赖专业知识的环节。把它 agent 化是自然的下一步，deepsec 的开源意味着这个能力现在人人可用，不再需要安全团队。Vercel 在把每一条开发者工具路径都 agent 化，deepsec 是这条线里最直接面向安全的一步。

Peter Steinberger（PSPDFKit 作者，独立开发者）：Crabbox 0.5.0 — agent 在 VNC 沙盒里复现 bug、把修复视频贴到 PR

Crabbox 0.5.0 正式上线桌面支持。新版本最核心的能力：agent 可以直接在短暂的（ephemeral，即任务完成后自动销毁的）Linux/Windows/macOS 沙盒里用 WebVNC（一种通过浏览器访问远程桌面的协议）模拟出 bug 的复现环境，完成修复后录制操作视频，自动附到对应的 PR（Pull Request，代码合并申请）上。等于把"这个 bug 我本地无法复现"变成了一个可以让 agent 来处理的自动化任务。

人文与哲学

Every.to：Codex 原生应用的黎明，以及"委托"与"协作"的真实区别

Every.to 本期主题是"Codex 原生应用"（Codex-native Apps）——不只是在应用里用了 Codex，而是从一开始就按照 AI agent 能自主完成任务的前提来设计产品架构。编辑 Dan 分享了自己用 Codex 实现"收件箱归零"（inbox-zero）的工作流，说明 agent 如何处理本来需要逐一手动操作的邮件任务。

但这期最有趣的是对"委托"（delegation）和"协作"（collaboration）的区分。委托是把任务完整扔给 AI，协作是和 AI 一起解决。两种模式对应截然不同的产品设计逻辑：委托要求 agent 有足够的上下文，协作要求界面能让人和 AI 在同一个流程里来回切换。另一个框架是把 Musk 的五条制造法则（先问这个步骤是否必要、能否合并、能否简化，最后才考虑自动化）翻译成 agentic 工作流的设计原则：不要把低效流程自动化，先把流程砍干净。Codex-native 应用的真正挑战不是接入 API，而是重新问一次：这件事到底应该由谁做决策。

Aditya Agarwal（Figma 联合创始人）："没有方向的速度，不值得追求"

Aditya Agarwal 在 X 上写道："我们从未想做加速器。没有朝向真北的扎根，速度本身不值得追求。"（"We have never desired to be an accelerator. Velocity is not interesting without a grounding towards true north."）在 AI coding agent 把开发节奏大幅提速的时代背景下，这句话有独特的反向质感。加速器文化的逻辑是：快就是好。但 Agarwal 的立场是：快是手段，不是目标；没有方向感的快，只是更快地走错路。

"真北"（true north）在这里不是修辞，是具体的产品判断：你知道自己在为谁解决什么问题，每一次迭代都在缩短和这个目标之间的距离。AI 让迭代速度上升了一个数量级，这使得方向判断的价值也相应上升——速度越快，走错方向的代价越大，扎根"真北"的必要性越强。AI 时代里，「做什么」的判断力比「怎么做得快」的执行力更稀缺。

AI 进展

Meta FAIR Autodata：让 AI 充当自己的数据科学家，34 点差距 vs CoT 自指导的 1.9 点

现状：模型训练的质量瓶颈越来越多地落在数据上，而高质量数据标注既昂贵又慢，标准合成数据（即让模型自己生成训练样本的方法）效果有限。

问题：能否让 agent 自动完成整个数据生成、过滤、评估的循环，把更多推理算力转化为更高质量的训练数据？

解决方案：Autodata 是一个以 agent 形式运作的"自动数据科学家"框架，核心是 Agentic Self-Instruct：主 agent LLM 协调三个子 agent 分别扮演"出题者"、"弱解题者"（预期通常答不对）和"强解题者"（预期通常答对）。只有强弱解题者得分差距足够大的样本，才被认为是"有效的训练数据"。整个过程不需要人工标注，闭环迭代。

价值：在计算机科学研究问答任务上，Agentic Self-Instruct 把强弱解题者的准确率差距拉到 34 个百分点，而标准 CoT（Chain-of-Thought，即让模型一步步写出推理过程的技术）自指导只有 1.9 个百分点——差距超过 17 倍。

未来方向：用推理算力换数据质量的路径，可能比单纯扩大模型参数更有效率；这套框架可延伸到任何需要"弱/强对比"来定义难度的任务域。

Meta FAIR · Latent Space AINews

Sakana Conductor（arXiv 2512.04388）：7B 导体模型用 RL 设计 agent 通信拓扑，GPQA-Diamond 达 87.5%

现状：多 agent 系统（MAS，即多个 AI 协作完成任务的架构）的性能通常依赖于人工设计的工作流图，规定谁和谁通信、谁负责哪部分任务。这种手工设计难以适应不同任务。

问题：能否训练一个"导体"模型，自动为每道任务学会最优的通信拓扑和 prompt 策略，同时调度一个由不同 worker LLM 组成的团队？

解决方案：Sakana AI 用强化学习（RL）训练了一个 7B 参数的 Conductor 模型，使其能同时完成两件事：设计 worker agent 之间的通信图（让谁看谁的输出、信息怎么流动），以及为每个 worker 生成针对性的 prompt。Conductor 在随机化的 agent pool（可以是开源或闭源模型的组合）上训练，推理时可以适应任意组合，甚至能把自己递归地加入 worker 池形成嵌套拓扑。

价值：这个 7B 的 Conductor 在 GPQA-Diamond（衡量模型研究生水平科学推理能力的基准测试）达到 87.5%，在 LiveCodeBench（实时代码能力评测）达到 83.9%，超过了它调度的所有单个 worker 模型的个人成绩，且已在 ICLR 2026 上发表。

未来方向：通信拓扑设计本身变成可学习的策略，意味着 multi-agent 编排从"工程问题"走向"训练问题"，降低了构建高性能 MAS 的门槛。

Zyphra 折叠张量+序列并行（TSP）：吞吐从 86M 跃升至 173M tok/sec，AMD MI300X 上验证

现状：在大规模 LLM 训练和推理中，张量并行（TP）和序列并行（SP）通常分开使用，各自有内存和通信效率的上限。

问题：如何在固定 GPU 数量的前提下，同时降低每卡显存峰值并提升 token 吞吐？

解决方案：Zyphra 提出折叠 TSP（Tensor and Sequence Parallelism），将两种并行机制融合为一种统一策略，实验在 1024 张 AMD MI300X GPU、128K 上下文长度、每个模型实例占 8 卡的配置下运行。该设计已扩展支持 MoE（Mixture of Experts，混合专家模型，一种通过只激活部分参数来降低推理成本的架构）的 MLP 层。

价值：TSP 达到 173M tok/sec（每秒 1.73 亿 tokens），而匹配配置下的标准 TP+SP 方案只有 86M tok/sec，吞吐翻倍。Zyphra Cloud 同步上线了基于 MI355X 的推理服务，主打长 horizon agent 工作负载。

未来方向：AMD 生态的开放性加上 TSP 这样的系统层优化，正在为开源模型的大规模部署提供可行路径，是削弱 NVIDIA 垄断的技术基础之一。

Latent Space AINews

DORA：异步 RL 系统用多个活跃策略版本解决 rollout 倾斜，端到端吞吐提升 2.12 倍

现状：在强化学习训练中，rollout（指让模型在任务环境中实际运行、收集轨迹的过程）和参数更新（policy update）通常是串行的。当 rollout 速度远慢于模型更新速度时，训练流水线会频繁等待，造成"rollout 倾斜"（rollout skew）——策略更新了但收集到的数据还来自旧策略。

问题：如何在不降低训练样本"新鲜度"的前提下，让 rollout 和 policy update 解耦并行？

解决方案：DORA 维护多个同时活跃的策略版本（policy versions），允许不同 rollout 工作节点并行采集不同策略版本的数据，训练端通过异步队列消费，确保数据新鲜度在可控范围内。

价值：rollout 速度提升 8.2 倍，端到端训练吞吐提升 2.12 倍，对 agent 的 RLHF（从人类反馈中强化学习，使模型更符合人类偏好的训练方法）和代码生成场景尤为重要。

未来方向：rollout 并行化是当前 RL 训练的瓶颈之一，DORA 类方案的普及将直接降低训练下一代 agent 模型的时间成本。

Latent Space AINews

HiL-Bench（Scale AI Labs）：测试 agent 在规格不完整时是否会主动提问

现状：现有的 agent 评估基准（benchmark）通常假设任务规格完整、需求明确。但真实工作场景里，需求往往是模糊的，"agent 什么时候应该问问题"是一个没有被系统测量过的能力。

问题：如何量化 agent 在遭遇不完整规格时的澄清（clarification）行为——它是猜测着继续，还是合理地停下来提问？

解决方案：Scale AI Labs 的 HiL-Bench（Human-in-the-Loop Benchmark）专门测试 agent 在规格缺失时的判断：它能否识别出"我需要更多信息"的时机，并提出正确的澄清问题，而不是盲目执行导致错误输出。

价值：这是目前少有的直接测量 agent"元认知"（metacognition，即对自身知识边界的感知）的基准，填补了任务执行能力测评和真实部署之间的重要空白。

未来方向：在自主程度高的 agent 场景（如代码编写、合同分析），错误执行的代价远高于多问一次，HiL-Bench 类评估将成为 agent 落地安全性验收的标准工具之一。
