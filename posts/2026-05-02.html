AI 方向观点

swyx / AINews：agent 运行时设计已是真正的竞争护城河，基础模型 IQ 退为次要变量

这期 AINews 有一个贯穿所有产品新闻的隐含论点：前端产品的竞争，已经从"谁的模型更聪明"转向"谁的 agent 运行时（runtime）设计更好"。运行时包括：沙盒隔离（sandbox，让 agent 的代码执行与主系统隔离）、回放与检查点（replay/checkpointing，让 agent 出错时可以恢复）、状态持久化（durable execution，让长任务跨越网络中断或超时继续跑）、以及人机协作节点（HITL，human-in-the-loop，在关键决策点暂停等待人类确认）。

具体证据：Devin 把 agent 嵌进终端快捷键；Hermes 加了 /goal 循环让 supervisor 模型强制 agent 跑到完成；Cloudflare 宣布 Dynamic Workflows 把持久执行加进 agent plan；LangChain 把 HITL 实现成可以把人类回复直接当 tool result 返回；LangSmith Agent Server 细化了多用户数据隔离、delegated credentials 和 RBAC（基于角色的权限控制）。这不是一两家公司的方向，而是整个生态在同时向同一层靠拢。

Theo 描述的 Codex vs Claude Code 差异印证了这一点：GPT/Codex 感觉更直接、更省 tool call；Claude Code 意图和品味更好但速度慢、tool call 多。这不是模型差异，而是 harness（agent 执行框架）设计差异。谁把运行时做成基础设施，谁就赢得了 agent 时代的平台战争。

Aaron Levie（Box CEO）：企业 AI 战略若只盯着"降本"，会在 agent 时代错过真正的杠杆

Levie 在两条推文里拆开了一个常见的混淆：企业买 AI 的理由通常被简化成"替人降成本"，但他认为真正的战略定位是"加速和增强（acceleration and augmentation）"而非削减人力。他的逻辑是：AI 主要做的不是砍掉人，而是让每个人能跑得更快——同样规模的团队在更短时间内完成更大的工作量。把 AI 定位成"降本工具"的企业，会因为只盯着效率指标而错过业务增速这个更大的收益。

这个观点配合他昨天关于"100 倍 agent 需求将重建企业基础设施"的判断来看，逻辑是一致的：agent 数量乘以 100 倍，但如果企业的应对策略只是"用 agent 替掉 100 个人"，那等于把一个乘法变成了减法。该用加速框架思考 AI 的地方，别误用成本框架。

Tim Ferriss 5-Bullet Friday：佛教四句心咒、回忆录写作课、Schwarzenegger 的名言

这期 5-Bullet Friday 有三个值得记住的东西。第一是 Maria Popova 整理的 Thich Nhat Hanh（一行禅师）四句心咒：当恐惧出现时，不是压制它，而是承认它、陪伴它、转化它——四句话依次是"我知道你在"、"我在这里陪你"、"我知道你是恐惧，不是我自己"、"我会照顾你"。用文字而非意志力来处理情绪，这是一种很不一样的实践路径。

第二是 Mary Karr 的《The Art of Memoir》，一本写作课，但 Tim 描述它更像一本哲学指南，严肃与好笑并存。任何需要用文字记录或讲述经历的人，这本书都值得读。

第三是 Arnold Schwarzenegger 的一句话："I don't follow trends. I outlast them."（我不追趋势，我比趋势活得久。）适合在刷了一天 AI 新闻之后，用这句话洗一下脑。三件事放在一起：一个情绪实践、一个创作工具、一句时间框架的校正，Tim Ferriss 的策展眼光一如既往准确。

Tim Ferriss · The Marginalian

Zara Zhang（a16z）：把 coding agent 当联合创始人对待，协作解题而非发号施令

Zara 分享了一个具体的工作方式转变：她不再把 coding agent 当工具来"命令"，而是当联合创始人来"协作"，把问题摆出来一起讨论思路，而不是直接发指令让它执行。这个框架改变了她与 agent 交互的方式，也改变了她对 agent 输出的期待——不是"帮我做这个"，而是"我们一起想这个问题怎么解"。

这个细节很实用。很多人对 AI agent 的抱怨是"结果不符合预期"，但问题可能不在模型，而在交互方式：把 agent 当执行机器用，得到的是执行质量；把它当思考伙伴用，得到的是协作质量。agent 的上限，有时候取决于你用什么框架跟它说话。

AI 进展

ReaLM-Retrieve：推理模型应在推理过程中动态检索，而非只在开始前检索一次

现状：标准 RAG（检索增强生成，先检索相关文档再送入模型）把检索固定在推理开始前，而现有的 IRCoT 方法（固定间隔检索）会产生大量不必要的检索调用。

问题：推理模型在思考过程中产生新的信息需求，预先检索的内容往往不够用，但频繁检索又有开销。

解决方案：ReaLM-Retrieve 让模型在推理过程中动态决定"何时需要检索"，只在推理链出现信息缺口时触发，而不是按固定间隔轮询。

价值：比标准 RAG 高 10.1% 绝对 F1 得分，比 IRCoT 少 47% 检索次数，每次检索的额外开销降低 3.2 倍。

未来方向：推理时检索（retrieval-during-inference）可能成为长上下文 agent 的标准组件，尤其对需要持续查阅外部知识库的任务场景有价值。

Latent Space / AINews

OCR-Memory：把 agent 执行轨迹存成图像而非文字摘要，严格上下文限制下达到 SOTA

现状：长任务 agent 需要记住几百步之前的操作，但上下文窗口（context window，模型一次能看多少内容）有限，通常只能存压缩后的文字摘要。

问题：文字摘要是有损压缩，细节丢失后 agent 无法准确还原之前的状态，导致长任务出错。

解决方案：OCR-Memory 把 agent 执行轨迹的每一步存储为图像（截图），并在图像上建立索引锚点，需要时精确检索对应帧，而不是读取文字摘要。

价值：在 Mind2Web 和 AppWorld 两个 web agent 基准测试上，严格上下文限制条件下达到当前最优（SOTA）。

未来方向：视觉轨迹存储可能是 computer-use agent（控制电脑屏幕的 agent）记忆问题的更自然解法，与纯文字摘要路线形成竞争。

Latent Space / AINews

Recursive Multi-Agent Systems：agent 通过共享潜在空间通信，token 减少 34–75%，速度提升 1.2–2.4×

现状：多 agent 系统（多个 AI 分工协作完成任务）通常让 agent 之间用自然语言对话，但这会产生大量冗余 token（语言模型处理的基本文本单位）。

问题：agent 间通信成本越来越高，尤其是在需要高频交互的复杂任务里。

解决方案：Recursive Multi-Agent Systems 让 agent 通过共享潜在递归计算空间（shared latent recursive computation）通信，而非完整自然语言，相当于在"概念层"而非"文字层"传递信息。

价值：9 个基准测试平均准确率提升 8.3%，端到端速度提升 1.2–2.4 倍，token 使用量减少 34.6–75.6%。

未来方向：如果 agent 间通信成本成为大型 multi-agent 系统的主要瓶颈，潜在空间通信是一条值得追的方向。

Latent Space / AINews

Meta FAIR 自改进预训练：让强模型改写训练语料续写，事实准确率提升 36.2%

现状：预训练（pretraining，用海量文本让模型学习语言）是大模型能力的基础，但传统预训练语料质量参差不齐，包含大量低质量续写。

问题：低质量训练数据会让模型学到不好的行为模式，而人工清洗成本极高。

解决方案：用一个已经训练好的强模型对预训练语料的"续写部分"进行改写，输出更安全、更高质量的版本；再用另一个模型对新旧版本评分，用 RL 风格的预训练信号引导学习。

价值：事实准确率相对提升 36.2%，安全性提升 18.5%，生成质量对比标准预训练胜率 86.3%。

未来方向：把 post-training（训练后微调）的知识反过来改善 pre-training 数据，是数据飞轮（data flywheel）的一个新变体，值得关注。

Latent Space / AINews

Microsoft 合成计算机世界：1,000 台虚拟电脑 + 8 小时 agent 仿真，解决 computer-use 训练数据瓶颈

现状：训练 computer-use agent（能像人一样操控电脑屏幕的 agent）需要大量真实电脑操作的轨迹数据，但收集成本极高，且难以规模化。

问题：computer-use 任务的训练数据瓶颈不是模型能力，而是缺乏足够多样的真实操作场景。

解决方案：Microsoft 生成了 1,000 台合成虚拟电脑，每台都有真实感的文件系统和文档内容，然后在上面运行平均 2,000+ 步的 8 小时 agent 仿真，批量生成训练轨迹。

价值：提供了一条可以大规模复制的 computer-use 训练数据生产流水线，不依赖人工录制真实操作。

未来方向：合成数据（synthetic data）的质量边界正在被持续扩展，computer-use 这类需要多样化环境的任务，合成世界可能比人工录制更经济。
