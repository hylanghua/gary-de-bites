「调步 AI」联署信：1178名前沿实验室员工请求美政府建立 RSI 国际管控机制

7月28日，来自 OpenAI、Anthropic、Google DeepMind、Meta 及其他前沿实验室的 1178 名员工联署「调步前沿」公开信，请求美国政府支持一项国际努力，以开发能够「蓄意控制自动化 AI 发展节奏」的技术与治理工具。RSI（Recursive Self-Improvement，递归自我改进）是指 AI 系统借助 AI 自身进行研究，可能在某个时点出现能力加速超出人类理解和控制的情形。Anthropic 数据显示，截至 2025 年 5 月，其代码库中超过 80% 的合并代码由 Claude 编写；2026 年第二季度，人均每日代码贡献量是 2024 年同期的 8 倍。

这封信在「个人立场」措辞下发布，但 Dario Amodei 本人联署，OpenAI 官方账号转推，Sam Altman 在播客中表态支持，Anthropic 官方声明将此请求与公司自身的 RSI 研究直接挂钩。OpenAI 和 Anthropic 随后均在公司层面背书——这使「以个人名义签署」的说法成为一层薄薄的法律修辞。直接引发联署的导火索，是 HuggingFace 披露的那起由 OpenAI 未公开模型执行的、历时 2-4 天、共 17600 次自主操作的安全攻击事件。

实验室领导层同步签下 RSI 管控请求和继续推进 RSI 能力研究，这不是矛盾，而是一种精心计算过的双重下注：如果有人要监管，最好是自己参与制定规则。

Claude Mythos 破解密码学：HAWK 后量子算法撤出 NIST，7轮 AES 攻击速度提升 200-1000 倍

Anthropic 前沿红队（Frontier Red Team）发布两篇研究论文，记录 Claude Mythos Preview 在密码学领域的自主发现。HAWK 是一种正在参与 NIST 后量子签名标准化进程的算法（后量子，即抵御量子计算机攻击的密码体系），历经两年两轮专家人工审查后尚未被攻破；Mythos 在 60 小时内将对它的最强已知攻击改进到足以让 HAWK 团队宣告撤出标准化进程。第二个发现针对 AES（Advanced Encryption Standard，对称加密标准，全球最广泛使用的加密协议，保护 Wi-Fi 流量、银行交易等）的七轮简化版本：Mythos 找到的攻击方法比人类此前的最快方法快 200 到 1000 倍。整个研究在多 Agent 环境下运行约 60 小时，API 成本约 10 万美元，期间有一名人类研究员提供项目管理辅助但非密码学专家。

两项发现均不直接影响生产系统——HAWK 此前未被正式采用，AES 攻击针对的是七轮简化版而非完整十轮。但意义在于：一个 AI 系统在没有领域专家指导的情况下，在一个研究员需要数月才能验证的问题上，以三个数量级的速度差距超过了人类历史最佳记录。

密码学领域是「AI 超过人类能力」的高可信度试验场——因为结果可严格验证。Mythos 的破解不是黑箱魔法，而是可由人工重现的数学推导，这让它成为至今最具说服力的 AI 科研能力证明之一。

MCP 2026-07-28：协议变无状态，正式解锁 Serverless 和边缘 Agent 部署

MCP（Model Context Protocol，模型上下文协议，让 AI 助手接入外部工具和数据的通用接口标准）发布自上线以来最大规模更新。最核心的变化：协议从双向有状态架构（每次连接需要维持持久会话）改为无状态请求/响应模型（stateless，即每次请求独立，服务器不需要记录会话历史）。这意味着 MCP 服务器可以部署在 Serverless（按需触发、无需常驻服务器）和边缘基础设施（edge，靠近用户的分布式节点）上，用普通轮询负载均衡器扩容，无需 sticky session（粘性会话，让同一用户始终路由到同一服务器的机制）。同时移除了初始化握手流程，新增 Multi Round-Trip Requests（MRTR，支持工具执行中途向用户确认的机制），以及三个官方扩展：MCP Apps（服务器渲染 UI）、Tasks（异步长任务）和 Enterprise Managed Auth（企业 IdP 身份认证）。

Roots、Sampling、Logging、HTTP+SSE 传输和动态客户端注册均被弃用，12 个月过渡期。GitHub、Claude 官方均已宣布对新规范的支持。

MCP 变无状态，是 Agent 基础设施从「实验性协议」到「可商业规模部署的生产标准」的关键一步——过去让运维团队头疼的 session 管理问题，现在消失了。

Swyx（@swyx，Smol AI 创始人、Latent Space 主播）：AI时代雇佣市场双轨分化，从未见过如此剧烈

Swyx 在 X 上发布了一条获 721 赞的判断，措辞极度简洁：「现在是 AI 原生独立贡献者/教练型玩家的大牛市，同时是传统职能管理层（'某业务负责人'）的大熊市。从未见过这样的极度两极分化。过度简化地说：1 年管理 10 个 Agent 的经验 > 10 年管理 10-100 个人的经验。」IC（Individual Contributor）指不带团队、自己动手交付成果的职位；player-coach 指既写代码/做产品、又带少数人的混合角色。

这个判断背后的逻辑：AI Agent 能覆盖大量执行性工作，使得单个 IC 的杠杆大幅放大；而传统管理层的价值在于协调人力资源和信息流——当 Agent 可以协调时，这种价值变得模糊。「管理 Agent」需要对 AI 工具链有直接操手经验，这是十年人力管理经验换不来的。这不是对管理层的全盘否定，而是对「纯职能管理，没有个人技术贡献」这个角色的淘汰判断。

Swyx 在描述一个已经在发生的市场信号：雇主不再为「管理人才」付溢价，正在为「能和 Agent 一起生产」的人付溢价。

纯银 Vol.20260729：产品的边界，人的边界

纯银今日在小报童更新，聊产品边界的本质——「这款产品的用户特质与用户心智，能够泛化到哪一片需求市场」。他用小红书拓展男性用户为正例：表面看是「女性社区」，更高层的抽象是「低创作成本、小颗粒度内容分发的算法驱动平台」，后一个心智可以泛化；而垂直赛道的小红书则全军覆没——不是资源不够，是用户心智就是过不去的死线。反例还包括支付宝和抖音做社交屡败，以及拼多多多多视频异军崛起（下沉用户时间廉价、「看视频赚小钱」与电商补贴闭环的独特组合，可复制的前提是拥有相同的用户基础）。

他的判断方法只有一个：「先收集信号，再判断边界。」信号越弱，对边界的信心越弱，可以谨慎尝试，不能万岁冲锋。从公司内部出发画的边界（「我想要这个增长」）九死一生；从用户信号出发画的边界才是活法。延伸到人的边界：纯银认为「不设边界」是错误的——人的边界是「当前环境与个人特质的组合输出的固定结果」。要拓宽一个人的边界，唯一有效方法是改变环境（换任务、换项目、换公司），而不是在原环境里施加更多压力。

「有没有头部模型的命，就要寻找差异化价值的空间」——纯银在用产品边界理论解释为什么大多数公司注定失败，核心不是执行力不够，而是对自己的用户心智判断失实。

纯银 Vol.20260728：豆包「无限对话流」——消除摩擦成本才是正确的全民 AI 战略

「没有头部模型的命，就要寻找差异化价值的空间」——豆包用产品形态换来了全民教育的先机，这种清醒只有高阶产品经理操盘时才有可能，技术出身的老板大概率会直接给你下辞退通知书。

Every.to：如果 Slack 变成你的 AI 指挥中枢，工作流会长什么样？

Every.to 今日文章探讨一个产品想象：把 Slack（企业即时通讯工具）改造成 Agent 原生的指挥界面（command center），而非只是消息传递通道。核心场景：在 Slack 频道里输入一条指令，Agent 调用工具、返回结果、完成任务，整个闭环不离开 Slack。作者 Laura Entis 还提到两个周边话题：Sol 5.6（OpenAI GPT-5.6）有时会删除东西，需要专门的防护工具；以及《连线》杂志联合创始人 Kevin Kelly 的播客存档。

这个想象的价值在于挑战了一个假设：AI 助手必须有独立界面（ChatGPT.com、Claude.ai）。如果办公室里本来就人人活在 Slack/Teams/飞书里，那么最高效的 Agent 入口也许不是独立 App，而是在已有的协作界面里植入一个 Agent 层。这也是为什么 OpenAI 把 Work 做成全平台能力而非独立产品的逻辑——习惯比功能更难迁移。

把 Slack 做成 AI 指挥中枢，意味着 Agent 不需要改变用户的工作场所，只需要在用户已在的地方生长——这是企业 Agent 产品化最阻力最小的路径。

Aditya Agarwal（@adityaag，Coda CEO / Dropbox 联合创始人）：十年迷茫后的两件清晰

Agarwal 在 X 上分享了他十年前在人生最迷茫时期（「Minus One journey」，他用这个词指职业低谷期）得到的两个内心答案（107 赞）：「我想要在世界上创造新的东西」和「我想和优秀、专注的人一起工作」。他写道：「在这样的一天，两件事都感觉异常充沛。」这条推文简短，但来自一个已经经历过多次创业周期、见过各种团队形态的人，分量不同。

这个时代里，「应该做什么」的答案极其嘈杂——AI 浪潮制造了大量焦虑性叙事（你的工作会被取代、你必须学会 prompt、你必须成为 AI 原生工作者）。Agarwal 的两件事反而是一种降噪：问题不是「做什么才能不被淘汰」，而是「什么让你真正想要进入那个房间」。这两个答案在 AI 时代不会过时，反而因为 AI 放大了个体的生产能力，让「想做新东西」和「想和优秀的人在一起」变得更加可达。

在焦虑文章泛滥的时期，Agarwal 的两句话是一种朴素的矫正：你不需要找到「AI 时代的正确答案」，你需要找到「不管什么时代，都让你想继续走下去的事情」。

Keep It InMind：Agent 记忆的「隐性关联盲区」——检索式记忆更像笔记本而非大脑

现状：目前的 Agent 记忆（memory）系统普遍采用「检索式」设计——把历史信息存储下来，需要时按语义相似度召回，类似给 AI 配了一本笔记本。

问题：人类记忆并不只是检索——我们会在无意识中把两件看似无关的事情联系起来（隐性关联，implicit association），形成「睡一觉突然想通了」的顿悟。检索式记忆完全缺失这种能力：如果信息没被显式检索到，它就不存在。

解决方案：Keep It InMind（arXiv 2607.24368）建立一个专门针对隐性关联盲区的 benchmark（评估基准），系统化测量 Agent 在「检索到但未被利用」「应该关联但未关联」等场景下的记忆失效模式，为记忆系统设计提供失效地图。

价值：首次把「Agent 记忆像笔记本而非大脑」这个直觉转化为可量化的研究问题，让下游系统改进有据可循。

未来方向：从诊断走向修复——如何在不增加检索成本的前提下，让 Agent 具备某种程度的隐性关联能力？

arXiv 2607.24368 · HuggingFace

OmniDelta：基于技能的 Token 压缩预算分配——让多模态 LLM 按任务动态减负

现状：多模态 LLM（能同时处理文字、图像、视频等多种输入的大模型）的 token（模型处理信息的基本单位，决定计算量和延迟）消耗巨大，尤其是视觉输入的 token 占比往往极高。

问题：现有 token 压缩方法大多用统一比例压缩所有输入，不区分任务类型——同样一张图，做简单分类和做细节描述所需的 token 预算完全不同，统一压缩要么浪费（简单任务）要么掉精度（复杂任务）。

解决方案：OmniDelta（arXiv 2607.25669）引入「技能驱动」（skill-driven）的动态预算分配：先识别当前任务属于哪类技能（感知、推理、细节识别等），再根据技能类型分配不同的 token 压缩额度，让简单任务多压、复杂任务少压。

价值：在多个多模态 benchmark 上，OmniDelta 在保持精度的同时显著降低 token 消耗，对推理成本和延迟有直接改善。

未来方向：技能感知压缩可以与模型路由（routing）结合，形成更精细的多模态推理成本控制层。

arXiv 2607.25669 · HuggingFace

PerceptionBench：原子级视觉感知评测——多模态大模型到底「看见」了多少？

现状：现有多模态模型评测主要关注「视觉问答」（VQA）、「图像描述」等高层任务，但这些任务可能靠语言先验（即模型对常识的记忆）而非真正的视觉理解来完成。

问题：模型究竟能否真正「看见」图像中的基础视觉元素——位置关系、遮挡、颜色深度、运动方向等「原子级」感知——目前缺乏系统性评测框架。

解决方案：PerceptionBench（arXiv 2607.24957）建立原子级（atomic）视觉感知评测体系，把视觉理解分解为不依赖语言先验的基础感知单元，逐一测量模型在这些单元上的表现。

价值：揭示了当前旗舰多模态模型在若干基础感知维度上的显著弱点，这些弱点在高层任务测试中被语言补偿所掩盖，实际部署中可能造成意外失效。

未来方向：为下一代多模态训练提供更精细的感知能力诊断工具。

arXiv 2607.24957 · HuggingFace

Towards Robust RL for Small-Scale LLM Agents：让小模型 Agent 的强化学习训练不再翻车

现状：强化学习（RL，通过奖惩信号让模型从经验中学习）是训练 LLM Agent 执行复杂任务的重要方法，但现有 RL 方法在小规模模型（1B-7B 参数）上稳定性极差，容易训练崩溃或性能剧烈波动。

问题：大模型有足够参数容量缓冲 RL 训练中的梯度噪声和策略波动，而小模型没有这个缓冲空间，导致相同方法在小模型上往往失效。

解决方案：论文系统分析小规模 LLM Agent RL 训练的失稳来源，提出针对性稳健化策略，包括奖励塑造（reward shaping）、梯度截断和策略约束的组合改进。

价值：让资源受限的研究者和开发者能够用小规模模型稳定训练出可用的 Agent，是 Agent 能力从大型实验室向更广泛场景扩散的关键基础。

未来方向：小模型 RL 稳定性提升后，端侧（设备本地）Agent 的可行性将大幅提高。

Wonder：视频世界模型的重做——更好的生成连贯性与时序推理

现状：视频世界模型（video world model，能生成未来视频帧、模拟物理世界动态的模型）在游戏、机器人、具身 AI 等领域有广泛应用，但现有方法在长时序一致性和物理合理性上存在明显缺陷。

问题：生成的视频在较长时间跨度后容易出现「时间漂移」——物体突然改变形状、运动方向违反物理规律、场景连贯性断裂。

解决方案：Wonder（arXiv 2607.26037）从架构和训练方式双管齐下，改进视频世界模型的时序表示与未来状态预测，提升跨帧一致性和物理动态的合理性。

价值：在多个视频生成和世界模型评测 benchmark 上，Wonder 显著优于当前主流方法，尤其在长序列生成中的优势更加明显。

未来方向：更可靠的视频世界模型是机器人训练和具身智能（embodied AI，在物理环境中行动的 AI）的核心基础设施，Wonder 的改进将加速这一方向的落地速度。
