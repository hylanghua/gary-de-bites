OpenAI 发布 GPT-Image-2 / ChatGPT Images 2.0：带推理的图像生成，Image Arena 全榜第一

OpenAI 发布了图像生成模型 GPT-Image-2，同时在 ChatGPT 和 API 上线 ChatGPT Images 2.0。核心升级是图像生成带上了推理（thinking）能力：模型生成前可以花时间解读 prompt、联网搜索、规划输出并自我核查。支持从单条 prompt 生成最多 8 张风格一致的图像，分辨率最高 2K，大幅改善了日文、韩文、中文、印地文等非拉丁文字的渲染质量。

Meta Model Capability Initiative：用员工键盘记录和截图训练 AI Agent，美国员工无法退出

Meta 启动"Model Capability Initiative"，在美国员工工作电脑上部署追踪软件，记录鼠标移动、键盘点击和周期性截图，用以生成高质量的 AI Agent 训练数据。监控范围覆盖 VSCode、MetaMate、Google Chat、Gmail 等工作应用，员工被告知没有退出选项（在欧盟境内此举违法，因此限美国执行）。

产品与商业

纯银：2026 互联网行业生存指南（下）

纯银在下篇里引用了犬校终身会员 Stove 的一个观点：AI 时代并不是一些职业被淘汰了，而是过去打包起来的职能组合中，一部分职能的价值被 AI 替代了，另一部分职能的价值是 AI 无法复制的。拆开来看，每个人手里其实持有的是一个"职能组合"，不是一个"职业头衔"——组合里哪些部分在缩水、哪些在升值，才是要搞清楚的问题。

这是一个比"某某职业会消失"更精准的分析框架。设计师不会消失，但"能用工具执行但不能判断好坏"的那部分设计工作会消失；产品经理不会消失，但"整理需求文档"这个职能组件的价值已经在缩水。上篇里纯银讲了行业结构为什么烂透了，下篇讲的是在这个结构里，有议价能力的人是因为持有什么。

AI 不是在淘汰职业，是在帮你显影你手里真正有价值的那部分——显影结果可能令人欣慰，也可能让人不安。

人文与哲学

Amanda Askell（Anthropic 研究员）："When you regain your will to power after burnout"

Amanda Askell 的这条推文只有一句话，但密度很高。她用了尼采的"权力意志"（will to power）这个概念——不是指权力欲，而是尼采意义上的那种向上生长、自我超越的驱动力——来描述从职业倦怠（burnout，一种长期高压工作后出现的精力耗尽状态）中恢复的那个节点：不是"感觉好一点了"，而是"那股想去做事的劲儿回来了"。

对于在高强度 AI 研究和工程环境里工作的人，burnout 是一个真实但很少被公开谈论的话题。Amanda 选择用一个哲学词汇来命名这种恢复的感觉，而不是用心理学语言——这让这条推文在技术圈里产生了共鸣，但又不像心灵鸡汤。

burnout 里失去的不只是精力，而是那个"想去做点什么"的冲动本身——等它回来的那天，你会认出它。

Dan Shipper（Every CEO）：蝴蝶效应问题

Dan Shipper 发了一个开放性问题，围绕蝴蝶效应（butterfly effect，混沌理论里的概念：初始条件的微小变化可以导致系统后期状态的巨大差异）展开——如果历史上某个微小的事件没有发生，今天的世界会是什么样子？这类问题的核心不是答案，而是它揭示的那个悖论：我们用线性的因果叙事来解释复杂系统，但复杂系统本质上不是线性的。

Dan 在 Every 的工作聚焦于用 AI 重新定义创作和知识工作的流程，他的这种哲学性 musing 往往能反映他对"AI 如何影响人类决策"这个问题的更底层思考——当 AI 帮你执行，你对"选择了不同路径会怎样"这类问题的好奇心，是否会反而更强？

我们越来越擅长执行，但对"为什么选这条路"的追问并没有因此减少——它只是换了一个形式出现。

AI 进展

HF ml-intern：开源端到端研究 Agent，GPQA 从 10% 跑到 32%，不到 10 小时

现状：AI 研究团队的后训练（post-training，即在预训练大模型基础上进行的任务对齐、指令微调等阶段）流程仍高度依赖人工：读论文、整理数据集、启动训练任务、分析结果、迭代失败的 run。这个循环耗时巨大且难以并行。

问题：现有的编程 Agent 能写代码，但缺乏将"读文献、设计实验、执行、评估"串成一个自主闭环的能力。

解决方案：Hugging Face 开源了 ml-intern，一个自动化后训练研究循环的 Agent：读论文、跟踪引用、整理和格式化数据集、启动训练 job、评估结果、针对失败做消融实验（ablation，即系统性地去掉某个组件来分析它对结果的贡献）。

价值：在 Qwen3-1.7B 上，GPQA（Graduate-Level Google-Proof Q&A，一个测试大学院级别科学推理的基准）从 10% 提升至 32%，耗时不到 10 小时；医疗场景下的实验在 HealthBench 上超过 Codex 60%；Agent 自主完成了一个 GRPO（一种强化学习训练方式）训练脚本的编写，并在遭遇奖励崩溃时自行通过消融恢复。社区测试显示 ml-intern 可以自主 fine-tune 并把产出发布到 HuggingFace Hub。

未来方向：研究 Agent 开始接管"执行层"——读文献到发模型的全流程自动化，加速了人机协同的科研节奏，也把实验成本压缩到以前的零头。

Latent Space / AINews

Google Deep Research Max：93.3% DeepSearchQA，MCP 原生支持，研究 Agent 进入 API 时代

现状：AI 研究助手大多是"帮你搜索、总结、生成"的轻量工具，不具备处理私有数据、生成结构化报告、执行多步计划的能力。

问题：企业实际需要的研究场景包含内部数据库、私有文档、跨模态分析，这些超出了现有研究助手的能力边界。

解决方案：Google / DeepMind 通过 Gemini API 发布了更新版 Deep Research 和 Deep Research Max，底座是 Gemini 3.1 Pro。新功能包括：协同规划、任意 MCP 服务器接入（MCP，Model Context Protocol，让 Agent 访问外部工具和数据的协议标准）、多模态输入（PDF / CSV / 图像 / 音频 / 视频）、代码执行、原生图表/信息图生成、实时进度流。

价值：Deep Research Max 在 DeepSearchQA 上得 93.3%，BrowseComp 上得 85.9%，HLE（Humanity's Last Exam，一个极高难度的综合性学术评测）上得 54.6%。Google 的设计意图清晰：把"隔夜尽调报告生成"做成可编程的 API 原语，支持私有语料库接入，让研究 Agent 成为企业数据处理的基础设施。

未来方向：简单浏览 Agent 和全栈研究 Agent 之间的能力鸿沟正在拉大，后者正在成为企业 AI 落地的新战场。

Latent Space / AINews

LightOn LateOn / DenseOn：149M 参数 Apache 2.0 检索模型，在 BEIR 上打败 4 倍大的对手

现状：RAG（Retrieval-Augmented Generation，即让 LLM 先检索相关文档再生成答案的技术路线）系统的检索质量直接决定最终答案的准确度，但高质量检索模型通常很大、授权受限或依赖专有数据。

问题：中小团队在搭建私有知识库搜索时，面临模型授权不友好、体量过大、缺乏配套训练数据三重障碍。

解决方案：LightOn 发布 LateOn（多向量 / ColBERT 风格检索，一种将文档和查询分别编码为多个向量、细粒度匹配的方式）和 DenseOn（单向量密集检索），均为 149M 参数、Apache 2.0 开源协议。同时发布 14 亿条 query-document pairs 训练数据集和基于 FineWeb-Edu 的刷新版网络数据集。

价值：LateOn 在 BEIR 基准（检索模型的综合评测集）上得 57.22 NDCG@10，DenseOn 得 56.20，两者均优于多个参数量 4 倍于自身的竞争模型。小体量、高性能、完全开放——对想要自建检索层的团队是直接可用的选项。

未来方向：配套数据集的发布表明 LightOn 在押注"把整个检索生态开放"，这会加速 RAG 系统的普及和私有部署。

Latent Space / AINews

FlashKDA（Moonshot）：CUTLASS 实现的 Delta Attention 内核，H20 上预填充提速 1.72×–2.22×

现状：超长上下文推理（inference，即模型实际运行生成答案的过程）的速度瓶颈越来越集中在注意力计算层，尤其是预填充（prefill，处理输入 token、生成 KV cache 的阶段）阶段。

问题：Kimi K2.6 使用的 Delta Attention（Kimi 的自研注意力机制变体，通过差分方式降低计算量）依赖高效的底层 kernel 实现，否则架构优势无法转化为实际速度提升。

解决方案：Moonshot 开源 FlashKDA，基于 CUTLASS（NVIDIA 的高性能矩阵运算模板库）实现 Kimi Delta Attention kernels，可作为 flash-linear-attention 的 drop-in 后端（直接替换，无需修改上层代码）。

价值：在 H20 GPU 上，预填充速度比 flash-linear-attention 基线快 1.72×–2.22×。社区测试在 8×MI300X 上实现 508 tok/s，比基线 autoregressive 设置提升 5.6×。中国实验室不只是发布模型权重，还在发布 attention kernel 级别的工程优化——这是技术积累向底层的下沉。

未来方向：开源 kernel 降低了其他团队复用 Delta Attention 优势的门槛，也让 Kimi K2.6 的部署经济性在中国硬件（MI300X 等）上有了具体数据支撑。

Latent Space / AINews

新 benchmark：Agent 会忽略环境里已经明摆着的线索，即使解决方案就在文件里

现状：大多数 Agent benchmark 关注的是"Agent 能完成多难的任务"，而不是"Agent 有没有用上已有的信息"。

问题：当 Agent 在实际环境里运行时，解决方案有时已经以某种形式存在于文件、日志或 API 端点里——但 Agent 并不会去检查，而是直接尝试从零构建解决方案，浪费了时间甚至走向错误方向。

解决方案：AINews 引用的这项研究专门设计了一类任务场景：解决方案线索已被明确放置在 Agent 可访问的环境中（文件、端点、日志），测量 Agent 主动发现和利用这些线索的概率。

价值：结果显示，即使线索是明摆的，当前 Agent 仍然大概率会忽略环境，而不是先探索环境再行动。这是一个在实践中被大量用户观察到但缺乏量化证据的问题，现在有了基准数据。

未来方向：对 Agent 工作流设计有直接启示：在 prompt 里明确要求 Agent 先审阅环境，而不是默认它会自主探索，是目前最实用的缓解方式。
