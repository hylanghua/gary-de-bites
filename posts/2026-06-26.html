Apple 上调 Mac 定价 15-20%、iPad 定价 15-25%，AI 算力需求已蔓延至消费端

Apple 宣布上调 Mac 电脑和 iPad 的官方售价，部分型号涨幅超过 200 美元。iPhone 价格暂未调整，但市场预计涨价只是时间问题。原因直指芯片供应链：过去一年间，HBM（高带宽内存）和存储芯片的价格已经涨了四倍，驱动因素是 AI 超算中心（hyperscaler）对内存的爆炸式抢购。这意味着 AI 算力扩张的成本不再只由云厂商承担，正通过制造成本层层传导，最终落在普通消费者身上。

IBM 声称率先突破 1nm 芯片门槛，0.7nm 纳米叠层架构公布

IBM 宣布开发出业界首个亚 1 纳米（sub-1nm）芯片架构，命名为 nanostack（纳米叠层）。这套设计以错位堆叠方式排列晶体管（芯片上控制电流通断的最小单元），在相同面积内封装更多计算单元。IBM 将其标注为 0.7nm 节点，但需注意：芯片行业"多少纳米"的命名早已是营销标签而非实际尺寸，真实物理尺寸更大。即便如此，这项技术若能量产，将提供 Moore 定律极限下最直接的密度突破路径。

AI 方向观点

Aaron Levie（Box CEO）：对"模型层"管控才是 AI 监管的真正转折点

围绕 Anthropic Fable 5 / Mythos 5 停服事件，Box CEO Aaron Levie 在 X 上发表了最犀利的一则政策分析。他指出，以往 AI 监管讨论总是停留在"应用层"——谁能做什么、哪些场景需要审批。这次美国政府直接在"模型层"下手，本质上等于政府获得了决定哪个模型能在全球范围存在、谁能访问的最终控制权。

Levie 认为，这一前例的连锁反应比事件本身更值得关注：其他国家看到后，会加速研发自己的主权 AI 能力，而最可能的路径是拥抱开源模型——因为开源模型可以本地部署、无法被外国政府一道令切断。他把这件事称为"AI 监管话语的真正转折点"，不是因为它解决了问题，而是因为它提前展示了大规模管控最终会长什么样子。

模型层的开关权落到政府手里，是 AI 治理史上比任何法规条文都更直接的事实。 X @levie

Swyx / AINews：OpenAI 内部 Codex 六个月涨 56 倍，真实的 agent 拐点正在发生

OpenAI 发布内部数据：从 2025 年 11 月到 2026 年 6 月，内部员工使用 Codex（OpenAI 的自主编码 agent，能独立完成数小时乃至数天的编程任务）的输出 token 用量在研究部门涨了 56 倍，客服部门涨 32 倍，工程部门涨 27 倍，法务部门涨 13 倍。数据采样显示，80.6% 的活跃用户每次 Codex 请求预计需要超过 30 分钟的人工等效时间。

Swyx 在 AINews 中将这组数据称为"写入 WTF Happened in 2025？档案"。他的观察：即使是有完全免费访问权限的 OpenAI 员工，在 2025 年底之前都还在大幅低估 AI 的使用量。真正的爆发不是模型能力跃升，而是人们终于学会了怎么把它用起来。这与过去若干月许多分析者描述的"agent 大规模落地"叙事形成了第一次真实可测量的佐证。

56 倍不是 Codex 的能力涨了 56 倍，而是使用者对"AI 能干多长任务"的信任边界，在六个月内扩展了 56 倍。 AINews / Latent Space · OpenAI

Sail Research 融资 8000 万美元：专为"跑数周"的 agent 优化低成本推理

Sail Research 以 4.5 亿美元估值完成融资，由 Sequoia 领投，Intel CEO Lip-Bu Tan 和 Alphabet 董事长 John Hennessy 等人参投。公司核心产品是 Sailbox：基于 Linux 虚拟机的 agent 运行环境，开发者可以安装自定义镜像并把多个 Sailbox 组成 agent 集群，支持连续运行数周的任务。他们声称同等任务下成本是竞争对手的十分之一，技术路径是在多个开源推理引擎上做深度定制优化。

背景是：市场上现有的推理服务都为"快速交互响应"优化，而 agent 的使用模式截然不同——一个研究 agent 可能需要 72 小时不间断运行，定价模型和基础设施设计都得重新来。Sail 的出现说明"长时 agent"已经是独立的工程赛道，而不只是把现有 API 叠加使用。

agent 基础设施正在从通用推理服务里独立出来，就像十五年前数据库从通用服务器里独立出来一样。 SiliconANGLE · AINews

人文与哲学

修饼：3D 打印进入"瞬间制造"时代，清华 DISH 技术 0.6 秒完成一个三维实体

清华大学最近发明了一种名为 DISH 的 3D 打印技术，完全颠覆了"一层一层堆积"的传统思路。传统 3D 打印像盖楼，物体越高、耗时越长。DISH 则是把整个容器装满液态光敏树脂，从四面八方同时投射数千幅精确计算过的光图案——这些光束在液体内部叠加，只有能量达到阈值的位置才发生固化，其余位置保持液态。整个三维实体在三维空间里同时成型，耗时仅 0.6 秒。

修饼强调了这项技术真正神奇的地方：液体从头到尾静止不动，真正在动的只有光。因此打印精度极高，最细结构只有十几微米，比头发丝更细。更重要的是，它能使用低粘度材料，未来有望打印水凝胶、生物组织、人工血管。目前还局限于毫米级小尺寸物体，但改变的不只是速度，而是制造的逻辑本身：从"二维叠加"到"三维同时成型"。

三维打印终于从"时间轴上一点一点画"，变成了"在空间里一瞬间召唤"。 小报童 · 修饼（静止的量子）

软件工程师劳动力重新定价：做"AI 工程师"不是护城河

TLDR 精选的一篇观点文章直指当下最流行的职业误区："AI 工程师"作为身份标签已经严重拥挤，这个工具层的迭代速度极快，今天拿过认证的技术栈可能明年就被替代。AI 能帮人搭建原型，但把原型推向生产（production，指在真实负载下稳定运行的系统）是完全不同的事，需要的是对可靠性、可扩展性、安全性、性能、可观察性和运维权衡的深刻理解。

文章的核心论点：在 AI 工具把生产力均质化的时代，真正稀缺的反而是把"一件极难的事"做到极致的专深能力（depth），而不是掌握 N 种 AI 工具的广度（breadth）。

AI 进展

Ornith-1.0：自我进化的 RL 脚手架 coding agent，SWE-Bench Verified 82.4

现状：DeepReinforce 发布 Ornith-1.0 系列（9B 到 397B MoE 四个尺寸），MIT 许可证完全开源，基于 Gemma 4 和 Qwen3.5 后训练。

问题：现有 coding agent 的 RL 训练中，"如何规划、调用工具、检查中间结果、修复失败步骤"的脚手架流程（scaffold，即控制 agent 行为的外层框架）是人工设计的，固定不变，成了性能瓶颈。

解决方案：Ornith-1.0 将脚手架本身作为可学习对象，与模型策略联合优化——模型会在 RL 训练过程中自动生成、修改自己的执行计划框架。Ornith-1.0-9B（可在边缘设备部署）在 SWE-Bench Verified 上达 69.4，相当于远大于其体量的模型。

价值：397B 版本 SWE-Bench Verified 82.4，超越 Claude Opus 4.7；SWE-Bench Pro 62.2，与 GLM-5.2 持平。Terminal-Bench 2.1 得分 77.5。

未来方向：自我进化脚手架是否可以推广到编程以外的 agent 场景——搜索、写作、科学研究——将是接下来的关键验证。

Ornith · GitHub · AINews

OpenRath：类 PyTorch 的多 agent 运行时，Session 抽象支持 fork/merge/replay

现状：多 agent 系统的工程复杂度高，各框架接口不统一，执行状态难以追踪和回放。

问题：当多个 agent 需要分支、合并、重放历史执行路径时，现有工具没有提供标准的运行时抽象——开发者要么自己实现，要么无法审计 agent 的执行历史。

解决方案：OpenRath 以 Session 为核心运行时对象，像 PyTorch 的 Tensor 一样统一了多 agent 的编程模型。Session 记录完整执行状态，支持显式 fork（分支）、merge（合并）、replay（回放）操作，让多 agent 系统的行为变得可控和可审计。

价值：把过去"黑盒调度"的 agent 系统变成了有版本、可追溯的工程制品，对需要 debug、测试、合规审查的生产场景意义重大。

未来方向：类 PyTorch 的生态效应——是否会围绕 Session 抽象形成工具链和社区，决定其长期影响力。

Meta Autodata：agent 循环自动生成合成数据，任务创建通过率 62% 提升至 79.6%

现状：高质量训练数据的生成依赖大量人工标注，速度慢、成本高，已成为模型迭代的主要瓶颈之一。

问题：数据生成本身能否被自动化？现有方法缺乏闭环的自我优化机制。

解决方案：Meta 的 Autodata 把数据生成建模为一个 agent 循环：数据科学家 agent 负责创建、分析、元优化训练和评测数据集，将额外的推理算力（inference compute，即运行模型所消耗的计算量）转化为更好的数据。经过元优化的 harness 将任务创建通过率从 62.1% 提升至 79.6%，在计算机科学、法律、数学等多个领域均有显著收益。

价值：把数据工程变成一个可以被 AI 自身接管的工程问题，而非只是人工劳动的放大器。

未来方向："自动研究"（autoresearch）从概念走向具体 loop 设计的第一个可量化样本。

FastContext：将仓库探索与代码求解分离，降低 coding agent token 消耗

现状：当前 coding agent 面对大型代码仓库时，需要花费大量 token（AI 处理文本的基本单位，决定推理成本）在"定位相关代码"这一步，降低效率、提高成本。

问题：探索仓库结构和求解具体编程问题，对模型能力的要求不同，但现有方法把两步混在一起，用同一个大模型完成所有工作。

解决方案：FastContext 引入专门的"探索模型"负责定位相关代码文件，再由更强的"求解模型"集中处理实际问题，两步分工、分别优化。

价值：在保持甚至提升解决率的同时，显著降低整体 token 消耗，对成本敏感的生产 agent 场景尤其实用。

未来方向：这一"分工专业化"思路能否推广至其他类型的长任务 agent 是下一步验证方向。

Datology：数据精选作为推理效率乘数，同等基准下输出效率提升 35 倍

现状：业界讨论模型效率时，通常聚焦于算法改进（如量化、剪枝）或硬件优化，而数据质量通常被视为"训练阶段的事"，与推理成本无关。

问题：高质量数据对推理效率的作用是否可量化？

解决方案：Datology 研究表明，数据精选（curation，即系统性筛选和去冗余训练数据）能诱导模型更简洁地生成答案，在不损失任务表现的前提下让模型输出更精炼——将答案生成效率提升 35 倍，相当于用同样的算力服务更多请求、降低用户感知延迟。

价值：把预训练/后训练的数据决策与推理服务成本直接挂钩，是继算法和硬件之后，第三个可独立优化的效率轴。

未来方向：数据精选是否会成为模型部署前的标准优化步骤，像量化一样普及。
