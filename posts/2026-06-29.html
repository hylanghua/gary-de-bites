AI 方向观点

Every.to Mike Taylor："AI Could Do Anything. Then It Met PowerPoint" — AI 系统性失手于需要品味和叙事的内容

Every.to 咨询团队的 Mike Taylor 写了一篇罕见诚实的「AI 自动化失败记录」。他从第一次让 Claude Code 生成 PowerPoint 开始讲起，结论是：AI 在"从空白构建幻灯片"上表现惊人，因为幻灯片本质是 HTML 布局问题，而 Claude 写 HTML 极为流利。但一旦涉及客户已有模板，或者需要叙事弧线（narrative arc，即让整套幻灯片讲出一个有起承转合的故事），就会系统性失手——超过 20 万 token（约 15 万字）的上下文会触发"上下文腐化"（context rot），模型开始犯低级错误；而 .pptx 格式是 XML 而非 HTML，模型实际上无法"看见"它在编辑什么。

Every 最终的解法不是找到一个更好的现成 AI 工具，而是自己搭建了"Claudie"——一个运行在纽约办公室 Mac Mini 上的 agent，整合了 Anthropic 官方 pptx 技能（59 个文件、16 个 Python 脚本、4000 字 skill.md），并加入"先出蓝图再执行"（blueprint-first）的人工审核步骤：Claudie 先在 Slack 发出幻灯片大纲等待确认，再开始实际生成。Opus 4.7 发布是一个关键节点，质量因此出现了一次显著跳升。Mike 可以登机途中开始请求，落地后幻灯片已经生成完毕，这才算进入真正可用的状态。

这篇文章的核心信息不是"AI 不行"，而是："AI 把容易的部分（布局、执行）做得很好，但'什么是一套有说服力的演示'这个判断本身，仍然属于人的工作。"而且，一个 80% 完成度的 AI 幻灯片往往比从头手做更危险——因为看起来精致让人降低了检查的警惕性。

AI 自动化的收益集中在执行层，叙事层和品味层仍是人类的主场，而这恰恰是高客单价服务最后可收费的部分。 Every.to

纯银：叶公好龙，也好活人 — AI 内容泛滥后的内容创作者困境

纯银今天的「产品分析 · 无限季」Vol.20260629 正面回应了一个流行的反驳：人们说 AI 内容泛滥之后消费者会意识到"活人味"可贵，从而给人类创作者带来红利。纯银的回答是：不会。他的依据很具体——这个论断在 AI 当道之前的微博上就已经被喊了两三年，那时候是因为对立和冒犯让大多数博主自我审查到"姿态僵直"，同样少有真正的活人感，但真实的活人博主也没有因此拿到更好的数据。

他用了自己的实际数据来支撑这个观点：写了 17 年微博，数据最好的两条，一是在清迈抓龙筋（638 万曝光），二是在大浴场花 2100 元找美貌技师纯聊（1023 万曝光）。两条都靠娱乐性和猎奇价值，文风和文笔只是"很次要的加权因素"。同期，他今年 2 月独自徒步穿越香港"猛鬼村之王"锁罗盆，图文并茂，数据却只有区区 8 万曝光。

他的悲观论点有一个结构性支撑：算法时代的传播逻辑从来不奖励风格，只奖励故事的稀缺性和娱乐价值，而好故事永远是稀缺的，这个稀缺性和 AI 是否泛滥无关。AI 内容加速了信息密度的提升，读者阈值随之水涨船高，但"好故事"的产量并没有因此增加。他把现在比作"五代乱世"：每一份努力换来的回报，和过去相比都在缩水，最终导致拥抱 AI 的"少许努力换取少许收益"反而成为心理上最平衡的选择。

他的最后一句带着收束感："AI 生成的内容，很难让你看完后还会回想起来，更难对内容背后的创作者留下印象。速朽是这个新时代的特征，低成本换取低收益，创作和消费都只在一瞬间。会心一笑，然后相忘于江湖。也许等到五代乱世结束的时候，大家都已经老了。"

活人味不是护城河，好故事才是——但好故事的产量从来没有随着时代一起通货膨胀，这才是创作者困境的核心。 小报童 · 纯银
AI 进展

DanceOPD（ByteDance Seed / NUS）：统一文生图与局部/全局编辑的蒸馏框架，编辑分数提升最高 21.9%

现状：现代图像生成模型（文生图，即根据文字描述生成图像）要求在同一个模型内同时支持"文本生成图像"（T2I）、局部编辑（修改图像的某个区域）和全局编辑（调整整体风格/颜色）三种能力，但这三者在训练时经常相互干扰——为编辑能力微调会拖累 T2I 的质量。

问题：现有方法将三种能力分开训练或串行蒸馏，造成"顾此失彼"——能力越多，单项越弱；另外 .pptx 格式的 XML 问题不适用于这里，真正的瓶颈是"分布偏移"（distribution mismatch，即蒸馏时学生模型的中间状态和被学习的专家模型的目标状态不匹配，导致学习效率低）。

解决方案：DanceOPD 是一个"在线策略生成场蒸馏"（on-policy generative field distillation）框架：每个训练样本被硬性路由给对应的冻结专家场（frozen expert field，即专门负责某项能力的预训练子模块），并在"学生模型自己生成的中间状态"下查询专家——这样学生始终在自己真实分布下学习，解决了分布偏移问题。

价值：在 T2I、局部编辑、全局编辑等多个任务上联合评测：编辑类别最高提升 21.9%，T2I 锚定质量同步提升最高 2.0%，两者不再是零和博弈。框架还能自然吸收 CFG（分类器引导，一种提升生成质量的常用技术）等外部信号。

未来方向：on-policy 蒸馏的思路可以推广到视频生成、3D 合成等其他基于速度场的生成框架，将多能力统一蒸馏变成一个通用范式。

OPID（清华 / 浙大 / CUHK）：从自身轨迹提取分层技能蒸馏，在 ALFWorld 和 WebShop 上超越所有基线

现状：用强化学习（RL，通过奖惩信号改进模型行为的训练方法）训练 LLM agent（大语言模型智能体）完成长流程任务时，奖励信号极为稀疏——通常只在整个任务完成后给出成功/失败，模型很难知道中间哪一步决策对、哪一步错。

问题：稀疏奖励导致"功劳分配"（credit assignment）极难，尤其是在需要 10 步以上的任务中，模型容易陷入低效探索或过拟合到某几条成功路径。

解决方案：OPID 在每轮 rollout（模型完整执行一次任务的过程）结束后，从已完成的轨迹里提取两类层次化"事后技能"（hindsight skill）：一是覆盖整个任务流程的"情节级技能"（episode-level skill），二是在关键决策节点（由专门的"关键性检测器"识别）提取的"步骤级技能"（step-level skill）。推理时，关键节点优先调用步骤级技能，其余时刻用情节级技能，生成的技能注入历史上下文，再用新旧策略的对数概率差作为 token 级（精确到每个词的）优化信号。

价值：在 ALFWorld（虚拟家务任务）和 WebShop（在线购物决策）上超越所有结果级 RL 和技能蒸馏基线，同时在样本效率和鲁棒性上领先；全程无需人工标注，技能完全来自模型自身的 rollout。

未来方向：这种"自己给自己打标"的 on-policy 技能提取路线，是长流程 agent 摆脱稀疏奖励困境的最省力方向之一，且模型无关，可直接迁移到任何 LLM-based RL 框架。

arXiv:2606.26790 · HuggingFace

ViQ（ECCV 2026）：与文本对齐的任意分辨率视觉离散表征，推理提速 20-70%

现状：多模态 LLM（能同时处理图像和文字的大语言模型）大量依赖视觉分词器（visual tokenizer，把图像切成模型能处理的离散或连续块），但现有方法要么语义理解强但重建细节差，要么重建好但语义对齐弱，且通常只接受固定分辨率的输入。

问题：固定分辨率 + 语义/重建二选一，导致视觉离散表征无法同时满足"理解"和"生成"两类下游任务的需求。

解决方案：ViQ 引入两个机制：一是"近端表征学习"（proximal representation learning，渐进式压缩视觉特征空间使离散 token 向文本语义对齐，同时保留重建保真度）；二是"位置感知分头量化"（position-aware head-wise quantization，把不同空间位置和不同特征头的量化解耦），让模型能以原始分辨率处理任意大小的图像，无需缩放。

价值：语义基准上与最先进视觉编码器持平，低层重建精度高；用 ViQ 表征训练多模态 LLM 后，推理速度相比连续 token 基线提升 20% 至 70%（取决于底层 LLM 和训练配置），是一个同时在质量和效率上正向的改进。

未来方向：分辨率无关的统一离散视觉表征，是让多模态 LLM 在图像理解和图像生成上共用同一套词表的关键前置条件。

GUI vs. CLI（2606.24551）：修复技能覆盖率后 CLI agent 胜率 69.3% 超越 GUI agent 的 59.1%

现状：计算机使用 agent（computer-use agent，能操作电脑完成任务的 AI）有两种主流路线：GUI agent（只看屏幕截图、用鼠标键盘操作界面）和 CLI agent（通过预设技能/脚本直接调用命令行工具）。两者的对比实验通常缺乏严格控制——任务不一样、起始状态不一样、评测标准不一样，导致结论可信度低。

问题：没有方法论严格的对比，就无法说清楚"GUI 更好还是 CLI 更好"——更重要的是无法知道为什么某一方失败。

解决方案：构建了 440 个桌面任务的匹配基准（每个任务由 GUI agent 和 CLI agent 在相同目标、相同初始状态下各执行一次，用统一的自动化验证器打分），并对两类 agent 做系统性瓶颈分析：GUI agent 的失败来自长流程中的"接地错误"（grounding error，即模型找不到对应 UI 元素）；CLI agent 的失败来自技能覆盖不足。

价值：最优 GUI agent 通过率 59.1%；CLI agent 原始技能集通过率 48.2%，但修复技能覆盖率后跃升至 69.3%，超过 GUI agent 上限。原始 CLI 技能仅覆盖验证检查点的 37.6%，这是 CLI 看起来输给 GUI 的全部原因——不是交互方式的问题，是工具准备的问题。

未来方向：CLI agent 的上限更高、可扩展性更强（技能可以精确撰写和迭代），GUI agent 的优势在于无需技能预先设计。这项研究为"该选哪条路线"给出了可测量的决策依据。

In-Context World Modeling for Robotic Control（HF W27 #2）：机器人通过自主探测，在测试时零微调适配新身体和新视角

现状：VLA 模型（Vision-Language-Action，视觉语言动作模型，能同时理解图像和语言指令并生成机器人动作的模型）在已知硬件和视角下表现出色，但换一台机器人、换一个摄像头角度，性能往往骤降——因为它们在训练时默认执行环境固定。

问题：部署时的"上下文漂移"（context shift，即实际硬件参数与训练时不同）无法通过重新微调解决——微调成本高，且现实中硬件变化频率远超可承受的标注和训练周期。

解决方案：ICWM（In-Context World Modeling，在上下文中建模世界）把系统参数识别重新定义为"上下文中的自适应问题"：机器人在执行正式任务前，先自主做一批与任务无关的"探测动作"（probe interaction），世界模型预测这些探测的后果，并从中提取关键系统变量（身体参数、摄像头配置、环境动力学）。提取结果作为上下文输入控制策略——机制类似 LLM 中的 few-shot in-context learning，但作用对象是物理机器人参数。

价值：无需人工标注上下文、无需重新微调，在测试时即可泛化到新的机器人形态和新的摄像头视角，直接缩短从实验室到生产环境的落地距离。

未来方向：自探测式在线系统识别（online system identification），是通用机器人走出实验室、进入真实生产环境的关键一步。
