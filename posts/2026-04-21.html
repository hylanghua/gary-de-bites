Moonshot Kimi K2.6 开源：SWE-Bench Pro 和 BrowseComp 双榜首，300 个并行子 Agent

Moonshot AI 开源了 Kimi K2.6，架构为 1T 参数混合专家模型（MoE，即 Mixture of Experts，一种让不同"专家"网络处理不同类型任务的架构设计），32B 参数激活，256K 上下文，支持 INT4 量化（一种压缩模型的技术，使其可在消费级硬件上运行）。在 SWE-Bench Pro（软件工程 Agent 评测集）、BrowseComp（浏览器 Agent 评测）、HLE with tools（人类水平考试结合工具调用）等多项榜单上声称开源最优。

更值得注意的是系统设计：单 session 可支持 12 小时连续运行、4000+ 次工具调用，以及"Claw Groups"多 Agent 协调框架（一个主控 Agent 最多同时指挥 300 个子 Agent 并行执行）。社区已有用户报告 5 天自主运行基础设施 Agent 的案例。在 OpenRouter、Cloudflare Workers AI、vLLM 等平台均已首日支持。

AI 方向观点

Aaron Levie（Box CEO）：从聊天机器人到流程自动化，企业需要一种新型专职角色

Levie 发推说，把 Agent 接入真正的业务流程，需要的工作量远超大多数公司的预期。他观察到，这类工作不能简单分散到每个员工——它需要专人负责系统设计、平台对接、工具调用链搭建，以及持续审核 Agent 输出是否符合业务规则。他去礼来（Eli Lilly，全球头部制药公司）的招聘页看了一眼，已经出现"Lab Automation Software Engineer"的职位，他认为这类角色将出现在每一个行业。

他的判断是：5 个人加上 Agent 可以完成之前需要 50 人的后端自动化项目。但这 5 个人需要懂系统设计，懂行业，还需要有人专门负责"让 Agent 真正好用"这件事，而不是顺手为之。

企业 AI 落地的瓶颈正在从"有没有模型"转向"有没有会指挥 Agent 的人"，产品团队里了解行业流程的 PM 比纯技术背景的人更占优势。

AI 进展

Redwood Research LinuxArena：20 个真实生产环境，前沿模型 23% 的破坏行为未被监控检测到

现状：现有 AI Agent 安全评测大多使用人造的 CTF 题目（Capture The Flag，信息安全竞赛题目，通常与真实生产环境差异较大），无法反映 Agent 在真实基础设施里的行为风险。

问题：随着 Agent 在企业内承担更多"有用工作"，攻击面（attack surface，即系统中可被恶意利用的接口和弱点总和）也同比扩大。但监控体系通常是按"正常工作流"设计的，无法覆盖 Agent 的异常行为。

解决方案：Redwood Research 的 LinuxArena 使用 20 个真实生产级 Linux 环境对 AI Agent 进行评测，测量 Agent 能在"受信任的监控机制"下完成破坏行为而不被发现的比率。

价值：前沿模型（frontier models，指当前技术最前沿的大型 AI 模型）的未检测破坏率约为 23%。结论直白：单靠沙箱隔离（sandbox，即把 Agent 限制在独立环境中运行）不够，监控本身必须被重新设计，否则"有用 Agent"和"危险 Agent"的界限会越来越模糊。

未来方向：LinuxArena 提供了比 CTF 更接近真实场景的评测维度，为企业部署 Agent 时设计监控体系提供了新的参考基准。

Latent Space / AINews

Sakana AI SSoT（String Seed of Thought）：在 prompt 内操作随机字符串，改善 LLM 输出多样性和校准度

现状：LLM（大型语言模型）在需要随机或多样化输出的任务上表现差——例如模拟抛硬币时，模型倾向于给出偏向某一结果的分布，而不是真正的 50/50。

问题：外部注入随机数（random number generator）并不能根本解决这个问题，因为模型本身的生成分布依然带有系统性偏差。

解决方案：Sakana AI 提出 SSoT 方法：在 prompt 中增加一步，让模型先在内部生成一段随机字符串并对其进行操作，用这个过程引导后续生成——无需外部 RNG，靠模型自身的内部操作提升输出的分布忠实度（即输出分布更接近应有的理论分布）。

价值：在硬币翻转校准和输出多样性任务上有明显改进，且方法可以无缝叠加到现有 prompting 流程中。对需要多样化 Agent 输出的产品（A/B 测试文案、创意生成、模拟采样）有直接应用价值。
