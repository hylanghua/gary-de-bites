Claude 接管 Anthropic 自家 App 的日常维护：388 个 PR，180 个合并，46% 合并率

Boris Cherny（Claude Code 创作者，Anthropic）宣布一个三周实验的早期结果：一个叫 proj-claude-maintains-apps 的 Slack 频道里，Claude Tag（Claude 在 Slack 的集成形式）每天自动跑一批 routine，覆盖 iOS、Android、Desktop、Web、CLI 和 Agent SDK 六条产品线，任务包括 crash fuzzing（模糊测试找崩溃点）、移除重复代码抽象、清理死代码、修复接口泄漏等。三周下来，这套系统在 Anthropic 各仓库开了 388 个 PR（pull request，代码提交请求）。

其中 180 个经过 Claude Code Review 和人工复查后合并，合并率 46%。Cherny 的观察是 Claude 通常一次就做对，做不对时团队让它调整 routine 参数，次日重跑。这不是一个实验性沙盒，而是 Anthropic 真实开发 pipeline 的一部分。换言之，Anthropic 正在用 AI 维护用来跑 AI 的工具本身。AI 维护 AI 工具这件事一旦规模化，维护工程师的工作内容将从"写代码、提 PR"变成"设计 routine、审阅 AI 的 PR"——这个角色转换比"AI 辅助编程"更激进，因为主动权已经换边了。

ChatGPT Computer History：OpenAI 让 Mac 记录你的点击、打字、App 切换，本地生成摘要

OpenAI 将此前的 Chronicle 预览版替换为 Computer History，一个 opt-in（用户主动开启）功能，追踪 Mac 上的点击、打字、App 切换和无障碍事件，在本地生成活动摘要，供 ChatGPT 和 Codex（OpenAI 的编程 Agent）调用。目标是让 AI 「记得」你最近在做什么，减少重复解释，并能自动化重复操作。

关键设计是本地化处理：摘要在你的 Mac 上生成，而非上传原始日志，这是 OpenAI 在隐私争议前的一个缓冲设计。尽管如此，追踪粒度（逐次点击、逐字输入）已经足够细到让部分用户不安。OpenAI 让你控制哪些 App 和网站参与记录，不参与的完全不留痕迹。Computer History 是 ChatGPT 从"问答工具"迈向"个人 OS 层"的关键一步——知道你在做什么，AI 才能主动介入，而不是等你开口。

Amjad Masad（Replit CEO）：明年用电脑将变成可选项，ARC-AGI-3 已近乎被"加个编程框架"解决

Masad 同一天发出两条形成呼应的推文。第一条（717 likes）：「明年，使用电脑将变成可选项。」没有更多解释——这是结论，不是预告。第二条（100 likes）：「ARC-AGI-3 仅凭加一个编程框架（coding harness，即让 AI 能写代码验证自己答案的脚手架）就几乎被解决了。」ARC-AGI 是一个被设计为"需要真正推理、不能靠记忆刷分"的 benchmark（基准测试）。从 AGI-1 到 AGI-3，每代升级都被认为是 AI 无法通过的门槛，结果每次都在数月内被突破。

这两条放在一起的逻辑是：如果 AI 现在只需要一个编程框架就能绕过"需要人类判断"的任务，那么人机交互界面（即"电脑"这个中间层）正在被 AI 直接消解。所谓「不需要电脑」，实际上是 Agent 可以代替你完成几乎所有需要鼠标键盘操作的场景。在 Replit，Masad 说这趋势「确实正在发生」。ARC-AGI-3「几乎被解决」的方式是一个诊断：AI 的真正进步不是更聪明，而是更会把问题转化成它能处理的格式——这个转化能力本身就是智能的核心。

Zara Zhang（a16z 合伙人）一句话：「很多人以为 AI 编程会让工程师需求下降。事实相反。」（106 likes）她没有展开论证，但逻辑并不难还原：AI 编程工具放大了工程师的产出——每个工程师能独立完成更大的项目范围——于是有能力消化这类工具、让 AI 真正出活的工程师反而更值钱。与此同时，可以被 AI 替换的是那些只做执行层任务的角色，而判断"让 AI 做什么"的角色需求反而上升。

Ben Tossell（Ben's Bites）：Personal agent 不神秘——一个文件夹、一个指令文件、一个记忆文件就够了

Ben 这期做了一件很有价值的事：把 OpenClaw、Hermes、Grok Bot 的底层结构拆光，发现它们本质上是同一套东西。Personal agent 的核心组成：一个指令文件（写清楚这个 agent 是谁、做什么）、一个记忆文件（用 append-only 日志记录重要事件，agent 靠读这个文件"记住"过去）、工具权限（能访问你的日历/邮件/文件系统），外加一台或共享或独立的虚拟电脑（computer use，即 AI 能像人一样操作屏幕）。Grok Bot 的核心设计——每个 Bot 有自己的独立线程——用 Codex 或 Claude 把线程钉住（pin thread）、指向特定文件夹就能复制。

Ben 的判断简洁：「它们不是不同产品，只是把同样的功能封装得不同。」他自己偏好单 Agent（「Jarvis」风格，一个 agent 统揽所有），但认可多 Agent 的价值——当你想给不同任务设置不同人格、不同记忆边界时，拆分 agent 是合理的。设置流程只有六步：创建文件夹 → 写指令文件 → 加记忆和用户文件 → 在 Codex 或 Claude 里打开该文件夹 → 钉住线程 → 给权限加计划。没有任何黑魔法。Personal agent 这个产品品类的护城河不在于底层技术，而在于谁能把这六步打包得足够无感——摩擦越低，用户粘性越高，回头再换的成本越大。

Peter Yang（产品顾问）：用 AI 导航家人重病——最高情绪压力下 AI 的真实价值

Peter Yang 分享了一个私人时刻：「我正在应对家人的健康状况。对我最有帮助的，是用 AI 梳理信息。」（123 likes）他没有给出细节，但这条推文在 AI 话语里很少见——大多数关于 AI 价值的讨论停在「效率提升」「省时间」，而他触碰到的是另一层：在高情绪压力、信息密集、需要快速判断但又不确定自己是否判断准确的时刻，AI 能不能成为一个可以信任的信息导航者？

医疗场景是 AI 辅助里最复杂也最有价值的地方之一：信息量大、专业壁垒高、时间紧迫、情绪成本高。医生的解释往往信息量不足或太专业，网上搜索结果质量参差不齐。AI 在这里能做的不是诊断，而是把你已有的信息整理清楚、帮你想到该问什么问题、把术语翻译成可操作的理解。Peter 这条推文用一个私人经历说出了 AI 能力边界之外最重要的一件事：不是 AI 有多聪明，而是在对的时刻它在不在。AI 在高压力场景的真实考验不是准确率，而是可信度——当你无暇辨别真假时，你愿不愿意先把它当作值得依赖的过滤器。

OpenART：1 万+ 红队场景，50 个领域，系统性测试 Agent 攻击面

现状：当前 AI 安全评测主要针对短任务、静态场景，但真实 Agent（AI 代理）攻击往往是跨多步、持续演进的，现有 benchmark（基准测试）无法捕捉累积风险。

问题：如何在动态、开放环境中系统性地评测 Agent 被攻击和被用于攻击的风险，同时覆盖足够多的任务域和工具组合？

解决方案：OpenART 提供超过 1 万个经验证的有状态场景（stateful scenarios），横跨 50 个领域，工具和技能池超过 50 万条。测试需要 Agent 平均发起 97 次工具调用——远超现有评测的复杂度。同时提出 EMHA（Evolutionary Markov Hypergraph Attack，演化马尔可夫超图攻击）算法，系统探索不断变化的攻击面；覆盖 75 种不同 Agent 和模型配置的统一评测框架。

价值：把 Agent 安全评测从"在受控沙箱里测单步拒绝"升级到"在动态多步场景里测累积风险"，填补了现有安全评测框架的主要盲区。

未来方向：如何让 EMHA 覆盖更多领域、以及如何把评测结果转化为可部署的防御策略，是下一步核心问题。

arXiv 2608.00677

AI4AI at Test-Time：强模型为弱模型造 harness，ToM 准确率最高提升 87%

现状：弱模型（参数少、能力低的模型）在推理任务上表现差，但强模型（大模型）做推理成本高。能否用强模型的智慧帮助弱模型提升表现，而不更新弱模型的任何参数？

问题：强模型是否可以在推理时（test-time，不涉及训练）为弱模型构建一个"框架脚手架"（harness），把弱模型难以稳定处理的推理步骤转移到确定性代码上？

解决方案：论文提出让强模型构建 inference-time harness（推理时框架），核心做法是把弱模型不稳定的推理步骤外包给可执行代码（如特定的路由规则、答案格式约束），而非让弱模型更多地采样或思考。在心理理论（Theory of Mind，ToM，即理解他人意图和信念的能力）benchmark 上，GPT-5.4-mini 的 macro-average 准确率从基础线提升 87%（相对值），达到 0.912，接近人工工程化的解法。

价值：弱模型收益最大，且不需要任何参数更新——这意味着一旦 harness 设计出来，任何调用接口的用户都可以直接用。对成本敏感的场景（如大规模推理部署）是明显的降本路径。

未来方向：harness 的可泛化性——在一个任务上设计的 harness 能否迁移到其他任务——以及如何自动化 harness 的生成，是下一步核心问题。

arXiv 2608.12307

Intern-S2-Preview：397B 科学领域 agentic 基础模型，多任务 RL + 长链 Agent RL

现状：现有科学领域 AI 模型（scientific AI）主要针对特定任务（蛋白质结构预测、分子生成等），缺少能在多个科学子领域同时推理、调用工具、完成长链任务的通用 agentic 基础模型。

问题：如何在视觉理解、多领域推理和长链 Agent 任务三个维度同时提升，而不牺牲任何一项？

解决方案：Intern-S2-Preview（InternLM 团队，397B 参数）引入三层训练：视觉语言预训练（直接从科学文献原始页面学习，无需中间解析，同时建模符号语义和视觉关系）、大规模多任务强化学习（覆盖数百个专业科学任务，35B 参数版本在多个领域达到强性能）、长链 Agent 强化学习（专门针对需要多步骤规划和工具调用的任务）。

价值：397B 模型在科学推理、多模态理解和 agentic 任务上同时取得提升；35B 版本在低算力下保持竞争性能，让小团队也能部署科学 AI。

未来方向：科学领域数据的质量和覆盖度是核心瓶颈；如何在保持通用性的同时做深度垂直专业化，是下一步需要解决的架构问题。

HuggingFace · arXiv 2608.13505

PlayWorld：用多模态 Agent 追踪长目标测交互式视频世界模型

现状：交互式视频世界模型（interactive video world model，即能预测"你在虚拟世界里采取行动后会发生什么"的 AI 系统）是具身 AI 和游戏 AI 的核心技术，但现有评测方法以短序列、单步交互为主，无法测试模型在长时间、复杂目标下的真实表现。

问题：如何系统性评估世界模型在几何一致性（前后帧的空间逻辑是否自洽）、交互保真度（AI 的动作能否引发预期的环境变化）和状态演进（世界状态随时间是否合理变化）三个维度的能力？

解决方案：PlayWorld 框架：用多模态 Agent（能同时理解视觉和文字的 AI）追踪长时间目标，在这个过程中系统评估世界模型的三个核心维度。用 Agent 的目标完成度作为评测信号，而不只是单帧预测误差。

价值：提供了一个与任务目标绑定的评测框架，比单纯测帧质量更能反映世界模型的实际可用性——一个图像精美但物理逻辑混乱的世界模型会在 PlayWorld 上暴露出来。

未来方向：评测场景的多样性（目前以游戏类环境为主）和对开放世界任务的泛化，是下一步扩展的核心方向。

A* 后训练：解决推理模型"过度思考"，路径规划比多次采样更高效

现状：推理模型（reasoning model，即在回答前展示思考过程的 AI）经过强化学习后往往产生远超必要长度的解题轨迹——这种"过度思考"（overthinking）浪费算力，且不总能提升答案质量。

问题：如何让模型在推理时找到更短、更高效的解题路径，而不是用大量采样（多次生成）来暴力提高正确率？

解决方案：论文提出用 A* 算法（一种启发式搜索算法，常见于游戏 AI 寻路）的思路做后训练（post-training）：让模型学会评估哪些推理步骤真正值得展开，哪些可以跳过，从而规划出更高效的推理路径，而不是无差别地延长思考链。

价值：在保持或提升回答质量的同时，减少推理 token 数量——对于按 token 收费的推理部署场景（如 API 调用），这直接等于成本下降；对于实时场景，等于响应更快。

未来方向：A* 启发式在开放域问题（没有明确终止条件）上的适用性，以及如何在不同任务类型之间迁移路径评估策略，是下一步核心问题。
