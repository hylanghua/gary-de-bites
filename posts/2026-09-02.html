Claude Fable 5.1 & Mythos 5.1 发布：Terminal-Bench-Science 翻倍、cache 读价砍七成、EFS 企业合规层

9 月 1 日，Anthropic 正式发布 Fable 5.1 和 Mythos 5.1，两款产品共享同一套模型权重，但访问门槛不同：Fable 对所有人开放，Mythos 仅面向经审核的网络安全和生命科学机构，因后者在高风险双用途知识领域有额外开放。评测数据说话：在 Terminal-Bench-Science 上，Fable 5.1 得分 52.6%，较 Fable 5 的 24.7% 翻了一倍多；Terminal-Bench 4.0 上也从 42% 升至 55.8%。同日宣布的还有大幅降价：cache 读取成本从每百万 token $1 降至 $0.25，降幅 75%。Anthropic 估算，常规工作负载（workload，指日常使用模式）可因此节省约 25%，高度自动化的 agent 工作负载（agent workload，指多步自主执行任务）最高可节省 45%。不过外部分析机构 Artificial Analysis 观察到输出 token 用量平均上升约 1.7 倍，综合算下来每任务成本仍可能上涨约 20%。

此次发布还附带 Enterprise Frontier Safeguards（EFS，企业前沿防护层）。传统上，零数据留存（ZDR，即对话数据不被保存用于训练）意味着跨 session 无法发现异常模式；EFS 在零留存基础上增加了自动化监控层，在企业自有云内运行，对 agent 跨 session 行为做异常标记。Alex Albert（Anthropic 研究员）将它定义为「ZDR++」，为 agent 时代新增了可观测性，秋季开始分批推出。

World Labs 发布 Atlas：首个多模态世界模型，7 张图生成 1 分钟 1440p 3D 场景

Fei-Fei Li 创立的 World Labs 在同一天推出了 Atlas，定位为史上首款多模态世界模型（world model，能理解并生成空间一致的三维世界的 AI 系统）。Atlas 从零开始训练，将 LLM 和视频模型的设计思路融为一体，把摄像机几何（camera geometry，即视角位置和方向）作为原生输入。实际效果：给它 7 张参考图片，它能生成一分钟长度、1440p 分辨率、可从任意角度观察的 3D 视频；给它一张或几张照片，可重建出完整 3D 场景，输出格式包括点云（point cloud）和 3D 高斯泼溅（3D Gaussian splat，一种高效的 3D 表示方法）。

目标应用是机器人训练数据生成：只需用手机拍几张真实空间的照片，Atlas 就能模拟机器人在该空间移动时摄像头和深度传感器的感知结果，替代昂贵的场景扫描设备。Atlas 现阶段不公开论文，不公开定价，进入早期访问阶段，合作伙伴名单未透露。

Meta Muse Voice Transcribe：实时语音识别 + 说话人分离，$3/千分钟，70+ 语言

Alex Albert（Anthropic 研究员）：EFS 是 ZDR++，agent 时代的可观测性与风险管控基础设施

Alex Albert 把 Enterprise Frontier Safeguards 定义得很精确：传统零数据留存（ZDR，即不保存用户对话数据）的问题是跨 session 无法看见 agent 在做什么。企业给 agent 的权限越来越大，接入的内部系统越来越多，但没有一个层可以发现跨 session 的异常模式。EFS 把这个空白填上：数据留在企业自己的云里，Anthropic 在外面加一层自动化监控，专门标记 agent 行为中出现的高风险模式，再通知企业安全团队。他用的比喻是：「可观测性（observability，即系统内部状态的可见性）加风险缓解（risk mitigation）层——企业要把越来越强的 AI 跑在自己系统里，这类工具迟早会变成标准需求。」

EFS 的意义不是「又一项隐私功能」，而是 Anthropic 在为 agent 时代重新定义「企业合规」的边界——从「数据不出去」升级到「我们可以看见 agent 在做什么、在出问题之前拦截它」。

Every Compound Writing Plugin（Katie Parrott）：把六个月写作流程工程化为可复用 AI skill 插件

Every 今日发布了 Compound Writing，一个花了六个月打磨的写作 skill 插件（plugin，可供他人安装的打包工具集）。Katie Parrott 的核心论点：AI 写作最大的进步不是「让 AI 帮你写草稿」，而是「把你自己的写作方法打包成 AI 可以反复调用的结构」。Compound Writing 把采访（interview）、大纲（outline）、起草（draft）、修改（revision）四个环节各自做成一个独立 skill，可以单独调用也可以串联使用，并通过 plugin 的形式让任何人安装。她的比喻是「写作健身房」：equipment 和结构由 skill 提供，你决定在哪里用力。

更值得关注的是背后的演化轨迹：2024 年 Projects 出现（让 style guide 可跨对话持久保存），2024 年秋天 Skills 出现（让方法论可复用），现在 Plugins 让这些方法论可分享给他人。每一步都把 AI 写作从「个人即兴聊天」往「结构化工作流」拉近一步。Compound Writing 最重要的不是具体工具，而是它所代表的方向：AI 时代的写作竞争力来自流程的可积累性，而不是一次性的 prompt 技巧。

Guillermo Rauch（Vercel CEO）：Fluid 统一计算平台，Functions + Builds + Servers 合并为一条边界

Guillermo Rauch 详细介绍了 Fluid——Vercel 内部已运行一段时间、现在对外说明的统一计算层。其核心是把 Functions（无服务器函数，按调用计费的短生命周期计算）、Builds（构建环节，把源代码变成部署产物）、Servers（长时运行的服务进程）三类以前相互隔离的计算形态，统一在同一个 Dockerfile（容器配置文件）、同一套安全边界（Secure Compute perimeter，指同一防火墙和网络隔离策略）、同一个文件系统和网络层之下。直接收益是：之前无法串联的能力现在可以共享——比如防止 agent 逃逸（agent escape，即 agent 突破容器边界做未授权操作）的防火墙规则，可以同时保护 Build 环境和 Function 运行时。

Fluid 不是新产品，是架构统一——Vercel 在用「一个平台管所有计算」的方向押注，而这个方向在 agent 大量使用 Sandbox（沙箱，隔离的代码运行环境）的场景里有直接的安全价值：只要 agent 在 Fluid 边界内，逃逸的攻击面就压缩了。

Aaron Levie（Box CEO）：Box 企业评测，Fable 5.1 在非结构化数据任务上整体提升 7 个百分点

Box 对 Fable 5.1 做了内部评测，任务是企业真实场景下的非结构化（unstructured，指文档、合同、报告等非表格数据）数据处理。整体评分比 Fable 5 提升 7 个百分点，Levie 举了三个具体案例：金融服务场景（+17%）：税调利润预测中，Fable 5.1 正确先扣资本摆免再计税，而 Fable 5 计算顺序错误导致数字全部偏差；科技场景（+37%）：成本优化分析中某指标定义模糊，Fable 5.1 识别出歧义并同时计算两种解读后选出正确版本；公共部门场景（+16%）：教育数据分析中，Fable 5.1 正确完成加权平均并给出正确排名，Fable 5 在分类步骤出错后全表级联错误。

Madhu Guru（Meta AI Sr Director）：自我改进产品是每家公司该实施的元理念，5 个核心要素

Madhu Guru 把「自我改进产品」（self-improving product，产品利用 AI 自动发现自身问题并推动优化）定义为一个应该普遍实施的元理念，并列出 5 个必要组件：（1）清晰的指标定义——首要、次要、保护性指标；（2）清晰的战略、路线图和最希望移动的指标；（3）过去产品决策和原则的知识库——让 agent 知道决策如何做；（4）接入内部产品系统的连接——仪表盘、API、MCP（模型上下文协议，一种让 AI 连接外部工具的标准）、工具；（5）针对端到端产品开发流程构建的 harness（执行框架，让 agent 按产品流程行动的脚手架）。

他引用 Shopify ML 团队作为企业自建后训练（post-training，在预训练基础模型之上针对特定任务再训练）的优秀案例，判断这是绝大多数企业目前严重低估的投资方向。「自我改进」不是一个工具，是一套飞轮——把产品数据、决策历史和 AI 行动力三者串联起来，是下一个为数不多没有被外部 SaaS 解决的企业内部机会。

Peter Yang（AI 教程创作者）：AI skill 卫生学——只装少量自己的 skill，定期删除，防止 prompt 漂移

Peter Yang 今日清理自己的 AI skill 库，分享了几条实操原则：不喜欢装太多随机 skill；目前只保留约十几个（大部分是自己写的）；定期删除不再使用的；尽量让每个 skill 保持简短。他的配套问题切中了一个真实的工程痛点：每次靠 AI 辅助迭代 skill 时，AI 往往「为这一次的对话过拟合（overfitting，在当前场景下表现完美但丧失了对其他场景的泛化能力）」，多次迭代后 skill 与原始意图越偏越远。他在询问社区有没有好的解法。

人文与哲学

Zara Zhang：「Be a person, not a persona」——AI 工具泛滥时代，真实性是唯一无法复制的护城河

Zara Zhang 的这六个字是今天被转发最多的短句之一。它的语境是 AI 内容生产爆炸式增长之后，越来越多人开始用 AI 打磨出一个精心设计的「人设（persona，有意识维护的公开形象）」：措辞更流畅、逻辑更自洽、每条发言都经过优化。但「persona」和「person」之间有一道裂缝——前者是一个被表演出来的形象，后者是一个真实的人，带着矛盾、犹豫、不完美的表达。

这句话不是反对用 AI，而是在提醒一件事：当所有人都在用同样的工具打磨同样的表达风格，真实性本身就成了稀缺资源。Zara 本人的写作风格印证了这点——她同日分享的另两条推文，一条是「希望每座城市都是东京」，另一条是「这种网站设计风格是什么时候开始流行的？」，都是未经过度打磨的即时感受。「做一个人，不是做一个人设」——在 AI 把表达成本归零的时代，这句话本质上是在说：真正的差异化，来自你没法外包出去的部分。

AI 进展

Prime Agent：自我改进 RLM harness，ARC-AGI-3 RHAE 从 30% 提升至 95.5%

现状：长时程（long-horizon，指需要多步、多轮才能完成的）编程和推理任务对 AI 的挑战在于：计算历史（history）、记忆（memory）、技能（skill）、子 agent 规范在任务中途丢失，导致 agent 无法在跨 session、跨轨迹的场景下累积进展。

问题：现有的 RLM harness（reinforcement learning model harness，驱动强化学习模型完成任务的外部执行框架）缺少持久状态和 agent 间通信机制，限制了测试时计算（test-time compute，模型在生成答案时消耗的额外计算资源）的有效利用。

解决方案：Prime Agent 使用持久 IPython REPL（交互式 Python 执行环境，让 agent 可以跨轮保留变量和执行历史）配合 Recursive Language Model（递归语言模型，可以把自身作为工具调用的模型架构）；Continual Harness 跨轨迹保存状态；递归子 agent（recursive subagent）通过直接消息通信协作；Agents View 让人类可实时检视和管理守护进程（daemon-backed sessions，后台持续运行的 agent 进程）。

价值：在 ARC-AGI-3 RHAE（推理+人类辅助评估指标）上，Prime Agent 将 Best@1 从 30% 推至 95.5%，同时在长上下文编程、GPU 核心生成、模拟器构建等任务上持平或超越同类框架。

arXiv 2608.23552 · HuggingFace

FreeToken：边缘原生 MoE serving，8GB 游戏本 GPU 跑 35B 模型达 39.3 tokens/s

现状：Mixture-of-Experts（MoE，混合专家模型，每次推理只激活一部分专家网络以降低计算量）模型在云端已有成熟服务方案，但部署到个人硬件（笔记本、台式机）时，硬件异构性（CPU/GPU 比例、带宽限制、内存容量）和 agent 工作负载的动态变化使既有方案无法高效运行。

问题：如何在个人设备上把 MoE serving（模型服务，即运行模型并响应请求）的整个栈（模型布局、专家驻留、CPU-GPU 协同、状态复用、内存管理）统一设计，适应不同机器的硬件资源比例？

解决方案：FreeToken 把个人机器视为「弹性统一推理平台」而非「小 GPU」，协同设计上述全栈，并特别针对 agent 工作负载（执行模式持续变化）做了带宽自适应调度（bandwidth-adaptive execution，根据实时带宽动态决定哪些专家常驻 GPU）。

价值：解码（decode，模型生成每个 token 的阶段）吞吐量比同类基线高 1.5–2.3 倍；8GB 显存的游戏本上，35B 模型达 39.3 tokens/s；支持 284B 模型跑在游戏台式机上，753B GLM-5.2 跑在单张工作站 GPU 上。

arXiv 2608.16157 · HuggingFace

BDH-CQ：循环隐空间推理 + ICL，150M 参数模型，中间推理步不解码成语言

现状：主流推理模型依赖 chain-of-thought（CoT，思维链，把推理过程写成自然语言中间步骤）来提升准确率，但这带来额外 token 消耗，且中间步骤必须转化为文字形式才能被处理。

问题：能否让模型的中间推理过程完全留在高维向量空间（latent space，模型内部的数值表示层）中，不解码为语言，同时仍能利用 in-context learning（ICL，上下文学习，给模型若干例子让它学会任务）？

解决方案：BDH-CQ 用循环记忆（recurrent memory，在序列处理中持续更新的内部状态向量）替代 CoT 文字步骤：推理时新输入持续更新记忆，模型在隐空间中迭代计算后直接输出答案，无需「说出」中间过程。与将 demonstrations（上下文示例）压缩为单一任务向量的方法不同，BDH-CQ 按序列逐元素处理示例，保留细粒度信息。

价值：150M 参数规模下实现了有竞争力的 ICL 推理性能，为「轻量高效推理」提供了无需 CoT 冗余 token 的新路径，适合资源受限的 edge 场景。

arXiv 2608.09888 · HuggingFace

WeMM-Embedding：WeChat 多模态 embedding，文 + 图 + 视频 + 交叉输入统一向量空间

现状：多模态检索和推荐系统通常需要分别训练文本、图像、视频的 embedding（嵌入，把内容压缩为固定长度向量以便比较相似度）模型，跨模态对齐靠后期拼接，难以处理真实产品中大量的「交叉输入」（interleaved input，如图文混排的帖子、带字幕的视频）。

问题：如何在单一模型中统一处理文本、图像、视频和交叉输入，同时达到工业规模的检索和推荐性能？

解决方案：WeMM-Embedding 提供 2B、4B、9B 三个参数版本，两阶段训练：先大规模多模态对齐（alignment，让不同模态的表示在向量空间中可比较），再用精选数据 + 细粒度相关性监督 + 跨尺度知识迁移（cross-scale knowledge transfer，大模型引导小模型学习）做精调。输出 2048 维 L2 归一化向量，已在 WeChat 频道、公众号、朋友圈、电商场景中大规模部署。

价值：2B 版本在 MMEB-v2 上超越原有 8B 级最优开源基线；9B 版本以 80.6 的整体分数创当时新 SOTA；模型权重和代码已在 GitHub 开源。

arXiv 2608.24053 · HuggingFace

ASTRA-bench：时序个人上下文 + 工具沙箱 agent 评测，2413 场景五维打分

现状：现有 agent 评测基准多基于静态、匿名场景，无法反映真实用户在时间积累中形成的个人上下文（personal context，如历史日历、邮件、消息）和工具依赖。

问题：如何构建一个评测框架，让 agent 必须在「真实个人的时间线上下文」中使用工具完成目标，并同时评测完成质量、工具使用规范性和泛化能力？

解决方案：ASTRA-bench 包含 2413 个人工编写的对话场景，来自 5 个虚构真实人物的纵向生活事件，配备交互式工具沙箱（email、日历、消息等）。目标按 referential（指称复杂度）、functional（功能复杂度）、informational（信息量）三轴标注复杂度，评分覆盖五个维度：任务完成、工具使用、信息检索、对话有效性、无幻觉（no hallucination，即没有捏造事实）。

价值：当前最优模型在高复杂度场景下表现显著下降，暴露了现有 agent 在「真实个人上下文中 + 工具依赖 + 多步规划」的系统性短板，是工具使用 agent 评测的重要新基准。
