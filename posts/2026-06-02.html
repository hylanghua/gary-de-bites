AI 方向观点

swyx（AINews 主编）：Agent 的主战场已从模型转移到 harness

本期 AINews 梳理了本周最值得关注的结构性趋势：真正的工程杠杆不在模型本身，而在 harness（Agent 的运行调度框架，控制任务流、工具调用、上下文管理的外层系统）。最清晰的例子是 Perplexity 的 Search as Code（SaC）：不再让模型发出一次次检索工具调用，而是让模型直接写 Python 代码，调用 Perplexity 自己暴露的检索 SDK，动态组装专属流水线。效果：内部 WANDR benchmark（衡量需要多步检索和推理的困难宽研究任务）分数从 0.152 跳到 0.386，提升 2.5 倍，但 benchmark 仍未饱和。

Google 同期推出 Managed Agents（托管代理，在 Gemini API 里单次调用即可启动一个能推理、写代码、运行代码、管理文件、操作沙盒的完整 Agent），LangChain 也在强调 Deep Agents 和持久 Context Hub。Memory 是共同的空缺：大 context 窗口不等于跨 session 记忆，一条来自 HydraDB 的线程指出这是尚未被主流框架解决的基础原语（primitive，指不可再分解的最小构建块）缺口。模型竞赛降温，harness 竞赛升温；谁造出最好的 Agent 操作系统，谁才是 2026 年的真正赢家。

Guillermo Rauch（Vercel CEO）：MiniMax M3 成 Next.js Agent leaderboard 开源第一，但 token 冗余问题值得警惕

MiniMax M3 是中国 AI 实验室 MiniMax 于 6 月 1 日发布的开权重多模态编码模型：1M token 上下文窗口，SWE-Bench Pro 得分 59%（超过 GPT-5.5 和 Gemini 3.1 Pro，接近 Claude Opus 4.7），MSA（MiniMax Sparse Attention）架构让 1M context 时的计算量仅为上一代的 1/20。Rauch 直接在 Vercel 的 Next.js Agent leaderboard 上测试，M3 拿到开源第一，前端生成和一次性 UI 输出令人印象深刻。

不过评测社区的反馈是双面的：M3 的 token 消耗量高、self-check 循环冗长，长任务里容易出现需求漂移（requirement drift，即执行过程中偏离原始任务目标）。Rauch 的评价是"质量优先、效率待解"的开源模型——评测数据部分跑在 MiniMax 自己的基础设施上，独立验证仍在进行中。开源模型正在触碰闭源前沿的门槛，但在 token 效率上还有一段路要走。

Aaron Levie（Box CEO）：AI Agent 时代的定义性问题是 context pipeline，不是哪个模型更聪明

Levie 把他在 Box 日常观察到的企业落地痛点再次梳理清楚：当 AI 模型进入真实的 Agent 工作流，真正的卡点不是模型能力，而是模型能否理解整个业务的上下文（context，即任务背景、数据关联、权限规则、流程历史）。

问题的根源在于 context pipeline（上下文供给管道）的断裂：企业知识碎片化在不兼容的旧系统里，访问权限控制和实际工作流脱节，大量关键决策只活在员工脑子里，从未被结构化。他还补充了一个有趣的 AWS 观察：AWS 已经积累了大量有多年锁定合同的企业客户，这既是护城河，也是 context 积累的隐性资产，是 Agent 落地时真正的竞争底牌。2026 年 AI 落地竞争的胜负手是谁掌控了最好的 context pipeline，AI 模型只是这个管道里流动的信号。

纯银：一人公司与软件贬值——AI 改变了分工，但没解决分发，这道题目前无解

纯银这期的切入点来自和孟岩（投资人）的一次对话。他的核心判断：一人公司根本不能称"公司"，而是一人生产线。AI 降低了信息类商品的生产摩擦，让一个人可以全攻全守地产出内容和软件；但公司形态所需的复杂经营职能（渠道、品牌、销售、合规），AI 至多提供套路化指引，做不到真正承担。

软件的部分更直接。供给泛滥带来两个问题同时出现：需求侧注意力收窄，能被算法分发的共性需求已经饱和；软件没有算法分发，碎片化产品找不到渠道。他引用了一个妙喻：个人化软件生产更像老北京大爷遛的鸟，"您看我今儿得一新鸟儿您掌掌眼"——自娱自乐的成年人玩具，而不是可商业化的产品。他并非在否定这条路，而是在说：先别贴"公司"的标签，先搞清楚这是不是真正有商业价值、有销售渠道的产品，两件事同时发生在一人公司身上是"极低概率事件"。AI 把软件供给塞爆了，但没有给软件装上分发引擎，所以大多数"一人公司"只是自嗨，而不是创业。

Tim Ferriss 引 Pattern Breakers："绝望的用户"才是真正的 PMF 信号，感兴趣不够用

Tim Ferriss 在这篇博文里重读了 Mike Maples Jr（传奇天使投资人，Floodgate 联创，Forbes Midas List 八次上榜）所著的《Pattern Breakers》。核心观点只有一个区分：interested（感兴趣的用户）vs. desperate（绝望的用户）。

感兴趣的用户会试用你的产品，会说"挺好的"，然后回去继续用之前的解决方案。绝望的用户没有退路：他们的问题足够痛、足够急、足够真实，以至于不管你的产品多粗糙、多难用，他们都会想方设法用起来——因为别无选择。这不只适用于早期投资或创业，同样适用于任何你想为世界创造的东西：受众是"觉得有趣"还是"没有你活不下去"，决定了你是在做爱好还是在做产品。Mike Maples 把这个区分作为他判断一个项目是否值得下注的核心测试。"感兴趣的用户"证明你在正确的方向上，"绝望的用户"才证明你找到了真正的市场。

AI 进展

NITP：用"隐式 token 预测"重塑 LLM 预训练的表示空间，解决各向异性问题

现状：主流 LLM（大语言模型）预训练采用 next-token prediction（下一个 token 预测，把文本切成最小单位逐步预测），这套方法用的是稀疏的 one-hot 监督信号（每次只告诉模型"这个词是正确答案"，其余全是 0）。

问题：稀疏监督让隐藏状态的表示空间欠约束（under-constrained），容易漂移成各向异性（anisotropic，即表示向量在空间中严重偏向某些方向，缺乏均匀分布），限制模型的泛化能力。

解决方案：NITP（Next Implicit Token Prediction）在离散预测之上叠加了连续的稠密监督：用同一模型浅层的表示作为稳定的自监督目标，让模型同时学习预测"下一个 token 的隐式语义内容"，而不只是预测哪个词汇表 ID。

价值：正则化了优化景观，减少欠约束自由度，强制更紧凑、更结构化的表示几何。在 HuggingFace 本周论文榜获得 21 票，是本周 LLM 预训练方向关注度最高的工作。未来方向：隐式表示监督有望成为大规模预训练的标准辅助目标。

Draft-OPD：让推测解码草稿模型真正从"被拒绝"中学习

现状：推测解码（speculative decoding，用一个轻量草稿模型提前猜多个 token，主模型并行验证，接受的留下、拒绝的丢弃）是 LLM 推理加速的主流方案之一，可大幅降低延迟。

问题：草稿模型通常用监督微调（SFT）从目标模型的输出学习，但训练数据是"离线"的固定轨迹；实际推理时草稿模型在自己的策略下生成，经历的状态分布与训练集不同，即 offline-to-inference mismatch（离线到推理分布错位），导致草稿质量快速达到天花板。

解决方案：Draft-OPD 用在线蒸馏（on-policy distillation）：草稿模型在推测验证过程中暴露的"被拒绝位置"（rejection-exposed positions）上重新训练，配合目标模型辅助的 rollout（向前推进补全）确保训练稳定性。

价值：草稿模型真正学会在自己最容易犯错的地方改进，加速比更稳定。未来方向：在线蒸馏方法有望成为推测解码系统的标准训练协议。

arXiv 2605.29343 · GitHub

Mellum2：JetBrains 的 12B MoE 编码模型，2 倍速推理，专为多 Agent 流水线中的快速分工节点设计

现状：多 Agent 开发流水线（如 IDE 内的 subagent、RAG 路由、代码审查代理）需要在主模型旁边部署快速、专用的小模型承担低延迟任务；现有开源编码模型要么太大、要么能力局限。

问题：兼顾编码能力、低延迟推理和长上下文（128K）的轻量开源模型几乎空缺。

解决方案：Mellum2 是 12B 总参数、2.5B 激活参数的 MoE 模型（64 个专家、每次激活 8 个），基于 Qwen3-MoE 构建，新增 Multi-Token Prediction（MTP，单次前向传播预测多个 token）和 Sliding Window Attention（减少长文本计算量），在约 10.6 万亿 token 上从头训练，RLVR（强化学习验证奖励，用可验证的正确性奖励来提升推理质量）后训练。权重已在 HuggingFace 全开放。

价值：比同规模模型快 2 倍以上，vLLM 当天支持。未来方向：专用小模型在 Agent 流水线中的分工将深化，Mellum2 是这个方向的代表性开源工作。

arXiv 2605.31268 · HuggingFace

VideoMLA：低秩 KV 缓存让分钟级视频扩散（video diffusion）KV 内存减少 92.7%

现状：自回归视频扩散模型（autoregressive video diffusion，逐帧生成视频的扩散模型）在生成分钟级视频时面临严重的 KV 缓存（key-value cache，存储注意力机制历史计算结果以避免重复计算的结构）爆炸问题，现有方案是固定大小的滑动窗口缓存。

问题：固定滑动窗口缓存信息损失大，且每 token 的 KV 内存占用随模型层数线性增长，制约生成质量和长度。

解决方案：VideoMLA 将每层的 keys 和 values 替换为一个共享的低秩内容 latent（低维度潜空间表示，用少量参数捕获核心信息）加一个解耦的 3D-RoPE 位置 key，每 token KV 内存降低 92.7%。论文还揭示了一个有趣的理论发现：虽然 MLA（Multi-Head Latent Attention）在语言模型中被常用低秩假设支撑，但预训练视频注意力并不是低秩的——VideoMLA 在实践中依然有效，说明其价值来自其他机制。

价值：在保持生成质量的前提下大幅降低长视频生成的内存门槛。未来方向：低秩 KV 压缩将成为长视频生成模型的标配设计。

arXiv 2605.30351 · 项目页

Perplexity Search as Code：搜索变成可编程 SDK，模型自己写 Python 组装检索流水线

现状：传统搜索增强的 AI 系统让模型通过工具调用发出检索请求，只消费最终结果——模型是搜索的被动消费者，无法控制检索策略。

问题：对于需要自定义排序、多路并发检索、结果聚合（map-reduce）的复杂任务，固定的工具调用接口表达能力不够；token 开销也更高。

解决方案：Search as Code（SaC）把搜索栈（search stack，从 query 解析、索引检索到结果排序的完整流程）拆解成 SDK 里的基础原语，让模型直接写 Python 代码、在安全沙盒（sandbox，隔离执行环境）里运行，动态组装针对当前任务的检索流水线。模型从信息消费者变成了检索流水线工程师。

价值：在内部 WANDR benchmark（困难宽研究任务评估）上得分从 0.152 跳到 0.386，提升 2.5 倍，同时降低 token 消耗。未来方向：可编程检索将成为 Agent 搜索系统的标准架构，取代固定工具调用范式。
