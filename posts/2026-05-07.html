AI 方向观点

Peter Yang：Dario/Daniela 最值得记住的几句话——"为指数建产品"，模型从写代码进化到"把建公司当任务"

Peter Yang 在"Code with Claude"活动现场整理了 Dario 和 Daniela Amodei 的几段原话。几句最有密度的：

"Build for the exponential（为指数增长而建）：有些产品现在的模型还做不到，但以后的模型可以，这让内部实验变得特别值钱——你必须实际试一试才知道行不行。" Dario 描述了模型进化的三段路：写代码 → 把软件工程当一项任务来处理 → 把"建立一个商业单元"当作一项任务。还有一句关于技术债："快速发货会积累大量技术债，但模型也可以帮你还债。"

最后这句很少被讨论。大多数人把 AI coding 当成"写新功能的工具"，而 Dario 的意思是：当模型强到一定程度，存量的代码库也可以被重构——AI 不只是让开发加速，而是让历史负担也变得可偿还。如果这个方向成立，"技术债"这个概念本身在 AI 时代的权重将大幅下降。

Zara Zhang（Infinity Ventures）：Boris Cherny 访谈三个高光——夜间数千 agent、手机上的 Claude Code、写代码将成新读写能力

Zara Zhang 整理了对 Boris Cherny（Anthropic 产品工程负责人）的访谈中最让她印象深刻的三个细节：Boris 随口提到他夜里跑着"数千"个 agent 做各种任务；他几乎只通过手机上的 Claude Code 来写代码，不用桌面；他相信"写代码将成为新时代的读写能力（new literacy），就像阅读和写作一样"。

"数千个 agent 夜里跑"这个细节最值得停下来想：这不是一个工程师在演示 demo，而是在描述他个人的日常工作状态。当 AI agent（能自主执行任务的 AI 程序）成为工具链的底层，工作方式的改变不是线性的——它意味着你的产出量在你睡觉时仍在增加。"写代码将成为基础识字能力"这句话，与其说是预言，不如说是对现在已经发生的事情的慢速确认。Boris 描述的日常工作状态，是大多数工程师两到三年后将面对的常态。

Harness（模型外壳）是第一级变量：同一个模型，不同 prompt/工具/中间层，benchmark 差距高达 10-20 分

Latent Space 本期 AINews 收录了多位工程师的同一个观察：在 agent 评测（benchmark，即系统性的能力测试）上，相同的底层模型，单靠调整 system prompt、工具接口和中间处理层（middleware，即模型调用前后的转换逻辑），分数可以差出 10 到 20 个百分点。换言之，模型的原始智能并不是决定实际产出的唯一变量，"把模型包起来的那层外壳"同样是第一级别的工程问题。

这个观察改变了一件事的含义：Anthropic 在"Code with Claude"活动上发布的 Dreaming（跨会话记忆）和 Outcomes（评分/迭代循环）这两个 Managed Agents 功能，与其说是"新功能"，不如说是 Anthropic 把它认为最有价值的 harness 工程实践产品化。问题随之而来：这些 harness 功能是真正的护城河，还是任何开源框架都能复制的模式？AI 产品的竞争，正在从"谁的模型更聪明"转移到"谁把外壳设计得更好"。

产品与商业

纯银：古典产品观——数据指导增长，但洞察来自人的判断

纯银在今日小报童（一个付费通讯平台）里写了一个在他的实际产品工作中反复得到印证的观察。他经常和产品拍档一起盯着有知有行（一个以长期投资为核心理念的中文平台）的数据看：数据用于指导增长往往是有效的——哪里的转化率低了，哪里的留存出了问题，这些数据都能给方向。但数据给不了的，是深刻的洞察。

他的核心区分：数据是结果的投影，不是成因的解释。你能从数据里看出"什么发生了"，但"为什么"和"下一步该往哪走"，仍然需要人对用户的理解、对行业的直觉和对产品本质的判断。把增长决策完全交给数据，往往会优化局部、错失方向。有洞察力的产品人并不是那些最会看数据的人，而是那些在看数据之外，还保留着大量非结构化思考的人。数据是产品经理的地图，但洞察是地图上没有画出来的那条路。

小报童 · 纯银

Claude Managed Agents 三件套：Dreaming 存记忆、Outcomes 立标准、多 agent 编排——"Code with Claude"活动的核心发布

Anthropic 在"Code with Claude"开发者活动上发布了 Claude Managed Agents 的三个新功能。Dreaming（字面意思是"做梦"）：agent 自动回顾历史会话，从中提炼模式、整理记忆，让 agent 随时间推移持续学习，而不是每次任务都从零开始。Outcomes（成果）：你写下一份 rubric（评价标准），一个独立的 grader（评分 agent）逐条核对主 agent 的输出是否达标，不达标则继续迭代，并通过 webhook（事件推送接口）在完成后主动通知你。第三个功能是多 agent 编排：由主 agent 把任务拆分，委派给专项子 agent，最后汇总结果。

三个功能合在一起，指向同一个方向：把现在工程师手动搭建的 agent 运行框架（记忆、评估、分工）变成 Anthropic 的平台原语（primitive，即基础功能单元）。Ben 评价这次活动"有点平淡"，但 Latent Space 的解读更深：这是 Anthropic 把 harness（模型外壳，见上文）工程的最佳实践往自己的平台里收。Anthropic 正在把 agent 工程师的工具箱变成订阅制基础设施。

Garry Tan（YC 总裁）："Lulu 就像《低俗小说》里的 Wolf"——把 AI 助手定性为专门清理烂摊子的"清道夫"

Garry Tan 在 Code with Claude 活动期间发了这条推。《低俗小说》里的"The Wolf"（哈维·凯特尔饰）是一个临危受命的专业清场人：局面已经乱了，他出现，有条不紊地解决，完事离开，不问问题。Garry 把某个叫 Lulu 的 AI 助手比作这个角色，说明他在使用中感受到的是：不需要解释、不需要过多输入，它进来，处理，搞定。

这个类比的价值不在于它描述了 Lulu 的具体功能，而在于它说明了产品人希望 AI 助手是什么感觉：不是需要被喂养的工具，而是不用管理的协作者。"Wolf 感"是当前 AI 产品一个极难做到但极有吸引力的特质——大多数 AI 工具还需要你花时间解释自己想要什么，而 Wolf 只是进来把事情搞定。用户对 AI 助手最深的期待，是"不需要我来管理它"。

开放权重（open weights）模型正在悄悄收紧：训练成本上升，许可条款趋严，开放生态或将终结

Open weights 模型（即厂商公开模型参数文件、允许任何人在自己的硬件上运行的模型）的吸引力在于：私密、灵活、低成本。它们让很多公司得以以极低的每 token（模型处理的最小文字单位）成本运行接近前沿水准的模型。然而，随着训练成本快速上涨，越来越多的"开放"模型在发布时附加了更严格的许可条款——限制商业用途、限制再发布、限制竞争用途。

Martin Alderson 的论点：那种真正意义上的竞争性开放权重生态系统（任何人都可以自由使用、修改、部署的模型库）可能正在走向终结。训练一个竞争力强的模型的成本，已经让多数研究者和初创公司难以独立承担。当只有少数几家公司有能力训练前沿权重，他们自然会在开放程度上施加控制。这对广泛经济体有巨大影响：依赖 open weights 压低 AI 成本的企业，将逐渐失去这个选择。开放权重不是一个技术事实，是一个商业决策——当训练成本高到足够，这个决策会系统性地往封闭方向移动。

martinalderson.com · TLDR

从内部设计：快速成长的工程团队没有蓝图可用，只能靠微小的表面改动让改善逐步显现

建筑师设计建筑可以先画平面图、做沙盘，然后按图施工。工程师在高速成长的创业公司里面对的是完全不同的处境：产品在快速变化，代码库在快速演进，任何试图提前"规划整个产品地图"的尝试都会在完成之前就过时。Matt Stromawn 把这种处境叫做"从内部设计（design from the inside）"——你没有外部视角，只能站在当前代码的内部，做出小小的改动，观察效果，再做下一步。

可行的应对方式包括：让设计环境和真实产品之间的距离尽量短（快速看到改动在真实情境下的效果）；压缩反馈循环；不断发布小改动。这个描述对 PM 同样有意义：在快速变化的环境里，宏大的产品规划往往不如一系列小实验有效，因为知识是在做的过程中积累的，不能在做之前就拥有。成长期产品的设计本质，是在迷雾里不断迈步，而不是站在高处俯瞰地图。

AI 进展

ZAYA1-8B：Zyphra 推出 <1B 激活参数的推理 MoE，开源 Apache 2.0，数学/推理接近更大模型

现状：推理型语言模型（在生成答案前经过多步内部思考的模型）通常需要大量参数才能在数学和逻辑推理上表现出色，这使得本地部署成本较高。

问题：能否在激活参数（模型运行时实际参与计算的参数量，不同于总参数量）极少的前提下，达到接近大型推理模型的效果？

解决方案：Zyphra 发布 ZAYA1-8B，采用 MoE（Mixture of Experts，混合专家）架构：模型总参数 8B，但每次推理只激活不到 1B 参数，在数学和推理任务上宣称接近大数倍于它的模型。以 Apache 2.0 协议开源，支持 AMD 硬件。

价值：如果声称成立，ZAYA1-8B 将大幅降低在本地 GPU 上运行有效推理模型的成本门槛，对中小团队尤其有意义。

未来方向：MoE 架构结合高效推理训练（post-training，即对基础模型进行进一步强化）是当前开源推理模型的主要优化路径。

Latent Space AINews

vLLM + Mooncake：前缀复用让 agentic 工作负载吞吐量提升 3.8 倍，P50 TTFT 降低 46 倍

现状：Agent 工作负载（即让 AI 连续执行多步任务的场景）有一个特殊性：多次任务调用往往共享大段相同的系统提示（system prompt，即给模型的固定背景指令）或上下文前缀，每次调用都重新计算这段内容是一种浪费。

问题：如何在 agent 大规模部署场景下，避免对共用前缀的重复计算，同时保持低延迟？

解决方案：vLLM（一个广泛使用的开源 LLM 推理框架）与 Mooncake 合作实现了可复用前缀（reusable prefix）机制：相同的前缀内容计算一次后缓存，后续调用直接复用缓存结果，无需重新计算。实验在最多 60 张 GB200 GPU 上进行。

价值：吞吐量提升 3.8 倍；P50 TTFT（即 50% 的请求的首 token 生成时间，衡量响应速度的核心指标）降低 46 倍；端到端延迟降低 8.6 倍；缓存命中率从 1.7% 提升至 92.2%。

未来方向：前缀复用将成为 agent 规模部署的标配优化，显著降低 agentic 应用的推理成本。

Latent Space AINews

OBLIQ-Bench：专门测试"找到微妙相关文档"的硬信息检索基准，当前检索系统普遍失败

现状：当前主流 RAG（检索增强生成，即让模型在回答前先从文档库检索相关内容）系统在检索"明显相关"的文档时表现尚可，但在面对"微妙相关"文档时（即只有深入理解后才能判断其相关性的内容）普遍失败。

问题：现有 IR（信息检索）benchmark（基准测试）对这类"硬召回"场景的覆盖严重不足，导致系统缺陷被高估值掩盖。

解决方案：OBLIQ-Bench 专注于第一阶段检索（first-stage retrieval，即从大规模语料库中初步筛选候选文档）中的硬案例，要求系统从大型文档库中找到需要深度理解才能识别相关性的内容。获得 IR 研究社区的广泛认可。

价值：为 RAG 系统提供更真实的评测维度，帮助开发者识别检索管道（retrieval pipeline，即从查询到结果的完整流程）中被常规 benchmark 忽视的薄弱环节。

未来方向：随着 agent 对长文档和知识库的依赖加深，高质量的检索能力将成为 agent 系统的关键瓶颈之一。

Harvey LAB：开源法律 agent 基准测试，1200 任务覆盖 24 个法律实践领域

现状：法律工作是 AI agent 落地最早、潜在价值最大的行业之一，但针对法律 agent 的长链条、多步骤任务缺乏系统性评测标准。

问题：现有通用 agent benchmark 无法覆盖法律实践中的专业任务（合同审查、尽职调查、诉讼策略等），导致法律 AI 产品之间缺乏可比性。

解决方案：法律 AI 公司 Harvey 发布 LAB（Legal Agent Benchmark，法律 agent 基准测试），MIT 协议开源，包含 1200 个任务，覆盖 24 个法律实践领域。LangChain、Baseten、Artificial Analysis 等工具链公司已接入评测。

价值：为法律行业建立了首个开源、可比较的 agent 能力评测框架，有助于加速法律 AI 产品的透明度和竞争。

未来方向：行业专属 agent benchmark 将成为各垂直赛道的标配，法律是率先建立标准的领域之一。

Latent Space AINews

OpenAI MRC（Multipath Reliable Connection）：开放的大规模训练集群组网协议，已用于 OpenAI 最大超算

现状：大型 AI 训练集群中，GPU 节点之间的高速网络连接（interconnect，即集群内部的通信网络）正在成为训练效率的主要瓶颈之一，超过存储和计算本身。

问题：标准以太网协议在大规模训练中容易出现丢包和重传，造成训练停顿；专有 RDMA 方案（一种高性能网络技术）成本高、兼容性差。

解决方案：OpenAI 开源 MRC（多路径可靠连接协议），采用多路径路由（multipath routing，即同时通过多条网络路径传输数据）和微秒级故障切换（microsecond failover，即在极短时间内切换到备用路径），已在 OpenAI 最大的超算集群上实际部署。

价值：网络层面的效率提升直接影响大规模训练的整体利用率，同时将该技术开放给社区有助于降低大规模训练集群的搭建门槛。

未来方向：网络连接已成为继 GPU 算力和能源供给之后，AI 基础设施竞争的第三个主战场。
