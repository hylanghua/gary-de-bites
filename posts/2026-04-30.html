四大超级算力玩家单季合烧 $1300 亿，需求仍在供给前方

微软、Alphabet、Amazon、Meta 四家公司 Q1 联合资本支出（即固定资产投资，主要用于数据中心和服务器）合计约 $1300 亿，仍报告同一个问题：需求在供给前面跑。Alphabet 季度营收 $1090 亿（同比 +22%），云业务增长 63% 至 $200 亿，积压订单接近 $4600 亿；Amazon AWS 同比增长 28%，Q1 资本支出 $440 亿，自研芯片业务已达 $200 亿年化规模；Meta 季度营收 $560 亿（+33%），将全年资本支出上调至最高 $1450 亿；微软季度营收 $820 亿（+18%），AI 年化收入达 $370 亿，Copilot 用户数 2000 万。

Tom Tunguz 的分析指出：拥有模型层的超级算力玩家将增长最快。这些公司的挑战不是卖不出去 AI，而是根本无法足够快地把算力建起来——已有数十亿美元需求坐在积压订单里等待供给落地。

Figure AI：BotQ 工厂 120 天内从日产一台跃升至时产一台，年产目标 5 万台

Figure AI 的人形机器人 BotQ 工厂已经达到每小时生产一台第三代 Figure 03 机器人的速度，120 天前这个数字还是每天一台。工厂有 150 多个工位，配备专属装配流水线和多层质量检查，目前已生产超过 350 台，年产目标 5 万台。

机器人规模化的瓶颈在转移。以前的核心问题是没有足够多的真实世界机器人来积累训练数据；现在变成了：大批量部署出去之后，机器能不能在重复劳动中长期稳定运行而不悄悄出故障。可靠性到位了，规模化就形成正向飞轮——每一台在外面跑的机器人都在喂养下一次迭代的改进。

Agent 基础设施三连发：Cloudflare 自助开户 · Stripe Link 一次性支付 · Cursor SDK

三家基础设施平台同日宣布向 Agent 开放核心能力。Cloudflare 让 Agent 可以自行注册账号、购买域名、启动付费服务、获取 API token 并部署应用，全程无需人工登录管理后台——人类只需在授权某些条款时介入一次。Stripe 在 Sessions 大会上宣布推出 Agentic Commerce Suite，其中 Link CLI（命令行工具）可让 Agent 从用户的 Link 钱包里获取一次性支付凭证，完成支付而不暴露真实银行卡信息，每笔交易均需用户推送通知批准。Cursor 则发布 TypeScript SDK（软件开发工具包，一套可复用的代码库），开放了与 Cursor 桌面端相同的 runtime（运行环境）、harness（代理执行框架）和模型选择，让外部开发者可以用几行代码搭起自己的编程 Agent，支持本地运行或 Cursor 云端。

这是很清晰的一天：基础设施层开始主动把 Agent 当成"一等客户"，而不是需要人工代劳的工具使用者。Agent 在外面跑，基础设施在后面撑着，越来越少需要人工在中间接力。

AI 方向观点

swyx / AINews：推理拐点——Noam Brown、Sam Altman、Jensen 三人罕见同日共鸣

OpenAI 研究员 Noam Brown 说"推理算力是战略资源，目前被低估"；Sam Altman 说"我们现在必须变成一家 AI 推理公司"；NVIDIA CEO Jensen Huang 更早说，过去两年 AI 计算需求增长了百万倍。这三句话出现在同一时间窗口，swyx 认为不是巧合，而是行业在同一个判断上的收敛信号。

更少被注意到的是 CPU（通用处理器，区别于训练专用的 GPU）的需求。Intel CEO 在 Q1 财报上给出数据说明 CPU 需求正在回升。背后逻辑是：Agent（AI 代理）大规模运行时，软件本身跑在 CPU 上；RL gym（强化学习训练环境）做模拟也大量用 CPU。过去两年所有预算都被 GPU 抢走，CPU 严重投资不足，叠上 2020-21 年采购的机器正好到了自然淘汰周期，可能出现 CPU 短缺，而这个趋势在算力讨论里几乎没人提。

GPU 之外 prefill/decode 分离（把模型"读取输入"和"生成输出"两个阶段拆到不同芯片上跑）正在成为新的推理架构标配：NVIDIA 收购 Groq、Intel 合并 SambaNova、Amazon 加入 Cerebras，这条线上的整合在加速。

推理基础设施的竞争已经从"谁有最好的模型"转移到"谁能最快把算力建起来"，而 CPU 是被遗忘的那块短板。

Aditya Agarwal（SPC 创始人）：Agent 今天仍是开发者产品，"和消费级还差得很远"

SPC（South Park Commons）创始人 Aditya Agarwal 投入大量时间亲手试用各种 Agent 工具之后，给出了一个不加修饰的判断："Agent 现在是开发者产品，和消费级还差得很远。"这不是技术悲观，而是一个有大量一手观察支撑的刻度感：能稳定工作的 Agent 场景，目前还几乎都需要用户有能力定义任务、处理异常、理解输出。

Kevin Weil（OpenAI CPO）：放射科医生的本质工作是帮患者做决定，不是分析图像

Kevin Weil 在讨论 AI 医疗影像时提出了一个重新定义：放射科医生（专门阅读 CT、X 光等影像的医生）的核心工作不是"分析图像"，而是"帮助患者在信息和不确定性之间做出最好的决定"。

这个区分很锋利。如果把医生的工作定义为"分析图像"，AI 一旦准确率够高，替代就是必然结论。但如果核心价值是"帮患者在焦虑、选择和权衡之间找到路"，AI 检测出病灶只是其中一步，解读、沟通、陪伴的那部分，还根本不在 AI 能力圈里。这个框架几乎可以直接套用到任何被讨论"会被 AI 取代"的职业上。被 AI 取代的是任务，不是角色；角色的核心是人类判断和关系，不是流程执行。

AI 进展

Agentic Harness Engineering：Harness 迭代十次，Terminal-Bench 2 pass@1 从 69.7% 升至 77.0%

现状：Agent（AI 代理）的表现不仅取决于底层模型的智能，还深度依赖"harness"——围绕模型的提示结构、工具定义、上下文管理、重试逻辑等执行框架的设计质量。

问题：harness 的优化通常依赖工程师的直觉和反复手调，缺乏系统化方法论，改一处不知道影响哪里，失败了也不好归因。

解决方案：Agentic Harness Engineering 提出让 harness 进化变得可观测：引入可还原组件（revertible components，可回退的模块化 harness 单元）、浓缩执行证据（condensed execution evidence，把 Agent 运行记录压缩成可分析的证据集）和可证伪预测（falsifiable predictions，提前声明改动预期效果）。在 Terminal-Bench 2 上，十次迭代后 pass@1（一次通过率）从 69.7% 提升到 77.0%，超过了人工设计的 Codex-CLI 基线（71.9%）。优化结果还能跨模型族迁移，SWE-bench Verified 上的 token 消耗减少 12%。

价值：对 PM/Builder 来说，这意味着 harness 本身是一个值得独立迭代的工程资产，不是一次性搭完就固定的脚手架。

未来方向：结合自动化评估（evals）做持续 harness 回归测试，是下一步的自然延伸。

HALO：用 trace 分析递归修补 harness 缺陷，AppWorld 从 73.7 升至 89.5（Sonnet 4.6 上）

现状：Agent 在复杂任务上频繁失败，通常被归因于模型能力不足，但实际上许多失败来自 harness 设计缺陷——错误的工具接口、不合理的提示格式、上下文截断等问题。

问题：定位 harness 失败点需要大量人工分析 trace（Agent 运行的完整执行轨迹），耗时且依赖专家经验。

解决方案：HALO（Harness-Adaptive LLM Optimization）提出递归自改进 Agent：用另一个 AI 自动分析失败的 trace，识别 harness 缺陷位置，生成补丁并验证。在 AppWorld benchmark（测试 Agent 完成多步骤应用操作任务的基准）上，Sonnet 4.6 加持下，完成率从 73.7 提升到 89.5，不需要修改底层模型权重。

价值：如果方法可推广，Agent 的 harness 调优将从依赖人工专家，变成可以让系统自己找到改进点。

未来方向：在更多 benchmark 上的复现验证，以及如何防止 harness 自改进引入新 bug，是当前的关键悬问。

Latent Space / AINews

IKP（Incompressible Knowledge Probes）：188 个模型、1400 道题，事实容量不随时间"压缩"

现状：业界普遍有一种直觉："模型越来越聪明，是因为更会推理，而不需要死记更多事实"。这暗示知识存储效率在提升，同样大小的模型可以越来越"懂得多"。

问题：这个直觉很难被直接检验，因为大多数 benchmark 混合了推理能力和事实知识，难以拆开。

解决方案：IKP 用 1400 道设计为"只考事实、不考推理"的问题，测试 188 个模型（来自 27 家厂商，参数量从 1.35 亿到 1.6 万亿）。结果：事实知识准确率与模型参数量的对数呈强线性关系，R²=0.917（开源模型），说明事实容量随参数量增长，且这个关系没有随时间被"压缩掉"。副产品：用拟合曲线可以反推闭源模型的参数规模估算。

价值：对做模型选型的 PM/团队：事实密集的任务（客服、知识库问答、合规检查）对模型大小的需求可能比想象中更硬，小模型+RAG 不总是完整答案。

未来方向：多语言和非英语事实知识的测量，以及对微调（fine-tuning）如何影响这个曲线的研究。

Latent Space / AINews

FlashQLA（Alibaba/Qwen）：长上下文线性注意力 kernel，前向提速 2–3 倍

现状：Transformer 模型的注意力机制（attention）在长文本场景下计算量随上下文长度平方增长，成为 Agent 处理长文档、长代码库的主要延迟瓶颈。线性注意力（Linear Attention）是一种降低这个成本的架构变体，但工程优化一直落后于标准注意力。

问题：现有线性注意力实现在实际硬件上的效率不理想，在小模型和多卡并行（tensor parallel）场景下尤其明显。

解决方案：Alibaba/Qwen 团队用 TileLang（一种面向 GPU kernel 优化的领域特定语言）实现 FlashQLA，引入门控驱动的自动卡内通信（gate-driven automatic intra-card CP）、代数重构和融合的 warp 专用 kernel。前向速度提升 2–3 倍、反向提速 2 倍，在小模型、长上下文、多卡并行场景下收益最大。明确定位为面向个人设备上的 agentic AI 设计。

价值：长上下文 Agent 在边缘设备（手机、本地服务器）上运行的成本门槛进一步降低。

未来方向：与主流推理框架（vLLM、llama.cpp 等）的集成，以及在多模态长序列场景下的表现。

Latent Space / AINews

Zhipu AI GLM-5 服务复盘：KV cache 竞争条件、HiCache 同步 bug、LayerSplit 提升 prefill 吞吐 132%

现状：超长上下文的 Agent 服务（如代码 Agent 要在几十万 token 的代码库里工作）对推理服务系统的稳定性要求极高，任何设计缺陷都会在高并发下暴露。

问题：KV cache（键值缓存，存储推理中间状态的显存结构）在并发请求下出现竞争条件（race condition，多个进程同时抢占同一资源导致状态错误）；HiCache（分层缓存系统）有同步 bug 导致缓存失效；prefill（预填充，模型读取输入阶段）是长上下文服务的主要延迟瓶颈。

解决方案：Zhipu AI 发布了 GLM-5 服务的工程复盘，描述了如何定位和修复这些生产环境中的实际 bug，并引入 LayerSplit（将 prefill 计算拆分到多个层并行处理），报告 prefill 吞吐提升最高 132%。

价值：这类工程复盘对任何在做生产级推理服务的团队都是直接参考——比学术 benchmark 更贴近真实踩坑路径。

未来方向：长上下文服务的 KV 管理和 prefill 优化还有大量工程空间；与 vLLM 等开源框架的协同优化是行业方向。
