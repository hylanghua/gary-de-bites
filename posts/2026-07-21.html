Google「Frozen v2」：把 Gemini 架构烧进芯片，推理效率目标 6-10 倍

《The Information》7 月 20 日报道，Google 正在开发一款代号「Frozen v2」的服务器芯片（server chip，数据中心专用处理器），把 Gemini 的神经网络架构（neural-network architecture，模型处理信息的基本电路设计）直接硬编码进芯片电路，而不是像 TPU 那样运行任意模型。这样做的代价是失去灵活性，收益是大幅节省数据移动（data movement，芯片内存与运算单元之间搬运数据的开销），Google 内部预期推理效率比现有 TPU 提升 6-10 倍。模型权重仍可更新，但架构本身被固定。目标部署窗口为 2028 年，Google 尚未公开确认该项目。

这个方向的含义远不止于效率：它意味着 Google 在押注 Gemini 的基础架构在未来几年不会发生颠覆性变化。把模型和芯片深度绑定，是一场对模型架构稳定性的大额赌注——赢了省下天量算力成本，输了就是一批废铁。

AI 方向观点

Guillermo Rauch（Vercel CEO，rauchg）：AI 时代最大的教训是「一切皆代码」

Rauch 在 X 上发布了一个他认为是当前 AI 时代最核心的洞察：「AI 的最大教训是，一切都是代码（everything is code）。」逻辑是：AI 时代之前，软件工程师是代码的守门人，能写代码的人才能让想法变成现实。一旦自然语言可以生成代码，所有流程、所有工作流、所有规则，都可以被表达为程序并自动执行。这不只是「写代码更快了」，而是代码本身的边界在扩张——以前只能用人工流程处理的事，现在可以变成可执行的指令。

作为 Vercel 的 CEO，Rauch 站在 AI 基础设施层观察这一变化，他看到的不是某个具体工具的胜负，而是一次底层范式的转移：会不会「把流程变成代码」，将成为未来几年区分团队效率的核心能力。

「一切皆代码」是一句语气轻描淡写的话，装的是一个重量极大的预判：组织效率的分水岭，将是谁能把自己的工作变成可自动运行的程序。

Aaron Levie（Box CEO，levie）：多模型 Agent 系统是 AI 的明确未来方向

Levie 在 X 上明确表态：多模型 Agent 系统（multi-model agentic systems，即用多个不同模型协作完成复杂任务的架构）是 AI 发展的确定性未来。理由是，没有任何一个单一模型可以在所有任务维度上同时最优——不同模型有不同的强项（推理、代码生成、视觉、速度）。未来的 AI 工作流将是：一个调度层决定每步任务该调用哪个模型，不同模型各自处理最适合自己的子任务，最终结果再聚合起来。

这和他此前关于「token 价格越低、需求越高」的论点一脉相承：当模型本身已经近似商品化，「如何编排多个模型」就成了新的稀缺能力，企业级 AI 平台的核心价值也将在这里体现。

多模型编排不是工程选择，是业务逻辑——谁能把对的模型用在对的子任务上，谁就能把 AI 成本压到地板、把输出质量拉到天花板。

产品与商业

纯银：需求爆兵——互联网传统业务几乎不可能实现的目标

纯银今天这篇是对「AI Coding 会不会带来需求爆兵（大规模快速上线）」这个问题的正面拆解，结论很泼冷水。他在犬校的调查发现：程序员个人提效了 3X-5X，但产品发版速度几乎没有明显变化。原因不是技术，是结构。

老项目有历史债，AI Coding 融合成本极高；更关键的是，程序员和设计师没有动力配合。爆兵意味着提效，提效意味着砍 HC（headcount，人力编制），没有人愿意亲手为自己挖坑。纯银还识别出一个关键人才缺口：真正能推动爆兵的人必须同时懂业务、懂 Coding、还要有权力，而这三者在绝大多数公司里不在同一个人身上。

他引用了犬校同学 Mellos 的「发电机悖论」类比：19 世纪末电动机诞生后，工厂主把中央蒸汽机换成电动机，生产率毫无提升；直到 30 年后工厂意识到需要把动力分布式化、推倒旧的厂房布局，才有了福特流水线。AI 对互联网组织的改造也要走这条路：不是「换引擎」，而是「重建整座工厂」。但旧工厂自己做不到——「拒绝自杀」有八百种理由搪塞。

他的结论是：真正的爆兵只发生在两种情景下——创始人既懂业务又懂 Coding 的新团队（AI native），或者有人「下黑手」强行打碎旧习惯的老团队。两种都是极少数。

「程序员提效，产品不加速」这个悖论揭示的不是技术问题，而是组织惰性：老结构里没有任何人有动力亲手终结自己的工作方式。

Every.to：AI 原型泛滥让 Whoop 决策陷入瘫痪，快速建出来不等于决策变好了

Hilary Gridley 曾在可穿戴设备公司 Whoop 负责产品，她在 Every.to 的这篇文章里复盘了一个「AI 原型反噬」的案例：当 Bolt 和 Replit 这类工具让人下午就能搭出原型之后，Whoop 的 PM 们进入了一场原型狂欢——想法从文档变成了屏幕，但没有人停下来想「这些原型是为了做什么决定」。结果是：原型从决策工具变成了推销工具，产生了大量感觉有用但实际无法比较的东西，反而让产品会议更难开、决策更难做。

她的核心洞察是：当建原型变得和画草图一样便宜，原来「用原型降低高成本决策风险」的逻辑就失效了。现在需要的是先想清楚「这个原型是用来证明还是证伪什么假设」，再造原型，而不是先造再讨论。

「建造速度的加速」和「决策质量的提升」是两件不同的事——当 AI 让所有想法都变得可见，你反而需要更严格的框架来决定值得追究哪些想法。

AI 进展

Remember When It Matters：主动记忆 Agent 为长时程任务提供实时记忆插入

现状：长时程 Agent（long-horizon agent，需要完成步骤数超过几十步、跨越大量上下文的复杂任务的 AI 系统）在执行中必须持续追踪任务要求、环境事实、已失败路径等状态，但这些信息随着任务推进逐渐被埋进过长的对话历史，或被推出上下文窗口（context window，模型单次能「看到」的最大文本量）。

问题：大多数解法是「在上下文快满时压缩历史」，但这会丢失精确的证据、文件路径和关键中间状态，而不是在决策需要的时刻主动补充。

解决方案：本文提出一个独立运行的「记忆 Agent」，与执行任务的主 Agent 并行，持续读取近期轨迹并维护结构化记忆库。每当主 Agent 做出新决策前，记忆 Agent 判断是否需要注入一条「记忆提醒」，把关键历史上下文重新放回主 Agent 的视野。整套系统无需修改主 Agent 本身。

价值：在 Terminal-Bench（终端任务基准）上提升 pass@1 成功率 +8.3 个百分点，在 τ²-Bench（多轮 Agent 基准）提升 +6.8 pp，对弱模型和强模型均有效。

未来方向：记忆 Agent 与执行 Agent 的联合训练，以及在工具调用密集型任务中的应用。

arXiv 2607.08716

Self-GC：像垃圾回收一样自治管理 Agent 上下文生命周期

现状：Agent 在完成长任务时，上下文窗口里积累着用户请求、Shell 输出、浏览器证据、中间产物、技能状态和局部计划等大量内容，这些「上下文对象」直接决定了成本、延迟和任务质量。

问题：现有系统主要依赖时间顺序剪枝（chronological pruning，按时间先后删旧内容）或接近上下文上限时的一次性摘要，前者无法感知哪些内容对未来仍然重要，后者会丢失可编辑的精确制品（如文件路径、命令行输出）。

解决方案：Self-GC（Self-Governing Context，自治上下文管理，GC 刻意致敬编程语言里的垃圾回收概念）把上下文对象分类为不同生命周期，系统实时判断哪些「对象」可以安全回收（压缩或删除），哪些必须保留到任务结束，并根据未来依赖关系而不是时间顺序做决策。

价值：在多个长时程 Agent 基准上改善了成本效率和任务成功率，同时减少了不必要的重新搜索。

未来方向：跨 Agent 共享上下文库，以及与外部记忆系统的集成。

arXiv 2607.00692

MSCE：记忆与技能协同演化，Agent 从历史轨迹中提炼可复用策略

现状：Agent 每次完成任务都会留下一段执行轨迹（trajectory，从任务开始到结束的完整操作序列），其中包含了工具调用顺序、错误诊断和成功路径等大量经验，但标准框架不会把这些经验系统化沉淀。

问题：Agent 在面对相似任务时往往从零开始推理，既浪费算力，又容易重蹈已知失败路径。

解决方案：MSCE（Memory-Skill Co-Evolution，记忆-技能协同演化）把 Agent 的经验分为三层：有依据的步骤轨迹（grounded step traces）、可复用的程序策略（procedural policies）和声明式的环境认知（declarative environmental cognition）。三层之间动态协同更新，无需额外训练（training-free），只需在推理时调用历史库。

价值：在长时程 Agent 基准上相比无记忆基线有显著提升，且随任务积累持续改善——Agent 越「老」越好用。

未来方向：跨任务类型的技能迁移，以及多 Agent 团队间共享技能库的架构。

arXiv 2607.16621

TimeLens（CVPR 2026）：用 RLVR 训练多模态 LLM 做视频时间定位

现状：视频时间定位（Video Temporal Grounding，VTG，给定一段自然语言描述，在视频里找到对应的时间段）是多模态大模型（MLLM，同时处理文字和视频的语言模型）的公认短板：现有基准数据质量差，时间戳编码方式不统一，开源模型的性能普遍落后于闭源方案。

问题：数据质量问题导致在"垃圾数据"上训练的模型无法真正理解视频时序，而缺乏高质量数据集又让研究者无从评估真实能力。

解决方案：TimeLens 从数据质量和算法设计两个维度同时入手：提出并验证了现有 VTG 基准中的质量缺陷，构建了 TimeLens-100K 高质量数据集，并在 Qwen2.5-VL 和 Qwen3-VL 基础上使用 RLVR（带可验证奖励的强化学习，即只有生成的时间戳真的准确才给正向奖励）配合改进的时间戳编码策略进行训练。已被 CVPR 2026 接收。

价值：在开源 VTG 模型中达到最优性能；TimeLens-100K 数据集、代码和模型权重完整开源。

未来方向：将时间定位能力扩展至超长视频，以及与搜索 Agent 结合实现视频内容的结构化检索。

AgenticSTS：有界记忆约束下的长时程 Agent 测试平台

现状：评测长时程 Agent 的主流做法是用开放的对话历史（即把所有过往交互都塞进上下文），但这掩盖了 Agent 在有限记忆下的真实能力，也与实际部署场景不符。

问题：缺少一个明确约束记忆边界的标准化评测平台，导致研究者无从比较「在同等信息约束下不同 Agent 的决策质量」。

解决方案：AgenticSTS（Agentic Structured Task Sequences with bounded memory）提出有界记忆合约（bounded-memory contract）：每次决策前，Agent 只能访问一条由结构化检索组装的新消息，不允许直接追加原始历史。这强制要求 Agent 必须学会主动整理和检索记忆，而不是依赖无限上下文。

价值：提供了一个可复现的测试框架，帮助区分「真正理解任务」和「靠上下文积累蒙混过关」的 Agent。

未来方向：与主动记忆 Agent（如 Remember When It Matters）结合，在约束环境下测试记忆注入策略的效果。
