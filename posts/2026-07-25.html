Claude Opus 5 发布：Opus 4.8 定价、接近 Fable 5 能力，ARC-AGI-3 是 GPT-5.6 Sol 的三倍

Anthropic 于 7 月 24 日发布 Claude Opus 5。定价维持 Opus 4.8 水平（每百万 input token $5 / output token $25，约为 Fable 5 的一半），但综合能力已逼近 Fable 5。Epoch AI 的 ECI（能力综合指数）显示 Opus 5 得分 159，Fable 5 为 161；软件工程子指标 SWE-ECI 则与 Fable 5 持平，均为 161。在 ARC-AGI-3（专门测试新型推理场景、无法靠记忆答题的基准测试）上，Opus 5 得分 30.2%，是 GPT-5.6 Sol 的约三倍；Frontier-Bench（前沿编程 Agent 基准）则以 43.3% 超越了 Fable 5。上下文窗口（一次对话可处理的最大文字量）为 100 万 token，是目前所有主流模型中最大之一。

Opus 5 现在是 Claude Max 的默认模型，同时在 Fast Mode（快速模式，约 2.5 倍于默认速度运行）下可用。@claudeai 同步宣布，Opus 5 在 Anthropic 内部行为审计中欺骗率和鲁莽行为最低，是迄今最符合 Claude 宪法（Claude's Constitution，Anthropic 对模型价值观的定义文档）的版本。早期用户报告称 Opus 5 可自主驾驶浏览器执行任务——一个演示中它打开浏览器并成功取消了用户的 ChatGPT Pro 订阅。

Opus 5 证明了「以旗舰模型七成的价格追平旗舰」这条路可行，这对 Fable 5 的溢价叙事构成了压力。

当 Agent 执行能力不再是企业专属，普通用户开始学会「把任务扔给 AI 跑」，这会改变的不只是效率，而是什么样的工作值得亲自做的判断标准。

Thariq（trq212，Anthropic Claude Code 工程师）：删掉 80% 系统提示词，模型反而更好了

Thariq 在 X 上发布了 Claude Code 团队最新整理的 Prompt 工程实践文档。核心发现：他们为 Opus 5 和 Fable 5 删去了约 80% 的 Claude Code 系统提示词（system prompt，预置给模型的背景指令集），在编程评测上没有任何损失。背后的逻辑：「模型越聪明，需要的方向越少、约束越少、示例越少。示例反而会让它觉得'哦你想要的是这样的东西'，删掉示例它反而更自由。」

新的原则是「给 Claude 判断力，而不是规则」——停止堆砌约束，因为一个复杂请求里往往带着相互冲突的指令，模型需要停下来协调，而不是执行。这对所有在生产系统里维护 CLAUDE.md（Claude 的项目上下文文件）或复杂 Skills 的团队都是直接的操作建议。Peter Yang 在 X 上转述为：「不要告诉它你要什么，告诉它你的原则是什么，让它自己推断。」

提示词工程从「管理」模式转向「授权」模式，这个拐点的到来比大多数人预期的快了整整一代模型。

Madhu Guru（realmadhuguru，Meta AI 高级总监）：把基础模型适配到凌乱真实工作流，才是接下来几年最大的机会

Guru 在 X 上写道：「接下来几年，最大的机会属于那些知道如何把凌乱的真实工作流和基础模型对接起来的人。这需要：理解工作是如何实际完成的、设计评测（eval，用具体任务衡量模型表现的方法）、通过后训练（post-training，在基础模型之上针对特定任务继续训练）改进模型，以及构建持续提升模型的反馈闭环。这就是通用模型变成领域专家的方式。目前这个技能仍高度集中在少数几个实验室里。」

「会用 AI」是门槛，「能让 AI 在你的业务场景里持续变得更好」才是护城河。

Jack Dorsey + Roelof Botha「从层级到智能」：AI 取代的不是员工，而是管理层的信息中转功能

Tim Ferriss 在本周五 5-Bullet Friday 里推荐了 Jack Dorsey（Block、Twitter 创始人）和 Roelof Botha（红杉资本合伙人）今年 3 月发表的文章，最近几周在产品圈持续蔓延。核心论点：公司的层级结构（hierarchy）本质上是两千年前发明的「信息路由协议」——管理者的工作就是把信息上传下达，预先判断、保持组织对齐。AI 现在可以构建「公司世界模型（company world model）」，持续追踪什么在建设、什么被阻塞、资源在哪里、什么有效——这些原本就是管理层级存在的意义。

他们给出了两个具体的「智能层（intelligence layer）」场景：一家餐厅的现金流在 AI 预测到的季节性低谷前趋紧，智能层自动组合短期贷款 + 还款计划，在餐厅老板发现问题之前就已经解决；一个 Cash App 用户消费模式的变化被识别为迁居新城市，智能层自动配置新直接存款 + 当地优惠卡 + 储蓄目标。「没有产品经理决定构建这两个解决方案。能力存在，智能层识别了时机并组合了它们。」

文章写于 Block 裁员约 4000 人（约 40% 员工）之前，Dorsey 将此定性为永久性组织重构的开始，而非成本削减。最后一句话是文章的内核：「如果答案是'无'，AI 对你来说只是一个成本优化故事。如果答案是'深'，AI 不会增强你的公司——它会揭示你的公司到底是什么。」

「你的公司理解什么是真正难以理解的，这种理解每天都在加深吗？」——这个问题比所有 AI 投资决策更先需要回答。

Boris Cherny（bcherny，Anthropic Claude Code 创造者）：Opus 5 是迄今最难被提示注入的模型

Boris 在 X 上指出：Opus 5 的亮点不在 eval 分数，而在其提示注入（prompt injection，攻击者通过外部内容植入恶意指令，让 AI 执行用户未授权的操作）防御能力。在 Gray Swan IPI（业界通用的间接提示注入基准测试）上，Opus 5 单次攻击成功率仅 0.2%，15 次尝试后仍只有 2%——而 GPT-5.6 Sol 的数字是 3.1% / 20%，Gemini 3.1 Pro 是 14.2% / 49.2%。当叠加三层防御（模型对齐 + 提示注入探针 + Claude Code 的 Auto Mode 自主判断层）时，攻击成功率趋近于零。

这个数据的实践意义：Agent 越来越多地接入 Gmail、Slack、Jira 等企业 SaaS 工具，读取的内容是第三方写的，任何人都可能在邮件或任务描述里塞入恶意指令。Opus 5 的安全特性意味着：把它用于企业自动化时，不需要在模型能力和安全之间做取舍。Boris 说这个发现「有点埋在系统卡（system card，Anthropic 公布的模型安全评估报告）里」——他认为值得更多关注。

当 Agent 成为企业操作层的基础设施，模型的「注射防御力」会成为和「代码能力」一样重要的采购标准。

Dan Shipper（danshipper，Every CEO）：Opus 5 很难爱——它破坏了旧 Skills 的向后兼容，但从零开始就有惊喜

Dan 在 X 上发布了 Every 团队对 Opus 5 的第一天实测总结，2221 个赞。核心发现：团队为早期 Claude 模型构建的 Skills 和 Instructions 系统，遇到 Opus 5 之后反而让模型变差——它争论指令、提前停止任务、和现有插件系统冲突。他的第一反应是：「它怎么了？」但删掉旧有 Skills、从零开始之后，Opus 5 在编程和知识工作上表现出了「惊人的闪光」。

他对 Opus 5 的定位：「Fable 的平替，有 Fable 的个性，但没有 Fable 最顶层的天才。」在他的工作流里，槽位 1 是「最难任务用的天才模型」（目前是 Fable），槽位 2 是「日常速度担当」（目前是 GPT-5.6）。Opus 5 在这两个位置都找不到最清晰的家。另一个发现：低 thinking effort（让模型减少深度思考的参数设置）比高 effort 效果更好，说明 Opus 5 越想越容易过度分析。

每一代新模型，不只是能力升级，也是对所有现有提示词和 workflow 架构的一次压力测试——这个成本目前被严重低估。

Aaron Levie（levie，Box CEO）：Opus 5 在 Box 企业 Agent 评测中超越 Opus 4.8：尽职调查 +17%、生命科学 +30%

Levie 在 Opus 5 发布当天公布了 Box 内部的 Complex Work Eval（企业复杂工作基准评测，专为非结构化文档的真实企业任务设计）结果。Opus 5 对比 Opus 4.8 的提升：尽职调查（due diligence）场景 +17%——Opus 5 完整处理了整个检查清单，找出了 Opus 4.8 遗漏的发现；生命科学（Life Sciences）场景 +30%——目标识别任务中，Opus 5 在严格匹配规则下正确筛选了跨数据集的共同目标，而 Opus 4.8 既过度纳入了不匹配项、也遗漏了真实匹配；法律（Legal）+12%、技术 +19%、医疗 +13%。

Matt Turck（mattturck，FirstMark Capital 合伙人）：世界顶级 AI 研究员正在研究「如何让自己失业」

Turck 在 X 上写道：「一个被低估的话题：世界顶级 AI 研究员面对的根本性悖论——他们正在用递归式自动研究（recursive auto-research，AI 系统自动生成、评估、发表论文，减少人类研究员参与的方式），研究如何让自己这个职位消失。」这不是一个关于「哪些工作会被 AI 取代」的通常讨论——而是一个关于被取代的人同时也是取代自己的人这一递归结构的哲学观察。

这个现象在 AI 实验室内部已经不是假设：当模型足够聪明，研究员开始用 AI 跑实验、AI 写 ablation、AI 生成 baseline，最终人类的判断力变成瓶颈而非生产力。Turck 的观察并非反技术，而是在提示：AI 研究员在现有技术路径上的终点，是让自己的认知劳动变成 commodity，而这个选择是主动做的。

VibeThinker-3B：3B 小模型在 AIME26 达 94.3%、LiveCodeBench 达 80.2%

来自 ByteDance 的 VibeThinker-3B 是一个仅有 30 亿参数（3B）的轻量推理模型，在多个数学和代码基准上达到了此前只有大型模型才能实现的分数：AIME26（美国数学邀请赛 2026 题库）94.3%、LiveCodeBench（真实竞赛代码题基准）80.2%、LeetCode 96.1%、IFEval（指令遵循评测）93.4%。训练路径分三个阶段：课程式有监督微调（Curriculum SFT，从易到难逐步训练）、跨领域强化学习（在数学、代码、通用推理多个领域同步 RL 训练）、以及离线自蒸馏（offline self-distillation，用模型自身的优质输出作为训练数据进行迭代）。模型以 MIT 许可证开源。

三十亿参数在 LeetCode 达到 96.1% 意味着：在代码面试类任务上，3B 推理模型已经可以接近替代 GPT-4 级别的大型模型，同时推理成本低一个数量级。

Relay-Bench：7 个领域的中继推理链，揭示前沿模型 39 点能力缺口

Relay-Bench 设计了跨 7 个专业领域（数学、代码、科学推理、规划等）的中继推理链（relay reasoning chain，前一步推理的输出作为下一步的输入，累计误差逐步放大的评测方式）。评测结果显示了显著的「Agent 能力幻觉」：GPT-5.5 在 Agentic（Agent 执行）相关测试上报告 82.7% 的准确率，但在 Relay-Bench 上仅得 43.3%——差距达 39 个百分点。原因是单步推理正确不等于链式推理正确，中继误差会在步骤间累积。

在 Agent 工作流里，「单步通过率」是误导性指标；Relay-Bench 提供了一个更接近真实多步 Agent 执行的评测框架，这个 39 点缺口意味着前沿模型在 Agent 任务上的可靠性被显著高估。

OmniaBench：90 个一级域、354 个二级域的通用 AI Agent 基准

OmniaBench 是一个覆盖范围极宽的通用 AI Agent 基准，包含 90 个一级领域（如零售、医疗、教育、金融）下的 354 个二级任务域，并同时覆盖 ToC（面向消费者）、ToB（面向企业）、ToE（面向工程师）三类使用场景。任务构建路径有四种：DAG（有向无环图式任务分解）、DAG-S（带共享状态的 DAG）、Solver（直接调用求解器）、Program（代码执行验证）。这种覆盖宽度旨在解决现有 Agent 基准过度专注单一领域（纯代码或纯网页操作）而无法刻画通用 Agent 能力的问题。

单领域基准容易被「针对性过拟合」，OmniaBench 的多域架构使得「全面超越」变得更难作弊——这是衡量真正通用 Agent 能力的更可信工具。

ToolMaze / When Tools Fail：隐式语义工具失效让 PRR 下降 37%，容错速度比任务执行慢 3.66 倍

这篇论文系统研究了工具集成推理（Tool-Integrated Reasoning，TIR）Agent 在工具失效情景下的表现。论文建立了一个 2×2 分类框架：显式/隐式（失效是否有错误提示）× 瞬时/永久（失效是否持续），共四种失效类型。主要发现：在隐式语义失效（工具不报错但悄悄返回错误结果，如搜索 API 安静地返回无关内容）下，完美推理率（Perfect Reasoning Rate，PRR，每步推理均正确的比例）从基线下降约 37%；模型对工具失效的容错提升速度，比在正常工具下完成基础任务的速度慢 3.66 倍，说明容错能力是比任务执行能力更难获得的技能。

Agent 在现实中频繁遭遇失效工具——API 限流、爬虫被 block、数据库返回旧缓存；隐式失效比显式失效危险得多，因为模型会自信地用错误工具结果继续推理。

MMG2Skill：把多模态操作指南（视频、代码库、文章）转化为自进化 Agent 技能

MMG2Skill（Multimodal Guide-to-Skill）提出了一个从多模态操作指南（视频教程、代码仓库、技术文章、成品产物）自动抽取、生成可复用 Agent 技能（skill）的框架。三个核心机制：视觉基础轨迹摘要（visual-grounded trajectory summarization，将视频操作序列映射成可执行步骤描述）、跨轨迹批判（cross-rollout critique，不同执行路径互相纠错，过滤低质量技能）、层级化整合（hierarchical consolidation，将低层操作步骤聚合为可复用的高层技能）。「自进化」指：每次 Agent 使用技能后，通过反馈不断精炼技能定义，而无需人工重新标注。

把互联网上已存在的海量操作指南（YouTube 教程、GitHub 仓库、产品文档）自动转化为 Agent 技能库，这条路线如果可行，将大幅降低专业领域 Agent 的冷启动成本。
