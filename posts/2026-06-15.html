AI 方向观点

Aaron Levie（Box CEO）：这次封禁，赢家是开源权重模型

Levie 在 Fable 封禁后直接写道："如果某个模型随时可能对你的国家用户或企业不可用，那依赖任何特定国家的模型都会带来真实风险。其他国家现在有更强的动机去发展主权 AI，而他们最可能依赖的答案是开源权重模型——目前这类模型大多不来自美国。"

他的逻辑：美国如果在模型层而不是应用层搞管控，会把其他国家推向开源，反而削弱美国在这个技术栈上的领导地位。同时他也看到了另一面：应用层会因此获得巨大价值，因为企业必须把自身 IP、知识和数据建成可迁移的 loop 架构，才能在模型随时可能被切断的世界里生存。

这是 Fable 封禁最清醒的商业分析——它不只是监管事件，是一次架构选择的压力测试。

Swyx（Latent Space / Cognition）：ultracode 的真正结构是"智能子例程"

Swyx 写道："havent seen many people outside anthropic ultracode yet. this thing is scarily good at burning tokens but you need to set up your repo to parallelize properly to make use of the fanout that i think subagents are best at."

他的核心判断：subagent（子代理，即 Agent 调用 Agent 的模式）的本质是"可判断的子例程"（intelligent subroutines）。一旦你意识到大量知识工作就是一层层的 yak-shaving（解决问题前必须先解决的前置问题），需要些许判断和智能，你就会理解动态工作流并不只适合写代码任务——它适合所有需要分叉和汇聚的思维型工作。

从"prompt 更好"到"并行 subagent"，这是 AI 辅助工作方式的一次结构性升级，不是技巧迭代。

X @swyx

Garry Tan（YC CEO）：AI 时代的新精英是会跑通多阶段 Agent 任务的人

Garry Tan 写道："The next generation of young people who change the world will almost certainly be the people who are most adept at making long-running multi-stage multi-team agent tasks work extremely well, and at high volume and across every part of their personal and work lives."

这句话的分量在于它重新定义了"AI 素养"的门槛。不再是"会写 prompt"，不再是"熟悉 API"，而是能够设计和运维跨团队、跨时间、高容量的 Agent 流程。换句话说：能让机器替你持续工作的人，而不是自己坐在那里提问的人。

这是 YC 在招人标准上的一次隐性更新——Garry 描述的能力集，正在成为下一个时代的基础生产力。

产品与商业

Claude Fable 5 实战评测：视觉超强，PRD 写出来没人看得懂

Lenny's Newsletter 的 Claire 把 Claude Fable 5（Anthropic 首款 Mythos 级公开模型）带进真实的产品工作流，做了一套压力测试：产品规格文档、Agent 流程、设计任务、视觉解析、多 Agent 协作。结果是高度非对称的。

它真正厉害的地方：视觉任务。Claire 让它帮 7 岁孩子制作手写练习单，输出的空间感、排版、留白比 Opus 4.8 好出一截。PDF 解析和文档格式化同样突出。它也像"经验丰富的工程师"一样会把问题多想一圈，100% 确认才动手——有时候这是优点，有时候你只是想要更快的答案。

它明显短板的地方：产品 PRD 和规格文档。写出来细节翔实、技术正确，但密密麻麻，内部交叉引用成堆，几乎没有人能直接拿去用。设计任务同样令人惊讶地差：一次性的设计输出是灰底黑字红色边框，完全没有审美判断。价格也是新台阶：输入 $10/百万 token，输出 $50/百万 token，消耗 token 的速度大约是其他模型的两倍。

Fable 5 是一个高度专业化的工具，用对了场景会让人难忘，用错了场景会让你掏很多钱买到一份没法读的 PRD。

Ted Chiang：AI 意识论是在浪费时间

《降临》原著作者 Ted Chiang 在《大西洋》发表新文，把"AI 是否有意识"这个问题正面拆了。他的核心类比让人难以反驳："对 LLM 可能有意识持开放态度，和对 Microsoft Word 可能有意识持开放态度没什么区别——更准确地说，是每一个包含对话记录的 Word 文档里，都沉睡着若干独立意识，每次打开文件就会唤醒它们。"

Chiang 不是在说 AI 不重要，他是在说：我们提出了一个根本无法被证伪也无法被证实的问题，然后为此消耗大量精力。在他看来，LLM 是极其强大的统计工具，这个定性本身已经足以让我们认真对待它，不需要额外给它套一层意识的光环来证明它值得被对待。

Chiang 把意识讨论变成了哲学上的奥卡姆剃刀：多余的问题，砍掉。

Zara Zhang（策展人 / Follow-Builders 作者）：技能是做出来的，不是写出来的

Zara Zhang 发了两条连续推文，说得很干净："You don't make a good skill by writing a skill. You make it by doing the thing, fixing it 20 times, then telling the AI to bottle up everything you just did."第二条更短："You make a skill by ending with one, not starting with one."

这两句话针对的是一个常见误区：很多人在设计 AI 技能（skill，即给 Claude Code 这类工具的可复用指令模块）时，试图一次写好，然后让 AI 去执行。但技能的本质是蒸馏出来的经验，不是设计出来的预案。先做、做坏、修 20 次，再回头让 AI 把这 20 次的知识打包成可复用的模块——顺序反过来，结果完全不同。

这是工程直觉，也是工艺哲学：只有做过的事，才有资格被提炼成流程。

AI 进展

Agentic Software: How AI Agents Are Restructuring the Software Paradigm

现状：传统软件工程的研究对象是静态源代码，控制逻辑由人预定义，人的角色是代码作者。

问题：当 LLM 成为推理引擎，Agent 在运行时动态生成并丢弃代码，这套范式已经不能描述正在发生的事情。

解决方案：本文（arXiv 2606.05608，2026 年 6 月）提出"Agentic Engineering"作为软件工程的延伸学科，研究对象是 Agent 系统，控制模型是 LLM 驱动的，人的角色变成"意图架构师"。文章分析了 SWE-bench Verified、EvoClaw 等基准证据，给出从现在到"自进化 Agent 生态"的四阶段路线图。

价值：不是又一篇"AI 写代码很厉害"的文章，而是在认真回答：这件事到底在改变什么的结构性问题，给从业者提供框架语言。

未来方向：如何在 Agent 系统大规模落地的过程中，重建工程学科的评估标准和治理方法。

arXiv 2606.05608 · June 2026

Externalization in LLM Agents: Memory, Skills, Protocols & Harness Engineering

现状：LLM Agent 越来越多地通过改造运行时环境而非修改模型权重来获得新能力。

问题：这种"外化"（externalization）现象散落在各个子领域，缺乏统一的理论框架。

解决方案：本文（arXiv 2604.08224，2026 年 4 月，Chenyu Zhou 等 20 余位作者）提出四类外化：记忆（跨时间保持状态）、技能（外化程序性专长）、协议（外化交互结构）、Harness 工程（协调前三类的治理层）。四类外化本质上是把模型不擅长的认知负担迁移到外部基础设施。

价值：给了 PM 和工程师一套讨论 Agent 架构的标准词汇，"我们缺的是 Harness 层"比"感觉 Agent 不稳定"能推动更有效的对话。

未来方向：如何让 Harness 层标准化，使得不同框架的 Agent 可以更容易地组合。

arXiv 2604.08224 · April 2026

Agentic Reasoning for Large Language Models — 综述

现状：LLM Agent 的推理能力研究快速增长，但各方向之间缺乏统一的分类框架。

问题：规划、工具使用、搜索、记忆、反馈驱动适应、多 Agent 协调——这些能力如何系统地整合进同一个 Agent 架构？

解决方案：本文（arXiv 2601.12538，Tianxin Wei 等）提出统一视角，梳理了 agentic 推理如何驱动 LLM 在不同动态环境中执行复杂任务，并引入了 AwesomeAgentic Reasoning 资源库（GitHub），供从业者系统追踪进展。

价值：不是前沿突破，是地图——在 Agent 研究百家争鸣的当下，一张能帮你定位自己在哪里的地图非常稀缺。

未来方向：多 Agent 协调和长期规划仍是最难啃的硬骨头。

arXiv 2601.12538 · January 2026

Route-and-Reason: 强化学习路由实现 LLM 节能推理扩展

现状：扩展 LLM 推理能力的标准做法是用更大的模型或更多的计算量，导致能耗和成本线性增长。

问题：并不是每个请求都需要同等算力，过度均匀分配资源是巨大浪费。

解决方案：Route-and-Reason（ACM Web Conference 2026）用强化学习训练一个路由器（router），根据请求的难度和类型动态分配给合适的模型。简单请求用小模型，复杂推理用大模型，整体能耗显著降低而精度保持不变。

价值：对于要在成本可控的条件下部署 LLM 的企业，路由层是比换模型更容易获得的节能手段。

未来方向：路由决策本身的延迟如何压缩，以及跨供应商路由的可行性。

ACM Web Conference 2026

VPG-EA: 变分后验引导的高效 LLM 推理

现状：LLM 的推理链（chain-of-thought）越来越长，很多 token 实际上对最终答案没有贡献，造成巨大浪费。

问题：如何区分"有效推理路径"和"伪高效路径"，并让模型自动学会只走前者？

解决方案：VPG-EA（arXiv 2605.11019，2026）采用参数共享的双流架构，分别建模后验分布和先验策略，通过跨视角评估过滤掉伪高效路径，再用变分蒸馏把高效模式传递给模型，整体推理 token 消耗下降而准确率不降。

价值：对于需要控制推理成本的应用场景（比如高频调用的 Agent），这类方法比换模型更快见效。

未来方向：与路由（如 Route-and-Reason）结合，构建端到端的节能推理系统。
