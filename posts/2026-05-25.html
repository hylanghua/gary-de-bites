Anthropic Mythos 1 迫近公开：Glasswing 项目已发现逾万个高危漏洞

Anthropic 的 Mythos 安全模型（一款专门用于发现和利用软件漏洞的 AI，有别于对话用的 Claude）正在受控的伙伴机构内小范围部署，累计已发现超过 10,000 个高危或严重漏洞。其中一项发现尤为引人注目：Mythos Preview 完全自主地找到并利用了 FreeBSD 操作系统中一个存在长达 17 年的远程代码执行漏洞，攻击者可借此在运行 NFS（网络文件系统）的机器上获取 root 权限。

Anthropic 表示，一旦建立起更完善的安全措施，将通过 Claude Code 和 Claude Security 向更广泛受众开放 Mythos。这款模型在受限期间已短暂出现在 Claude Code 界面内又消失，引发外界广泛关注。Anthropic 正在把 AI 的攻击能力包装成防御基础设施。

Google Antigravity 2.0 亮相：96 个子 agent 12 小时搭出操作系统，$1K 以内

Google 在 I/O 2026 上正式推出 Antigravity 2.0，这是一个以 Gemini 3.5 Flash 为主力模型的独立 AI 编程 agent 桌面应用，完全脱离 IDE 运行。最引人瞩目的 demo：96 个并行子 agent 在 12 小时内从零构建了一个可运行的操作系统，总 token 消耗约 26 亿，成本不超过 1,000 美元，且能运行 Doom 游戏。

AI 方向观点

Aaron Levie（Box CEO）：CEO 的 AI 精神错乱，源于与真实工作的距离

Levie 写道，CEO 特别容易陷入 AI 精神错乱，因为他们离真实交付"最后一公里"太远。当他们自己玩 AI 时，看到的都是 happy path：做出了漂亮的产品原型（但没看见上生产前的代码审查和反复修改）、生成了一份合同（但没经历核对条款和对接历史合同数据的过程）。

于是他们下达宏观 AI 指令，员工则用低努力度的 demo 来应付考核指标。两年后，一家管理层亲自上手 AI 的 startup 悄然颠覆了它。Levie 建议：CEO 应该大量亲自使用 AI，理解 agent 的上行空间和真实代价，而不是停在"看 demo"阶段。

企业 AI 落地的最大障碍，是高层离真实工作太远而产生的认知泡沫。

Thariq（Anthropic Claude Code 工程师）：存量代码库是 AI 最好的蒸馏原料

Thariq 在 Bun（JavaScript 运行时）将自身重写为跨平台版本的背景下写道：遗留代码库（legacy codebase）将成为极有价值的资产，用来把代码"蒸馏"成新形态。他的推论是：每款游戏都应该跨平台，所有老软件都应该能在 Web 上运行，COBOL（金融行业仍在大量使用的一种 1959 年编程语言）时代不再需要了。

AI 对软件的最大价值，不是生成新代码，而是让几十年的遗产代码重获生命。

产品与商业

Felix Rieseberg（Anthropic工程师）：把收件箱当数据库，live artifacts 让仪表盘永不过期

Felix Rieseberg 是 Claude Cowork 和 Claude Code Desktop 的工程负责人。在 Lenny 的 How I AI 播客中，他展示了几个颠覆性工作流。一个具体例子：搬家时需要整理家具，他让 Claude 扫描多年来的购买收据邮件，自动建立家具清单，然后直接生成可交互的 3D 楼层平面图——维度都是真实的，因为收据里有型号，型号里能查到尺寸。

更通用的原则是"升一层抽象，然后再升一层"：每次发现自己在做无聊工作，就问 Claude 能不能做，再问 Claude 能不能自己搞清楚要做什么。Live artifacts（实时刷新的可视化组件，与 Claude 对话后直接从已授权的服务如 Gmail、Calendar、Spotify 拉取最新数据）是他认为最被低估的功能：个人仪表盘一旦连上 live artifacts，就再也不需要手动更新了。

模型选择策略：问题定义清晰时用 Sonnet，需要 Claude 帮你理清自己"真正想要什么"时用 Opus。AI 使用的心理障碍不是技术，而是用户还没建立起"有问题先问 AI"的肌肉记忆。

Peter Yang（Roblox PM）：别先 build MVP，先 build 能 build MVP 的系统

Yang 的嘉宾 Ryan Carson 已融资 200 万美元但明确不打算招人，他的逻辑是：先把每个岗位的工作做一遍、感受痛点，再判断能否用 agent 取代，而不是直接招人。实操工具：OpenClaw 做 AI 首席助理（处理邮件、预约、销售外联），Codex 和 Devin 做 AI 工程团队（趁他睡觉时发货）。

Ryan 的三条原则：花大量时间在前期建立技能文档和流程，之后就能解锁 10 个人的工作量；给 agent 分配真实的邮箱、日历和 GitHub 账号，像对待真实员工一样对待它；先花钱让设计师建立设计系统，之后 AI 能持续生成符合品牌风格的物料。过去"先做 MVP"的范式正在被替换：先建造能制造 MVP 的工厂，再开始生产。

人文与哲学

纯银：AI 应该怎样学会遗忘

纯银从一个旅行攻略的亲身经历出发：用 Gemini 做欧洲行程时，把所有想要的东西一次性塞进 prompt——行程逻辑、目的地总结、景点亮点、交通、门票、营业时间、摄影建议……结果 AI 就"疯了"，交付极为随机。他很快意识到，把约束收缩到最在意的两三件事、给 AI 自由发挥空间，质量反而大幅提升。Gemini 自带的"优化提示词"功能犯了同样的错：看起来更丰富全面，实际上指令过载，交付劣化。

由此引发的延伸思考：AI 的上下文和记忆从来都是应用瓶颈。人类记忆靠"情绪激烈、印象深刻、反复发生"来筛选，这套机制不完美，但节约算力且能持续运行一辈子。AI 并不拥有无限算力，即便未来算力翻千倍，盲目堆 token 的价值也存疑。真正的功课是：怎样对海量历史上下文"抓重点"——用高维度抽象覆写低维度冗余，而不是把什么都塞进 MEMORY 文件（一种让 AI agent 跨会话保存记录的机制）。

"既要又要"对人类不行，对 AI 同样不行。减法总是比加法难，也更重要。

AI 进展

Lance：双流架构统一多模态理解、生成与编辑

现状：现有多模态模型通常把"理解图像"和"生成图像"分开训练，切换任务需要不同模型。

问题：任务割裂导致知识无法共享，图像理解模型不能直接编辑图像，生成模型又缺乏语义理解能力。

解决方案：Lance 通过双流架构（一条流负责语义理解，一条流负责视觉生成）和协同多任务训练，让同一个模型同时处理图像/视频的理解、生成和编辑任务，三类任务互相增益。

价值：统一模型意味着"看图后立即编辑"或"生成后立即理解"可以在单次推理中完成，无需切换工具。

未来方向：扩展到更长视频序列和更细粒度的跨模态编辑任务。

PhotoAgent：带美学判断的 3D 机器人摄影师 agent

现状：拍出好照片需要同时理解 3D 空间位置和主观美学判断，这两者此前由不同系统分别处理。

问题：纯几何方法无法捕捉构图美感，纯 LMM（大型多模态模型）推理又难以转化为精确的相机位置控制。

解决方案：PhotoAgent 用 LMM 驱动的思维链（chain-of-thought）把美学目标转化为几何约束，用解析求解器计算最优初始视角，再通过视觉反馈循环迭代优化，底层用 3D 高斯泼溅（一种实时 3D 场景重建技术）构建逼真内部世界模型。

价值：机器人可在真实场景中自主完成摄影任务，兼顾空间精度和构图美感。

未来方向：向无预建场景模型的真实环境迁移。

HuggingFace Weekly Papers

OpenGuardrails：开源企业级 AI 内容安全与提示注入防护平台

现状：企业部署 LLM 面临提示注入（prompt injection，即通过恶意输入劫持 AI 行为）、越狱（jailbreaking）、恶意代码生成、数据泄漏等多类安全风险，现有防护工具碎片化。

问题：没有统一的开源平台能同时处理内容安全、模型操控检测和数据泄漏识别，企业只能自行拼凑方案。

解决方案：OpenGuardrails 提供一个统一模型（含上下文感知的安全与操控检测）加独立 NER（命名实体识别）数据泄漏管道，支持企业级部署，完全开源。

价值：降低企业自建 AI 安全层的成本，提供可审计、可扩展的防护基础设施。

未来方向：扩展对多模态输入（图像、音频）的安全检测。

AlphaProof Nexus（DeepMind）：求解 9 个 Erdős 开放问题，证明 44 个 OEIS 猜想

现状：AI 数学系统过去主要针对考试题和 benchmark 题目优化，对真实数学研究中的开放性猜想无能为力。

问题：LLM 生成数学证明时容易产生幻觉（hallucination，即看似合理但实则错误的推导步骤），缺乏可靠的验证机制。

解决方案：AlphaProof Nexus 将 AI 生成能力与 Lean 形式化证明助手（一个逐步检查每个逻辑步骤是否严格正确的系统）结合，AI 提出证明思路，Lean 验证每一步，错误的证明直接被拒绝。结果：求解了 353 个 Erdős 开放问题中的 9 个（含两道已悬而未决 56 年的问题），并证明 OEIS（整数数列百科全书）中 492 个猜想里的 44 个。

价值：每道题成本仅数百美元，证明 AI 已能参与真实数学研究，而非仅作为解题工具。

未来方向：将方法迁移至其他形式化证明语言，扩大可攻克问题的范围。
